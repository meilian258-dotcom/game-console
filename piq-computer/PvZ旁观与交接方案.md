# PvZ旁观与控制权交接 · 下一项方案

2026-09-26，用户希望旁边玩家能观看、可交换鼠标。此文件是方案，不是已完成的功能；电脑prototype.2仍为本机运行。

## 推荐行为

- 开机并启动PvZ的客户端为主持者，独占运行核心及自己的存档。其余玩家只看音画，不要求提供main.pak；不传游戏资源或存档。
- 默认不允许抢操作。旁观者申请交接，当前操作者明确同意后，服务器先撤销旧票据、释放全部键鼠，再签发新票据。主持者可收回操作；只有一人能输入。独立的键鼠持有者不等同存档所有者。
- 先支持同一服务器、同维度附近旁观；超距、断线、破坏/拔线/关机清除观看/输入权限。主持离开则正常结束并保存，不自动迁移存档或换主持。
- 原“Esc暂停”要按共享会话重新定义：操作者退出先松键，旁观不能暂停主持程序；无操作者时是否暂停由主持控制。

## 已核对的复用点与缺口

FC75公开 `WatchMediaStream` 已有异步音画编解码、分片接收/输出队列、video/audio读取。它**没有**网络权限、观众身份或座位管理，不能创建实例就把流发给任何人。需要电脑自己的有界消息、距离/设备UUID/主持票据校验、订阅租约、流量限制和观众清理。

现PvZ7 `PvzRuntime` 公开 poll/releaseFrame 可以取RGBA；但PCM在私有read→audio队列→本机playAudio消费，**没有公开音频tap**。必须新增受控出口或共用后端接口，不能由第二个消费者抢原音频队列或截取整机系统声音。音频44100Hz，现媒体桥使用pcm48k，需要有界重采样及统一时间戳/时钟设计。

`ComputerEntity`/`InputLease` 已有单人占用和过期保护，可保留硬件/领地校验，但共享会话必须把“主持执行者”和“当前操作者”拆开；当前原型pc.operator改变会终止本机程序，不能只改这个字段就交接。

## 分阶段验证

1. 扩展PvZ媒体出口，不改变原播放盒行为及存档布局，测试音频不重复消费/不泄露其他应用声音。
2. 同服旁观的授权与音画传输；800×600缩放/编码预算、无观众停止发送、音画时钟和慢网背压。按实际字节量测带宽，不宣称零流量。
3. 申请/同意/拒绝/收回控制；票据换代、旧输入拒绝、快速按下/松开、主持优先与失焦保护。
4. 真实三客户端：主持、操作者、只读观众；重进/失焦/断网/关机/保存验证。没有这些证据前不标稳定。

不需要先把PvZ改成确定性Netplay。这是“一份游戏＋音画串流＋独占远端输入”，更符合目前想要的旁观和轮流操作；带宽、延迟与画质有取舍。
