## 2. 现成方案和来源

阅读日期 2026-10-03：

- [Libretro docs](https://github.com/libretro/docs)与 [Genesis Plus GX 文档](https://docs.libretro.com/library/genesis_plus_gx/)：核对 MD 内容、保存与 Netplay 声明；该声明是选型依据，不代替本模组适配测试。
- [Libretro 核心开发：序列化与线程](https://docs.libretro.com/development/cores/developing-cores/)：恢复供回滚使用，调用由同一个原生拥有线程执行；完整状态和实际一致性须另外检查。
- 当前 [MD3 GX 记录](MD3-GenesisPlusGX.md)：核心固定 `c2838c7dc4236fc2fe94e5dbd08b41486067918e`，DLL SHA `9ffa10a115b20e1b49e9caf0b53f287c640ed4e5bb93f7ed9a23b416a4ccfdf7`。旧回滚探针有 RAM／音频差异，SRAM 不在即时状态中。本轮不靠放宽断言或把字段排除掉来判通过。
- 公共 [运行器说明](../../piq-retro-platform/README.md)、[全组件技术总览](../../piq-fc-arcade/design/全组件运行流程与复用接口总览.md)、FC/SFC/原生街机 Netplay 调用链。采用现有房间、传输、时间线和授权内容，不复制下载协议或专有桥。

| 方案 | 结论与边界 |
| --- | --- |
| 继续使用 MD MEDIA | 保留旧业务与旧档；不满足本轮 JNI Netplay 目标。 |
| 直接复制 FC NetplayClient | 不采用，含 FC 内容／端口／保存私有假设。 |
| 复用公共 JNI session 与服务器权威输入 | 已接入，MD 两个真实端口，远端运行同一核心及种子／输入时间线，不是接收模拟视频。计算主持不强制等于 1P。最终制品仍待验证。 |
| 给按钮解锁但不接核心与生命周期 | 不采用，不满足任何模式验收。 |

输入策略必须明确：服务器权威输入需要“操作者→MC 服务端→计算主持→其他模拟端”的传输；远端以确认帧运行，**不能宣传本地预测的低延迟效果**。回滚与完整恢复基础仍须独立验证，不能因当前策略使用确认输入而忽略损坏状态／晚加入或保存问题。

## 3. 复用合同与安全边界

- 准备：复用 HomeLaunch 请求代次、连接和内容身份；新增公共 JNI 主持 `waitForActivation` / `activate()` 门，准备／恢复完成后 `ready()` 可报告，但服务端确认之前不公开运行、输入或写回。取消只 abort，旧调用默认自动激活保持兼容。
- 输入：复用现有服务端租约和 Netplay authority 路径；公共适配按核心真实 1～4 端口运行，未用端口必须为零。MD 配置实际为两口，不虚报四口。
- 内容：复用已授权分片与限额；远端取得内容不隐式启动普通 MEDIA 引擎。只读旁观票据不能授予操作者或保存权限。
- 保存：新 JNI Netplay 身份与现有 MEDIA／私人／旧核心档隔离，不改原身份算法或静默转换。档主来自本次开局确认，不随取还 1P／2P 或计算者改变。持久化成功与原生关闭分别确认。
- 菜单：公共 JNI 模式与 RetroArch 模式分开；附属明确声明和持久配置。门禁未通过不开放，禁用不能作为完成标准。

公共 API 详细合同见[接入接口 FC76.35 节](../../piq-fc-arcade/design/Netplay附属接入接口.md)。MD 只取内容使用 `ContentCardClient.expectDownload/cancelDownload` 与服务器 `ContentCards.downloadOnly`，仍沿本次实体席位／观看许可，不创建普通 MEDIA 播放器。准备／激活之外另增加远端 `SeatReady`：等自己的 ROM、核心、种子恢复完成后才确认输入就绪，服务器复核原 wire／connection／port／loan；下载权限不依赖此确认，避免等下载才能就绪、又等就绪才能下载的循环。

当前明确边界：本轮 JNI Netplay 的实体 RESET 不做主持单端重置，提示正常关机保存后选择从头开局。普通 MEDIA 的已有 RESET 不变。该同步重置缺项须保留，不宣称 MD 完整功能全部完成。

## 3.1 独立核心修复依据

旧固定 GX 的失败不是按钮问题：恢复后真实 68K RAM／时序发生差异，SRAM 未跟快照回滚，PCM 长度/样本不一致；两个 DLL 实例还在 YM2612 派生指针字段产生地址差异。增强晚加入测试进一步发现 libretro 前端尺寸缓存未恢复，导致主持 320×224 而新加入首帧 256×192。

新核心单独命名、固定来源与 SHA，加入原快照遗漏的 CPU 刷新／预取、六键握手、SRAM／EEPROM 协议状态、FM 和完整 blip 音频历史、滤波及前端几何状态。派生指针按同一源码的重建规则处理，不把其他实例内存地址当作游戏状态；没有简单屏蔽未知差异、放宽比较或只给菜单解锁。详见[核心补丁与重建](../native-genesis-netplay/README.md)。

原 MEDIA／私人 GX 及 BlastEm DLL 不替换、不迁档；新模式使用 `md-netplay-saves/v1`，同样按个人总三槽或卡带 CardId 一份进度。存档库按当前 ROM 的对应身份分别列出串流和 JNI Netplay，避免误把模式切换当作旧档丢失。

## 6. 安装、选择模式和试用顺序

1. **备份世界与已有存档，退出游戏后换包。** 客户端和服务端同时换成 FC `0.31.0-alpha.76.35` 与 MD `0.1.0-alpha.11`；不能保留同一 modId 的旧 JAR。内容协议为 `content-card-6`、MD 公共协议为 `md-public-4`，不能只升级一端。安装端依据是 MD 方块／实体／公共服务与双方网络注册，不是仅凭依赖项 `side`。
2. 运行环境仍为 Minecraft 1.21.1、NeoForge 21.1.236+ 的 21.1 系列、Java 21。此次原生核心仅 Windows x64 客户端；服务端不加载它。沿用已安装的完整 SFC43/core9、街机1.5.5、GBA14、电脑11、PvZ11，不为本轮重复安装薄包。Flash/PvZ 不纳入本轮业务适配。
3. 主机完全关机并等保存结束，由有权限的玩家用螺丝刀打开 **MD 设备设置 → JNI Netplay（试验 / 本机确认）**。这是新增的第五种独立选项，不是点击 RetroArch Netplay。服务器必须允许本地核心同步；权限、忙碌、本机禁用及不支持平台各有原因提示。普通本地输入同步／服务端托管／RetroArch Netplay 仍未接入 MD，继续禁用。
4. 本次连接要使用公开会话，不选私人模式。之前显式用 `/gameconsole-jni-netplay off` 拒绝本机 JNI 的玩家，可用 `/gameconsole-jni-netplay` 恢复；服务器选项不能替玩家撤销本机拒绝。JNI 原生故障可能使 Minecraft 整体崩溃，不能承诺进程级隔离。
5. 沿既有实体流程：拷卡／确认游戏人数和存档方式 → AV 接电视并开电视 → 插卡 → 点主机电源 → 按需选档 → 独立确认本局是否允许 2P → 加载／恢复 → 就绪 → 领取对应手柄。NONE 双人内容也有独立 2P 许可；单人内容不会凭空开第二口。
6. 2P 和附近旁观端会取得获准的同一 ROM、固定核心身份和种子，在各自客户端运行同一局。远端未下载／恢复就绪前不接受输入；旁观只读，不因本地存在核心而获得写档或操作席。双方必须满足相同核心资源与平台要求，不再是 MEDIA 的“旁观只看视频”策略。
7. 正常关机要等待服务器确认保存和原生会话退出，之后再插拔卡或换模式。本轮 JNI Netplay **不支持同步 RESET**：使用正常关机后从头开局；不会偷偷只重置主持端。旧 MEDIA 的 RESET 不变。

新模式使用独立 `md-netplay-saves/v1`。个人档仍按玩家、MD 全体游戏合计三槽；卡带档仍跟同一 CardId，不因借还手柄而换档主；不存档模式不产生进度。MEDIA 的 `md-public-saves/v1` 和私人／旧核心档完整保留，不自动导入新模式。切回原模式继续原进度，不要把新模式空槽误认为旧档丢失。

### 如果 JNI 选项仍不能改

- 页面没有第五项 JNI Netplay：先核对客户端和服务端实际加载的 FC76.35／MD11，而不是只确认下载文件名；退出旧游戏进程再使用新版本。**也可能是服务器 `allowLocalSync=false`**：当前未选 JNI 的附属页面会隐藏该行，不能单凭缺行判断包旧。由服主核对下一条配置，确认启用后重新开页。
- 提示服务器未允许：由服主核对当前世界加载的 `serverconfig/piq-sync-server.toml` 中 `allowLocalSync = true`（源码默认值为 true）；这是同步准入开关，不代表 MD 的普通“本地输入同步”模式也已实现。不要用启用服务器托管代替。
- 提示运行／保存中或权限不足：等待主机正常关机、存档窗口关闭和保存完成，再由 OP2 操作。不得为让按钮变亮而跳过正在保存的会话或保护检查。
- 显示 JNI 已勾选：当前项通常禁用以防重复提交，直接按实体电源试用；如果本机曾关闭许可，当前 JNI 项仍可点击恢复，不代表设备设置未保存。下方“2P：开局选择”是流程说明，双人许可仍在每次适用开局时确认，不在这里改成永久准入。
- 本机显式拒绝或平台不支持：按上面的本机命令恢复许可；只有实际受支持的 Windows x64 才能运行，不支持的平台不会静默改用串流。
- 窗口过小只显示关闭并提示缩放：降低 GUI 缩放或扩大窗口后重新打开，不根据这个紧凑提示页判断模式能力。
