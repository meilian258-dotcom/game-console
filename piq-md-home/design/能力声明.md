# MD2 附属能力声明

## 当前开发变更：BlastEm 已退役（2026-10-04）

- 当前执行核心只有原 Genesis Plus GX（MEDIA／私人 JNI／PROCESS）与原 Genesis Plus GX PIQ Netplay（显式 JNI Netplay）。移除 BlastEm 正常选择、可执行 profile、旧输入／恢复分支及新包内 DLL；旧标识明确拒绝，不静默切核。
- 两颗 GX 的固定字节、选项、端口、保存命名空间和原公开默认不变。保留旧 BlastEm 存档、历史制品／原始库和许可证据，不读取或迁移旧档。`BLASTEM` 仅为能明确报退役原因的拒绝标记，不是可运行能力。
- 原公共开局／2P／保存／旁观仍沿下方 alpha.11 与 alpha.12 实现；同步 RESET、CD／32X等原未完成项没有因此补齐。版本／最终交付另由本批记录确认，自动测试与真人验收分开，详见 [退役与验证记录](BlastEm退役-20261004.md)。

## 既有 alpha.11 / FC76.35 基线（2026-10-03，JNI Netplay 实验候选）

- 保留默认公开 MEDIA 和原私人本机模式，新增共用设备页的显式 **JNI Netplay** 设置；旧机器不强迁、无失败后自动公转私或换核心。普通本地输入同步、服务端托管、RetroArch Netplay 仍未开放，不能只按 JNI 字样推断运行模式。
- 两端配套 FC76.35 / MD11，`content-card-6`、`md-public-4`、`home-launch-1`；新旧 MD 协议不混用。原生执行端 Windows x64 / Java21；专服管理房间与保存，不执行本轮 MD 原生核心。本机 JNI Netplay 禁用许可仍有效。
- 复用 `HomeLaunchServer/Screen`：实体与内容校验 → 按需选档 → 双人内容独立 2P 确认 → 加载／恢复 → READY／激活。内容最大人数、存档单双人标签和本局 2P 许可独立；NONE 双人也确认。取消／失败撤销未激活写权限，正常关闭同时等待最终服务器持久结果与核心释放。
- 复用 `NetplayProcess`／房间／Watch 与 `ContentCards.downloadOnly`，两真实端口、原物理手柄租约和公共输入映射。计算主持不强制等于 1P；远端操作端与旁观端是无保存／直接输入权限的只读复制核心，操作端另以原租约上报按键。每个远端须完成 ROM／种子恢复并确认就绪后才可输入；不是 MEDIA 编码视频，也不是低延迟本地预测保证。
- 使用独立 `MdNetplayProfile`、固定的 Genesis Plus GX PIQ Netplay 核心与选项；48kHz 呈现、两个六键设备。MEDIA／私人仍使用原核心、资源与身份，不静默更新旧档。许可证及固定源码见[本轮记录](MD-JNI-Netplay-20261003.md)和[核心重建说明](../native-genesis-netplay/README.md)。
- 新服务器进度根 `md-netplay-saves/v1` 与原 `md-public-saves/v1` 隔离；各命名空间个人总三槽／卡带 CardId 一份，不是每 ROM 三槽，也不合并旧命名空间。存档库明确区分模式；旧私人档不上传、不迁移。旁观与远端操作者不得直接写主持存档。
- 延续 MD9 本人／附近公开按键动画与 MD10 公共业务，动画仍来自服务器验证的 canonical 输入；私人按键不外发。本轮 JNI Netplay **同步 RESET 未支持**，明确提示正常关机保存后从头开局，MEDIA RESET 不变。CD／32X、额外外设、服务器托管等未因此完成。
- 独立核心和真实公共多实例会话门禁通过，已开放源码能力；最终包、实际测试数字和交付状态统一见[MD11 验证记录](MD-JNI-Netplay-20261003.md)，不沿用旧测试数。Minecraft 真人双客户端、保护插件、输入与视觉、弱网／长时待验，仍为实验候选，不标稳定。

以下版本声明均为历史，不覆盖顶部现状。

## 历史 alpha.7 / FC76.32（2026-10-02，测试候选）

- 在既有实体机器／卡带／工作台／AV 基础上增加玩家主持公开音画串流、两端口及附近旁观。默认 GX/JNI，ROM 仅主持下载和运行；2P 的输入与媒体按实际手柄租约授权，旁观没有操作／保存权限。
- 服务器个人总三槽、卡带 CardId 进度、不保存、选档、继续／重新开始、存档库改名／确认删除接入；周期、手动、正常关机保存等服务器确认，旧私人本机档不迁移。同一玩家全部三槽／同一卡只有一个写者。
- 复用 `HomeSystems`、`ContentCards`、`WatchProviders`、`WatchMediaStream`、`CabinetMediaSender`、`NetplaySaveServer/Client` 及 `CartridgeSaveScreen`；MD 提供会话、双端口、核心和保存归属适配。保存传输名称含 Netplay 不代表实现了 MD Netplay。
- 主持与手柄占用分离：单端口超 6 格只释放该柄；主持暂时不看电视不应终止附近其他人的会话。主持掉线、跨维度、硬件卸载／失效不能无缝接管，最近已确认检查点保留。
- 新协议两端配套 FC76.32/MD7，服务器不运行原生核心；实际执行端 Windows x64、Java21。私人兼容路径仍需显式选择，失败不自动公转私、不迁移进度。
- 本地同步、服务器核心托管、Netplay、CD/32X、更多外设及精细实体按键动画未开放；不把上游支持当作模组已完成。核心许可和固定 SHA 不变。
- B01～B16、适用 C 项、操作和分层验证以[本轮记录](MD公开会话与服务器存档-20261002.md)为准。真实双客户端、保护插件、远近返回、弱网和长时仍待验，不标稳定。

## 历史 alpha.2 / FC76.27（2026-09-30）

- 增加服务器内容卡：老式电脑服务器目录选取 / 本地明确上传写卡、不可变 SHA256 内容身份、8 MiB 普通 MD ROM 上限。全服读/上传权限沿用管理终端；不是卡带内嵌 ROM，不做跨服自动搬运。
- 实体电源经公共按钮/遮挡/保护校验、MD 借用租约和内容校验后启动既有运行器。默认 JNI；本机本次连接可显式改兼容进程，不能运行中切换或静默失败回退。
