# 方块电玩 Git 接管计划

2026-09-29，Codex。用户明确要求“给源代码的版本控制转向标准的git”。

## 范围

以当前工作区为本地单仓库根，白名单管理方块电玩11个源码组件，保留同级目录和既有构建相对路径。现有空`.git`目录不是有效仓库、没有历史可迁移；只建立真实的当前基线，不伪造历史提交或稳定版本标签。其他MOD、管理服务、工作台数据、部署脚本和凭据不纳入仓库。

R01：建立main分支和当前源码初始提交；R02：忽略缓存/制品/游戏/用户数据与凭据；R03：建立提交前检查、日常分支/提交/回滚规则与外部制品清单；R04：校验提交/克隆/文件未变，更新维护与本地项目资料。

## 不包含

不修JNI或其他游戏功能，不搬迁/删除现有源码、素材、制品或用户数据，不上传远程，不创建远端仓库，不改全局Git配置，不发布或重启服务器。本次Git基线不是稳定发行；历史打包依赖及未通过真人验收状态保留。

## 验收

1. 只提交白名单源码、测试、构建脚本、模型资源、许可与文档；提交清单检查大小/敏感文件/可疑密钥字面量。
2. 初始基线从真实磁盘捕获，元数据审查后提交；Git对象回读与工作文件SHA一致，不能用忽略规则隐藏本次修改。
3. 本地独立临时目录克隆、git fsck、提交前检查与策略测试通过；已存在文件除明确的规范入口变更外字节不变。
4. 生成本机Git bundle备份，记录可恢复位置；不把同盘备份当远程灾备。
5. 维护手册、管理台项目文档入口回读；无新MOD/JAR，不变更成品版本、稳定标记或假报构建成功。
