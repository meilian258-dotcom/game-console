# SFC JNI 核心候选验证

2026-10-11，维护者：像素匠 / 方块电玩维护组。

SFC52 的固定 Mesen-S 核心在指定内容的状态恢复和双人回滚测试中出现不一致，仍不能作为 2P 断线修复版发布。未修改的上游 Snes9x 已通过下列隔离验证，但尚未接入 SFC 玩家包；旧核心、保存身份和默认运行路线保持不变。

## 候选来源

候选取自 [Libretro 官方 Windows x64 nightly](https://buildbot.libretro.com/nightly/windows/x86_64/latest/snes9x_libretro.dll.zip)，取得日期为 2026-10-11。运行时报告 `Snes9x 1.63 fae2fea`。DLL 为 3,840,000 字节，SHA-256 为 `5ce01616184f255623405793e192f79aef5089fa796b29bc11ddc5e052060124`；归档 SHA-256 为 `af334c14699af8784f751223d6ee63a0c22226eaa95d448dd95d3543452ff845`。测试不修改 DLL，不重编模拟器核心。

[官方说明](https://docs.libretro.com/library/snes9x/)列出的 Netplay 能力用于选型，不替代本模组验证。适配使用现有公共 JNI 会话、双标准手柄端口和固定核心选项，并未接入 RetroArch 前端或其 Netplay 协议。

## 已通过的隔离验证

验证使用指定内容和原有 FC76.46 公共 JNI，以独立测试 JVM 运行，不访问玩家存档。

| 场景 | 实际结果 |
| --- | --- |
| 状态恢复对照 | 前 300 帧与恢复后 120 帧，逐帧原始状态、RGBA、PCM16 及音画元数据完全一致 |
| 只读保存对照 | 相同帧范围，序列化及读取保存内存不改变状态、画面或 PCM |
| 双人完整流程 | 双向各 50 ms 延迟，2P 加入、晚旁观、2P 重连、手动与最终保存、重开续帧通过；CRC 保持启用 |
| 变化输入 | 固定延迟下双端至少各 1200 帧通过，产生实际回滚重演，不只测试固定按键 |
| 资源收尾 | 上述测试结束后全部 4 个公共 JNI 槽位归还，输入文件身份保持不变 |

完整联机流程验证的是确认状态 CRC、非空立体声及输出采样率；它不是双端逐帧 PCM 对照。逐帧音频一致性来自前两项独立对照。

## 待解决的发布条件

有序 25～75 ms 抖动测试另暴露公共会话推进时的回滚历史容量错误，首轮以 `Rollback history exhausted` 退出，而非核心 CRC 不一致。定向夹具在 FC76.50 上稳定复现四帧追赶中的第三帧失败；FC76.51 增加推进前的容量保护，先校验到期 CRC、仅回收已确认的旧历史，容量仍不足则等待，不发送或消耗本帧输入。32 帧历史、2 MiB 状态上限、原超时与 CRC 校验均不变，原失败记录保留。

FC76.51 完整 `check jar` 通过：2947 项测试，0 失败、11 跳过，并通过原打包核心烟测。与同一未修改 Snes9x 候选配合，固定延迟 1200 帧、有序抖动 1200 帧、有序抖动 6000 帧三轮变化输入测试均无 CRC 或容量错误。6000 帧测试约 113 秒，主持和客户端分别重演 25670／3636 帧，全部 JNI 槽位归还；这属于短时双端隔离验证，不是长局稳定性验收。

同一 FC76.51 最终 JAR 的双人、晚旁观、重连、手动与最终保存、重开完整隔离流程也已复跑通过。FC76.51＋完整 SFC52（core11）＋MD16 在 NeoForge 21.1.236 专服完成三包四 ID 的加载和正常退出；SFC52 仍是旧核心，不把这项专服检查当作 Snes9x 已接入或 Minecraft 双人验收。

候选尚未覆盖 Minecraft 双客户端、真实手柄租约、自动旁观发现、显卡、声卡听感、长局及其他游戏。核心接入还需为控制者和旁观者发放相同可信变体，隔离新旧保存身份，并保留清晰的旧核旧档入口；不得静默覆盖 Mesen-S 或转换旧进度。
