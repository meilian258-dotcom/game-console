# 方块电玩 SFC 附属

这个附属增加 SFC/SNES 家用主机、卡带和两只手柄，复用方块电玩主模组的电视、视频线、老式电脑工作台、遥控器和调试工具。它也为通用街机提供 SFC 游戏选项，但家用机与机柜的多人能力不同。

第一次安装先看[玩家指南](../piq-fc-arcade/docs/玩家指南.md)。本页只说明 SFC 的区别和限制。

自有适配代码保留 GPL，并在[有限链接许可](../piq-fc-arcade/SNES9X-LINKING-EXCEPTION.txt)列明的范围内允许与固定 Snes9x 组合。Snes9x 的非商业条件及其他组件许可不变；[源码与运行库通知](third-party/snes9x-runtime/NOTICE.md)说明所需发行材料和当前边界。

## 需要安装什么

- Minecraft 1.21.1、NeoForge 21.1.229 或以上兼容的 21.1 版本、Java 21。当前原生游戏运行端为 Windows x64。
- 客户端和服务器都安装配套的方块电玩主模组与 **完整 SFC 附属包**，名称形如 `game-console-sfc-版本.jar`。
- 完整 SFC 包已经包含家用组件和历史 SFC 核心组件，保留两个注册 ID。不要再叠加安装旧 SFC core 包。
- 本目录 `build/libs/piq_sfc_home-*.jar` 是开发薄包，不是完整玩家安装包；也不需要另装内部公共平台或 RetroArch。
- GitHub 的源码 ZIP 不能直接放进 `mods`。公开下载以[下载中心](../piq-fc-arcade/docs/下载中心.md)实际附件为准；本地 FC76.57／SFC55 按[本批候选说明](../piq-fc-arcade/design/旧本地同步退役.md)及交付清单操作。2026-10-07 整套清单只是历史配套，不能拿其中旧主包搭 SFC55。

当前源码为家用 `0.1.0-alpha.55` 本地开发候选，完整包沿用 core11，因调用新增公共检查接口，配套主包至少为 FC76.57。公共设备设置、选档和 SFC 协议分别为 `home-sync-6`、`home-launch-3` 和 `15`，客户端和服务端须使用同批配套主包与附属，不能只换一端。此候选尚未公开发行；更新前备份世界、配置和 `game-console` 数据。历史核心路径处理见 [SFC51 说明](design/SFC51-核心路径隐私说明.md)。

## 怎样开始游玩

1. 准备 SFC 卡带和自己有权使用的 `.sfc` 或 `.smc` 游戏。FC 黄卡不能代替 SFC 卡带。
2. 持 SFC 卡带右键老式电脑，通过工作台选择本地或服务器游戏并确认写入。上传和修改人数受服务器权限控制。
3. 用视频线连接 SFC 主机与电视，插入卡带，打开电视，再点击主机实体电源。
4. 按当前模式选择可用进度；开局读取本设备的 2P 许可，不再逐次弹出双人确认或加入审批。等待加载完成后领取或使用本机手柄。
5. 使用公共控制设置里的 SFC 配置调整按键。归还手柄是退出操作；正常关机才结束本局并执行适用的保存。

本地 ROM 和封面目录以工作台按钮为准。家用服务端内容在实例根 `game-console/world-content/<世界scope>/piq-sfc-home/` 下，仍按世界隔离；它不是玩家存档目录。

## 多人和存档有哪些区别

家用设备默认允许 2P。管理员可在关机且没有开局或保存任务时，用螺丝刀进入设备设置，将“2P：允许／禁止”按设备保存，下次开机生效。旧设备缺少这项新字段时也按允许处理；旧的加入审批字段不再控制逐次申请。允许 2P 不会绕过卡带人数、私人模式、手柄占用、距离、交互权限或加入同步检查。

在全服新机策略保持“自动”且 JNI 可用时，新放置的 SFC 家用机默认选择“JNI Netplay（试验 / 本机确认）”。已保存设备的显式模式保留，不因升级改为新默认；有权限的管理员仍可在设备空闲时选择其他已接通模式。SFC55 不再提供旧“本地输入同步”的新选择；若原配置选中了旧路线，菜单说明已退役，服务端拒绝新开局并要求管理员重选，不自动换核心或迁移旧档。未实现或被策略禁用的其他模式仍保持不可选。SFC 旧菜单中标作 RetroArch 的那条路线实际已经使用 JNI；真实 JNI 标志及旧字段兼容读取均保留，**不表示已接入 RetroArch Netplay**。

- 家用 JNI Netplay 支持按开机玩家或实体卡带保存，也可不保存。SFC53 新进度和不保存开局使用 Snes9x，每游戏保留该核心的一份对应进度，不是三个通用槽。
- 有合法的 Mesen-S 旧进度时，选档页另外显示“旧进度（回滚风险）”，只可继续，不能从这行新开旧核心进度。旧核心的回滚风险仍在；新旧档各自保存，不转换、不互相覆盖。旧档损坏时停止该次保存开局并保留文件，不悄悄当空档处理。
- SFC54 工作台提供“存档设置”和“存档库”。前者选择不保存、个人或卡带；后者复用公共页面，只读展示当前持卡及本人可见的新旧核心进度。现有格式不支持在库中改名、删除或三槽管理，页面会说明限制，不更改旧保存身份。
- 玩家串流、服务器托管和私人模式的保存仍有各自规则。旧本地同步的进度文件保留，但不能通过新开旧路线继续运行。私人本机档、恢复备份与服务器个人或卡带档不能互相当作同一份进度。
- 家用 JNI Netplay 已接入按机器区分的公共旁观；家用支持不代表通用 SFC 机柜也支持 Netplay，后者目前尚未接入。
- 老 WASM、Mesen-S 与 Snes9x 档不自动转换。核心或模式不兼容时，不要通过覆盖文件来强行恢复。

高级同步设置由有权限的管理员在设备空闲时调整，通常下次开机生效。服务器托管还要求服主允许且运行平台满足条件，不是每台服务器装上附属就会自动运行核心。

## 当前状态

SFC55 配合 FC76.57 退役独立旧同步选择和公开开局，保留现有 JNI Netplay 与私人模式。原核心、存档身份及旧 JNI 字段兼容读取不变。实施边界与本轮验证见[旧本地同步退役](../piq-fc-arcade/design/旧本地同步退役.md)；下列 SFC54／53 记录是沿用基线，不是 SFC55 的新增实机结果。

SFC54 还移除了机壳前盖的品牌标识；只改独立展示面，不动核心、插口、碰撞或存档。工作台和外观的最新验证见[设备体验候选](../piq-fc-arcade/design/设备体验与PGM运营设置-20261012.md)。下列 SFC53 核心验证仍作为沿用基线，不代表本批的完整游戏验收。

FC76.52／SFC53／MD16 是未发布本地候选。构建、独立核心验证和 Minecraft 真人验收分开记录；图形、声音、自动旁观、弱网和长期运行仍需按实际组合测试。

原 Mesen-S 核心存在中途状态恢复失配，真实输入回滚可触发 CRC 分歧和 2P 退出；不只涉及保存或晚加入旁观。SFC53 在公共 JNI 中接入独立 Snes9x 变体，新开局、2P 与旁观一致使用服务端冻结的变体，不能由客户端随意换核。原 Mesen-S 入口只用于兼容旧进度，并不表示旧核心问题已修复。

实现、固定来源及验证范围见 [SFC JNI 核心候选验证](design/SFC-JNI核心候选验证.md)。遇到退出时应保留双方及服务器的对应日志或复制设备诊断；不要关闭 CRC 校验、放宽超时或覆盖旧存档来规避。切换模式不会自动迁移原 JNI 存档，临时可明确选择已有玩家音画串流。

SFC 家用普通串流、服务器托管及私人模式仍使用 Mesen-S；SFC53 的核心变更只涉及家用 JNI 新进度。SFC55 已停用独立旧本地输入同步的新开局。完整包中的旧独立街机保留 jgenesis/WASM 兼容链，它们的玩法、保存和旁观不能互相推定。
