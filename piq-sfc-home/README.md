## 安装

客户端与服务端均需安装以下正式交付包：

- `game_console-0.31.0-alpha.67.jar`：基础模组；SFC37 的最低依赖为 FC67，提供附属模块核心资源读取入口。
- `game_console_sfc-0.1.0-alpha.37.jar`：SFC 附属完整包，内置 Windows x64 Mesen-S 核心，保留原 SFC core9 的注册/资产及历史原型入口。

安装端依据是两端注册的 SFC 物品/方块、服务端会话与协议处理以及客户端输入、画面和核心运行逻辑，而非仅依据依赖元数据中的 `side` 字段。

不要额外重复安装相同 MOD ID 的旧 SFC 核心，也不要直接拿 `build/libs/piq_sfc_home-*.jar` 薄开发包替代完整交付包。源码构建引用 FC67 与原 `piq_sfc_arcade-0.2.0-alpha.9.jar`；完整成品由精确冻结流程合并，不代表玩家要自行安装三个 JAR。不另装 RetroArch 或 Wasmtime 运行库。

更新前正常退出、安排停服并备份实例/世界/存档，将旧同 ID 模组移到实例外保留，再成套更新两端。SFC 主协议为 10；请统一使用本轮配套版本。先在副本测试，不混装 Flash prototype.8。本文不表示已经安装、部署、发布或重启任何服务器。

## SFC33 玩家上传与游戏库

OP2 使用 `/gameconsole content` 分别设置 ROM/封面上传与所有玩家/UUID名单访问范围，两个上传开关默认关闭。
授权玩家持卡右键电脑可查看服务器已有 SFC 游戏并写自己的卡；浏览不是管理员权限，人数仍由OP设置。
运行会话自动下载不变；未提交上传在撤权后取消，已提交后台的文件可能完成入库但不再写卡，不删除历史文件。
详细命令、安装与测试清单见 `../piq-fc-arcade/design/玩家上传与游戏库-FC55-SFC33-测试说明.md`。

## 使用入口

1. 使用 SFC 主机与灰色 SFC 卡带，FC 黄卡不能互换。通过写卡电脑的既有界面导入或选择自己有权使用的 `.sfc` / `.smc` 文件，填写卡带设置。
2. 用视频线连接主机与电视，插入写好的卡带，按现有实体电源和手柄交互流程开机、借取控制器；游戏自身仍需选择合适的单人/双人模式。
3. 遥控器用于电视显示/声音设置；主机同步模式等高级设置由 OP2 在主机空闲时用调试螺丝刀调整，下次开机生效。
4. 按键使用公共输入设置中 SFC 配置，支持重绑。打开菜单、失焦或切出手柄时释放输入；归还手柄与关闭整台主机不是同一个操作。
5. 不要在运行中拔视频线或拆设备来代替正常退出。更新或故障测试前先保留可用的世界与备份副本。

不提供商业 ROM、原厂 BIOS 或其下载链接；模组免费。媒体接收端无需为该会话下载 ROM，但主持仍须按既有游戏库流程准备有权使用的文件。

## 同步模式与存档边界

| 模式 | 核心运行位置 | 存档/恢复能力 |
| --- | --- | --- |
| 本地输入同步（默认） | 参与运算的客户端 | 运行玩家本机恢复备份，不自动恢复，不是服务器卡带档 |
| 玩家音画串流 | 开机主持的原核心；远端只收音画和发授权输入 | 主持本机恢复备份，不自动恢复；远端不产生完整核心备份 |
| 服务端托管音画 | 服务端核心 | 独立服务器 SRAM，不是本机完整即时状态备份 |

玩家托管需服务端 `piq-sync-server.toml` 允许 `allowPlayerHosting`；服务器托管还受配置和平台/核心运行条件限制。切换模式需要管理员权限、设备空闲及原交互保护校验，不能靠客户端强行解锁。

主持和 P1 控制者是不同职责。主持归还手柄后可继续后台运算；主持断线安全停机，不自动换主持。旁观没有输入权限。切到个人背包只暂停输入，仍保留合法租约时音画可继续；丢弃、转交、复制、越界或权限失效仍按原规则处理。

## 沿用 SFC32 可靠性改动

- 媒体接收端首帧等待最多约 60 秒；已有画面连续约 3 秒不更新时暂停输入，约 15 秒仍无有效视频则退出本端控制。时间从最后一帧成功解码的视频计算，音频和碎片不能保活。恢复后需先松键再操作，不自动重开游戏。
- 本机音频输出失败显示提示，说明游戏仍在运行；检查系统设备、正常关机重开后可重试声音，不因声卡故障擅自结束游戏。
- 调试页明确区分本机恢复备份与独立服务器 SRAM，不再误称 SFC 存档位于卡带菜单或会自动续玩。
- 本机恢复备份改为新会话独立、多代成组提交，具体策略如下；实际构建与人工验收状态仍以最终记录为准。

### 本机恢复备份防覆盖

每个新 SFC 播放会话使用随机 UUID，在游戏目录下写入：

`piq-sfc-home/local-backups/<ROM_SHA256>/sessions/<会话UUID>/backup-<递增序号>-<随机后缀>.zip`

一个 ZIP 包含 `state.bin`、`sram.bin`、`metadata.txt`。完成写入和强制刷盘后原子提交；不把不同代的状态与 SRAM 混合。目录占位、路径不安全、权限或原子移动条件不满足时拒绝新提交，保留已有完整备份。

每个会话在新份成功提交后正常保留最近两份；旧份清理失败时记录警告并保留，最多暂留三份，继续受阻则停止新增。旧 `latest.state` / `latest.sram` / `latest.txt` 与其它会话均不删除或覆盖。

历史会话暂不自动清理，磁盘占用会累积，需要玩家在正常关闭游戏后自行归档。单份状态上限 128 MiB、SRAM 上限 8 MiB。周期和退出备份均为尽力执行，失败不表示已有备份也丢失；应核对最后成功结果，不要以目录存在代替成功证明。

这些文件是恢复材料，**不是自动续玩或服务器卡带存档**。本版没有一键导入恢复包、自动从 ZIP 读档或跨模式迁移功能。不要将 ZIP 改名为旧 `latest.state`；进程崩溃仍可能丢失最近成功备份之后的进度。
