## test.4 编辑预览与声音恢复

本版只改独立客户端补丁，适用 FC76.46／76.49、ReForgedPlay 0.3 与 NeoForge 21.1.250；保留既有 v1 画面／音轨、核心、游戏保存和运行模式。“旁观式预览”是录像时间驱动的呈现，不接通实时 WatchClient，不联网重跑模拟器。缺失的旧画面和声音不能补录，也没有自由镜头空间重混音或有声视频导出。

沿用现有 ReplayFile、播放时钟、音轨和 `ScreenRenderMaterial`，不另造录像容器或引入运行器。此前每像素调用压缩流的整数读写成本较高，画面解码又在整个归档锁内进行，会阻止音频同时取数据；本版在锁内读取有界压缩字节，锁外解码，并用 16 KiB 像素块读写。关闭前后检查、长度／膨胀／尾随校验和所有配额保持。

| 需求 | 本版实现 | 验收与边界 |
| --- | --- | --- |
| 连续预览不反复处理同一画面 | 内容与几何／时刻分离；精确相同像素共享最多 16 个固定纹理槽，只在内容变化时上传 | 纯逻辑和真实编译字节码通过；真实 GPU／帧率待测 |
| 不显示错误时间的残留 | 只绘制当前准确帧；等待解码仅保留分配，不绘制旧图；当前渲染视锥剔除不可见面 | 暂停、seek、关闭、共享来源变化与满槽回归通过；导出相机视觉待测 |
| 短暂拥塞后恢复声音 | 背压／旧代次不标坏轨；后续有效 tick 从当前时刻恢复，声卡异常最多三次延迟重开 | 真实壁钟限速替身与代次回归通过；物理声卡听感待测 |
| 新录像更密集采样 | 每来源目标 20 帧/秒，50 ms 采样时钟保留相位；卡顿不追补，NativeImage 使用现有批量像素拷贝 | 30／60／75／144 渲染回调节拍模拟均每 10 秒采集 200 帧；游戏中实际帧率待测 |
| 旧格式和安全边界保持 | v1 编码未换，损坏内容仍拒绝，源关闭／暂停／退出不串入下一代 | API、旧格式、实际 ZIP、剪切与生命周期回归通过；原录像只读未改 |

总帧数、大小和队列上限没有增加。20 帧/秒下，单屏按 72000 帧估算约 60 分钟、四屏约 15 分钟，其他限额可能更早达到；不能把更高采样率宣传为无限时录制。原约 10 帧/秒录像不会凭本版产生未记录的新帧。

## test.3 改动与范围

test.2 已能记录画面，但原回放器在每次所选帧变化时再次异步读取压缩块，期间返回空列表；画面和就绪状态又分别读取，存在跨线程不一致。这会在连续播放时产生画面空档。test.3 改用原子 `PlaybackView`、有界解码缓存和预读，同块帧直接选取；多个来源分别就绪，不因另一个来源等待而清空整个画面。仍只绘制准确时间的记录，不用无限保留旧图掩盖缺帧。

声音此前未实现。本版增加独立 `piq-audio/v1/` 与纯 Java `AudioReplay v1`。八个既有 JavaSound 最终输出端使用薄适配，保留原调用、返回字节数及异常；阻塞 write 前取得录制/来源代次，返回后只复制实际接受的 PCM。公共输出覆盖的设备不再从核心生产端重复记录。麦克风、系统混音、其他程序与模拟核心不在采集范围。

回放解码及音频设备调用在独立工作线程，客户端只发布时间和控制状态；队列、缓存、分块及轨道大小有上限。暂停、跳转、关闭、非 1× 速度和视频导出清空旧声音。当前只做正向 1× 预览，保留录制视点音量，不重新按自由镜头位置混音，不导出设备声音。归档保存沿 Replay 保存后台执行；15 秒工作线程等待不是底层文件系统永久卡住时的硬关闭保证。

## test.2 修正

test.1 已确认存在新录像无屏幕轨的缺陷，不能仅凭旧版编译和字节码签名检查判断采集有效。Iris 的 `FullyBufferedMultiBufferSource` 覆盖了原版缓冲区方法而不调用父类，导致旧采集入口被绕过；它还在 `getBuffer` 内替换材质参数。仅在返回点补钩子会丢失原始屏幕材质身份。

test.2 用加载器已有的 MixinExtras `WrapMethod` 保留原调用参数，为已核验的 Iris 实现添加可选适配，不修改 Iris、方块电玩主包或核心。未知 Iris 实现不强行接管，输出 Log4j 警告；不装 Iris 时走原入口。世界显示姿态核对使用 NeoForge 实际渲染事件字节码，没有猜测性增加反向矩阵变换。

同时把录制日志接入 `PIQ-ReplayScreen`：启动、首次接受屏幕帧、实际提交的帧/来源/块计数和失败分类。零采集与部分失败保存最多 4096 字节的诊断及警告，不保存本地路径、游戏名、来源 ID 或坐标。空轨剪切/分段保留诊断，正常帧仍沿用原时间重映射。日志不把屏幕轨提交当作外层 `.mcpr` 保存完成。

## 现成实现与最小扩展

本次先检查仓库公共显示链及安装的 ReForgedPlay 0.3，参考上游 [ReForgedPlay](https://github.com/ferriarnus/ReForgedPlay) 与 [ReplayStudio](https://github.com/ReplayMod/ReplayStudio)。Replay 记录 Minecraft 数据包，并不自动包含客户端模拟器产生的纹理。旧公共层没有帧订阅 API，因此旧版使用固定目标薄适配，新机型使用可选公共接口。

复用 ReplayFile 归档、事件、录像时间与导出生命周期，不复制 Replay 本体；复用现有屏幕材质，不全屏截图、不读 GPU 帧缓冲、不回滚模拟器状态。默认剪切处理会重建归档，因此显式保留、裁剪屏幕轨，不只做“存进去”而忽略导出。

当前 API 与适配实现为 MIT；第三方程序未打入补丁，使用者需自行安装对应依赖及遵守其许可。
