# 方块电玩 Replay 画面与声音兼容补丁

这是独立、可选的客户端补丁，为新录制的 ReForgedPlay 录像保存方块电玩的屏幕画面和设备声音。回放只读取记录，不通过重新运行模拟器重建音画。

当前版本为 `0.1.0-test.7`，本批配套 **FC76.54／SFC54／街机1.5.12／电脑 prototype.13**，沿用主包公共回放接口 v1，属于待 Minecraft 实机验收的测试候选。主包提供显式画面、最终音频和只读回放保护入口，补丁不再注入主包的 14 个私有实现挂钩。主包更新后按接口合同判断兼容，不再按主包小版本设置上限。保留约 **20 帧/秒** 新录制与 **1× 设备声音回放**，不修改模拟器核心，不支持有声视频导出，也不自动补回旧录像中未记录的内容。

**FC76.46～76.52 继续使用保留的 test.5；FC76.53 的原配套保留 test.6；本批使用 test.7。** test.6／7 要求主包真实提供公共接口 v1，不能给旧主包单独安装，也不要只删除旧补丁的版本限制。后续主包必须保持 v1 的签名和行为，破坏性升级须提供兼容层或新补丁；附属边界仍须单独核验。独立的快速模式兼容补丁不是同一组件，不用移除。

“旁观式预览”指按录像时间连续呈现已记录的音画，不是连接当前服务器，也不会在编辑器里启动游戏核心。旧录像可受益于读取、显示与声音恢复修复，但原来约 10 帧/秒的录像不会变成 20 帧/秒；要看更高采样率，须用本版重新录制。

## 安装

本候选的目标组合如下。加载器声明的版本范围不等于范围内每个版本都已验证。

| 组件 | 目标版本与安装位置 |
| --- | --- |
| Minecraft | 1.21.1，Java 21 |
| NeoForge | 21.1.250 |
| 方块电玩主模组 | 本批 `0.31.0-alpha.76.54`；公共接口基线为 FC76.53，必须实际提供 v1，未提供或未知接口会在加载时拒绝 |
| ReForgedPlay | `0.3`，客户端模组 ID 为 `reforgedplaymod` |
| 音画兼容补丁 | `game-console-replay-compat-1.21.1-0.1.0-test.7.jar`，仅客户端 |
| Iris（可选） | 已适配 `1.8.14-beta.1+mc1.21.1` 的世界缓冲实现；其他实现未经核验时停用此适配并输出日志，不宣称自动兼容 |

1. 关闭游戏，备份原有录像，在隔离客户端中准备上述组合和需要测试的附属。
2. 将配套 FC76.54 主包按原有两端安装要求更新；只在录制／回放客户端放入 test.7。先备份并移出旧主包与旧音画补丁，不要两版同装，不向专用服务器安装 Replay 补丁。不更换 ReForgedPlay 或模拟器核心。
3. 不要把 `game-console-screen-api-0.1.0-test.7.jar` 放进 `mods`；它只供编译使用。主包公共 API 随主包提供一次，补丁的录像 API 随补丁提供一次，附属不能重复打包。
4. 正常启动客户端并录制一段新录像。已有设备按原来方式使用，无需给核心换文件或添加启动参数。
5. 完成录制并等待 ReForgedPlay 保存，再进入录像查看和导出。保留原始录像，先确认下文的测试场景通过，再用于重要录制。

卸载时关闭游戏并移除这一个兼容补丁 JAR。它不会修改设备内容和存档；移除后也不再负责显示已经录入的屏幕画面轨。主包及附属的安装要求见各自玩家指南。

### 附属兼容范围

主包的公共接口不等于全部附属已经迁移。test.7 对仍访问附属内部类的适配保留精确边界：SFC54、MD16、街机1.5.12、GBA15、电脑 prototype.13、PvZ prototype.12；仅在需要相应机器时安装。其他版本要先完成适配核验，不能从 FC 的开放上限推断可任意混装。旧 SFC53／街机1.5.8／电脑 prototype.12 配套继续保留 test.6，不能混搭新旧附属；Java ME 仍拒绝同装。

进入录像前请正常结束并保存私人游戏。不支持“无保存退役”的活动私人附属，或尚未结束的保存任务，会阻止打开录像；正常完成后重试。回放不会用自动保存覆盖退出前的游戏进度。

### 先做一段短录像

更新后重启客户端，录制约 20 秒：让正在运行的电视或街机屏幕进入视野，然后结束录制并等待保存。查看 `logs/latest.log` 中的 `PIQ-ReplayScreen`：应先出现 `First screen image accepted`，收尾出现 `Screen track finalized`，其中 `images` 和 `chunks` 应大于 0。收尾日志表示屏幕轨已交给 ReplayFile，不代表外层录像文件已经保存完成。

先打开 test.3 已有声音的录像，以 **1×** 播放几分钟，测试暂停后继续、前后拖动和退出，确认恢复的是新位置的声音，没有旧声音残留。再录制新的 20～30 秒片段，对比画面流畅度。音频日志为 `PIQ-ReplayAudio`，收尾计数 `frames` 和 `chunks` 应大于 0。test.2 已录下的画面可继续使用，但旧录像没有设备音轨时必须重录才能有声音。

若没有录到帧，录像内部会留下有界诊断和警告；诊断只含计数及结果，不包含本地路径或游戏内容。反馈时提供上述日志和测试版本即可，无需发送 ROM 或存档。

## 录制和回放范围

画面轨位于同一个 `.mcpr` 录像内部的 `piq-screen/v1/`，不是单独的外部视频文件。它保存屏幕像素、维度、时间、世界空间四边形和关闭事件，不保存模拟器状态，也不能代替设备存档。

现有机型通过特定绘制与上传位置适配；未来机型可以显式接入[公共屏幕 API](API.md)。下表描述已实现的适配范围，不表示每台机器或每种联机模式已经通过 Minecraft 验收。

| 显示路线 | 当前适配与边界 |
| --- | --- |
| FC、公共家用机电视、公共机柜 | 捕获公共屏幕材质及世界绘制位置；具体开关机、旁观和联机组合仍需逐项实测。 |
| SFC、MD 等公共家用机显示 | 适配世界显示面与姿态；仅安装了相应附属才存在这些机器。 |
| 老式电脑及复用其显示的 Flash、PvZ | 适配电脑原始像素上传和世界显示面；不通过全局 GPU 读屏获取画面。 |
| J2ME | 仅有源码适配草稿，旧会话关闭与 RMS 保存隔离未验证。本候选声明不兼容并拒绝同装 Java ME，不能当作已支持。 |
| GBA | 当前不录制第一人称手持显示。其他经公共显示路线出现的画面也需独立实测，不能据此宣称 GBA 全形态兼容。 |

当前只捕获世界屏幕，不包含 GUI 或第一人称专用绘制。原客户端没有绘制、未进入录制范围或因预算被跳过的屏幕，不会在录像中凭空补全。私人画面也只可能记录该录制客户端实际看到的内容，不会获取其他客户端的隐藏画面。

回放期间，现有适配为指定设备路线阻止核心启动或推进、设备输入与设备网络载荷处理，并只绘制记录下来的屏幕。此机制不是任意附属的安全沙箱；新增路线必须自行接入回放保护。退出回放后应恢复正常游戏，这也是实机验收的一项。

## 限制和失败处理

- 旧录像没有屏幕轨时无法恢复当时的游戏画面。本补丁不会为补图启动真实模拟器。
- 设备音轨在同一录像的 `piq-audio/v1/`。只采集录制客户端设备的最终 PCM 输出，不录麦克风、系统混音或其他程序。音量及距离衰减按录制时保留，不随回放自由镜头重新混音。
- 音频适配 FC、SFC、公共机柜与旁观输出（含经此路线的 MD/街机）、GBA、旧街机输出、电脑以及 PvZ 两个输出端；各设备与运行模式的实机听感仍待验证。仅提供最终 PCM 的未来设备可用公共音频 API 接入。GBA 声音可采集不等于第一人称画面已支持。
- 声音仅支持正向 **1× 回放**；暂停、跳转、其他速度和视频导出期间静音并清除旧队列。**导出视频仍不带本补丁的设备声音。** 不接管 ReForgedPlay 原有 Minecraft 声音。
- 音频输出队列短暂拥塞时清掉过时输出，并在后续播放时刻恢复，不再将整条音轨判失败。真实设备异常有有限次数重开；重试耗尽或轨道损坏仍会提示并停止音频，画面继续，不无限重试。
- 音频同时最多 8 个活跃输出、全录像最多 256 个来源，录制队列 2 MiB/256 帧；轨道最多 512 MiB 压缩数据、1 GiB 原始 PCM、30000 块/1000000 帧。达到限额会停止补充或丢弃并记录警告，不能当完整录音。
- 自动捕获按每个显示面 50 毫秒的采样时钟运行，目标约 20 帧/秒；显示帧抖动不累计推迟时钟，卡顿后不集中补录。实际帧率受游戏绘制、来源帧率与队列负载影响，不保证每台设备恒定 20 帧。画面超过 2 秒没有刷新会过期；关闭事件可更早清除画面。
- 同时最多显示 16 个屏幕。单帧最大 `1024 × 1024` 像素、4096 个顶点；单条录像屏幕轨最多 1024 个来源、72000 帧、9000 块、2 GiB 压缩块数据。多个屏幕共同消耗配额。
- 提高采样率不提高总配额：仅按帧数估算，单屏持续 20 帧/秒约可录 60 分钟，四屏约 15 分钟；其他限额可能更早达到。长录制应分段并检查收尾警告。
- 录制队列有界，过载会跳过部分画面；达到轨道配额或发生写入错误会停止补充屏幕轨，并记录警告。不能把缺帧视为完整录制。
- 画面使用有界已解码缓存和预读，同一块内换帧不重复读盘。缓存为 96 MiB/32 块，另有最多 16 个当前选定图像及单块解码工作区。交互预览遇极慢读取仍可能暂时未就绪，不显示错误时间的旧帧；导出等待目标画面，超时或解码失败会报错。
- 画面解压在归档锁外进行，不占用音频读取所需的锁。相同像素可共享最多 16 个固定纹理槽，时间或几何变化不强迫重新上传相同像素；只绘制当前镜头可见的记录，不套用实时旁观距离，也不拿上一时刻的旧图掩盖缺帧。
- 已对 ReForgedPlay 0.3 的剪切和分段标记增加屏幕与音轨映射。处理失败时输出警告，不伪造内容；请保留 ReForgedPlay 原始备份。其他编辑器及其他 Replay 版本不在当前适配声明内。
- 本补丁不替代其他独立 Replay 补丁，也不宣称修复所有快速模式、网络包或其他模组的兼容问题。

## 验证状态

test.7 已使用本批最终主包和附属完成有／无 Iris 两组隔离构建，每组 26 个 Java 测试入口通过，两组生成相同玩家 JAR。真实音频、生命周期、Open Guard 和 Iris 变换回归通过，完整结果见 [TESTING.md](TESTING.md)。这不是 Minecraft 图形客户端、实际声卡或多人验收。新增 PGM 运营配置保存仍须遵守只读回放保护：回放开始及回放结束后返回的旧会话任务，不得提交运营设置或游戏进度。

test.6 增加公共 API 的实际字节码校验、主包明确调用点检查、无保存退出及迟到任务阻断测试，移除对主包私有实现的 Mixin。测试涉及公共 API、像素编解码、输入边界、捕获预算、回放保护条件、录像时间、轨道生命周期、剪切与索引。实际完成的组合见 [TESTING.md](TESTING.md)，具体构建输入、测试类和成品 SHA-256 以本次成功构建输出目录内的 `verification.json` 为准；不要把旧记录当作后来修改的验证结果。

test.4 增加限速音频输出拥塞恢复、归档并行读取、旧格式编解码对照、纹理共享与可见性决策、20 帧采样时钟回归，保留原 API、Iris、剪切与生命周期测试。具体结果见 [TESTING.md](TESTING.md)。完整客户端应用、实际音画同步与听感、方向与遮挡、光影、多人、导出及正常游戏回归仍待实机验收；自动测试不能替代这些检查。

建议在隔离实例中逐项验收，使用自己的可测试内容，并保留日志和原始录像：

1. **未录制的正常游戏：** 装补丁后进入世界，确认设备开关机、输入、旁观、声音、网络和适用的保存仍正常。再用不装补丁的同配置作对照。
2. **新录制：** 拍到至少两个世界屏幕，移动视角，改变屏幕朝向，测试遮挡、离开视野、关闭设备和切换维度；保存时检查屏幕轨警告。
3. **回放：** 在没有运行设备的条件下打开录像，检查颜色、UV、世界位置、朝向和关闭时刻。前后拖动、暂停和变速，确认不显示错误时间的残留画面。
4. **只读保护：** 在隔离环境观察核心进程、设备网络与测试存档，确认回放没有启动真实设备、发出设备控制或写入设备存档。分别测试正常退出和错误退出，再进入正常游戏。
5. **剪切和导出：** 剪切或分段后核对起点画面和关闭事件，导出短片并逐帧抽查。失败时保留原始备份，不把警告输出当作成功。
6. **边界：** 打开没有画面轨的旧录像；在副本上测试损坏轨道。确认不重启设备、不崩溃进入错误游戏状态，且提示与日志可辨认。

GBA 第一人称、J2ME、每种附属和不同光影组合应分别记录结果，不能从一种电视的通过推断全部机器通过。

## 从源码构建

手动构建入口为 [build.py](build.py)，需要 Python 3.11+、JDK 21、对应客户端的模组 JAR、NeoForge/Minecraft 命名客户端 JAR，以及包含完整依赖列表的启动器版本 JSON。脚本只读取指定依赖；必须用 `--build-dir` 指定不存在的、绝对 ASCII 工作目录，Windows 下不可使用系统盘或目录链接，旧构建不会覆盖。不启动游戏、不安装或发布成品。

在本目录执行，替换下列占位路径；`--libraries` 应指向启动器库根目录，而不是任意 JAR 收集目录：

```powershell
python -B build.py --java-home "<JDK21目录>" --libraries "<客户端libraries目录>" --mods "<客户端mods目录>" --version-json "<完整版本JSON路径>" --build-dir "<工作盘ASCII新目录>"
```

默认 NeoForge 为 `21.1.250`，Minecraft 命名工件为 `1.21.1-20240808.144430`。脚本检查 ReForgedPlay 和 FC 唯一依赖，编译源码并以 `java -ea` 运行测试；任何一步失败都不算本次构建成功。

可用 `--fc "<已核验FC的JAR路径>"` 指定主包；构建器调用仓库的 `source-control/replay_api.py` 检查最终 JAR，而不是主包小版本白名单。构建补丁需保留仓库的 `source-control` 目录。`--mods` 的只读输入须为上述配套版本，避免旧附属抢占类路径。`--without-iris` 只从测试依赖列表排除 Iris，验证可选依赖缺失，不改客户端文件。MixinExtras 使用 NeoForge 自带版本，不在玩家补丁内额外打包。

成功输出包括：

- `<build-dir>/libs/game-console-replay-compat-1.21.1-0.1.0-test.7.jar`：玩家客户端补丁。
- `<build-dir>/libs/game-console-screen-api-0.1.0-test.7.jar`：开发者 `compileOnly` API，不供玩家安装。
- `<build-dir>/verification.json`：本次依赖版本、哈希、测试列表及待实机验收状态。

构建成功不等于发布、服务器部署或稳定版认证。后续机型接入见 [API.md](API.md)，许可见 [LICENSE](LICENSE)。
