# 方块电玩街机附属

这个附属让方块电玩的通用机柜运行街机游戏，复用主模组的机柜、屏幕、操作席、投币和管理入口。它包含 MAME 与 FBNeo 的不同运行路线，不是给 FC 游戏换一个外壳，也不是所有街机 ROM 都通用。

第一次安装或找不到操作入口，请先看[玩家指南](../piq-fc-arcade/docs/玩家指南.md)。

## 需要安装什么

- 客户端和服务器都安装配套的方块电玩主模组与 `game-console-arcade-版本.jar`，不需要为了街机再装 SFC。
- 目标为 Minecraft 1.21.1、NeoForge 21.1.229 或以上兼容的 21.1 版本、Java 21。实际执行原生核心的一端需要 Windows x64；服务器托管也受此条件约束。
- 所需固定核心和辅助运行库由对应成品提供，不要求玩家另装 RetroArch，也不要将运行库 JAR 当作模组放进 `mods`。
- 从 [GitHub 整套测试版](https://github.com/meilian258-dotcom/game-console/releases/tag/full-test-20261007-r1)取得配套成品；安装步骤见[本套说明](../piq-fc-arcade/docs/整套测试版-20261007.md)。Code → Download ZIP 是源码，不是可安装成品；不随意替换 DLL。

当前开发候选为街机 `0.1.5.11`，配套主包 `0.31.0-alpha.76.49`，不是上面的旧公开整套下载。新增原版 FBNeo 的 RetroArch Netplay 显式试验，不修改核心本体，不替换旧 FBNeo JNI 或 MAME，不迁移旧档。状态一致性验收尚未通过，不能据此宣称旧 JNI 闪退或全部联机问题已解决。客户端与服务器须一起更新，候选尚未作为正式默认下载发布。

## RetroArch Netplay 试验

关机后，管理员用调试螺丝刀打开设备设置，进入 Netplay 后端页，选择“RetroArch · 原版 FBNeo（实验）”并确认启用。此入口无需 JVM 参数；`-Dpiq.arcade.mediaBackend=retroarch` 只影响下节的 MAME 音画串流。房间、席位、投币及只读旁观仍经过主包的公共接口。

新入口暂不保存，不读取或转换 JNI 旧档；回旧路线也须关机后明确选择。固定原版核心已在隔离双进程中进入《恐龙快打》双人游戏，双方独立操作和正常退出通过；但同模拟帧状态 CRC 差异仍存在，画面匹配不能代替完整同步验收。MC 多人、弱网、晚加入和长局待验。详情和其他附属接入方法见[试验接入说明](../piq-fc-arcade/design/RetroArch-Netplay-街机试验接入.md)。

## 统一 RetroArch 后端首批（开发验证）

默认仍使用 MAME JNI。仅在独立测试实例的 Java 启动参数显式添加 `-Dpiq.arcade.mediaBackend=retroarch`，才将**通用机柜客户端的玩家音画串流计算端**交给公共 RetroArch LOCAL 会话。删除此参数回到兼容默认；不支持的值会报错，不静默切换。参数不是聊天命令、机柜的联网模式或服务端发来的设置。

关机后在设备设置选择“玩家音画串流”（旧版按钮叫“玩家托管”），开机后进入“查看音画诊断”，应显示“MAME · RetroArch 独立进程”。不要选择 Netplay 来测试这条新路线。

新路线使用同一固定 MAME 核心和匹配的运行库，不另装 RetroArch，不更换 ROM 集；复用四口输入队列、投币释放和公共席位／旁观音画分发。当前支持 Windows x64；独立进程不等于操作系统沙箱。进程结束和临时目录释放必须实际确认，当前仍可能强制结束子进程，不能宣称核心正常卸载。

此 MEDIA 入口不是 Netplay：FBNeo JNI Netplay、旧独立柜、服务器托管及旧本地同步保持原路线；上节的新 Netplay 试验需另行选择。家用机与掌机尚待逐项迁移。MEDIA 没有新增整局存档，公共 LOCAL 保存接口使用独立身份，不读取或转换旧档。首批范围与证据见[统一后端说明](../piq-fc-arcade/design/统一RetroArch后端-20261009.md)。

## 怎样开始游玩

1. 放置主模组提供的通用机柜。管理员 Shift＋空手右键配置，选择街机系统和本地或服务器游戏。
2. 使用与所选核心匹配、自己有权使用的 ROM ZIP。保留原驱动文件名，不随意改名或混用不同 ROM 集。
3. 需要 BIOS 的游戏按下节准备完整内容，再确认上传或选择服务器已有内容。
4. 点击机柜正面左下的电源开关，等待就绪后右键操作区域入席。是否收费、能否加入及最大人数由服务器设置、本局许可和游戏共同决定。
5. 再次右键退出自己的操作；这不一定立即关机。结束整局用实体电源，空席自动关机策略由管理员统一设置。

控制键可以在公共控制设置中调整。允许加入也不能让原本只支持两人的游戏变成四人；机柜上的人数标签不替代游戏内部设置。

## ROM 和 BIOS 怎样放

在本地上传流程中，所需 BIOS ZIP 放在所选游戏的同一目录。当前共享清单仅识别 `neogeo.zip`、`pgm.zip`、`qsound.zip`、`qsound_hle.zip`；不是所有上游 BIOS、父集合或任意目录都能自动分发。补 BIOS 后要重新选择并上传完整内容，再重开本局。

“运行环境已就绪”只表示模拟器程序组件齐全，不证明某个游戏 ROM 完整。RetroArch 是运行器，不会使一份 FBNeo 游戏集合自动兼容 MAME；MAME 仍可能需要独立的设备数据，例如 QSound 的 `dl-1425.bin`。应准备与当前核心匹配、有权使用的完整游戏和配套数据，不能靠改 ZIP 名、替换 DLL 或跳过校验修复。

本版 RetroArch 媒体启动失败时会保留本机诊断。MAME 明确报告必需文件缺失时，提示列出缺件及日志中的已支持配套包候选；到“模组设置 → 运行环境 → 复制诊断”查看详情，分享前检查其中的私人路径。未知退出保留原始退出或输出结束提示，不猜成缺 BIOS；本机运行失败不再写成 Netplay 退出。原生输出仅留在有界本机诊断记录中，不广播给服务器或其他玩家。

服务器正式内容在实例根 `game-console/piq-cabinet/server-games/`：`objects/` 按内容摘要存文件，`indexes/` 保存可按原名搜索的清单。内部文件不是乱码，不要将 `.data` 原地改名；只有目录里的文件也不代表它已获当前世界授权。

FBNeo JNI 路线的主 ZIP 上限为 96 MiB，最多一个游戏加四件 BIOS、合计 128 MiB；单件 BIOS 仍限 16 MiB。旧 MAME 路线的主内容仍限 64 MiB。大小通过并不保证 ROM 集和核心兼容。

## 联机和存档边界

- **FBNeo JNI Netplay**：已接入共享会话和只读旁观；两台兼容双人柜连接后最多四席，实际仍受游戏能力和设置限制。可选不保存、个人档或机器档，默认不保存。
- **RetroArch · 原版 FBNeo（实验）**：同一公共房间选择，独立进程与只读副本；暂只允许不保存，完整同步未验收。不按本机音画就绪推断所有玩家同步成功。
- **玩家或服务器音画串流**：由主持一端运行核心，其他端接收音画并发送获准输入；服务器托管需要服主开启且环境满足要求。
- **旧 MAME 本地同步**：仅对已核验的 `kof97.zip`、`mslug2.zip` 内容组合开放，最多两席，不是全 ROM 通用的 Netplay。
- 家用机的双人开局、旧独立柜和公共街机有不同入口。菜单显示某种模式，不代表其他核心或机型也具备相同能力。
- 整局存档可能包含币数和游戏设置，但不等于已经完成通用 Test、DIP 或 NVRAM 运营设置持久化。

## 当前状态和限制

目前是测试候选。竖屏方向、晚加入和内容库有对应修复与测试记录，但不能据几款游戏通过推断所有 ROM、弱网和四人长局都已验收。Iris 光影透屏涉及主包的公共屏幕渲染，仍有兼容问题，需要按具体光影包实机验证。

不附带商业 ROM 或 BIOS，不提供自动下载。不同核心的游戏集合和存档不自动互换；固定核心更新也不能直接覆盖旧保存格式。
