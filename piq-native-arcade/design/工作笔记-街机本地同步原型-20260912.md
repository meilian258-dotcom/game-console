# 街机本地同步：可行性突破与 IPC 原型

日期：2026-09-12。维护者：像素匠。

## 本轮结论

**现有 MAME 可以继续做本地同步，但已证明的是“固定初态＋完整输入重放”，不是任意存档瞬间恢复。游戏内可玩的联机版尚未完成。**

固定 DLL、ROM、BIOS 和 RTC 时间后，《拳皇97》《合金弹头2》各两个依次独立进程，共用第32帧初态，再重放12,000帧：每帧完整画面/PCM与21个完整状态检查点全部一致，无字节屏蔽。实验时区/机器一致；不是两台Minecraft、公网或四人游戏验收。

正式证据：`native-sync-study2/RTC-RESULT-20260912.md` 与其中两份 fixed-rtc-replay 报告。原始失败证据保留，避免把“固定初态重放通过”误读成“原生任意快照恢复已修复”。

## 完成的实现与验证

1. 新建独立 `NativeStepProtocol` / `NativeStepWorker`：准确STEP才执行一次 `retro_run`；4口12位按键，同线程SAVE/LOAD，返回真实帧号/时钟/视频/48k PCM，首个无视频帧明确为空；旧媒体协议3/旧helper不变。
2. 新建 `NativeStepSession`：Minecraft父进程不加载JNA；固定SHA验证，ROM/允许BIOS临时复制，共享旧Native精确子进程互斥槽；每命令15秒期限、空闲等待不超时、参数先验证再消耗ID、异步取消只终止本次子进程、确认退出后释放槽和清临时副本。
3. 修正watchdog过期读竞态：同生命周期锁开始/结束deadline，超时处理再次核对deadline身份，不能用上一命令的过期值关闭新命令。
4. 源级helper：149条真实Session/旧Engine回调断言、12项协议JUnit；父端9组/308条生命周期断言，包含真实15秒超时、16.25秒空闲、阻塞取消、ID/帧错误、双实例互斥与无关sentinel存活。fake core/child证据不冒称真MAME。
5. 新helper最终JAR配真实MAME运行，两款各3,400个逐帧调用，分别5,611条IPC断言通过。初始空视频为1帧，实际59.18560791015625fps/48000Hz；空闲SAVE不改变状态，精确子进程回收与槽释放通过。

第5项同时再次证实快照边界：恢复后600帧画面相等，但KOF97的600帧、mslug2的240帧PCM不同，最终完整状态各差10字节。该IPC试验使用直接ZIP启动，没有固定RTC重放策略；其 `ipc_ok=true` 不能当作 `native_sync_qualified=true`。

私有helper文件：`build/native-step-prototype-v1/piq-native-step-helper.jar`，SHA256 `AA515AB5E4981EFEA667FBDFFA839B13FE035A4C40F1A6B1F15B7E9711CF7E77`，39,840字节。新构建工具 `tools/build_native_step_helper.py` 重用旧helper全部19项class的原始字节，仅加入独立STEP类。**它不是MOD，不要放入mods，也不能替换旧piq-native-helper.jar。**

## 为什么暂不开放游戏内开关

- MAME任意快照恢复仍有音频/完整状态差；FBNeo官方构建的NORMAL及NETPLAY上下文也未通过本项目同样的完整恢复要求。没有自动替换核心，FBNeo许可/采样率另有边界，见`fbneo-study/README.md`。
- 固定初态重放约203秒游戏花22.73/23.68秒，长局等待会增长。此速度来自独立QA，不能保证Minecraft负载下同速。
- FC32现有900tick（约45秒）恢复窗和7,200帧历史不适合直接套用长局重放；不能暗中延长所有核心期限，不能停止主持人来掩盖追赶，也不能用输入日志hash代替真实运行状态hash。
- 当前STEP helper尚未包含固定RTC配置、跨时区规范化、服务器权威历史传送、重放进度及前台UI。研究中的固定参数文件只由libretro读取，绝非执行Windows命令。

带追赶等待的恢复方式仍为实验设计；长局等待尚未通过玩家体验验收，不作为默认稳定方案。

## 如继续实验版，落实顺序

1. 固定启动profile：RTC、时区、32步引导、DLL/helper/ROM/BIOS/输入映射、禁读私有配置，真实native日志和完整初态双端校验；先严格限实际测试内容，不能按文件名宣称全部街机通过。
2. 独立恢复策略和协议：服务器保留自己生成的紧凑四口权威输入历史；每300帧仍校验真实完整状态。恢复传初态及有界历史，不能让Host重新定义过去的输入，也不能周期性复制全局龄日志造成二次增长。
3. helper内部批次重放：准确执行每帧全部音频计算，不向声卡播放历史PCM；每批进度/结果有界，取消和超时可以中止自己的子进程。
4. 单端追赶：旧连接/租约/令牌/乱序重放均拒绝；候选未校验完成不授控制；只拒绝超时加入者，不结束主持局，不自动切模式。超过历史/等待预算明确提示，允许继续旁观或下局重新选择。
5. 再做最终成套FC/Native JAR、真实两客户端及长局/断网/四席位验证。FC/SFC原精确快照同步不降级；现有媒体模式保留为明确可选项。

具体接口审查：工作区根路径`piq-fc-arcade/design/native-sync33-contract-review.md`；helper审查`native-sync-helper-review.md`及`native-step-handoff-20260912.md`。
