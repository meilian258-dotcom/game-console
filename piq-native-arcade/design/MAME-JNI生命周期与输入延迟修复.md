# MAME JNI 生命周期与输入延迟修复

适用范围：街机附属的 MAME JNI 音画运行路线及其使用的公共运行器。对照基线为主包 0.31.0-alpha.76.43、街机 0.1.5.7；候选为主包 0.31.0-alpha.76.46、街机 0.1.5.8。候选不等于稳定版或全部街机故障已修复。

## 目标与边界

| 项目 | 预期行为 | 验证 | 状态 |
| --- | --- | --- | --- |
| 原生生命周期 | 所属线程负责运行与收尾；核心仍有执行任务时不得卸载，不强杀线程或假释放资源 | 隔离 JVM 真实核心反复启停、异常收尾和公共调用者回归 | 固定核心、公共 JNI 长测及最终成品调用者检查通过；实机待验 |
| 输入延迟 | 区分核心变慢与输入排队；减少允许合并的状态积压，保留已接受的投币、短按和方向轨迹 | 确定性慢消费者测试、多端口及真实核心运行 | 自动测试通过，游戏实测待验 |
| 诊断 | 有界记录帧耗时、输入等待及本局峰值；不记录玩家身份、ROM 路径或原始输入序列 | 隐私、只读及错误路径测试 | 已接现有诊断页，界面实测待验 |
| 交付 | 精确配套主包与附属、安装说明、测试结果及实机待验项 | 最终 JAR 复验 | 本地测试候选，不是已发布稳定版 |

MAME 保持 0.289 固定源码版本，仅修补退出清理并重新编译；不换成其他模拟器。新核心摘要及保存身份独立，旧档保留，不自动转换。不改变 ROM/BIOS 身份、授权、投币收费、多席位或旁观距离。FBNeo JNI Netplay 是独立路径，本次不替换其核心，不能以 MAME 验证替代其联机验收。未重现的原生异常不归为已修复。

## 复用与流程

沿用 `NativeJniMediaSession`、公共 `LibretroJniRuntime` 和原生桥的 owner 线程合同；输入仍由席位授权后进入机型适配，音画仍走公共机柜呈现。正常关机、异常退出、准备中取消分别验证，不能把退出一席等同整机关机。

本次不新增机器或独立联机体系。MAME 退出补丁基于 `4fc9a9312baaf34963847f884961ad9793fbbc1d`；补齐 OSD 对象销毁，让其持有的后台定时器线程在卸载前结束。此外，在机器和 UI 消费者销毁后、OSD 清理前，显式回收 UI 系统列表缓存线程，避免在 DLL 静态析构期间等待该线程而卡住加载器；等待线程结束时释放其发布结果所需的缓存互斥锁。源码及构建入口见[同版本补丁](../native/mame-lifecycle/BUILDING.txt)。

输入缓冲仅压缩允许的邻近按钮状态：同一键不能在同一核心帧内变化两次；出现按下后不再合并后续释放，保留短暂组合键；同一帧至多越过一次方向变化，保留下、右下、右等轨迹。失焦按原有合同松开操作键，并保留已接受的投币脉冲。旧独立进程 helper 的输入实现及摘要不变。

这不是完整墙钟时序保真，也不让慢核心变快。同一键变化频率长期超过核心采样频率时仍会积压；满队列原子拒绝并结束会话，不静默丢操作。诊断显示每端口当前队列、最老等待及本局峰值，打开菜单释放输入也不会抹掉此前峰值。

公共诊断接口为默认空结果，现有后端无需新增实现；MAME 在已有音画诊断页显示核心帧耗时、输入队列及本局峰值。街机候选要求至少主包 `0.31.0-alpha.76.46`，以使用配套公共桥及其固定共享运行库。

修补核心使用独立的 `core/mame-jni/windows-x64/mame_piq_lifecycle1.dll` 资源。旧 MAME 资源、旧独立进程 helper、FBNeo 核心及已有存档保留；JNI 核心身份由新摘要区分，不把旧即时档重命名为新档，不自动迁移。MAME 音画适配当前仍不新增持久化存档功能。

## 验证状态

旧核心的失败加载、正常媒体会话结束、三次连续启停，均在隔离 JVM 中复现相同的卸载后原生访问异常。关闭接口返回、槽位回收以及 DLL 已从模块表消失，都不足以证明其后台线程已退出。

输入及诊断自动测试已通过；旧版已编译后端对新增默认诊断接口的二进制兼容检查通过。第一轮退出补丁候选在成功/失败启动、重复启停后的 330 秒观察中未再崩溃，但句柄仍逐轮增长，未通过资源回收验收，不能作为修复版交付。

后续候选保持同一 MAME 源码，生命周期补丁涉及五个源码文件，单独调整 Windows x64 libretro 构建为 CLANG64、共享 libc++ 和原生 TLS。使用上游编译器及标准运行库，不新增锁或线程框架；共享运行库由公共 JNI 桥持有到 JVM 退出，核心仍按会话卸载。公共加载接口、真实源码清理顺序、完整核心编译及公共 JNI 长测已完成。构建差异和来源见[共享运行库构建说明](../native/mame-lifecycle/CLANG64-SHARED.txt)。

资源核对不再仅按整个 JVM 的冷启动总数判定：保留原始严格计数失败，另逐项检查核心卸载、会话目录、槽位、句柄类型、Key 身份和线程对象。新增自身观察器会影响初始化基线，这一结果不替换原冷基线记录。成功与缺文件拒绝加载各三轮，每轮关闭后至少 330 秒；所有关闭后样本没有新增句柄类型数量、Key 或精确 Thread 对象，中途新增的 OS 线程 ID 在同次进程退出前最后两份快照均消失。第一轮 330 秒时仍可有中途线程，因此不声称每个阶段都回到启动前计数，也不凭系统模块名豁免未知残留。

独立核心资源准备工具保留旧版单补丁清单，并支持显式声明共享运行库、两份源码补丁摘要的新清单。它只打包固定身份的核心和公开来源说明；共享 libc++ 仍由公共桥提供，不重复打包。准备工具的单元测试不等于核心验收，不授权将候选接入游戏、迁移旧档或改变默认下载。

最终 JAR 中的 `NativeJniMediaSession` 已完成三次成功开局和三次缺文件拒绝开局；三次成功局均产生音画，六次关闭请求均未阻塞，实际 owner 线程已结束，核心模块、会话目录及槽位检查成立。六个关闭会话在同一 JVM 中继续观察 330.756 秒，进程正常退出；没有用额外注入的 DLL 或替代媒体实现绕过成品资源。该结果验证的是隔离环境下的实际调用者，不是 Minecraft 图形或真人多人验收。

独立候选工作流使用全新 Windows 构建环境、固定同版本源码与补丁、逐包校验的工具链；完整编译后在另一台独立运行环境中检查原生生命周期。测试内容由仓库原创诊断生成器产生，不需要商业 ROM/BIOS。原生 ABI 检查通过后仍须验证实际 Java/JNI 调用链，再制作配套主包和街机附属。

该工作流只保存候选与对应源码，不发布 Release、不改变默认下载。正式修复版须使用通过检查的固定核心身份；不能在打包时被未含此补丁的普通 nightly 覆盖。默认下载入口的切换应在成品验证和发布后完成，测试快照继续独立标识。

恐龙快打的实际长局、Minecraft 多客户端、诊断页显示及其他原生异常仍待验证。轻量原创诊断的帧率不能代表商业游戏负载。所有自动检查与实机结果分开记录，没有实机证据不标记稳定。
