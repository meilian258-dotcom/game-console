# MAME 本地同步实测：本轮不开放

2026-09-12，cabinet_reuse_review；用户授权的本地双实例验证，root 负责最终维护记录。没有改 Native 生产源码、helper、DLL、版本、原包、用户实例、ROM、BIOS 或存档，没有接触正在运行的核心。

## 结论

当前固定 MAME 0.289（4fc9a931）确有可工作的 `retro_serialize` / `retro_unserialize`，两次调用均成功。不能因此认定快照适合多客户端持续同步：本次 KOF97、mslug2 均未通过严格音频与状态恢复一致性要求，**不注册 sync 能力、不新增伪 STEP 开关、不替换现有视频同步**。通用同步 UI 由负责协议的代理通过 Setting.reason 提示“当前 MAME 核心快照恢复未通过音频与状态一致性验证，请使用视频同步”。

## 实测与边界

每个游戏使用两个独立、低优先级、无窗口 Java JVM，加载相同的固定官方 DLL，直接复用实际交付 helper 的 Engine 环境、视频、PCM、按键转换回调。没有重写核心、没有修改选项。逐次串行调用 `retro_run`，调用返回后在同线程保存/恢复；每次运行前清本次 PCM 计数。两个实例均从新临时目录开局，不读取用户 NVRAM、配置或即时存档。

- 2200 次运行后保存，接着执行 600 次相同输入；从该快照进行本机重放和跨实例重放。
- 两游戏各自两个实例的 2800 次独立运行，视频/PCM/头信息比较无差异。首次核心初始化未给视频回调，被明确记为空画面记录，未伪造视频帧。
- KOF97 三路恢复后的 600 次画面和头信息一致，PCM 600 次均有差异，最后 60 次仍然不同。
- mslug2 三路恢复后的 600 次画面和头信息一致，PCM 前 86 次不同，后 514 次在这段输入序列内一致；这不证明其它时刻都会收敛。
- 两游戏状态都是 1,029,356 字节。原地连续保存两次 SHA 一致；恢复后未推进一帧就重新保存，SHA 已不同。独立启动的状态以及恢复重放后的状态也不能达到 SHA 一致。
- 同一组声明选项一致，实际 helper 固定关闭 game button profiles、thread mode、throttle、读写配置和自动存档。报告绑定 helper 与 DLL SHA；实际时序为 59.18560791015625 fps、48000 Hz。
- 这不是手动操作 Minecraft 的联机验收，未证明全部 MAME 游戏都不确定或全部快照都不可用。有限两组实验没有产生可开放的游戏/核心/配置白名单，故安全保持媒体模式。

## 官方源码依据与未证明部分

使用与固定二进制提交一致的官方源码（仅只读取得文本）：

- [libretro.cpp:1002–1033](https://github.com/libretro/mame/blob/4fc9a9312baaf34963847f884961ad9793fbbc1d/src/osd/libretro/libretro-internal/libretro.cpp)：对 MAME save manager 缓冲区提供序列化接口。当前项目原已保存对应源码片段在 `piq-native-arcade-poc/vendor/source-reference/libretro.cpp`。
- [save.cpp:388–494](https://github.com/libretro/mame/blob/4fc9a9312baaf34963847f884961ad9793fbbc1d/src/emu/save.cpp)：读入后执行 postload 回调，不能假设 load→save 是字节恒等映射。
- [sound.cpp:811–820](https://github.com/libretro/mame/blob/4fc9a9312baaf34963847f884961ad9793fbbc1d/src/emu/sound.cpp)：声音 postload 重置 effects 时间并重建重采样器。此路径与观测到的恢复后 PCM 差异相符，但本实验没有把所有差异定位到某一个具体字段；不能把这段源码单独当成唯一根因证明。

没有通过忽略音频、屏蔽不明状态字节、静音若干帧或更换不明 DLL 来降低验证要求。若未来继续，需要专门处理并验证 MAME 的恢复语义，而非仅加 IPC 命令。

## 复现

新增 `tools/check_native_determinism.py` 和 `tools/qa/NativeDeterminismProbe.java`。脚本只编译探针，直接使用旧交付 helper、固定 DLL/JNA。每轮复制明确指定的用户 ROM/BIOS 到自有临时目录；结束验证源 SHA、字节数及修改时间不变。子进程有 180 秒期限，只终止其自己启动的 JVM，成功后先完成 native unload/deinit，再结束专用 QA JVM。临时 ROM/快照和日志不进入交付包。

```text
python piq-native-arcade/tools/check_native_determinism.py --rom <已有的kof97.zip或mslug2.zip> --bios <已有neogeo.zip> --report <不存在的新报告.json>
```

报告的 `ok=true` 仅表示研究流程完整执行，是否可开放必须看 `sync_qualified`；本次二者均为 false。
