## 测试方法

1. **核心测试**：使用真实 `NativeNetplayProfile.runtime()`，执行生产同序列的启动精确恢复检查；即使该检查失败，独立核心探针仍继续运行以区分“不能启动 Netplay”与“核心不能运行”。900 帧后保存，分别在原实例和第二个独立实例恢复，重演相同的 180 帧输入，比较完整画面、完整立体声 PCM 和结束状态。
2. **JNI 串流计算端**：真实 `NativeJniMediaSession`，收集 600 个输出帧、音频及几何/旋转元数据；这是串流计算端音画冒烟，不包含网络编码、Minecraft 屏幕绘制或其他玩家实际观看。
3. **四实例 Netplay**：真实 `NetplayProcess` + `NetplayRelay`，模拟每段链路 50 ms 延迟、四路主持权威机柜输入和投币调用。加强版要求主持再推进 900 帧、各参与者至少推进 850 帧、无核心错误/异常连接拒绝/relay 拒绝，检查手动及最终保存回调。保存只写 QA 目录，不代表 MC 服务端落盘链路已验收。
4. **补充对照**：仅诊断 JVM 临时省略不适用的 `fbneo-diagnostic-input`，验证三款启动失败原因。生产 profile 不变，不把该对照计入正常入口通过数。X-Men 和 KOV 另作 7200 帧核心运行/恢复重演。

源码：[核心/串流探针](../tools/qa/ArcadeCompatibilityProbe.java)、[四实例探针](../tools/qa/JniArcadeProbe.java)。探针需要与上述开发配套资源相同的 classpath，不能拿旧发行包替代。

```text
javac -encoding UTF-8 --release 21 -cp <开发主包及街机类/固定资源classpath> -d <QA类目录> <探针.java>
java -Xcheck:jni -Xmx768m -cp <QA类目录及同一classpath> cn.piq.nativearcade.bridge.ArcadeCompatibilityProbe <全新QA工作目录> core <合法ROM绝对路径>
```

模式 `media` 测 MAME，`diagnostic-options` 只供省略上述选项的诊断对照；`-Dgc.probe.baselineFrames=7200` 延长核心基线，范围 900～7200。ROM 同目录中已存在的 `pgm.zip`、`neogeo.zip`、`qsound_hle.zip`、`qsound.zip` 可作为配套内容。工作目录必须与正式实例及存档隔离，原生测试需外层进程超时控制。新探针捕获的最后一帧图像和保存文件仅留在私有 QA 目录，不纳入源码或分发。

### 精确恢复差异，不只看序列化大小

900 帧基线后，相同的 180 帧输入重演（本实例 / 第二实例）：

| 游戏/条件 | PCM 不同帧数 | 结束状态不同字节数 |
| --- | --- | --- |
| `kov` / `orlegend` / `ddp2` 正常 profile | 0 / 0 | 0 / 0 |
| `dino` 正常 profile | 180 / 180 | 1624 / 1482 |
| `mslug` 正常 profile | 180 / 180 | 33 / 5 |
| `mslug2` 正常 profile | 104 / 103 | 66 / 5 |
| `kof98` 正常 profile | 180 / 180 | 25 / 0 |
| `contra` **仅诊断省略选项** | 180 / 180 | 30 / 25 |
| `1942` **仅诊断省略选项** | 4 / 4 | 0 / 0 |
| `raiden` **仅诊断省略选项** | 180 / 180 | 15 / 27 |

X-Men 在 7200 帧基线后 PCM 不同帧数 49 / 49，结束状态差异 52 / 45 字节。PGM 的音频和状态重演一致不等于全部音画逐字节一致：所有完成重演的测试仍记录了 1 帧画面差异；追加索引检查的样本定位在恢复后的第 0 帧，后续 179 帧一致。尚未验证其具体原因和 MC 呈现影响，没有通过忽略首帧来声明“完整 AV 零差异”。

### 重复联机发现与探针修正

- 初始 300 帧旧探针在 `dino` 和一次 `kov` 失败时，先关闭调度器再关闭 relay，导致 `RejectedExecutionException` 覆盖原始异常。现只修 QA 清理顺序、保留原始诊断和等待槽释放；不能把当次 KOV 原始失败断言为纯测试脚本问题。
- 加强后 `dino` 在确认帧约 119 复现 CRC 差异，与独立恢复重演不一致相互印证。
- `ddp2` 第三轮在确认帧约 385 触发时间线校验。该错误由公共 `JniNetplaySession` 的三项条件共用文案产生；日志不能区分确认帧倒退、next 倒退、或 next 超出本机 32 帧窗口，**根因待定位**。不能直接归罪 ROM、网络乱序或放宽安全窗口。
- 三款 PGM 加强版总计 9 轮：8 过、1 失败。没有“所有 PGM 稳定”的结论。

## 证据与交付边界

维护工作区的 `outputs/jni-full-migration-20260929/` 保留以下证据（独立克隆不含私有 ROM、日志或截图）：

- `arcade-matrix1`：11 款正常 profile / MAME / 初始 Netplay。
- `arcade-network2`、`arcade-network3`、`arcade-network4`：加强版联机，共 10 次（PGM 9 次、dino 1 次）。
- `arcade-option-diagnostic`：3 款省略选项对照。
- `arcade-long-core`：X-Men、KOV 7200 帧检查。
- 每组有 `inputs.json`、每例日志/结果和 `results.json`，记录 ROM/BIOS 哈希、实际核心、QA 源码版本及原件不变检查；失败日志不删。

本次共 41 次受控子 JVM 调用，无进程超时、未发现 `-Xcheck:jni` 警告；新探针报告的原生槽均回到 4。旧探针两次被覆盖错误没有槽释放回执，不能补写为通过。没有 Minecraft 真人联机、端到端旁观、实体投币扣币、维护菜单、长期存档/重连完整链路或长时性能验收。图像变化、模拟按键和 PCM 输出也不等于已人工进入每一关验证操作。

**结论：不是只有拳皇97有问题。** 街机迁移至少还有选项适用性、NeoGeo/其他硬件的精确恢复、重复联机时间线异常，以及既知 NeoGeo 特殊本地同步时钟隔离问题。GC-110 保持开发中/未验收，无新 JAR、无安装/发布/服务器重启；这次补测没有修复生产功能。
