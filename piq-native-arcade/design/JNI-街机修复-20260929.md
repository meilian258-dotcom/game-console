## 兼容与不变项

- 公共运行器属于主包/内部平台；游戏核心差异属于街机附属。共用网络修改须回归 FC/SFC。
- 目标 Java 21、Minecraft 1.21.1、NeoForge 21.1。当前 build/libs 仅开发中间件，不可作为已冻结安装组合。
- 不改变席位/OP 维护权限、距离、关机、投币、保存归属或玩家配置；无新增 UI、模型或服务器设置。
- 固定原生来源/版本/哈希，FBNeo 原许可证保留；新状态布局使用新核心身份，旧保存不覆盖、不自动迁移。
- 原生核心先在有界隔离子 JVM 验证；保留线程归属、超时、队列、原生槽位与网络校验。不强杀 MC、不卸载活跃 DLL。
- 保留原 ROM/BIOS 和用户保存，仅使用独立测试副本；测试资源不入 Git、不分发。
- MC 真人多人及长时验收单列，不能用探针代替。

## 结果

2026-09-30 完成本批加载/恢复/Netplay 缺陷的源码修复和本地回归。**不是全部街机、全部模式或整批 JNI 迁移已经完成；没有新可安装冻结发行包。**

### 根因与实现

1. 无维护输入的 FBNeo 驱动没有声明强制 profile 中的诊断选项。现在一致声明，只有实际提供输入的驱动绑定维护键；可信选项/OP 权限不放宽。
2. 遗漏声音芯片的插值/滤波/包络历史、CPS 延迟精灵缓存和 PGM 周期余量；部分 postload 又重复写寄存器/清零缓存。改为完整扫描标量/缓冲并仅重连本进程派生指针。
3. 恢复后查询 AV 无条件重建同尺寸画面缓冲，丢掉首帧；现在仅真正尺寸改变时重建。
4. 合金弹头长时间跨实例音频差异：FM 包络释放的芯片类型判断误用赋值，运行中改变芯片类型；修正为比较，没有屏蔽 PCM 差异。
5. 接收端一次消费过多合法有序消息，模拟帧未推进就超出窗口。增加有界收包背压及每轮最多 4 帧追赶；保留 32 帧权威窗口、512 队列、CRC/序列/席位校验，不跳帧或扩大接受窗口。新增积压 75 主持帧用例，修复前失败、修复后通过。

### 最终验证

使用原始固定 ZIP + 17 文件补丁干净重编的 state-v3 核心，不是诊断 DLL。SHA-256：`3e0ab5db5898e9e75e1704caa703d6f4e4cb269c4f971ab498b434f22d18f885`，61,380,608 字节。源码、构建及独立许可证见 [state-v3 说明](fbneo-study/jni-state-v3/README.md)。

游戏：`dino`、`contra`、`xmen`、`1942`、`raiden`、`orlegend`、`ddp2`、`mslug`、`mslug2`、`kof98`、`kov`、`kof97`。仅使用现有本地资源的测试副本；所有原件 SHA、大小、修改时间不变。

- 12 款分别运行至 900 和 7,200 帧；两个帧位各在原实例和新实例重演 180 帧，状态字节、完整画面、完整 PCM 全部一致，包含恢复后第 0 帧；严格断言 `exactRestorePassed`。
- 12 款各做一轮固定核心及一轮实际构建 JAR、不覆盖生产 profile 的真实四实例 JNI Netplay：单向延迟 50ms，主持推进 900 帧、每个加入端至少 850 帧，四路服务器授权输入、付费投币、CRC、手动/最终保存，再新建实例读档推进。无超时、JNI 警告或拒绝，四槽全部回收。
- dino/ddp2/kov/mslug 另有包级重复测试轮次。
- 主包完整 `check jar`、SFC `check`、街机 `check jar`：2578 + 488 + 119 = 3185 项，0 失败/错误、9 个既有跳过；准备工具另 3 项通过。主包三个包级冒烟通过。
- FC Mesen 光枪三实例和 SFC Mesen-S 双人/旁观重新跑真实核心：输入、迟到旁观、重连、CRC、立体声、手动/最终保存和读档推进通过。
- 新旧核心 profile 的存档身份不同，错误身份必须拒绝；旧字节仍可按旧身份解码。新核心路径 `win-x64-fbneo-state-v3`；旧核心、缓存和玩家档不覆盖、不自动迁移。

### 保留的失败证据与限制

测试环境曾因临时空间不足触发保护，该轮不计为通过；空间问题处理后重新测试。SFC 首轮 classpath 缺少内部 core JAR，补齐后重新测试通过。环境修复不代表生产核心修复。

MAME 音画模式仍报告 dino 缺 `dl-1425.bin`（qsound_hle）及该 MAME ROM 集所需文件；是现有内容与核心所需集合不匹配，改代码不能补出游戏数据。同一个现有 dino 在本轮 FBNeo JNI Netplay 通过，**不代表 MAME 模式缺文件已修好**。

NeoGeo 特殊“本地同步”仍走固定专用核心/旧子进程 `TZ=UTC0`，未改 MC 全局时区；不同于本轮验证的 FBNeo JNI Netplay，不能改名宣称已迁移。

开发 JAR 仍沿用工作分支版本号（FC76.26 / 街机1.5.4），不供安装。MC 真人多人、并排多机、光枪几何、实际弱网/长时、跨时区及最终版本冻结仍待验。仍为开发中／未验收。
