本机执行 PvZ 需要 Windows x64、可用的 OpenGL 2.1 兼容上下文。本版未验证其他系统或无显卡服务器运行。

## 安装和操作

1. 正常退出游戏，在测试世界副本使用。客户端和服务器都安装 `game_console_pvz-0.1.0-prototype.7.jar`，双方需已有相同版本 FC70～75；本轮配套 FC75。把旧 PvZ 附属移到 mods 外保留，不同时装两个版本。SFC/GBA/街机/Flash 不需要，不安装独立 RetroArch。原 main.pak 路径和保存目录不变，不要删除 piq-pvz/saves。

prototype.7 仅更新 FC75 加载兼容范围；没有替换 PvZ DLL、保存格式或新增联机。该组合仍是本地候选，Minecraft 实机验收待完成。
2. 本版是本机功能验证，使用创造模式、有管理员权限的玩家测试。输入 `/give @s piq_pvz:player_box`，或在方块电玩物品栏找到「PvZ 测试播放盒」。
3. 放置播放盒与电视，用主模组的视频线连接，打开电视。建议先用新版桌面电视，两台设备放在同一桌面。
4. 解压你收到的 `pvz_libretro.7z`，在播放盒界面填入 **`dist/system/pvz/main.pak` 的完整本机路径**。旁边的 `properties` 文件夹可保留。不是填 `.7z`、DLL 或文件夹。
5. 双手空着右键播放盒，点「开始」。初次生成缓存需要等待。点击预览画面上的开始，首次用户名默认 Player，可直接确认。
6. 鼠标可在预览画面点选；方向键移动光标、K 左键、J 右键、Enter 确认、Tab 游戏菜单、Q/E 滚轮。也接入标准 GLFW 手柄：十字键/左摇杆移动，A 左键、B 右键、Start 菜单、Back 确认。实体 USB 手柄尚待用户实测，不是领取 FC 实体手柄。
7. Esc/「返回看电视」只关闭操作界面，电视继续显示，键盘/手柄不在世界画面接管人物。要继续操作，空手右键播放盒重新打开预览。本版尚不支持瞄准电视直接种植物。
8. 点「结束并保存」并等待完成。进度由 PvZ 自身保存，再次开始、选择冒险模式后，已有可恢复关卡会出现 Continue 提示。

如果你只在单人世界测试，客户端 `mods` 安装即可（内置服务器与客户端共用安装）。多人服务器两端安装是因为本附属注册了共同方块、物品、方块实体和菜单授权消息；不是因为 DLL 要在服务器运行。

## 存档、暂停与诊断

- prototype.5只修正加载兼容声明，允许FC70/71/72/73，不放行未核对的FC74及以后；28项测试通过。生产Java、原生程序、DLL和资源与prototype.4逐字节相同，未接入2026-09-25新提供的优化DLL，保留原保存格式；不是重新承诺Minecraft内60FPS，也没有新增PvZ联机。
- 个人本机档：`实际游戏目录/piq-pvz/saves/<玩家UUID>/<main.pak的SHA256>/PvZ-Portable/`。不同资源版本隔离，不覆盖其他模式/玩家的保存。建议退出游戏后备份整个对应目录。
- 首版不接 FC 的个人/卡带设置，不跨电脑同步、不把存档写进服务器或物品；不提供即时存档按钮。菜单/开场等状态能否保存由游戏决定。
- 同一档案有文件锁，防止两个运行器同时写入。关闭失去连接/拆线/距离超过8格/退出世界时正常结束；失焦、其他菜单、电视关机时暂停并释放输入。异常强退仍可能丢失最近进度，不能把“已停止”视为写盘必然成功。
- 日志：`实际游戏目录/piq-pvz/logs/`。缺 OpenGL、损坏数据、内置组件校验失败会报告错误；不会联网下载安装运行库。
- 音频通过本机 Java Sound 输出，跟随 MC 主音量并有固定0.7增益；电视关机暂停。暂不支持电视遥控器独立音量、空间衰减与音频设备热切换；其他玩家听不到。
- prototype.2 改为整帧传输、三缓冲复用和批量纹理上传，画面上限由30提升到60 FPS。运行器仍目标60次核心调用/秒，不改变上游游戏时序或保存格式。独立同机对照收图从16.40提升到59.99 FPS；这不是 Minecraft 内实测承诺，实际表现仍由硬件、场景和其他模组决定。
- 预览界面显示最近窗口的「核心调用」「收图」「显示」和平均纹理「上传」耗时。核心调用不等于游戏内部更新率，收图不等于 Minecraft FPS；上传耗时不是完整输入延迟。进入游戏并等加载结束后观察，暂停/切菜单期间的数字不用于判断性能。仍卡顿时请截图这些数字，并提供 piq-pvz/logs 日志（每5秒记录核心、抓图和传输耗时）。
- 本地探针发现续玩弹窗的短点击偶有未响应，较长按住后松开可继续；若遇到请重试并附日志。此项仍待实际游戏界面和上游核心排查，不视作已经修复。

## 范围与限制

只有本机单人；服务器只发送设备菜单授权，不传 main.pak、输入、画面、声音或存档。同服其他玩家看不到这一局。没有 Netplay、双人、服务端托管或公开旁观。

播放盒暂用简易外观，没有生存配方。航空学/光影/实际多人/多显卡/低分辨率界面尚待验收。包内不包含 main.pak 或其他游戏素材，不自动修改用户实例、安装、部署或发布。

## 开发边界

- `native/pvz_host.cpp` 是专门用于评估 libretro 硬件渲染的新子进程，使用 Windows WGL。旧公共软件 worker、FC/SFC/街机核心均未改动，不复制原公共 Java 桥。
- 模组通过 `ExternalHomeConsoleBlockEntity`、`HomeSystems`、`HomeVideoDisplay` 和既有线材接口接入；本机两项 mixin 仅在这一台已就绪电视隐藏闲置画面/无信号音，不改服务端电源状态。
- 原生程序与 DLL 从附属自身资源读取，固定 SHA256 校验后放独占临时目录。没有从服务器接收或按用户指定路径执行 DLL；临时目录与原游戏文件、持久保存目录分开。子进程隔离不等于操作系统安全沙箱。
- 构建：Java21 下运行 `../piq-fc-arcade/gradlew.bat --offline check jar`。`tools/build_native.py` 使用工作区固定 LLVM 工具链重建 host 并生成 SHA 收据；更新 host 时必须同步固定 SHA 并重跑验证。原 DLL 原样取自用户提供包，未宣称与包内源码可重现一致。
- 附带的 `piq-pvz-addon-source.zip` 仅包含本附属源码和 libretro 头文件，不是上游完整源码包。重建需本工作区的 Gradle/FC70/LLVM 环境，并将原包的 `dist/cores/pvz_libretro.dll` 复制到 `src/main/resources/core/pvz/`，构建 host、核对并同步固定 SHA 后再构建 JAR。上游完整源码仍在你提供的原始7z中，公开分发前须另行完成来源与依赖清单核对。
