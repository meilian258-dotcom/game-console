## 怎样测试和保留旧版本

1. 正常退出游戏、正常停服，备份原 `mods`、世界、配置和 `game-console`。优先使用独立测试实例，保留原组合及存档。
2. 只安装本次发行页列明的主包与可选附属组合，同一模组只装一个版本。内部公共平台 JAR、SFC 薄包、源码 ZIP 和开发 API 包都不放进 `mods`。
3. 有 Replay 需求时，在客户端使用配套 test.7，不与旧 Replay 兼容补丁同时加载。独立的快速模式补丁属于另一组件，不因本次更新就视为已替换。
4. 先在测试世界检查开关机、保存和再次恢复，再测试多人及旁观。需回退时使用备份中的完整原组合，不覆盖新旧核心身份或直接迁移即时存档。

## PGM 四人设置怎样保存

此项适用于 **FC76.54 + 街机 0.1.5.12 的已适配 JNI FBNeo 路线**。运营设置与整局游戏进度分开保存；MAME 和 RetroArch 路线尚未接入同一持久化能力。

1. 由有 OP 权限的本局 1P／主持进入 Test／PGM 后台，修改游戏内部人数等运营设置。
2. 从设置子菜单选择 `EXIT`，再从 Test 主菜单选择 `EXIT`，直到返回游戏。只关掉模组界面不等于完成这一步。
3. 正常关闭街机，等待保存结果，再打开同一柜的同一游戏。

停留在游戏后台就直接关机时，游戏可能尚未提交设置；此时不能保证保留。三国战纪设为四人后逐级 EXIT、正常退出，再由全新独立进程仅恢复运营文件，已验证仍显示四人。**这项结果不等于 Minecraft 四位玩家联机已验收。**

游戏内部人数、机柜可用席位、模组游戏资料人数标签是三件事，设置四人不会凭空增加机柜端口。成功换另一款游戏后不沿用上一款的运营设置；历史数据保留，不自动迁移。加载旧整局即时档仍可能带回当时的旧人数，不通过改核心或状态内存强制覆盖。

## 其他操作变化

- **提示**：FC76.54 不再在启动时自动打开运行环境页。错误改为本机聊天中的简短提示，同类限频，不弹右上角通知；模组设置／设备设置中的“运行环境”和“复制诊断”仍可手动使用。
- **新街机默认**：在后端支持 JNI Netplay 且服务器新机策略允许时，新机柜默认 JNI Netplay。已有机器明确保存的模式不变，这不是迁移到 RetroArch。
- **家用双人**：从 FC76.52／SFC53／MD16 配套起，设备默认允许 2P，可由有权限的管理员在空闲时用螺丝刀修改并保存，下次开机生效，不再每局询问。卡带人数、核心端口和私人模式限制仍有效。
- **SFC54 候选界面**：工作台统一为“存档设置”和“存档库”。库内只读展示当前游戏下本人或当前卡带可见的新旧核心进度，不伪造三槽、改名或删除能力；旧档不自动转换。机壳前盖 Nintendo 标识移除。这些说明不代表该成品已公开下载。
- **电脑接收器**：缩小左右手的第一／第三人称持物，放置后的世界模型和碰撞不变。
