# 方块电玩玩家指南

方块电玩让你在 Minecraft 中摆放游戏设备、制作卡带、游玩和观看朋友的游戏。第一次体验建议只装主模组，用 FC 和一台电视熟悉操作，再添加你需要的机型。

## 获取和安装

先打开[下载中心](下载中心.md)，按配套要求选择主模组和所需附属。表内版本可直接下载，旧版不能替代尚未公开的新版。

找旧版本使用[各模组历史列表](下载历史.md)，仍须按所属批次配套。部分组件更新不等于整套已发布；历史整套也不包含之后的修复。GitHub 的 Code → Download ZIP 和自动生成的 Source code 均为源码，不能作为模组安装包。

当前主要组件面向 Minecraft 1.21.1、NeoForge 21.1.229 起和 Java 21，默认构建基线为 NeoForge 21.1.236。原生游戏运行端以 Windows x64 为支持范围；这不是 Forge 1.20.1 或其他 Minecraft 版本的安装包。整合包其他模组有更高要求时，不能为本模组强行降级。

可选回放工具有额外的 NeoForge 和 ReForgedPlay 要求，仅安装在客户端；屏幕／声音兼容与快速回放兼容用途不同，不能互相替代。具体公开版本及依赖见[回放兼容下载表](下载历史.md#回放兼容)，基础组件的最低版本或服务端测试环境不替代补丁要求。

1. 正常退出游戏；服务器升级先正常停服。
2. 备份原 `mods`、世界、配置及实例中的 `game-console` 目录。
3. 安装主模组 `game-console-<版本>.jar`，再安装所需附属。客户端和服务端使用同一套配套版本。
4. 移出旧的同一模组 JAR 并保留备份，不让新旧两份同时存在。
5. 启动后先在测试世界确认设备、游戏和保存恢复正常，再用于重要世界。

WaterFrames 是可选联动，不是体验内置设备的必装前置。加入别人的服务器时，以服主提供的整套包为准，不从不同历史批次各挑一个“最新版本”。

### 怎么选附属

| 想玩什么 | 安装方式 |
| --- | --- |
| FC/NES | 主模组已包含 |
| SFC | 加装完整 SFC 包，不另装家用薄包或独立内部核心 |
| MD | 加装 MD 包 |
| GBA | 加装 GBA 包；不代表支持原机通讯联机 |
| 原生街机 | 加装 Arcade 包，再按游戏准备相符的 ROM 集和 BIOS |
| 电脑程序 | 加装 Computer，并按目标程序说明准备内容 |

Flash Box、PvZ 是开发验证机型，Java ME 是独立原型，不作为入门必装项。源码中的 `piq-retro-platform` 不是玩家安装包。

## 第一次玩家用机

下面以主包 FC 为入门示例；SFC、MD 沿用相近实体操作，但可用模式以各机型说明为准。

1. **准备游戏**：自行准备有权使用且格式匹配的 ROM。手持对应卡带右键老式电脑，打开卡带工作台；用“ROM 目录”找到本机目录，放好文件后刷新。
2. **制作卡带**：在列表里选择游戏，查看预览，按需设置名称、封面、人数和存档方式，最后确认写入。选择本地游戏并上传时会把内容送到服务器，不是只在本机选文件。
3. **摆放和连接**：放置对应主机与电视，用视频线连接设备接口，然后插入卡带。
4. **开机**：先打开电视，再按主机实体电源区域的提示开机，需要保存时先选存档。当前家用配套直接读取设备的“2P：允许／禁止”，不再每次开机询问双人。
5. **开始操作**：完成开局提示后领取对应手柄，按游戏内按键设置操作。修改过按键时以你自己的设置为准。
6. **结束游戏**：归还手柄与关机不是同一件事。需要保存时正常关闭设备，等待保存完成反馈，再退出游戏或服务器。

从 FC76.52、SFC53、MD16 对应配套起，家用设备默认允许 2P；有权限的管理员可在设备空闲时用螺丝刀修改，随设备保存并在下次开机生效。允许时朋友直接领取空闲 2P 手柄，不反复向 1P 弹申请。较旧版本可能仍有开局确认，以该批次说明为准。

卡带人数、设备允许 2P 和实际手柄占用是不同条件。单人游戏、私人模式或不支持双人的核心端口，不会因为开启 2P 就增加双人玩法。

卡带工作台分为游戏列表、预览与设置、确认写入三个部分。先选择游戏和设置，点击“写入卡带”后才会修改卡带；具体按钮以所用机型和版本为准。

## 街机和掌机

- **街机**：先通过机柜的游戏选择入口选定后端和游戏，再按机柜提示开机、入席或投币。不是所有后端都支持相同人数或联机方式；四人玩法还需要对应游戏和机柜组合。
- **GBA**：主副手分别持掌机和对应卡带，Shift + 右键插卡；Shift + 左键拔卡，运行中先正常关机。其他操作见 [GBA 说明](../../piq-gba/README.md)。
- **设备设置**：用调试螺丝刀打开设置。需要停机的选项先正常关机，灰色条目查看原因；“不可用”不等于忘了点击某个隐藏开关。
- **服主设置**：影响全服的权限和资源设置从管理终端进入，不通过改玩家本机偏好来代替。

FC76.54 配套街机 0.1.5.12 时，支持 JNI Netplay 且服务器新机策略允许的**新机柜**默认选用 JNI Netplay；旧机器明确保存的模式保持不变。这不是切换到 RetroArch。

### PGM 后台人数怎样保留

以下适用于 FC76.54 与街机 0.1.5.12 候选的已适配 JNI FBNeo 路线；是否可下载以本批发行附件为准，不代表所有后端已支持。

1. 由有 OP 权限的本局 1P／主持，通过街机的 Test／PGM 后台入口修改游戏运营设置，例如将三国战纪设为四人。
2. 在设置子菜单选择 `EXIT`，再从 Test 主菜单选择 `EXIT`，直到真正返回游戏。不要停在后台直接关机。
3. 正常关闭街机，等待保存结果，再重开同一机柜的同一游戏。

游戏内人数设置、机柜席位数、模组游戏资料中的人数标签各有作用，修改其中一个不会自动修改其他两个。运营设置按机柜与游戏保存，不依赖个人／机器游戏进度；成功切换另一款游戏后不沿用上一款的运营设置。恢复旧即时存档仍可能带回旧人数。MAME 和 RetroArch 路线尚未接入这项保存，不能按上述步骤承诺保留。

## 联机和观看有什么区别

| 菜单里的方式 | 大致怎么运行 | 玩家需要知道的事 |
| --- | --- | --- |
| 玩家音画串流 | 一位玩家运行游戏，把画面和声音传给其他人 | 观看端不必为观看再运行一份模拟器 |
| JNI Netplay | 各参与端在本机运行核心，交换输入与同步数据 | 对核心、游戏、BIOS、选项和资源要求更严格；具体机型要已适配 |
| 私人模式 | 只在自己的本机运行 | 不当作向其他玩家公开的房间 |
| 旁观 | 看某台正在运行的设备，不取得操作席 | 具体使用串流还是本地核心，取决于该设备的运行模式 |

JNI 是“游戏进程直接调用原生核心”的技术方式，不等于已经联机。RetroArch Netplay 是另一条模式，不能看到名字类似就认为与 JNI Netplay 可以互换。

当前 FC／SFC／MD 家用配套在能力及服务器新机策略允许时默认 JNI Netplay，保留旧设备明确选择的模式。历史 SFC 菜单中有一条标成 RetroArch 的路线实际使用 JNI；标签修正不代表迁移了后端。统一 RetroArch 后端是后续方向，当前版本不能据此混用两种联机方式或存档。

附近观看、第二位玩家加入、服务器托管也是不同功能。是否能用看设备当前显示的能力；不要因为某台 FC 支持某个模式，就认为所有附属都支持。

## 存档怎样选择

卡带存档设置中常见三种方式：

- **不存档**：每次从头开始。
- **卡带存档**：进度跟随这张卡带。
- **个人存档**：每位玩家使用自己的进度。

并非所有设备和模式都使用完全相同的保存方式。已有档通常可以继续或选择从头开始；删除、覆盖与重新开始要看清确认提示。

SFC54 候选将工作台入口统一为“存档设置”和“存档库”。存档库只读列出当前游戏下本人／当前卡带可见的 Snes9x 新进度与 Mesen-S 旧进度，不提供改名、删除或 FC 式三槽管理。旧进度保留原核心身份和风险提示，新旧进度不自动转换；上述能力由当前公开 SFC55 沿用，SFC54 当时仅为本地候选，未单独公开。

换核心或换运行模式后，旧存档不一定兼容。不要通过改文件名、删除校验文件或拿新核心强读旧档来解决。升级前保留世界及 `game-console`；仅备份一个 ROM 文件夹不能保护所有进度。

## 服主怎样找 ROM 和 BIOS

现行服务端内容的共同入口是**服务器实例目录里的 `game-console/`**，不是只看世界文件夹。单人游戏则是该游戏实例目录。客户端“ROM 目录”按钮打开的是客户端位置，不会打开远程服务器磁盘。

| 内容 | 相对于服务端 `game-console/` 的位置 |
| --- | --- |
| FC 游戏 | `piq-fc/roms/` |
| MD 内容卡游戏 | `content-cards/piq_md_home/md/` |
| GBA 内容卡游戏 | `content-cards/piq_gba/gba/` |
| SFC 家用游戏 | `world-content/<世界标识>/piq-sfc-home/roms/` |
| 历史独立 SFC 机柜游戏 | `piq-sfc-arcade/roms/` |
| 通用街机内容对象 | `piq-cabinet/server-games/objects/` |
| 街机原名和文件位置索引 | `piq-cabinet/server-games/indexes/` |

上传后某些磁盘文件以内容哈希命名，是去重存储方式，不是游戏名乱码。MD/GBA 原名另存于同根 `content-card-metadata/` 中对应机型目录；街机通过索引查原名和 ROM/BIOS 对象，不要直接把 `.data` 改名或删除共享对象。磁盘文件存在，也不代表当前世界已经授权并登记该游戏。

### 街机提示缺 BIOS

以当前 FBNeo 上传路线为例：

1. 准备有权使用、与核心要求匹配的游戏 ZIP。
2. 将对应 BIOS ZIP 放在所选游戏的同一目录。目前该上传路线接入的名称为 `neogeo.zip`、`pgm.zip`、`qsound.zip` 和 `qsound_hle.zip`；不是支持所有上游 BIOS 的自动搜索器。
3. 重新选择游戏，确认完整上传，然后重开本局。只往远程目录补一个文件，不会自动更新原有清单。
4. 在街机索引中确认本次清单包含 BIOS。名字相同仍可能不是相同版本，不要混用 ROM 集。

当前 FBNeo JNI 路线主游戏 ZIP 上限为 96 MiB，单 BIOS 上限 16 MiB，最多五件合计 128 MiB；其他后端限制可能更小。更多目录迁移和权限细节见[内容库说明](../design/内容库收尾与核心退役-20261004.md)及[BIOS 说明](../design/服务端内容目录与街机BIOS-20261003.md)。旧文档中的更小额度仅属于它标注的旧批次。

## 遇到问题时提供什么

FC76.54 起不再在启动时自动打开运行环境诊断页，实际错误改为本机聊天框的限频摘要，不弹右上角系统通知。需要详情时，从模组设置或设备设置手动进入“运行环境”，使用“复制诊断”；摘要消失或页面没有自动打开不代表错误已解决。

在 [Issues](https://github.com/meilian258-dotcom/game-console/issues) 写清：

- Minecraft、NeoForge、主包和附属的具体版本。
- 单人还是服务器，出问题的机型和运行模式。
- 从哪一步开始、预期是什么、实际发生什么，能否重复。
- 游戏显示名和文件格式即可；不要上传商业 ROM 或 BIOS。
- 必要的错误日志；闪退时附相关崩溃报告，提交前去除地址、令牌和个人信息。
- 图形问题附截图、显卡信息、Iris 版本和光影包名称。

光影、不同 ROM 集和多人长时间运行仍有待验证的组合。“能启动”或“单元测试通过”不代表这些场景全部正常。
