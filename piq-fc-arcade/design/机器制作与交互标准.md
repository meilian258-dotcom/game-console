# 方块电玩：机器与附属通用制作规范

更新日期：2026-10-07。适用于方块电玩主模组、已有设备及今后新增的机器、程序和外设附属。

本文统一回答：**一个新东西在方块电玩里应该长什么样、玩家怎么操作、数据怎么保存、怎样才算做完。** 制作和验收所需的玩家行为要求与四张参考图放在同一文档中，不需要先读某个机型的修复记录才能理解。具体版本进度、故障定位、代码实现和测试结果另记在各组件说明，不混进通用条款。

参考图展示已确认的外观、交互和菜单风格；图中的具体机型只是示例，不要求所有设备使用同一外壳、接口或按键。图片不代表某个实现已经验收；图中的坐标、玩家、游戏、封面和实验标签不作为默认数据，也不随 JAR 分发。图号保留原顺序，另可通过[参考图集](机器交互参考图集.md)按图查阅。

“模拟器已经能运行”不等于“机器已经做好”。外观、真实操作、反馈、内容、保存、适用的多人体验和异常收尾都属于成品要求；未做好的适用项标记缺失。**未实现不等于不适用**，也不能用假按钮或临时原型降低规范。

## 0. 怎么用这份规范

### 一个制作目标入口，不维护多套流程

本文是所有机器与附属的通用制作目标：第 1 节规定完整业务流程与类型分支，第 2～10 节规定每个环节的具体操作和参考效果，第 11 节规定怎样验收。新增机器先按这里确定要做什么，再查接口；旧机器补齐也使用同一标准。

[全组件运行流程与复用接口总览](全组件运行流程与复用接口总览.md)记录源码实际怎样运行、有哪些可复用接口及缺口；行为细则和工程规范补充距离、权限、线程等约束；历史版本说明只作兼容与问题追踪依据。它们不再各自定义另一套开局顺序。**以下是目标合同，不表示现有公共层或所有机器已经实现。** 新的明确需求应替换对应旧条款，过时目标不与新目标并列生效。

### 先确定设备类型，再落实适用功能

| 类型 | 必须落实的体验 | 不应硬套的部分 |
| --- | --- | --- |
| 家用卡带机 | 实体主机／电源灯、电视与可见视频线、卡带工作台、插退卡、手柄借还／动画、个人与卡带保存、公共设置和适用的多人体验；见第 1～8 节 | 不加街机投币或空席自动关机策略 |
| 街机 | 机柜与机身屏幕、电源、摇杆／按键动画、游戏库、投币、操作席、适用的组柜与保存；见第 2、7～9 节 | 不强加实体卡带或可借走的家用手柄 |
| 手持机 | 掌机物品、可读屏幕、举起／放下与独立电源、手持输入、适用的卡带和保存；见第 5～8、10 节 | 不强制放置成方块、接电视或另领手柄 |
| 电脑及程序附属 | 主机／配件、显示连接、键鼠操作、统一程序入口、权限与适用的保存／旁观；见第 2、3、6～8、10 节 | 程序附属复用电脑交互，不再造一台重复电脑，也不必伪造卡带 |
| 控制器、显示器、线材及其他外设 | 对应的连接、取还、输入或显示、动画／反馈、权限与失效清理；见第 2～4、7、8、10 节的适用条款 | 不要求每件外设自行启动核心、拥有游戏库或独立存档 |

新增类型先按最接近的使用方式选适用项。确有新的介质、操作或联机机制时，先明确差异并补入本规范；不得默默沿用一台旧机器的全部行为，也不得为了省事删掉适用功能。所有类型均执行第 11 节的适用验收。

### 开工前先查现成方案

1. 先列清机器类型、外形／控制器／介质、内容来源与支持格式／所需固件、实际核心与平台、人数／原生联机、保存类型／归属／额度、运行方式和特殊外设，逐项对应本文要求。原生能力不支持与本模组尚未实现分别记录。
2. 阅读相近设备、公共组件及核心的调用说明和官方文档，查找仓库与上游的成熟实现；记录复用对象、来源、适用范围和未满足的要求，再开始实现。
   **使用 Libretro 的新机器，制作前必须阅读 [Libretro 官方文档仓库](https://github.com/libretro/docs)中与目标机型、核心和接入方式相关的文档，主动查找有用信息与现成方案；不能只打开首页或凭以往经验跳过。** 可结合其[官方文档站](https://docs.libretro.com/)检索，重点核对适用的内容格式／BIOS、输入端口／外设、核心选项、音画接口、存档、联机限制和许可说明。在制作记录中写明阅读日期、具体页面或仓库路径、采用的信息与待验证限制；找不到或无法访问时如实记录，补齐依据前不将该项视为完成。文档中的核心能力仍须经过本模组适配和测试，不能直接当作功能已实现。
3. 公共的电视／线材、控制设置、工作台布局、内容传输、权限、保存、旁观和运行器优先复用；本机型只适配外观、端点、端口、目录、格式与真实能力。复用界面必须同时接通功能，不能只复制按钮。
   先查[全组件运行流程与复用接口总览](全组件运行流程与复用接口总览.md)，沿“玩家动作 → 界面 → 请求与服务端校验 → 核心 → 保存／旁观 → 收尾”核对相近类型及公共组件。现有机型也可能偏离规范，不能把旧缺陷或历史原型当作新机器模板；总览中的建议接口不当作已存在 API。
4. 只有现有能力确实不足才补最小公共扩展，并核对原有设备兼容性；实现进度与待验项留在对应组件记录，不能把临时缺口写成永久规范。

### 统一的交互原则

- 可见部件与功能对应：电源负责电源，卡槽负责介质，控制器负责操作；工具打开设置，不代替日常物理操作。
- 分开管理电源、游戏运行、操作席、旁观和显示。归还控制器／退出菜单／走远看不见，不能无故关闭别人仍在使用的会话；各类型明确规定的安全收尾除外。
- 同类动作使用同一入口、术语和反馈。机型外观可以不同，但不能每个附属重新发明一套拷卡、存档、拿手柄和设置操作。
- 未完成、暂不可用和不适用要分清；失败说明原因，保护原物品和旧数据，不能显示假成功。

## 1. 完整统一流程：准备、开局、游玩、保存、收尾、再继续

统一的是每一步的职责、数据含义、界面入口和成功／失败结果，不是让所有机器长得一样或支持所有核心功能。家用机用卡带和手柄，街机用机柜、投币与操作席，掌机用机身按键，电脑用程序与键鼠；同一环节优先进入共用业务和界面，由设备适配实际能力。

### 1.1 所有类型都要交代完整闭环

| 阶段 | 玩家能做什么／看到什么 | 必须完成的业务 |
| --- | --- | --- |
| 准备内容 | 查看本地／服务器游戏或程序、搜索、识别名称与封面、选择后确认写入／装载 | 按设备的目录和格式扫描；校验权限与内容身份；上传成功后保留可读名称；预览不是写入，写入不是开机。 |
| 准备设备 | 放置或拿起设备、接线、装入介质／配件、按实体电源 | 校验连接、介质、设备类型及可用运行方式；物品事务不吞不刷。已有内容不要求重新选 ROM。 |
| 准备本局 | 按需选择保存进度和多人许可，明确继续／新开／取消 | 尚未确认完只允许有时限的准备状态；不算已经运行，不提前授予输入或默认同意加入。 |
| 启动与恢复 | 看到加载、就绪或具体失败原因 | 取得授权内容、建立对应核心／程序、恢复兼容进度；准备成功后才开放操作和公开音画。 |
| 操作与加入 | 取得对应手柄／席位／键鼠控制；看到实际使用者与按键反馈 | 服务端维护公开席位和端口，拒绝无权输入；第一／第三人称与旁人视角按隐私规则呈现。 |
| 旁观与设置 | 附近玩家按能力观看；工具进入一致设置与诊断 | 旁观不占操作席；只同步授权范围内的数据；设置回读真实状态并说明生效时机。 |
| 保存与结束 | 知道是否保存成功；可以安全关机、退卡或退出 | 按本局归属持久化，再释放会话资源；区分只退出操作与真正结束运行，失败保留旧好档。 |
| 下次继续 | 原内容、连接和有效配置仍在；看到兼容的已有进度 | 重新校验并重新执行适用开局确认；不继承上局的临时加入许可，不把旧不兼容档当作空档删除。 |

完整实现必须贯穿这张表。工作台能打开、核心能启动、存档文件能生成，只能分别证明局部能力，不能据此认定整机做好。

### 1.2 家用机的标准开局顺序

日常准备：拿卡带右键老式电脑拷卡 → 摆放主机和电视 → 用视频线连接 → 插卡 → 打开电视 → 右键主机实体电源。手柄允许提前借出，但借到实体手柄不等于已获游戏输入权限。

主机收到开机请求后，统一按下面顺序执行，不再由各附属另定先后：

1. **检查并建立本次准备请求。** 核对设备、卡带／游戏、连接、权限、运行方式和真实能力，固定本次内容身份；缺卡、缺核心、错误格式、忙碌或受限时明确失败。重复点击不能并发开两局。
2. **按需选择存档。** 不存档模式跳过槽位页；个人档、卡带档显示对应的真实兼容槽位，允许选择已有进度继续或空位新开。更名、删除、从头开始按第 6 节处理，不能在这里只改标签而不改实际选择。
3. **独立确认本局是否允许 2P。** 支持双人的公开家用局弹一次“是否允许第二名玩家加入”，提供允许／不允许和取消开局。不存档也要经过这一步；单人内容或私人模式则明确单人并跳过不适用的确认。
4. **加载并恢复。** 按已确认的内容、保存身份、运行模式和加入选择启动／恢复；等待期间不得操作未就绪核心。加载失败不回退成另一核心、另一存档或默认双人，必须可读地报告并安全取消准备。
5. **进入就绪运行。** 就绪后才允许已授权端口输入、播放游戏音画和建立适用的公开旁观。1P 领取或使用已借出的本机手柄；已允许加入的朋友领取空闲 2P 手柄即可进入，不反复弹申请打断 1P。

游戏的最大操作人数、本局是否允许加入、存档的单双人信息是三个字段，不能互相顶替。允许加入也不能突破内容人数或核心端口上限；拒绝加入不影响已确认的单人开局。再次开局重新确认本局许可，不默认沿用旧回复。

选择期间按取消／Esc／关闭开局窗口都取消本次准备，清除临时锁和未生效许可；不启动核心、不清空旧进度、不把拒绝加入当成取消单人游戏。返回上一步只是修改未提交选择。迟到的选择回复必须按设备、请求／会话代次和连接身份校验，不能影响另一局。

### 1.3 存档分支和归属贯穿整局

| 保存选择 | 开局时 | 运行与正常结束 | 下次进入 |
| --- | --- | --- | --- |
| 不存档 | 不加载旧进度、不弹槽位；仍执行适用的加入确认 | 不写入本局进度；不删除以前的档 | 从头开始。 |
| 公开个人档 | 按开局确定的玩家保存身份和兼容范围选档 | 写回这位玩家的所选槽，换操作者或计算主持不自动换所有者 | 同一玩家在兼容设备上可继续，另一玩家不得串档。 |
| 卡带档 | 按这张实体卡的唯一身份与内容选档 | 写回这张卡对应的进度，不以当前持有人替代卡身份 | 转交玩家／换机器仍可继续，不同实体卡不因同 ROM 自动共档。 |
| 街机机器档 | 按主柜／机器身份与当前游戏选取适用进度 | 保存到该机器的兼容范围；副柜和观看者不另造一份档 | 原机／组按策略继续，不与个人档混用。 |
| 私人本地档 | 明确仅自己玩，按本机兼容命名空间选取／恢复 | 只写本地私人档，以本地持久化结果确认，不上传进度 | 不自动继承、覆盖或合并公开档。 |

这张表统一语义，不强迫所有设备提供所有保存形式：家用卡带机按第 6 节落实不存档／个人／卡带；街机按第 9 节；掌机电池档、电脑程序数据等按第 10 节声明。即时状态、SRAM、电池／RTC、记忆卡和程序存储的字节格式仍由对应适配器负责，不能把“统一保存”做成全设备共用一份文件。

开局玩家、存档所有者、核心计算主持、1P 操作者是四种身份，必须分别明确；某人归还手柄、加入、旁观或接替计算都不自动获得别人的档或管理权限。保存归属、内容哈希、核心／格式版本、槽位和会话代次共同约束写回。沿用既有额度和兼容隔离，不借统一界面合并旧命名空间。

### 1.4 不同类型如何接入同一闭环

| 类型 | 准备与开局 | 取得控制／多人 | 保存和退出的差异 |
| --- | --- | --- | --- |
| 家用机 | 卡带工作台、插卡、电视连线、实体电源；严格走 1.2 | 手柄借还；本局一次 2P 确认后直接取空位；旁观独立 | 归还某个手柄只退出该端口，不自动关机；物理关机、关联电视关机／拆线走结束流程。 |
| 街机 | 游戏库或已选内容、机柜电源、适用保存／组柜；不是家用卡带流程 | 摇杆操作席、投币、主副柜端口、按类型定义的加入申请；不套用家用手柄弹窗 | 主柜统一会话；最后一席主动退出和空席计时按全服街机策略，旁观不计操作席。 |
| 掌机 | 物品内插卡、独立电源、适用电池档／保存恢复 | 机身控制；右键举起／放下；原生通讯只有实际适配后才出现 | 放下只改变姿势／显示和输入，不关机；Shift 插拔卡及电源按第 10 节优先级，安全拔卡保护进度。 |
| 电脑／程序 | 配件、显示和键鼠连接，统一程序入口装载内容，按程序恢复数据 | 键鼠取得／交接控制；程序附属复用电脑入口，交接不等于双人游戏或核心迁移 | 返回普通菜单或交还控制不隐式关机；程序退出、主机关机与程序数据保存分别声明。 |
| 外设 | 按设备类型连接真实端口并校验兼容性 | 控制器获得对应席位／端口权限，显示器与线材提供其职责 | 跟随所属会话解除输入／画面和借还关系，不自行再开核心或复制游戏档。 |

同类公共环节不重写一套；确有类型差异就在适配策略中声明，不靠藏按钮或绕过校验实现。原生联机、Netplay、本地输入同步和玩家音画串流不是一回事；每个模式的实际能力分别声明，不能因核心有某能力就自动开放。

### 1.5 每类操作结束后必须处于什么状态

| 操作／事件 | 应有结果 |
| --- | --- |
| 关闭准备开局的窗口 | 取消本次启动，释放准备状态；没有暗中开局、扣重复物品或授予 2P。 |
| 关闭游玩中的普通设置菜单 | 返回原会话，不关机；菜单／失焦期间释放输入，回来不重放旧按键。 |
| 归还手柄、退出一席、切走控制物品 | 释放相关端口输入／姿势；仅前两者按规则退席，切槽不当作整机断电；不影响其他合法端口。 |
| 走出操作范围 | 按该类型撤销控制或归还租借物，不能拿旁观范围代替操作范围。 |
| 走出显示／旁观范围 | 停止不必要的绘制、播放和订阅；计算主持仍按会话需要运行，不能关掉别人的局。 |
| 正常关机、退卡、换内容、拆除／断开运行所需连接 | 先停止新输入并进入收尾，完成适用保存确认后再提交物品／内容变化、结束核心、清理席位与显示。可取消的动作在保存失败时不冒充成功；保留介质和可恢复进度，明确重试／恢复办法。 |
| 保存进行中再次点关机／退卡／换游戏／重启 | 同一次收尾去重或显示忙碌，不并发销毁旧会话、创建新局或重复物品事务。 |
| 断线、死亡、换维度、卸载、核心崩溃 | 撤销输入和临时授权，按类型执行安全结束／可验证的接管；仅能保存仍可取得的检查点，不能保证最后一帧。有限超时后释放临时锁，保留旧好档与有效恢复材料，明确未确认进度，不能无限等待离线端 ACK。 |
| 旧请求／旧保存结果迟到 | 拒绝修改新局、另一玩家、另一张卡或另一内容；不能复活旧输入／动画／旁观，也不能覆盖新进度。 |

公开保存以有权存储端完成校验、持久化并确认成功为准；私人保存以本地持久化为准。发出请求、存在缓存、核心已经停止都不是“保存成功”。先写入并验证新版本，再安全替换旧好档；从头开始也不提前删旧档。正常可控退出与不可控故障分别验收，异常不能用永久锁机来掩盖失败。

### 1.6 界面与接口怎样复用

| 共同职责 | 应由公共层提供的合同 | 设备／核心适配内容 |
| --- | --- | --- |
| 内容工作台 | 名称／来源／封面展示、预览后确认、上传下载反馈与权限、返回上下文 | 命名空间、目录、格式／依赖文件、介质身份；绝不打开另一机型目录。 |
| 开局协调 | 校验、保存选择、加入确认、启动／恢复、就绪、取消及失败收尾 | 类型开局策略、人数和模式能力、实际装载／恢复回调。 |
| 控制与表现 | 席位／借还授权、端口路由、释放全部按键、使用者信息、适用的公开动画同步（家用远端按钮非必做） | 按键映射、端口索引、手柄／机柜模型、命中区、姿势和接线端点。 |
| 保存服务 | 保存身份与额度、真实列表、命名／删除确认、事务写回、兼容判断和错误反馈 | 对应核心／程序的数据格式、版本兼容范围、导入导出与检查点。 |
| 音画与旁观 | 授权订阅、帧／音频路由、距离与预算、晚加入／重连、解除订阅 | 视频／音频格式、运行器、显示面与能力限制；不重造专属电视。 |
| 设备设置 | 一致布局、状态回读、真实禁用原因、生效时机、控制／性能／网络／诊断入口 | 机型能力和配置字段；JNI 是运行器信息，不冒充联机模式。 |
| 生命周期与配置 | 请求代次、幂等、清理、权限、全服强制／新机默认／设备配置／本机偏好的归属 | 类型策略和资源释放；不同范围的距离、空席计时不能混成一个全局开关。 |

本表是待落实的职责边界，**不是已经存在的类名、稳定 SDK 或接口清单**。实现前必须到技术总览和对应组件调用说明核实：可直接复用什么、只需适配什么、公共层还缺什么。缺口先补公共合同并覆盖旧调用者，附属不要复制 FC 私有代码后只改标题；也不要把某核心专属输入掩码或存档格式推广到所有机器。

### 1.7 改造与完成判定

先补影响数据安全和正确身份的缺口，再贯通公共开局／保存／控制链，再补齐各类型表现与配置。采用一个同类设备接入验证时，必须同时回归已有调用者；其他机器接入也逐项登记差异，不能认为第一个设备通过即全系列通过。

每个声称可用的模式都要从真实玩家入口走完“准备内容 → 开局 → 操作／适用的加入与旁观 → 保存／结束 → 再开继续”，并覆盖取消、失败与旧数据。证据必须对应同一版本、同一内容和保存身份，不能拼接几张不同测试的截图作完整闭环。只完成局部时交付为明确列出缺口的候选，不标整机达标。

### 1.8 JNI Netplay 是模拟器多人体验的重点，不是“用了 JNI”就完成

对需要共享同一局游戏的模拟器设备，**优先完善公共 JNI Netplay，再推进其他未完成的运行模式**。这是制作优先级，不代表现有机型已经实现，也不豁免前述内容、开局、权限和保存安全要求。玩家音画串流、私人单人或独立进程 Netplay 可以有自己的适用场景，但不能顶替 JNI Netplay 的交付目标；不能因为这些模式能启动，就把 JNI Netplay 永久列为灰色按钮后宣布整机完成。

必须分别声明三件事：使用什么核心；由 JNI 还是独立进程调用；本局使用哪种同步方式。**JNI 核心能运行 ≠ JNI Netplay 已接通；RetroArch Netplay ≠ 本模组 JNI Netplay；本地同步 ≠ 音画串流。** 菜单必须按真实能力区分，不能只改标签、默认值或解锁按钮。适用的附属复用公共 JNI Netplay 入口，不把功能限成 FC 专属，不复制每机型一套联机、内容传输和保存系统。

最低完成条件如下，按同一版本、同一核心和内容组合验证：

| 环节 | JNI Netplay 必须证明的结果 |
| --- | --- |
| 核心与兼容身份 | 固定核心版本／摘要、内容及依赖、影响确定性的选项、真实端口和同步协议；不匹配拒绝加入。支持即时存档的官方标记不代替实际回滚测试。 |
| 确定性与回滚 | 相同初态与输入在独立实例得到一致结果；延迟输入触发恢复／重演后，模拟状态及影响后续运行的 SRAM／RTC 等仍一致。音频／视频呈现不重复播放旧帧或错误时间线；任何跳过、归一化或不比较的字段都须有源码依据和行为验证，不能屏蔽未知差异来过测试。 |
| 正常开局 | 仍走本类型的公共开局链；家用为校验→按需选档→独立 2P 许可→加载／恢复→就绪。准备状态不得提前运行公开游戏、授权输入或写回新档。 |
| 双人及端口 | 两名真实操作者分别控制正确端口；加入许可、租约、失焦／退出释放有效。计算主持、档主、1P／2P 分开，归还 1P 不等于结束仍有人玩的房间；输入经服务端转发或直接同步的策略与延迟代价明确记录。 |
| 只读旁观 | 晚加入、离远返回和重连能取得匹配种子并追上本局；旁观不占操作席、不发游戏输入、不写档。内容取得走已有授权流程，不隐式启动另一种模式。 |
| 保存与再次继续 | 不存档／个人／卡带等适用归属保持一致；只有有权主持提交已确认进度，持久化确认后才算成功。周期保存、手动保存、正常关机、再次恢复分别验；不同模式／核心的旧档不自动合并或覆盖。 |
| 失败与设置 | 取消、断线、弱网、不同核心、坏状态、加载失败及关机中的晚包均有有限收尾，旧好档保留。不暗退回音画串流或另一核心；菜单分别说明未实现、服务器限制、实验未确认、正在运行不可改等真实原因。 |

验证分为单元／协议、隔离真实核心、MC 双客户端及晚加入旁观、弱网／长时四层；通过一层不替代另一层。未达到的项列为缺口和下一步，不标“已完成／稳定”。具体版本的通过与失败证据放在组件制作记录，按[验收清单 N10～N15](功能制作验收清单.md)逐项填写。

本优先级适用于共享模拟会话，不强迫单机程序或纯外设提供 Netplay，也不把掌机原生联机线等同于共享输入。确实需要不同通讯机制或核心尚不能满足确定性时，说明适用边界、证据和待办；**“尚未适配”不能改写成“本来就不需要”**。开发验证机型可按明确的版本范围暂缓，不能借暂缓结论降低以后正式机器的标准。

## 2. 主机本体：不只是摆一个模型

- 按设备类型提供可辨认的正面、介质槽、控制器位置、视频接口、电源键和电源灯；只提供真实存在的部件。有 RESET 的机型提供独立重置功能，不用隐藏组合键替代已有按钮。掌机电源手势见第 10 节。
- 放下时正面对玩家。四个朝向下，模型、插口、按钮点击位置、线和屏幕都一起转，不能只有外观转了。
- 放桌面不悬空、不埋进桌子；占地与机身相符，不能在空白区域多占一格。并排或靠墙时，看得见的按钮不能被另一台机器的空选框挡住。
- 选框简洁、贴近整体外形，不画成一排阶梯框；碰撞、选框、按钮点击范围分别处理。按钮可适当扩大容差，但不能穿过实心机壳或墙壁点击。
- 卡槽空／已插卡、手柄在位／被取走、电源开／关都要有对应外观。插入的卡带要显示正确封面，不能固定画一张假卡。
- 模型与贴图风格一致，不闪面、不漏底、不镜像；手持、物品栏、掉落显示和创造栏图标都要清楚，不能只做好放置模型。

机器应稳放桌面、实体部件清楚、插入卡带可见。各机型保留自己的外形和接口；电源灯的位置与实际开关状态分别验收。

### 电源、重置和指示灯

| 操作／状态 | 应有表现 |
| --- | --- |
| 右键主机电源键 | 开机；运行中再按则正常关机。不要把右键任意外壳当作电源键。 |
| 右键 RESET | 重启当前游戏，不退卡、不换游戏、不清空原有存档；不能顺手重置别人的机器。 |
| 只打开电视 | 电视进入待机显示，不代替按主机电源。 |
| 有已选游戏时请求开机 | 不重新进入游戏库选 ROM；按第 1.2 节完成校验、适用选档与独立加入确认，再加载／恢复，成功后显示运行状态。 |
| 未插卡时请求开机 | 明确提示“未插卡”，不建立已运行状态或占席；主机回到关机／待机指示，插卡后仍需按电源发起开局，不因插卡自动启动。不得同时写成“已正常开机”却又要求同一电源键执行开机。 |
| 缺少游戏／核心或启动失败 | 简短说明原因并提供诊断入口；不能一直假亮、假占用或只黑屏。 |
| 正常关机 | 按第 1.5 节先停止新输入、取得并持久化适用进度，确认后结束核心和释放占席；保留插入卡带、已选游戏和有效设置，不能先销毁核心再尝试取档。 |
| 关掉关联电视（家用机） | 结束关联游戏并走正常收尾；不是“离远隐藏画面”的同一种操作。其他类型按自身显示设备的生命周期处理。 |

家用机、电视已有电源灯的位置应区分关机／待机红灯和开机绿灯；街机使用红色发光翘板开关，不强行改成绿灯。灯跟随真实状态，不能仅根据有人拿手柄就亮。主机指示灯自发亮即可，不必照亮周围；电视开机应有适当屏幕照明。

开关有按下／切换状态和一次按键音效。RESET、插卡、拔卡、取还手柄、接线成功也要有相应反馈；不要双端各播一次，或每次同步状态、重新进入区块都重播。

准星对准实际可操作部件时，应显示对应的简短提示，例如“右键 · 开机”；状态改变后提示相应动作，移开消失，按玩家实际绑定显示按键。提示与真实命中一致，不用反复刷聊天代替，也不把旁边机器的按钮提示串过来。

提示必须与点击结果一致。不能写着“开机”，实际却弹出选游戏或调试菜单。

## 3. 接线：必须接得上、看得见、拆得掉

- 对外统一叫“视频线”。拿线依次右键主机和电视完成连接，先点哪一端都可以；支持共用电视，不给每个附属再做一套专属电视。
- 家用视频连接沿用现有 8 格上限；超距、目标不匹配、接口被占用等情况明确失败，不扣线。不能把线长上限和手柄 6 格活动范围混为一谈。
- 正常连接成功后，生存模式消耗一份线，并真正渲染两端插头和中间线材。断开时只返还实际消耗的那份，不因重复点击刷线；创造模式也不能产生额外物品。
- 插头贴合本机型的真实接口并随朝向转动；电视端按其接口分支表现，逻辑走共用视频连接，不因换机型另造连接系统。
- 线的粗细和风格统一，端头衔接自然；不要从机身中央拉出一条斜直线，也不要悬空起飞、折返打圈、插进前面板。
- 桌放电视的线自然落向桌面，壁挂电视的线沿背面／墙面向下；主机放在电视或接口正下方也能正常连接。几何变化不能导致连接判定失败。
- 两手空时，右键主机实际露出的后部视频接口可拔线；保留持视频线 Shift＋右键端点的拆线方式。普通右键电视屏幕不等于拔线。
- 运行中拆线或拆除设备要结束受影响的关联会话、处理保存和物品返还，不能残留声音、画面、手柄占用或悬空连线；不影响旁边未连接的机器。
- 重新进区块、重进服务器后连接与线材仍一致；不能要求玩家把设备拆掉重放才能看到线。

街机通讯线与电脑键鼠的例外见第 9、10 节。手柄线不能用一条永久装饰线代替，须跟随实际领取状态。

## 4. 手柄：取、用、还和外观都要做齐

### 领取与归还

| 玩家动作 | 应有结果 |
| --- | --- |
| 右键主机上对应的 1P／2P 手柄或收纳位 | 领取对应端口手柄，优先放空主手，其次空副手；两手都满则提示，不能吞掉手中物品。 |
| 没开机、没插卡时领取 | 可以拿下来；拿到实物不代表游戏已启动或获得某局的控制权。 |
| 游戏运行后领取 | 按人数、空位及加入规则取得该端口控制，不重开游戏、不抢另一个人的手柄。预先领出的手柄也通过同一控制入口接入本局。 |
| 主手或副手拿原手柄，右键原主机／对应收纳位 | 归还并退出自己的控制；不需要 Shift，不应因为槽位点不准而无法归还。实体按钮仍按自己的功能处理。 |
| 拿手柄右键电视 | 不负责归还、不代替主机开机；不要重新弹出选游戏界面。 |
| 按 Q 或从背包往外丢借来的手柄 | 归还原主机，原收纳位恢复；不生成可拾取掉落物，不刷出新手柄。1P、2P 一致。 |
| 切换快捷栏／暂放自己的背包 | 停止这只手柄的输入和手持线显示，不把这个动作当作整机关机。 |
| 超过主机 6 格 | 自动断开并归还对应手柄，清掉它的按键；不顺带释放其他玩家的端口。6 格内含边界。 |
| 死亡、离服、跨维度、主机被拆或手柄被非法转移 | 安全释放相应手柄，不留下幽灵占席或可复制的有效手柄。 |

归还手柄＝退出操作，**不等于关机**。主机关机也不必强行收回仍在有效范围内的手柄，但必须解除游戏输入。朋友直接领取空闲 2P 手柄，不通过丢弃转交借用物取得端口权限。

### 模型、持握和按键动画

- 主机上必须有真实收纳槽／停放位置。领取后那只手柄从机器上消失，留下正确内壁；归还后回到原位，不把手柄塞进实心外壳。
- 手中型号与原主机相符。按钮布局、厚度、间距和配色匹配该机型，不能套用另一型号的按钮外形。
- 第一人称双手持握，略向上倾斜，能看清按键；不要竖着只看见背面，也不能小得像指尖捏着。第三人称也应是双手拿手柄，不是单手拿工具。
- 有线手柄显示从真实端口到实际持握位置的动态线，随玩家移动；主副手、第一／第三人称及其他玩家视角都要正确。收回、失效或不再手持时不留残线。
- 十字键、AB／其他功能键、Start／Select、肩键按实际映射播放按下动画，松开回位。左右、A／B、1P／2P 不能对调，快速短按也应显示。家用机只要求本人第一人称和 F5 的按键动作，其他玩家可见的按钮动画不再是必做项；持握姿势、型号和线材仍要正确。街机摇杆／按钮的旁观动画要求不变。

### 持握姿势与按键动作必须分开完成、分开验收

“第三人称可见”不能只指人物把手抬起来。**持握姿势**是人物如何拿设备；**按键动画**是十字键倾斜、按钮按下和松开回位。模型、手臂姿势或手柄线可见，都不能证明按键动画已经接通。

| 观察视角／场景 | 持握与外观要求 | 按键动作要求 |
| --- | --- | --- |
| 本人第一人称 | 正面朝向、双手姿势、比例及适用的线材正确 | 对应实际映射后的游戏输入，方向／功能键、短按／组合键及松开回位正确 |
| 本人 F5 第三人称 | 人物、手中型号、主副手和线材一致，不倒拿或穿手 | 同一席位的按键动作仍然可见；不能只有第一人称会动 |
| 另一位附近玩家看公开操作者 | 可见正确的持握姿势、设备和适用线材 | 家用手柄允许静态按键，不要求补远端同步；已有远端动画保留时必须跟随操作者端口，不能套用观察者自己的输入 |
| 私人模式 | 本人视角仍完整；其他人可以看见正常持物外观 | 本人仍有按键动作，但私人游戏输入及其按键动画状态不得为此上传；不能为了旁人动画破坏“仅自己玩”边界 |

- 动画使用实际生效的游戏输入，覆盖自定义改键、键盘与实体手柄；不能只读取默认物理键。主副手、1P／2P 及多台机器的状态独立，观察动画不授予控制权。
- 已实现或选择实现的公开远端动画只面向有效可见范围内的观察者，跟随真实操作者、设备、会话、端口及手持身份；各实现明确自己的范围／失效规则，不把手柄操作距离、画面旁观距离和动画可见范围混成一个数值。不为动画向全服广播输入、强加载机器或启动额外核心；不为满足本规范新增家用远端按钮同步。
- 菜单、失焦、切换手持物、归还、超距、关机、断线及失去授权后，不留按下状态；迟到的旧状态不能重新点亮已经释放或新借出的手柄。只清受影响玩家／端口，短按显示补偿不能反过来延长真实游戏输入。
- 物品栏、掉落物、物品框及主机停放位的控制器保持静态，不跟随当前玩家的按键乱动。掌机、光枪、机柜按钮等按实际部件应用同样的“真实输入、可见范围、松开清理”原则，不虚构不存在的按钮或强加家用手柄形态。
- 交付分别填写“持握姿势”和“按键动画”的本人第一人称、本人第三人称、他人视角结果。家用远端按键未接通记为“非必做／静态”，不是缺项，也不能冒称已完成远端动画；既有 MD 远端动画不因取消要求而删除。私人模式不外发是隐私规则，不是缺陷。

第一人称手柄位于下方中央、双手持握、比例清楚且不过度挡电视。按本机型适配按钮造型；拿到手柄与开机是两件事。

![04 第三人称双手持握及连回所属主机的动态手柄线](reference-images/machine-interaction-20260930/04-third-person-controller.png)

图 04：本人第三人称和另一位玩家视角都要看得到正确持握、型号与线材。此静态图只参考持握效果，不能证明按键动作或远端同步已经实现；第二客户端检查移动、取还和线材失效清理，家用远端逐键动画不再必做，私人模式仍验按键不外发。

### 输入与人物移动

- 拿着有效手柄进入游戏操作状态，已分配给游戏的功能键不再触发原版或其他模组同键功能；人物仍可自由转头。
- 默认 N 锁定／解锁人物主动移动。锁定后 WASD 控制游戏；解除后恢复人物走动，不能残留游戏方向键。锁的是操作，不是冻结重力或击退。
- F7 打开统一控制设置：明确列出方向键方案、小键盘方案、WASD 方案、自定义和实体手柄入口，显示具体键位而不是“现有设置”。已有自定义不得被升级重置。
- 实体游戏手柄默认启用检测，提供设备选择、按键映射、摇杆死区和测试反馈；Xbox／NS／PS 等按实际识别能力适配，不把所有设备都写成已验证。
- 打开聊天、背包、设置菜单、切出窗口、归还或失去控制时释放自己的输入；返回后不能把失焦前的按住状态粘住，也不能顺便清掉朋友的输入。
- 启动或取得控制时短暂提示当前实际绑定的锁定键、设置键；不在每次右键刷长篇聊天说明。

## 5. 卡带和拷卡：统一使用老式电脑

卡带操作与工作台适用于卡带设备；本节的内容来源、目录、格式校验及失败处理原则同样适用于街机游戏库、电脑程序等外部内容入口。

- 家用卡带机有对应实体卡带，不用“私人模式占槽物”作为正式名称或完整内容功能。拿对应卡带右键老式电脑，进入统一风格的卡带工作台。
- 工作台有游戏库、封面、名称、人数、存档设置、具体存档库、ROM 目录、封面目录、刷新、搜索、分页和关闭入口。按权限禁用相关操作，不为每个附属另做一页不同布局的简陋选择器。
- 清楚区分服务器已有文件与本地文件。选中只是预览，点击明确的“写入服务器游戏”或“上传并写入”才执行；已存在的内容不重复上传。本地选择不等于同意公开上传。
- 超时／无权限／格式不支持不能统称“没有文件”。扫描不应静默藏掉玩家放入的游戏；可列出不支持原因。大列表分页和搜索可用，操作人数、改名后不无故跳回第一页。
- 名称、已写入的游戏、预览中的游戏不能混淆。更改封面只改封面，不顺带换游戏或清档。封面页显示实际支持的格式、尺寸、比例和大小上限，各卡壳按自身贴图区适配，不硬套参考图的比例。
- 内容哈希、磁盘文件定位、游戏库显示名、这张卡的自定义名称分别管理。上传后游戏库仍显示可读名称，刷新、重新进服和重启后可按名称搜索；不能把内部 SHA 摘要直接变成玩家看到的游戏名。改卡名不改全局库名，改库名不改变 ROM／卡身份或存档归属。
- 本地与服务器拥有同一内容时，按可靠内容身份合并来源或清楚标出关系；同名不同内容不能选错。开局与存档页优先显示本次卡带／内容的正确可读名称，诊断另外提供可追踪 ID，不用 ID 代替名称。
- 拿写好的卡带右键对应家用主机插入；已插卡有可见模型，手上数量正确减少。错误机型、忙碌或物品空间不足时不吞卡、不覆掉原卡。
- 家用卡带机以空手 Shift＋右键主机退卡；运行中先走安全结束／保存再交还卡带，不能把“已发起保存”显示成“保存完成”。具体电源按钮优先自己的含义，不把按键误判成退卡。掌机的退卡入口不得占用其电源手势。
- 拷卡完成不强迫自动开机；换游戏、拔卡、改名、改封面分别是独立动作。
- 有可拆卡壳的机型：拆开后外壳保留封面，游戏身份和进度跟卡芯走，不能复制出第二份有效卡芯。具体已有机型兼容操作见第 10 节；不可拆的介质不强加拆壳。

### 卡带外观、工作台与封面页

![06 卡带封面、游戏名称、操作说明和保存方式提示](reference-images/machine-interaction-20260930/06-cartridge-cover-and-tooltip.png)

图 06：物品栏、手持和主机插槽显示同一张实际封面。名称、插卡／编辑操作及当前存档方式可读；“已保存进度”只能在确有成功保存时显示。

拷卡工作台布局：上方名称／人数，中部游戏库／封面／搜索，左侧列表、右侧预览与写入，下方目录和分页。复用这一布局和对应业务，标题、数据、目录与按钮操作都绑定当前机型，不能只换显示名称。

**封面页**与存档页分开。应用封面只改当前卡的封面，不能换游戏或清档；本地目录、扫描、预览和应用须相互对应。

### 目录必须属于当前机型，复用不等于串用

- “ROM 目录”打开当前机型真正扫描的本地游戏目录；“封面目录”打开当前机型约定的本地封面目录。目录按钮、扫描列表、写卡读取及页面说明使用一致的路径规则，不能串到另一机型。
- 开工和交付说明都列清该机型的本地 ROM、本地封面、服务器内容各在哪里；目录不存在时正常创建或明确报错，不能默默回退到其他机型。服务器路径和客户端路径分开，不要求玩家把本地文件放到远端目录才看得到。
- 可复用通用封面校验、缓存、上传及服务器资源库；共用服务不等于共用某台机器的专用本地路径。确有共用本地目录设计须明确说明，不能靠遗留硬编码形成。
- 目录在模组统一数据根下按机型与用途区分，正式游戏、封面、配置、缓存、临时文件和存档分开；具体相对路径记入该组件使用说明。调整目录保留玩家原文件，提供兼容读取或明确的迁移办法，不让玩家反复挪文件掩盖实现错误。
- 服务端正式 ROM／BIOS 的共同入口为**服务器实例根目录下的 `game-console/`**，不要有的放实例根、有的藏在世界里。需要世界隔离的内容在这个根下分 scope，世界授权及玩家存档仍保持各自归属。客户端缓存不得包含或清理服务端正式库存；集成服同样要验证。
- BIOS／依赖文件必须与游戏一起形成可追踪的内容清单，列出原名、摘要、大小和存储位置；同名不同版本保留独立身份，不用一个全局同名文件静默覆盖。上传／补依赖完成后，以**本次校验通过的完整清单**建立开局与保存身份，再允许核心加载；不得提前使用旧清单，也不得靠关闭身份校验解决缺件。哈希实体库另提供原名可读索引，但索引和文件存在本身不授予跨世界／跨设备访问。现有接入与限制见[服务端内容及 BIOS 说明](服务端内容目录与街机BIOS-20261003.md)。

### 读不到时，要能分清是哪个文件、哪一步失败

- 本地与服务器分别扫描、分别显示状态。本地文件列表不以服务器列表成功为前提；远端超时、拒绝或无权限时，本地仍可列出合法可读内容，是否允许上传／写卡另按服务端权限判断。
- 一个被当前校验拒绝、无法读取或格式不支持的文件不能让整批游戏消失。保留已成功项，给失败项文件名与具体原因，可用列表或可展开的失败摘要展示；失败项不可写入，不通过放宽安全校验伪装兼容。
- 扩展名或操作系统显示的文件类型不能单独决定兼容性；应按该机型的内容格式校验。校验失败说明当前格式／读取规则不接受，并给出具体原因，不能据此断言所有模拟器都不能运行。
- “扫描中”“扫描成功但为空”“部分成功”“目录读取失败”“服务器无权限／超时”分别显示；只有完整扫描确实没有候选项时才写“目录暂无游戏”。失败不清掉仍有效的已加载列表，不假报加载完成。
- 刷新限流可以提示“请稍后再试”，但不能覆盖尚未解决的文件／服务器错误，导致原因无处可查；保留详情和可恢复的重试入口。页面重建、切页不应无故触发重复刷新；不能为了绕过限流改成逐帧全盘扫描。
- 写入成功后再次打开工作台、插入机器，实际读取的仍须是刚选的机型与 ROM；列得出游戏、写得进卡、核心能启动是三个分别要验证的环节。

## 6. 存档：先分清是跟人还是跟卡

卡带设备按下表处理；街机的机器档和其他设备的差异见第 9、10 节。保存归属、保存格式和保存位置是三件事，必须分别说明。所有支持保存的设备和程序都遵守本节的权限、旧档保护、成功反馈与兼容要求，不强制无卡设备伪造卡带档。

有工作台权限的普通玩家也能为**自己正在制作的这张卡**选择方式；不要求为了选存档就给 OP。修改一张卡不能让所有同游戏卡带一起改变。

| 方式 | 应有行为 |
| --- | --- |
| 不存档 | 每次新开，不保存、不恢复，也不反复弹选槽；切成此方式不删除原来已存在的进度。 |
| 个人存档 | 卡带只记模式。开机玩家选自己的槽；带去别的兼容机器仍用自己的进度，把卡给别人则对方用自己的进度。槽位总额、是否按游戏分配及适用范围须明确，不擅自共用／增加容量；已有额度见第 10 节。 |
| 卡带存档 | 一张卡对应一个随卡进度。换机器、转交别人仍可继续这张卡；有进度时提供继续／从头开始，成功保存后卡带显示【已保存进度】。不是保存在某台主机名下。 |

- 新增卡带家用机采用不存档／个人／卡带这套归属体验，不能把“个人本机文件”冒充服务器个人档或随卡进度。掌机也应说明卡带与电池进度的归属，不能因为提供实体卡就默认旧电池档自动变成随卡档。
- 卡带编号标识那张实体卡；进度文件可由服务器保存，不要求把整份快照塞进物品。换壳、转交、改显示名不丢身份；复制同编号物品不能开两局互相覆盖。
- 多人同局使用开局选定的一份进度，不是每个旁观者各保存一份。操作玩家退出、主持玩家断线、关机应区分处理。
- 支持保存的模式要有开机恢复、手动保存、自动检查点和正常关机保存。Netplay 也要接这些入口，不能联机能跑却没接存档；现有 Netplay 以约 30 秒检查点为基准。
- “电池存档”保存游戏自身支持的长期进度，“即时存档”恢复当时运行状态，两者不能混称。核心不支持某一种就明确说明，不伪造成功。
- 有可查看、命名、确认删除的具体存档列表，不只提供一个模式切换按钮；普通玩家只能管理有权访问的档，OP 可管理服务器范围。
- 从头开始不立即销毁旧好档，下一次成功保存再更新；保存失败、坏档、磁盘满都要保留上一份有效进度并反馈。崩溃或强退不保证最后一段进度。
- 同一兼容格式的公开模式应尽量沿用同一归属；换核心、JNI／旧运行器或不兼容保存格式不能强读、覆盖或暗中转换。界面说明当前进度属于哪个体系。
- “仅自己玩”是明确的例外：游戏输入、音画、按键动画状态和进度不外发，实体借还仍联网；不得因私人游玩隐式上传或公开本地内容。已有服务器卡资源仍可按原有权限下载，这不等于上传私人档或开放旁观。私人档以本地持久化确认，不自动继承或覆盖公开档；私人模式是额外选择，不替代家用机公共联机和卡带流程。
- 管理终端提供个人档闲置清理，默认关闭，0 表示不清理，范围 0～3650 天。卡带档不自动清理，活动玩家、未知归属和旧机器档保留；清理明确列出覆盖的机型与保存范围，不删除未接入管理的档案。

### 三个不同的存档界面都要接齐

**选保存方式**：解释进度跟人还是跟卡，只设置当前卡带，切换方式保留已有进度。“个人”是归属，“仅本机”是保存范围，不能混称。

**管理具体进度**：列出该玩家有权访问的实际存档，能查看详情、改名和确认删除；同名档不能删错。本机私人档、恢复备份与服务器档分别标明，不能拿保存方式按钮替代这个列表。

**开局选择进度**：空槽布局不证明已有进度加载成功。有档时显示实际档名、可用详情和继续／从头开始；空槽显示新建，不存档则不强弹此页。槽位额度和卡带档行为按本节规则，不因复用横排三槽布局就给每款游戏增加三份容量。

## 7. 电视、声音与旁观

### 多台机器的公共观看规则

电源、计算主持、操作席、观看订阅必须分开。玩家可以观看多台已运行机器，但“多屏旁观”不等于同一玩家已经能主持多台，也不等于一套键盘同时操作多台。多人加入仍使用前述开局许可、申请和真实端口，不另做一套加入界面。

| 玩家行为 | 实际调用方式 | 必须保持的边界 |
| --- | --- | --- |
| 靠近多台公开 JNI Netplay 机器 | 各机独立只读 JNI Netplay 副本，经公共 Watch 租约取种子／确认输入，在本机生成画面 | 不是视频串流；需要兼容核心、获准内容及本机资源。无操作席、无输入／写档权。 |
| 自己操作一台，同时看旁边机器 | 操作会话仍走其原 JNI Netplay；其他机器走只读旁观 | 自己这台复用已有画面，不重复开核心。旁观不能夺走操作输入、保存或关闭它。 |
| 走远、某机关闭或某路同步失败 | 只释放对应源的 Watch、下载、音频、纹理和只读核心 | 不关闭另一台机器，不重开主持、不清其他屏幕；晚包按源、连接、租约代次拒绝。 |
| 多屏同时有声音 | 优先正在操作的游戏；不操作时选择最近有效旁观音源 | 不把多路声音叠成一团；切换时清旧音频队列。 |
| 额度不足 | 读取真实原生槽和准备／关闭中的占用，明确提示 | 不提高四实例上限，不强杀关闭中的核心、不假释放、不静默改串流。新操作自动腾槽属于另行实现的调度能力。 |
| 旧 MEDIA 或独立进程 Netplay | 沿已声明的单源旧链 | 不因公共接口升级就宣称已支持混合多屏；不得用其失败回退冒充 JNI 多屏。 |

各附属复用公共订阅、显示资源、下载及预算接口，按具体机器身份判断“是否已在操作”，不能用“这个玩家操作任意同类机器”屏蔽全部旁观。默认仍为发现16格、退出20格，同维度、有效显示端、不强加载区块。当前版本已接通范围、四槽示例和实机未验项放在[第一批实施记录](公共JNI多屏旁观第一批-20261003.md)，不把制作目标当全机型完成证明。

当前范围不包括“一人主持多台机器”；多屏旁观独立完善，不因此新增限制改变已有行为。低帧率预览串流／Opus和自动主持交接如需实施仍须独立安排；未来预览只降低呈现／编码频率，不能降低游戏模拟速度。Flash/PvZ 开发验证机型仍暂缓。

旁观管理复用公共诊断入口，逐台说明实际调用方式（JNI Netplay、进程 Netplay或音画串流）、来源位置、准备／播放／关闭状态和本机资源占用；未取得实际运行器时明确“待确认”，不猜测。玩家应能暂停某一路并显式恢复，暂停不关机、不退出他人操作、不清存档，也不能过几秒偷偷重新订阅。暂停的连接／会话范围明确展示，重连或新局的规则不能含糊。

满槽时给出可操作的提示：先暂停一路旁观，等原生实例真实关闭后再重试。关闭中不能提前报告空槽；不能为了开始操作，暗中强退另一台无关机器。操作授权仍经原开局／加入流程，旁观管理不直接授予席位。

世界屏幕须分别检查普通渲染和声明支持的光影环境。共用材质应沿光影加载器支持的渲染接口适配，保留正确方向、比例、不透明与遮挡；不能以全局关闭深度测试、允许所有未知着色器或移动屏幕穿过机壳来“修好”。关闭／开启／切换光影与资源重载分别验证，不用普通模式正常或单元测试通过代替具体光影包实测。

### 屏幕与音画基础要求

- 游戏画面显示在世界里的电视／机身屏幕上，不为普通游玩强制打开全屏 GUI，不放出鼠标指针锁死视角。
- 电视有电源、音量＋／－及遥控器入口；液晶也要有好点的开关区域。开关转场平滑，不跟服务器卡顿逐帧跳动，不因重复同步重播。
- 电视关机黑屏；开机但无连接或主机关闭时无信号彩条及低音量提示音；主机通电无卡时显示未插卡；有游戏信号就停止无信号提示音。故障、加载和正常黑屏有可辨别状态。
- 画面明亮清楚，贴合屏幕，正确处理宽高比和横竖屏；宽屏放 4:3 游戏可以留黑边，不强行拉伸、镜像或二次旋转。
- 附近玩家无需右键就能旁观公开会话；晚到、走远再回来都能重新同步。追赶期间显示简短“同步中”，不要让玩家看错乱快进，也不占操作席。
- 家用机旁观沿用默认 16 格发现、退出缓冲 4 格（默认超过 20 格退订）；街机游戏画面超过配置显示范围不渲染，默认 16 格。订阅缓冲期间不能宣称零流量。
- 显示与旁观范围从有效显示端计算，不是从服务器里任意在线玩家计算；100 格外普通玩家不应被加入重型音画／游戏文件／同步发送。正常区块数据不等于游戏串流。
- 超出显示范围只停止对应画面工作／旁观，不直接关主机，也不剥夺仍在操作的朋友的权限。电视实体不会因为游戏画面超距就消失。
- 声音从机器／电视发出，有距离衰减、音量与静音设置；多台机器独立，不让同局重复声源叠加。尚未追上画面时不播放一串陈旧声音。
- “正在使用”的文字可开关，朝向与机器固定，不跟观看者转动；街机连接组不要每台重复一份。设备拆除后文字／排行榜不悬空残留。
- 大文件下载进度应与观看距离分开：已经授权开始的下载不能仅因走出旁观范围就丢掉全部进度；再次靠近应复用校验后的缓存／断点。显式取消、撤权或换服另行终止，临时文件安全清理，不删除玩家原件。

## 8. 配置入口：玩家找得到，附属用起来一致

### 各入口管什么

| 入口 | 必须能做的事 |
| --- | --- |
| 卡带＋老式电脑 | 拷游戏、改封面／名称、卡带保存方式、具体存档管理。不能搬到普通电视遥控器里。 |
| 电视遥控器 | 电视开关／音量／静音、扫描线等显示效果；使用者文字、加入设置等关联选项按权限提供明确跳转，不借持有遥控器越权。 |
| OP 调试螺丝刀右键主机 | 同类设备统一的“设备设置”，包含状态与适用配置；诊断是下级入口，不能代替完整设置。空手点外壳不直接进调试。 |
| OP 手持管理终端右键 | 全服权限、统一策略、新机默认、存档清理、全服模组监控；生存模式的 OP 也可用，创造模式本身不等于 OP。 |

### 设备设置应有哪些内容

- 状态：机型、游戏名称、当前开关机／运行状态、插卡和连接、使用者／端口，街机组的主副关系。
- 运行方式：玩家音画串流、本地输入同步、服务端托管、Netplay，以及适用的“仅自己玩”。当前选择明确标记；按真实能力启用，不支持说明原因，不静默退回另一种模式。
- 运行器信息：例如 JNI、实际核心及异常诊断。**JNI 不是联机模式**，不能用“换成 JNI”解释所有同步方式，也不能让旁观者为了看到画面再手选 JNI。
- 新增模拟器附属默认接入公共 JNI 运行器，按核心能力适配音画、输入、保存和生命周期；不以“只接私人模式”代替适用的公开玩法。普通程序、工具或不适用此运行接口的设备不强行套用 JNI，既有其他后端也不因本条自动迁移。
- 统一控制设置、运行环境／复制诊断、音画／性能、网络统计、适用的保存与加入设置，以及刷新、返回／关闭。
- 网络页显示实际模式、当前速度、累计流量；OP 终端可看全服本模组汇总，不冒称整台服务器全部网络。
- 影响当前会话的更改注明生效时机，通常正常关机后下一次开机生效；关闭菜单、返回或按 Esc 不应被当作物理关机。

### 核心更新与退役

使用哪个核心、通过哪个运行器调用、采用哪种联网方式分别声明。升级或退役核心时全仓核对菜单／配置／profile、运行入口、打包脚本、依赖清单、测试与说明；只隐藏一个按钮不算移除。新构建不再调用或打包已确认退役的核心，不在启动失败后偷偷回退；仍需保留的历史证据明确标历史。

退役核心不等于删除该核心的旧保存、玩家内容或历史成品，也不等于停用同一运行器供其他核心使用。旧保存继续保留原兼容身份，界面说明为何当前核心不能读取；迁移必须有明确依据、授权和验证。某个核心的退役范围与实施进度留在组件／技术总览，不写成所有附属都使用该核心。

菜单采用参考图所示的紧凑原版风格、统一分组和按钮含义；不铺满全屏、不糊背景文字、不夹长篇技术警告。细节放提示或诊断页，失败保留输入，保存成功说明影响范围。不同窗口、GUI 缩放和长名称下仍可读、可操作。

### 菜单对齐必须包含功能，不只是排版

- 复用公共菜单时，逐项接通本机型的能力、状态读取、权限、操作请求与返回结果。标题／布局一致只算界面复用，不算串流、同步、存档或旁观已经接通。
- 每个声称可用的模式都要走完：选中 → 服务器确认 → 设置保存／回读 → 按提示时机启动 → 实际模式正确 → 加入／旁观／保存按能力工作。请求失败保留旧有效设置并显示原因，不能只把按钮勾选状态改掉。
- 不支持的模式不能仅为“能点”而解锁；应补实际能力后再开放。以公共家用机为目标却只完成私人单人的版本，明确标阶段原型和公共功能缺项；原本就不适用某种原生联机的设备注明能力边界，不伪造支持。
- 本机控制、运行环境、诊断、返回／关闭等已可用入口应清楚可达，不被“没有公共联机能力”连带禁用；性能、网络、保存等入口按各自真实能力判断，不用一面灰按钮冒充完整功能。

| 按钮不可选的原因 | 玩家应看到什么 |
| --- | --- |
| 当前已经选中 | 明确“当前”，无需重复选择；不是功能故障。 |
| 该机型尚未实现 | 说明未接通的具体能力；不得暗示装错包或给 OP 就能解锁。 |
| 已实现但服务器禁用 | 说明服务器策略限制及适用的管理入口。 |
| 玩家没有权限 | 说明需要的权限，服务端也必须校验。 |
| 运行中暂时不能更改 | 说明何时能改，或设置将在下次开机生效；不能统一写“不支持”。 |
| 状态尚未取得／请求失败 | 显示加载或错误、保留重试入口；不伪装成已知的不支持。 |

### 全服设置必须进管理终端

- 分开授权普通玩家使用服务器 ROM、使用服务器封面、上传 ROM、上传封面；普通玩家按服主许可操作，不一律要求 OP。
- 家用同步方式的全局项是“新机默认”，不覆盖旧机器已有选择；不能和“全服强制”混叫。
- 街机退出关机、空席倒计时、显示距离是全服统一策略，新旧街机都生效；设备页显示有效值并指向终端。
- 保存清理、模组流量和适用的全服资源限制有明确入口。新附属新增全局行为时一起接终端，不能只藏在配置文件或自己的设备页面。
- 键位、本机音量等个人偏好不变成全服设置；修改游戏人数、街机 PGM／Test／DIP 等管理操作服务端再次检查 OP，不能只靠隐藏按钮。

## 9. 街机专门要求

- 单人、双人、3:4 竖屏柜都要接齐电源、控制、屏幕、摇杆／按钮动画和音效，不能只做双人柜。
- 统一开关位置：**面向屏幕时正面左下、投币口左侧**。小翘板有开／关姿态，开机发红光，点击区域够用。
- 普通右键操作区域进入控制，再右键退出自己的操作；不每次弹游戏库、不强制 Esc 结束。退出控制默认不是立刻关机，物理开关负责明确通断。
- 配置保留游戏库、所选游戏、一级外观／皮肤入口、投币、存档、联机及关机／显示设置。外观不必先选核心才能改。
- 支持服务器／本地游戏查看。游戏名称、人数、横竖屏、比例由管理员修改并全服保存；“标为四人”不等于游戏内部已经设置四人。
- 有实体投币和免费模式；新机默认实体币，旧数据不擅自覆盖。实体币点正确投币口，成功才扣一次，给对应玩家端口真正的投币信号；不能用键盘 Select 绕过收费。免费模式按配置使用投币键。
- 数据线依次右键两台兼容机柜联接，成功扣线、断开单次返还；单人柜也接入。两台双人柜在核心支持时映射 1P～4P，共用一局、两屏一致，副柜也能投币／开始／操作。不能为每台柜分别启动一份不相关游戏。
- 通讯线从**背面底部沿地面**走，不从前面或高位插口垂下来；靠墙、并排、四朝向和旧机器都检查。
- 操作席在对应柜 8 格内有效；释放席位与主持运算分开。一个玩家退出，不得让另一席或隔壁独立机器一起退出。
- 关机保留所选游戏，重新按电源即可启动，不必进菜单重新选择。无保存模式下重新启动游戏，不代表恢复刚才关机前的进度。

### 自动关机规则（仅街机）

1. “最后一名玩家右键退出立即关机”：独立开关，默认关；开启后仍须等最后一席主动退出，不能 1P 退出就踢掉其他人。
2. “无人占席倒计时”：默认 60 秒，可设 0～3600 秒，0 禁用。所有操作席空了才计时，有人重新入席就取消；看过场、不按键不是无人占席，旁观者不算占席。
3. 立即关机关闭＋倒计时 0＝不因退出／空席自动关机；主持断线、设备卸载等必要安全终止不因此关闭。
4. 超过默认 16 格停止游戏画面渲染不等于关机。不要恢复“16 格内无人就关机”，也不为了自动关机再为每台机每秒扫描附近玩家；按席位变化维护倒计时。
5. OP 在管理终端统一设置，新旧机一起生效；不把这套规则套给家用机、掌机或电脑。

街机长期进度可选不保存／个人／机器，默认不保存；机器档按该机及游戏分开，连接组按主柜归属。PGM／DIP 运营设置是另一类：只有 OP 可改，跟机柜和当前游戏保存，关机、重启、换玩家保留，成功切换另一款游戏才清除；不能拿整局即时存档冒充这项功能。

支持排行榜的游戏可另外提供空闲屏榜单和墙面面板，默认未启用时关机黑屏；页数／轮播／是否显示可配置，破纪录及结束通知不能每次加分都刷屏。排行榜不是每个新核心必备，也不能假设能通用读取任何游戏分数。

## 10. 其他机型的明确差异

### 手持机

- 手持机以物品使用，不强制做成可放置方块；采用卡带的机型有自己的卡带，仍在老式电脑拷卡。其他介质先明确装载方式，不用调试页代替正常操作。
- 掌机与卡带分拿主副手，两种顺序都能 **Shift＋右键插卡**；保留普通右键双手插卡兼容。检测到对应卡带时，插卡优先于开关机和举起动作，一次只处理一次，已插卡不被无声覆盖，失败也不顺带切换电源。
- **Shift＋左键拔卡**：按第 1.5 节先停止新输入、取得并持久化适用进度，确认后结束核心并退还原卡；等待时不能重复操作，失败／超时保留卡带与旧好档并给原因。该手势不能同时触发挖方块或攻击实体；背包空间、身份和重复请求仍由服务端复核。
- 普通右键举到眼前并放大到能看清屏幕；再右键放下，**仍开机**，但退出操作、释放按键。不是打开模糊的全屏选游戏 GUI。
- 未同时持有可插入的对应卡带时，Shift＋右键负责开／关机。放下与关机不能共用同一状态；丢失物品、跨维度、断线等安全结束另外处理。操作提示明确两种条件下的含义，不只写一条容易误用的“Shift＋右键”。
- 手持比例、双手姿势、屏幕贴合、按钮动画、电源灯、音画、电池保存和再次开机恢复都要做；单台掌机能运行不代表原生联机已经接通，联机按实际协议单独适配。

### 光枪外设

- 可放置支架，用数据线连接支持的主机；可在未开游戏时拿起，归还到对应支架，模型和有线表现随领取状态变化。
- 支架处两手空 Shift＋右键可拆线，正确扣还；接入光枪不应使普通手柄整个失效，端口冲突要明确说明。
- 对准实际电视游戏区域瞄准，不按整个窗口坐标硬套；大／小电视、宽高比、离屏与触发都验证，扳机有动画。拿光枪时保留该系统需要的功能键操作。
- 光枪支持的游戏／核心／运行方式逐项适配，JNI 迁移也不能漏掉；普通电视右键不再兼任开启光枪游戏。

### 可组装电脑

- 按对应槽位装入必需配件后才能开机；侧盖无论开关机都能打开，实际安装／拆除配件的安全限制需明确。电源按钮、灯、开机风扇动画要齐。
- 组合键盘鼠标放在一起，鼠标位于操作者右侧；键鼠使用主机接收器，不恢复横穿桌面的键鼠线。主机到电视的视频线仍保留，并贴合相应接口。
- 右键键鼠直接取得屏幕操作，不先弹全屏菜单；支持自由视角与对准电视右键固定视角的操作方式，退出时释放鼠标／键盘，不能把 MC 鼠标永久锁住。
- 游戏／应用在统一程序入口选择，各程序附属复用电脑显示、输入和设置。真实支持旁观或交接控制时要接齐；不能把“旁观”冒充原游戏多人。电脑操作范围 8 格、显示／串流范围 32 格，不套用街机的 16 格规则。

### 已有机型的兼容约束

以下只约束对应已有行为，不扩大成所有新设备的要求：

- FC 个人存档沿用**每位玩家总共 3 槽**，不是每款游戏各 3 槽；新机型的额度须明确，不因复用存档选择布局自动获得相同额度，也不擅自更改原额度。
- FC 黄卡保留 Shift＋左键拆壳：外壳保留封面、游戏身份与进度跟电路板走，裸板不暴露游戏字样；非可拆卡壳不硬套这一操作。
- 已有独立 RESET、特殊端口或实体部件的设备保留其功能；相近外观不能作为删掉部件或改成隐藏组合键的理由。
- 旧介质身份、路径、玩家配置、存档及不同核心格式不得因新增设备或复用公共层被清空、重置或暗中转换；兼容和迁移另列可验证方案。

## 11. 新机器交付前，按玩家动作逐项验收

每项记录通过／未通过／待验证／不适用及理由；不能只写“编译成功”。至少用单人世界、专服双客户端各走一遍适用流程。“尚未实现”记未通过，不能填不适用。

- [ ] 四个朝向放置；桌面、靠墙、并排时按钮／选框／卡槽／接口都对位。
- [ ] 主机 POWER、RESET、指示灯、成功／失败状态、按键声一致；关机再开保留原内容并重走适用开局确认，不重新挑 ROM。
- [ ] 老式电脑拷卡的服务器／本地、封面、改名、人数、存档及权限流程完整一致。
- [ ] 在实际游戏中点 ROM／封面目录，核对打开位置与当前机型的扫描路径一致；多机型并存不串目录，重进工作台仍能列出文件。
- [ ] 合法 ROM 与一个被拒绝的 ROM 混放：合法项仍可选，失败项有原因；全空、全失败、部分成功分别正确。封面列表也不因一张失败图片整体丢失。
- [ ] 服务器目录失败／超时／无权限不阻断本地列表；快速刷新不会抹掉原错误。选择、上传／写卡、插机启动全程使用同一个机型和游戏，不能只做脱离工作台的核心启动测试。
- [ ] 中文／空格文件名上传后刷新、重进、服务器重启仍可读可搜索；库名、卡名和物理文件身份不串用，同内容不同来源与同名不同内容分别正确。
- [ ] 同一张卡的名称、人数、保存方式贯穿编辑、上传／写入、插机、世界重载和开局；旧字段缺省时界面与服务器一致，不把不同测试卡的截图当成同一条证据。
- [ ] 插卡、退卡、错卡、已有卡、满背包、重复点击不吞物品、不刷物品、不丢进度。
- [ ] 视频线两种连接顺序、正下方、壁挂、四朝向都能连接且看见线；拆线正确返还。
- [ ] 关机时取手柄、开机后取得控制、主副手归还、Q 归还、6 格边界与第二端口互不干扰。
- [ ] 手柄原槽位取还、双手姿势、型号／朝向和动态线，在本人第一人称、本人 F5 第三人称、另一玩家视角分别检查，不能只验静态模型。
- [ ] 按键动画另行逐视角验收：本人第一／第三人称逐键、方向、短按、组合键、改键、实体手柄及 1P／2P 不串键。家用远端按钮动画非必做；街机及主动声明远端动画的实现仍用第二客户端验证，不能用本人 F5 替代。
- [ ] 私人按键及动画状态不外发；菜单／失焦／换手／归还／超距／关机／断线后回位，晚到旧包不复活动作；GUI／掉落／物品框／停放位不受游玩输入驱动。
- [ ] N 锁定、F7 设置、实体手柄、短按、聊天／失焦／返回不冲突、不粘键、不残留移动锁。
- [ ] 支持双人的家用机开局独立弹窗一次选择允许／拒绝；不存档／空槽／已有档分别检查，不用存档单双人标签代替询问。允许后 2P 直接领取空位，不反复弹申请干扰 1P；不能把单人游戏改成双人。
- [ ] 公开会话附近未右键者能看；晚到、离开再返回正常；远处玩家不参与无关重型同步。私人会话不外发输入／音画／进度、不隐式公开本地内容；已授权内容下载与私人数据上传分别验证。
- [ ] 声音衰减、音量、屏幕比例／方向、开关转场、使用者文字、无信号与未插卡状态正确。
- [ ] 旁观管理逐源显示真实运行方式与占用；暂停 A 不停 B，超过旧冷却仍不自动重订，恢复、准备中取消、关闭中满槽、断线与新局规则均正确。
- [ ] 普通渲染和所声明支持的光影加载器／包分别验屏幕；横竖屏、单／双／竖柜、电视、本人／旁观、墙体遮挡、雾／玻璃／水及光影切换／资源重载记录版本与结果。未测光影包明确待验证。
- [ ] 螺丝刀／遥控器／管理终端入口一致，OP 生存可管理，非 OP 创造不能越权。
- [ ] 每个已声明支持的运行模式实际切换、回读、按时生效，适用的加入／旁观／保存可用；未实现、服务器禁用、无权限、当前已选、忙碌、请求失败分别说明，不能只查按钮排版。
- [ ] 以公共联网为目标但尚未接通的阶段版本明确标原型；本机控制／环境／诊断／关闭按真实能力可用。关闭菜单不关机，不靠解锁未接通的按钮假装修好。
- [ ] 不保存不弹槽；个人档换人不串档；卡带档转交／换机能继续；普通关机保存结果可核实。
- [ ] 保存失败、坏档、断线保留旧好档；不兼容后端不冒充可继续；关闭菜单不误关机。
- [ ] 街机的投币、主副柜各端口、前面开关、背后地线、三种柜动画、空席倒计时都覆盖。
- [ ] 掌机的双手插卡、举起／放下、Shift 电源及电池档，光枪或电脑的适用专项已验。
- [ ] 多台机器同时运行互不串线／抢输入／误关机，主持断线安全结束，不谎称自动无缝接管。
- [ ] 重进世界后卡带、连接、设置仍正确；拆除无残留画面／音频／标牌／借出的控制物。
- [ ] 图标大小清晰，创造列表按主机、介质、外设、线材、配件、家具等用途归类，不抢原版首页；测试物品不混在正常入口。
- [ ] 第 1 节完整闭环在每个声明可用模式下走通；家用顺序为校验 → 按需选档 → 独立 2P 确认 → 加载／恢复 → 就绪授权，取消／超时／旧回复不会偷开局。
- [ ] 保存身份在开局明确；退柄、换操作者／主持不暗换档主。待保存时重复操作不并发写档／退卡；正常持久化确认与断线／崩溃未确认结果分开记录，旧好档可恢复。
- [ ] 公共接口改动同时回归原有调用者；类型适用项缺失仍标未完成，不能用可选模式禁用或一组相似菜单冒充整机达标。

### 每次交付必须留下什么

- 设备类型、适用条款、复用调查、差异说明，以及每项功能的完成状态；不能只给“核心能运行”的结论。
- 实际玩家操作说明：怎么放置／拿起、装载内容、连接、开关、取得控制、保存／恢复和打开设置；具体目录、格式、依赖及安装端写清。
- 测试对象与版本、所走操作、结果和证据；自动检查、核心测试、游戏实机、多人测试、人工验收分别记录，待验项不标稳定。
- 对旧世界、介质、配置和存档的兼容说明；已知限制及失败后的恢复办法。
- 本次成品、源码版本与配套关系。无新构建就写无新 JAR，不把旧包当新成果；保留历史版本及公开变更记录。
