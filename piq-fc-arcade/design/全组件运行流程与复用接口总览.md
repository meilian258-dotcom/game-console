# 方块电玩全组件运行流程与复用接口总览

源码审计：2026-10-02；目标导航更新：2026-10-03。维护：像素匠（Codex root 与协作审计）。源码基线仍为 `e1c81ad9dac3880e40e5b00300ccaba24f1ef13a`，分支 `feat/gba-handheld-cartridge`；本次流程规范整理未改变运行实现，不重新认证历史实测结果。

GitHub 同步边界（2026-10-03）：上述审计基于维护工作区的本地提交；MD7～9 及其公共接口实现未随本次文档同步，不代表 GitHub `main` 已有这些功能。尚未上传的源码／指南下文以本地路径标注，不提供无效链接。其余同名源码链接也可能仍指向较早实现，尤其 `ContentCards.Features`、`HomeSystems`、`CartridgeSaveScreen`、`NetplaySaveClient`、`HomeSyncSettingsScreen`；实际可调用的签名与能力须以所检出源码核对。完整统一流程的制作目标不受这一上传边界影响。

本文回答：现有各组件怎样运行、玩家看到什么界面、界面调用谁、核心在哪里跑、数据归谁、哪些可以复用，以及哪些只是外观相似。它是新增和补齐附属前的技术地图，不是 MD 专项修复单，也不是稳定 SDK 声明。

**主要结论：公共硬件、布局、输入、运行器和部分传输已经存在，但完整开局、加入、目录元数据和保存编排尚未统一。FC、SFC 也有规范缺口，不能把任意旧机器照抄成新机器的标准。**

应做成什么样，以[机器与附属通用制作规范第 1 节](机器制作与交互标准.md)的完整统一流程为准，12 张用户参考图仍在相应正文内；本文记录实际实现，不能用这里的缺项降低目标。家用目标顺序现已明确为“校验 → 按需选档 → 独立 2P 确认 → 加载／恢复 → 就绪授权”，不是本文源码链已经改好的意思。旧[2026-09-30 现状盘点](附属功能基线与现状对照-20260930.md)保留历史时点，不覆盖本次源码核对。

查阅顺序：第 2 节找组件归属，第 4 节看实际操作链，第 5 节找界面，第 6～7 节查内容/人数/保存，第 8～9 节找接口与外设，第 10 节看已知差距，第 12 节用于新附属开工和回归。

## 1 审计范围和证据边界

本次覆盖方块电玩 11 个源码组件，以及主包内显示器、控制器、线材、工具、家具和公共服务；另列两个原生实验目录。没有把工作区无关 MOD 纳入“所有组件”。

本次逐类核对注册、玩家入口、界面、请求与服务端处理、核心适配、保存、输入、旁观和停止的主要调用链，并结合既有制作规范、README、维护记录和用户截图。**没有本轮新 JAR，没有运行 Minecraft 图形客户端，没有宣称所有按钮、每个 ROM 或多人场景实测通过。** 既有自动测试/交付记录只属于其注明版本，不能自动覆盖本次发现。

| 状态用语 | 本文含义 |
| --- | --- |
| 已接入 | 当前源码存在完整的相应调用路径；不等于真人验收或稳定 |
| 部分接入 | 有接口、布局或某个模式，但完整业务仍缺环节 |
| 未接入 | 在已核对的现行入口没有适配，不把“核心理论支持”当实现 |
| 历史兼容 | 保留旧入口、旧设备或旧格式，不作为新附属的默认模板 |
| 待验证 | 需要同物品/同版本数据或实机证据；不根据截图猜成已定案 |
| 建议 | 尚未实施的整改或抽象，不是仓库已存在的 API |

来源优先级：最新明确用户要求决定目标；当前源码决定接线事实；精确制品回执决定某包验证范围；旧文档只作历史。截图中的名称、玩家、坐标和游戏文件不是默认配置，也不随成品分发。

## 3 先分清运行方式与状态

| 名称 | 谁运行核心 | 其他玩家怎样参与 | 不能混同 |
| --- | --- | --- | --- |
| 玩家音画串流 MEDIA | 某个玩家客户端 | 控制输入发给主持；接收画面/声音 | 不是每个观众都跑核心，也不是回滚联机 |
| 本地输入同步 LOCAL_SYNC | 参与方本地核心，按各实现同步 | 同步输入/必要状态 | 不保证任意核心确定性；旧快照同步另有适配 |
| 服务端托管 SERVER_MEDIA | 专服上的受限核心会话 | 客户端收音画、发有权输入 | 需要 ServerCoreFactory；不是把按钮设为可用 |
| Netplay | 相应 Netplay 适配器/运行器 | 协议、内容、端口、状态共同约束 | 上游支持不等于本模组完成；RetroArch 与 JNI 路径分开 |
| 私人模式 | 本机 | 不公开游戏输入/音画/进度；实体硬件交互仍可能联网 | 不等于服务器个人存档，也不能替代公开玩法 |
| 电脑共享与交接 | 程序原运行者 | 附近看屏幕；获准者接管同一套键鼠 | 不是同时双人游戏，不是迁移核心或存档 |
| JNI / 独立进程 | 调用/隔离方式 | 不决定联机模式 | JNI 不自动带来 Netplay、兼容存档、旁观加速 |

**五种状态分开：设备电源、核心运行、操作席、旁观订阅、显示可见性。** 归还手柄、关闭菜单、走出显示范围不能随意合并为整机关机。每种机型还须交代下载中、开局确认中、正在保存、正在退出等过渡态。

## 4 各机型从玩家动作到运行的实际链路

### 4.1 FC 家用与 NES 旧会话

入口为实体电源/手柄命中，不是普通右键外壳任意位置。[HomeApplianceService](../../piq-fc-arcade/src/main/java/cn/piq/fcarcade/home/HomeApplianceService.java) 的 `tryButton` 分派至 [HomeConsoleRuntime](../../piq-fc-arcade/src/main/java/cn/piq/fcarcade/home/HomeConsoleRuntime.java)，后者委托 [ServerArcadeSessions](../../piq-fc-arcade/src/main/java/cn/piq/fcarcade/server/ServerArcadeSessions.java)。关机或未插卡时可先取实体手柄；取得实物与取得本局控制权分开。

当前公开开局如下；独立 2P 询问仅对有效 maxPlayers==2 的局出现，单人局不弹。光枪两端口的含义另按外设规则处理。

| 条件 | 实际顺序 |
| --- | --- |
| 不存档 | 创建/同步会话 → 双人游戏独立询问允许/不允许 2P |
| 个人档 | 选择当前保存命名空间三个槽之一 → 创建/恢复会话 → 独立 2P 询问 |
| 卡带已有档 | 继续/从头选择 → 创建会话 → 独立 2P 询问 |
| 卡带空档 | 直接创建 → 独立 2P 询问 |

`powerHomeConsole`（约 276～295）、`createHome`（约 990～1046）是核对点；[ClientArcadeEvents](../../piq-fc-arcade/src/main/java/cn/piq/fcarcade/client/ClientArcadeEvents.java) 的 `offerMultiplayer` 显示独立确认，通过 `FcNetwork.setMultiplayerEnabled` 回到服务端。**这是 FC 的源码现状，不是新的完整前置向导**；目标现以通用规范第 1.2 节为准，要求适用选档后独立询问、确认完再加载／恢复。现状的后置询问不能作为新附属跳过前置确认的理由；本次尚未改动 FC 代码。

本局允许后，其他玩家领取空闲第二手柄取得端口，不要求每人重复弹审批。光枪局第二端口有专用占用，不允许普通 2P 与光枪抢同口。归还只撤相应控制；开局者/计算主持/1P 不应在新设计里当成同一个概念。

FC 的 NES 机柜仍通过 `ServerArcadeSessions` 原路线；即使 NES 出现在 `CabinetBackends`，[CabinetClientBackends](../../piq-fc-arcade/src/main/java/cn/piq/fcarcade/client/cabinet/CabinetClientBackends.java) 也明确拒绝附属注册覆盖 NES，不可宣称全部走同一个通用客户端 backend。

核心入口 [NesCoreVariant](../../piq-fc-arcade/src/main/java/cn/piq/fcarcade/session/NesCoreVariant.java) 按内容及光枪选择 variant，[NesCores](../../piq-fc-arcade/src/main/java/cn/piq/fcarcade/core/NesCores.java) 保留旧 WASM 兼容，而当前 Libretro 适配由 [GenericLibretroNesCore](../../piq-fc-arcade/src/main/java/cn/piq/fcarcade/core/libretro/GenericLibretroNesCore.java) 承担。不同 variant 有保存 namespace；不能因为残留旧类就断言当前默认仍在使用旧核心。

### 4.2 SFC 家用

[SfcHomeMod](../../piq-sfc-home/src/main/java/cn/piq/sfchome/SfcHomeMod.java) 注册硬件、网络、公共机柜和服务端核心；家用 [SfcHomeServer](../../piq-sfc-home/src/main/java/cn/piq/sfchome/server/SfcHomeServer.java) 是自己的会话管理器。实体按钮走共享 HomeSystems 钩子，普通外壳交互不代替开机。

公开流程是电源 → 建立 SFC 会话 → 领取/绑定控制。当前 `powerOn` 将 `multiplayer=true`；之后 `requestJoin` 按卡带人数和 `joinApprovalRequired` 决定是否逐人审批。虽然 [SfcJoinClient](../../piq-sfc-home/src/main/java/cn/piq/sfchome/client/SfcJoinClient.java) 留有旧 Offer 对话框，现行源码没有找到对应 Offer 发送入口，**不能把残存界面当作已实现的独立开局确认**。

[SfcCartridgeData](../../piq-sfc-home/src/main/java/cn/piq/sfchome/data/SfcCartridgeData.java) 对旧卡缺 `MaxPlayers` 默认 2，而 [SfcCardEditorScreen](../../piq-sfc-home/src/main/java/cn/piq/sfchome/client/SfcCardEditorScreen.java) 只有显式字段且为 2 才显示“双人”；可能形成 UI 单人、权威上限双人的分歧。卡带人数修改的 OP 权限也与 ContentCards 不同。

家用普通串流/本地同步、托管、Netplay、私人保存是四条不同链，见第 7 节。核心 [LibretroSfcCore](../../piq-sfc-home/src/main/java/cn/piq/sfchome/core/LibretroSfcCore.java) 默认 JNI/Mesen-S；Netplay 另经自己的 profile/握手，不能以家用支持反推公共机柜同样支持。

### 4.3 MD 家用

[MdMod](../../piq-md-home/src/main/java/cn/piq/mdhome/MdMod.java) 注册 `ContentCards.Adapter` 和 `Features(true,true,true,2)`、实体按钮、HomeSystems、公开网络；实际公共模式掩码仅玩家串流。[MdConsole](../../piq-md-home/src/main/java/cn/piq/mdhome/MdConsole.java) 负责整张卡 ItemStack 插取、两手柄租约、电源和 NBT；不是借用 FC 的 NES 会话类型。

公开链：

`实体电源 → MdPublicServer.start → MdPublicSaves.choose → 自有开局/存档页 → SavePlan → begin → 授权下载 → 主持 MdEngine → 两端口输入与 Watch 串流`。

本地审计路径（本次文档发布未包含对应实现）：`piq-md-home/src/main/java/cn/piq/mdhome/save/MdPublicSaves.java` 的 `Pending` 保存整卡快照与人数上限；同目录 `MdSaveSlotsScreen.java` 把“允许 2P”放在存档页同一个按钮里。不存档且最大 1P 时直接开局，不存档双人走其自有开局页，没有 FC 的独立 2P 确认步骤。允许后，`piq-md-home/src/main/java/cn/piq/mdhome/MdPublicServer.java` 根据实际手柄租约直接分配席位；不应为弥补开局缺页反而给每次借柄加审批。

本地 `piq-md-home/src/main/java/cn/piq/mdhome/client/MdPublicClient.java` 公共启动固定 Genesis Plus GX＋JNI（本次文档发布未包含此实现）；[MdCoreChoice](../../piq-md-home/src/main/java/cn/piq/mdhome/client/MdCoreChoice.java) 的 BlastEm 选择属于显式旧私人兼容，默认 GX，退出连接重置默认，没有公共开机失败后自动退到 BlastEm 的正常路径。包内保留旧 DLL 不证明新会话使用它。核心、调用方式与旧保存命名空间不能因改菜单一并替换。

私人偏好会让 MD 实体开机走另一支授权启动；仅本机 1P，无公共旁观，卡带归属服务器存档不能被私人模式覆盖。公共停止经退役会话与服务器持久 ACK；私人停止等待本机保存完成，不等待公开存档 ACK。发送保存请求不等于成功。MD 私人实体卡内容仍可能经服务器授权下载，不能概括为“ROM 从不经过服务器”；其游戏输入、音画、进度不外发。

### 4.4 公共机柜与原生街机

公共实体入口 [ServerCabinets](../../piq-fc-arcade/src/main/java/cn/piq/fcarcade/cabinet/ServerCabinets.java) → [CabinetRooms](../../piq-fc-arcade/src/main/java/cn/piq/fcarcade/cabinet/CabinetRooms.java)。当前只有 CabinetCoinPolicy 支持的 Native 后端走实体电源命中通断；其操作区负责入席/退席，配置入口走菜单。SFC/GBA provider 尚未接该物理开关分支，普通非菜单点击直接 launch。所选游戏、适用的免费/实体币、连接组、同步策略各有状态，不能把 Native 的开关经验概括成所有公共后端已经一致。

| 后端 | 普通媒体 | 本地同步 | 服务端托管 | Netplay |
| --- | --- | --- | --- | --- |
| Native 公共机柜 | MAME JNI；按注册能力最多 4 席 | 旧 snapshot worker，最多 2 席 | 已注册工厂，须按支持平台/核心限制判断 | FBNeo 适配最多 4 席；不是所有 MAME ROM 自动兼容 |
| SFC 公共机柜 | SFC provider，最多 2 席 | 已适配 | 已注册工厂 | 未注册 CabinetNetplay / 未实现 prepareNetplayFactory |
| GBA 公共机柜 | mGBA，最多 1 席 | 未接 | GbaServerCoreFactory 单会话路径 | 未接 |
| NES 机柜 | 主包保留原 FC 会话链 | 依原链判断 | 依原链判断 | 依原链判断；不能用附属表替代 |

Native 入口 [NativeArcadeMod](../../piq-native-arcade/src/main/java/cn/piq/nativearcade/NativeArcadeMod.java)、[NativeCabinetBackend](../../piq-native-arcade/src/main/java/cn/piq/nativearcade/client/NativeCabinetBackend.java)；SFC 入口 [SfcCabinetProvider](../../piq-sfc-home/src/main/java/cn/piq/sfchome/client/cabinet/SfcCabinetProvider.java)；GBA 入口 [GbaCabinetBackend](../../piq-gba/src/main/java/cn/piq/gba/client/GbaCabinetBackend.java) / [GbaServerCoreFactory](../../piq-gba/src/main/java/cn/piq/gba/server/GbaServerCoreFactory.java)。模式注册和客户端 factory/服务端 factory 两侧都要检查，不能只看一个 flag。

有多人容量的非 NES 公共机柜 ready 后独立问“开启多人模式？”，允许的是申请；后续申请仍由主持批准。[CabinetJoinClient](../../piq-fc-arcade/src/main/java/cn/piq/fcarcade/client/cabinet/CabinetJoinClient.java) 与 `CabinetRooms` 的审批不同于家用一次允许后直接领 2P。主副柜端口由 [CabinetSeats](../../piq-fc-arcade/src/main/java/cn/piq/fcarcade/cabinet/CabinetSeats.java) 分配，受后端人数约束；未连接普通非竖屏柜目前上限为 `min(2, supported)`，不能只看外壳叫“单人柜”便认定实际限制为 1。

操作距离对应柜 8 格；公共显示/发现默认 16 格，既有订阅有 +4 格退出缓冲。[CabinetCoinService](../../piq-fc-arcade/src/main/java/cn/piq/fcarcade/cabinet/CabinetCoinService.java) 在授权、命中、输入接受后才扣币。[CabinetServerRules](../../piq-fc-arcade/src/main/java/cn/piq/fcarcade/cabinet/CabinetServerRules.java) 默认“最后主动退出立即关机=false、空席60秒、显示16格”；倒计时 0 禁用，不把没按键算作没人。

### 4.5 GBA 掌机

[GbaHandheldItem](../../piq-gba/src/main/java/cn/piq/gba/item/GbaHandheldItem.java) 是物品而不是可放置主机。[GbaHandheldClient](../../piq-gba/src/main/java/cn/piq/gba/client/GbaHandheldClient.java) 提前处理手势，[GbaHandheldGate](../../piq-gba/src/main/java/cn/piq/gba/client/GbaHandheldGate.java) 区分插卡、电源、举起，[GbaHandheldServer](../../piq-gba/src/main/java/cn/piq/gba/item/GbaHandheldServer.java) 验证实际持物、设备/请求身份及卡带下载权限：

- 主副手各持掌机和卡，Shift＋右键插卡；普通右键双手插卡兼容。插卡优先于电源与举起。
- Shift＋左键安全退卡，不顺带挖方块/攻击；关闭与保存结果完成后才退还，失败不吞卡。
- 普通右键举起/放下；放下释放输入但继续运行。
- 无待插卡时 Shift＋右键开关机。
- 页面 [GbaHandheldScreen](../../piq-gba/src/main/java/cn/piq/gba/client/GbaHandheldScreen.java) 提供控制、运行器、诊断等，不是普通游玩必开的全屏游戏页。

掌机使用公共 ContentCards 授权下载，但未像 MD 注册封面/公开保存等 Features；不能因为显示同一工作台就写成全功能卡带。当前本机电池档按世界或服务器地址＋玩家＋后端＋ROM 隔离，**不是随卡服务器档、三槽或 GBA Link**。卡带转交与电池进度转交不是一回事。

输入复用 SFC 键位 profile 与 GamepadInput 后再映射 GBA，不能因此声称与 SFC 同存档/同联机。[GbaJniSession](../../piq-gba/src/main/java/cn/piq/gba/bridge/GbaJniSession.java) 用 mGBA，JNI/进程仍独立保存；单 GBA 会话限制不能从公共四槽推成可同时四台。机柜 GBA 是另一条配置/席位/托管链。

### 4.6 可组装电脑与程序

[ComputerEntity](../../piq-computer/src/main/java/cn/piq/computer/world/ComputerEntity.java) 管理配件、电源、连接与键鼠租约；[ComputerBlock](../../piq-computer/src/main/java/cn/piq/computer/world/ComputerBlock.java) 的 Shift/外壳装配入口打开 [ComputerScreen](../../piq-computer/src/main/java/cn/piq/computer/client/ComputerScreen.java)，实体电源需配件齐全和有效显示连接。[PeripheralBlock](../../piq-computer/src/main/java/cn/piq/computer/world/PeripheralBlock.java) → [ComputerNetwork](../../piq-computer/src/main/java/cn/piq/computer/net/ComputerNetwork.java) → [ComputerWorldInput](../../piq-computer/src/main/java/cn/piq/computer/client/ComputerWorldInput.java) 直接进入世界中的键鼠控制，不先弹全屏游戏。

程序入口 [ComputerProgramScreen](../../piq-computer/src/main/java/cn/piq/computer/client/ComputerProgramScreen.java) → [ComputerPrograms](../../piq-computer/src/main/java/cn/piq/computer/client/ComputerPrograms.java)；文件选择 [ProgramFileScreen](../../piq-computer/src/main/java/cn/piq/computer/client/ProgramFileScreen.java) 只选择本机路径，配置确认后再运行，不能视为 ROM 上传。公开共享默认关闭；显式开启后 [ComputerStreamServer](../../piq-computer/src/main/java/cn/piq/computer/world/ComputerStreamServer.java) 处理附近看屏幕和可选交接，范围按电脑 32 格，而不是公共 Watch 的默认 16 格。控制授权范围 8 格，与显示分开。

[ProgramBackend](../../piq-computer/src/main/java/cn/piq/computer/client/ProgramBackend.java) 已抽象帧、输入、音频、暂停、状态、释放和关闭；但 [ProgramKind](../../piq-computer/src/main/java/cn/piq/computer/ProgramKind.java) 仍固定 HARDWARE/PVZ/FLASH，启动 switch 也在电脑内。**添加新程序尚不能只注册外部 provider 就自动出现在菜单。** 新程序如需扩展应先补最小注册边界，不复制电脑、视频线和输入系统。

| 程序 | 核心/运行器与内容 | 保存和共享 |
| --- | --- | --- |
| 硬件测试 | 电脑自身显示/输入检测 | 不伪造游戏核心或游戏存档 |
| PvZ | 可选 PvZ 附属，默认公共 JNI；显式进程兼容；用户自己的 main.pak | 本机运行者进度；电脑层负责旁观/键鼠交接，不是双人 Netplay |
| Flash | 电脑内重定位的 Flash 适配＋外置 Ruffle/WebView 运行器 | 当前不提供进度保存；共享来自电脑层，不要求装旧 Flash 盒子 MOD |

退出操作、暂停/继续、关闭程序、关闭电脑是不同动作。旁观者不能因为关闭自己的菜单而结束运行者的程序；交接也不把存档复制给接手者。

### 4.7 PvZ 与 Flash 的独立盒子兼容入口

[PvzServer](../../piq-pvz-addon/src/main/java/cn/piq/pvz/server/PvzServer.java) 的旧盒子入口要求创造模式且 OP2，通过 [PvzClient](../../piq-pvz-addon/src/main/java/cn/piq/pvz/client/PvzClient.java) 打开 [PvzScreen](../../piq-pvz-addon/src/main/java/cn/piq/pvz/client/PvzScreen.java)（本机资源路径/预览）。当前客户端启动调用 [PvzJniRuntime](../../piq-pvz-addon/src/main/java/cn/piq/pvz/runtime/PvzJniRuntime.java)，电脑适配 [PvzComputerBackend](../../piq-computer/src/main/java/cn/piq/computer/client/PvzComputerBackend.java) 则按明确偏好选 JNI/进程。盒子没有因此获得电脑的共享会话；保留旧入口不作为新家用机的交互模板。

PvZ 保存是核心产生的用户文件，不是 FC 三槽即时状态。公共 JNI 文件 workspace 有所有者/内容隔离和锁；进程档、旧 JNI 试验档、公共 JNI 档分开。旧专用桥类的存在不代表现行调用仍走它。vendor/PvZ-Portable 是固定 gitlink，不得因跟踪 libretro 分支自动升级 pin 或声称它与任意旧二进制同源。

Flash 旧盒子通过 [FlashBoxScreen](../../piq-flash-box/src/main/java/cn/piq/flashbox/client/FlashBoxScreen.java) 选择 SWF/预览/进入电视操作，[FlashBoxClient](../../piq-flash-box/src/main/java/cn/piq/flashbox/client/FlashBoxClient.java) 管理独立 helper。旧 README 声明无公共 ROM/服务器保存/多人同步，不能用电脑后来接入的旁观倒推旧盒子具备。鼠标、软键、音频和运行器版本按实际适配声明，不强行套 Libretro/JNI。

### 4.8 历史独立机台与研究工具

旧 SFC 街机 [SfcServerManager](../../piq-sfc-arcade/src/main/java/cn/piq/sfcarcade/server/SfcServerManager.java)、[SfcRomLibraryScreen](../../piq-sfc-arcade/src/main/java/cn/piq/sfcarcade/client/SfcRomLibraryScreen.java)、[LocalSfcSession](../../piq-sfc-arcade/src/main/java/cn/piq/sfcarcade/client/LocalSfcSession.java) 是自有库/协议/单 owner 会话，核心为历史 WASM；已占用返回已有使用者状态，不走公共多席申请。[SfcOccupancyDisplay](../../piq-sfc-arcade/src/main/java/cn/piq/sfcarcade/server/SfcOccupancyDisplay.java) 仍有 `billboard=center` 和通用“玩家”回退，和固定朝向真人名目标有差距。

Java ME [J2meArcadeBlock](../../piq-j2me-arcade/src/main/java/cn/piq/j2mearcade/world/J2meArcadeBlock.java) → [ClientJ2meArcade](../../piq-j2me-arcade/src/main/java/cn/piq/j2mearcade/client/ClientJ2meArcade.java)，Shift 选库、普通进入操作；[J2meNetwork](../../piq-j2me-arcade/src/main/java/cn/piq/j2mearcade/J2meNetwork.java) 的服务器选择写入要求 OP 与 8 格。[MicroEmuHeadlessSession](../../piq-j2me-arcade/src/main/java/cn/piq/j2mearcade/core/MicroEmuHeadlessSession.java) 使用 `--rms memory`，不能称长期 RMS 保存。它没有公共机柜的多人席和 Watch 订阅；本地 VM 运行不等于多人服务器游戏。

原生独立旧柜与公共 Native 后端并存；[NativeArcadeClient](../../piq-native-arcade/src/main/java/cn/piq/nativearcade/client/NativeArcadeClient.java) 的 `openAt/startGame` 仍是 Windows x64、未开放 LAN 的单人世界路径。Shift 配置打开 [NativeArcadeSetupScreen](../../piq-native-arcade/src/main/java/cn/piq/nativearcade/client/NativeArcadeSetupScreen.java)（继承公共 LocalRomPickerScreen）；普通启动记住的游戏，复核完整结构、身份与距离，再后台启动 NativeJniMediaSession。启动时关闭 GUI，使用公共 KeyboardInput/Gamepad 自由视角操作；同柜再次右键停止。`NativeArcadePlayScreen` 是无现行 new 调用的保留类，不能把里面的旧全屏/双人键盘说明当当前行为。

旧 SFC 库按 SHA 合并服务器/本地行，点行直接调用 [ClientSfcRomTransfers](../../piq-sfc-arcade/src/main/java/cn/piq/sfcarcade/client/ClientSfcRomTransfers.java).select，不是公共柜的选择后确认。该方法在检查 serverHasRom 之前要求本地文件存在，因此 server-only 条目虽然能显示，却会报本地缺失；本地有、服务器无时分片上传，运行缺资源则通过 ensureLocal 下载/校验。这是独立链中已发现的缺陷，不是公共内容库已具备的行为。

Java ME 三页分别是 [J2meLibraryScreen](../../piq-j2me-arcade/src/main/java/cn/piq/j2mearcade/client/J2meLibraryScreen.java) 本地列表/翻页/打开文件夹，[J2meGameScreen](../../piq-j2me-arcade/src/main/java/cn/piq/j2mearcade/client/J2meGameScreen.java) 纯 GUI 游玩，[J2meMachineControlScreen](../../piq-j2me-arcade/src/main/java/cn/piq/j2mearcade/client/J2meMachineControlScreen.java) 透明操作层＋世界机身屏幕。机台库发送选择请求后立即本地启动，服务器是否接受是另一结果；不是等待保存确认再启动。两种游玩页采用固定 J2meKeyMap，而不是公共可改键 profile：方向键，Enter/Space=Fire，Z/Q和X/E=左右软键，主键盘数字，数字小键盘按电话布局翻转上下行，Multiply/Divide 对应星号/井号。纯 GUI removed 关闭会话；机台页关闭后 runtime 继续，未见 removed/失焦统一释放按键路径，须单列按键粘住风险。

两个实验目录只提供核心探针/快照比对方法，不能安装为机台或代替最终 JAR/MC 验收。

| MD/GBA 通用卡 | [ContentCardStore](../../piq-fc-arcade/src/main/java/cn/piq/fcarcade/home/content/ContentCardStore.java) 上传保存 hash.ext；扫描 Entry.name 是磁盘名，实体卡另存 Title | [ContentCards](../../piq-fc-arcade/src/main/java/cn/piq/fcarcade/home/content/ContentCards.java) / [ContentCardNetwork](../../piq-fc-arcade/src/main/java/cn/piq/fcarcade/home/content/ContentCardNetwork.java) / ContentCardClient；Features 逐系统声明 |

公共目录 [ContentCardDirectories](../../piq-fc-arcade/src/main/java/cn/piq/fcarcade/home/content/ContentCardDirectories.java) 将机型和用途分开：

- ROM：`game-console/content-cards/<namespace>/<path>/`。
- 封面：`game-console/content-card-covers/<namespace>/<path>/`。
- MD system 为 `piq_md_home:md`；掌机 GBA 为其注册 system；客户端按钮和扫描按同一规则，但本地实例与服务器根不是一台电脑。
- GBA 公共机柜另用 `game-console/piq-gba/roms`。有两个入口必须明确写两条路径，不能把一个当另一个的自动回退。
- FC 有自己的 `piq-fc/roms`、`covers`；不能复用这一硬编码给 MD。
- 游戏内容、目录元数据、封面、缓存、临时传输、配置和保存必须各司其职。改显示名不要求移动旧 hash ROM 或迁移卡身份。

### 6.2 上传后名字变成 hash 的确定原因

本地原名/卡带草稿标题 → `ContentCardStore.store`（约 105 行）存为 hash.ext → `scan`（约 85 行）把磁盘名填进 Entry.name → 工作台显示并搜索这个名字。

`ContentCards` 的上传/写卡仅将草稿 Title 写入**这张实体卡**，没有持久服务器目录显示名。重新刷新/重启不会凭空恢复原名；选择服务器 hash 行还会把它填回名称草稿。MD 开局页又发 `q.entry.name()` 而非卡带 Title，所以卡名“测试”和开局“Zero Wing”可以不同，不能仅据此认定换了 ROM。

这不是中文编码乱码，也没有证据表明上传破坏 ROM 字节；它是身份字段与显示字段混用。SFC 独立目录有同类债务；MD/GBA 共用链都受影响。

**建议的修复合同，尚未实现：**

1. 分开内容哈希、物理文件定位、库显示名、卡带自定义名；保留旧 File/hash/CardId。
2. 持久保存可读库名；中文、空格、同名不同内容、同内容异名及重启后搜索都验。
3. 不能直接把 Entry.name 改成任意标题，因为 `ContentCardStore.read` 仍用它定位文件；目录元数据也不能随意塞进会被 ROM 配额扫描的目录。
4. 卡带改名只影响该卡，目录管理员改名影响库条目，两者分别授权。
5. 按 hash 合并本地/服务器来源显示，避免一项原名、一项摘要名造成“两个游戏”的错觉；不擅自删除任何旧文件。

### 6.3 人数和保存字段不是一个统一 schema

| 数据 | FC | SFC | ContentCards/MD |
| --- | --- | --- | --- |
| 最大人数 | ROM 库元数据，默认/特殊外设另算 | 卡字段；旧缺省 2 | 卡字段 Players，缺省/无效为 1 |
| 修改最大人数 | ROM 管理语义 | 工作台 OP 操作 | 有工作台权限者修改这张卡 |
| 本局是否允许加入 | session.multiplayerEnabled | 默认开启，另有逐人批准 | SavePlan 中开局选择 |
| 存档人数标签 | session.savePlayers，与加入开关不同 | 没有 FC 同等三槽流程 | 槽位元数据可初始化按钮，不应改变卡带最大人数 |
| 保存方式数值 | 依 FC 自身枚举/数据约定 | 0 不存、1 个人、2 卡带（Netplay） | 0 不存、1 卡带、2 个人 |

**不能跨系统直接拷贝整数。** 新公共抽象应使用明确语义适配，旧 NBT/文件不原地重解释。

本次追踪 MD `Players`：改名/写入保留 → 插机复制完整组件 → NBT 保存/读取整卡 → 开机从快照读取。没有发现“选择双人后写卡必然清成 1”的路径。截图来自不同世界环境，不能断言同一张卡；灰色 1P 的进一步根因需要同一卡 CardId、完整组件、主机内快照及真实服务端版本，保持“待验证”。

新增附属如果这些接口足够，只更新自身；确有缺口才列出最小公共扩展与旧调用者回归，再更新主包。不能承诺每次都不用更新主包，也不能为了新机器把名字/专用格式写死公共层。

## 11 应统一的合同与不能统一的差异

### 已有能力优先直接复用

硬件连接/命中、目录根、输入捕获、基础窗口布局、音画预算、Watch订阅、持久保存传输、核心生命周期、文件锁和诊断，按第8节真实接口接入。不得按机型复制同一套原生桥/上传服务/电视/按键设置。

### 需要补公共层的合同（目标已明确，实现待落实）

业务目标见通用规范第 1 节，以下四类公共扩展及其具体实现仍待设计／接通，不是已存在的类名：

1. **内容目录合同**：物理标识与展示元数据分离，同内容来源合并、持久可读名、范围正确的改名权限；FC/SFC/ContentCards 用适配器兼容旧库。
2. **家用开局合同**：内容／设备／卡身份校验 → 按需选档 → 独立 2P 确认 → 加载／恢复 → 就绪授权；取消／失败／超时与旧回复按同一请求代次回退。顺序不再留给各附属自行决定，也不直接复制 NES 会话。
3. **保存业务合同**：归属/额度/兼容身份/槽位/管理/确认/旧档退役分层，统一界面可调用真实能力；不会把SRAM/快照/PvZ文件强制同格式。
4. **能力和状态合同**：运行模式、核心、平台、人数、忙碌、失败原因和工具可用性分开；设备页根据真实状态，而不是零散硬编码灰按钮。

这些扩展如确需修改主包，应说明协议版本与客户端/服务端配套，回归既有调用者。先小范围验证，再迁移其它组件；不一次删除旧链或改全体玩家存档。

### 必须保留的类型差异

家用领柄、街机入席/投币/组柜、掌机举起/卡带手势、电脑键鼠与程序交接互不硬套。FC光枪、GBA肩键、MD六键、街机Test、PvZ指针等都属于输入/外设适配，不应靠“统一UI”丢掉。

私人数据边界、不同核心保存格式、真正不支持的原生联机、旧注册ID/卡身份都须保留。人类体验可以统一，运行器和磁盘格式不必伪装相同。

### 旧核心退役的后续范围

用户要求核对 BlastEm 在整个方块电玩项目中的退役，而非只隐藏 MD 菜单。全仓核对的实际运行／构建引用集中在 `piq-md-home` 的旧私人兼容；其他组件未发现真实运行依赖，外围还留有历史制品盘点和版本文档。后续实施需清理相关选择、profile、构建／打包、依赖和测试入口，新构建不再携带或调用它；不移除其他核心使用的 JNI／进程运行器。

**本轮仅记录目标，尚未执行移除。** 第 4、7 节中对 GX 默认、旧 BlastEm 私人入口和保存隔离的描述仍是本次源码事实。旧保存、ROM、世界、历史 JAR 和必要的兼容证据保留；不把退役当作自动迁移授权。

## 12 新附属开工和回归清单

每个新机器先填写[功能制作说明](功能制作说明模板.md)和[能力声明](附属能力声明模板.md)。使用 Libretro 时仍必须阅读相关官方文档/现成方案；本次内部审计不能代替上游调研。本轮没有新核心选型、下载或外部技术验证。

### 开工必须交代的十条链

1. 玩家入口：物品/部件/按键 → 提示 → 哪个界面或世界操作。
2. 界面：复用哪种布局 → 字段来源 → 权限/禁用理由 → 请求 → 成功/失败回读。
3. 内容：本地扫描 → 服务器列表 → 上传/选择 → hash与可读名 → 实体介质或设备选择。
4. 开局：按类型采用通用规范第 1 节；家用校验 → 按需选档 → 独立加入确认 → 加载／恢复 → ready，逐步核对取消／重试终态。
5. 输入：哪个玩家/租约/端口 → 改键+实体手柄 → 核心映射 → 动画 → 松开清理。
6. 音画：核心格式 → 转换 → 世界屏幕/音源 → 旁观和预算 → 不可见时行为。
7. 保存：模式 → owner/额度/格式 → 读/写/ACK → 旧档保留 → 具体档库/删除权限。
8. 工具：螺丝刀/遥控器/终端/控制页/诊断分别管什么，服务器在哪复核。
9. 收尾：退席/放下/关机/拆机/失焦/断线/换服 → 哪些资源清理，哪些状态保留。
10. 兼容：旧卡/旧设备/旧档/旧配置/旧核心 → 保留、拒绝或另行批准的迁移。

每条写明“直接复用哪个入口”“必要适配”“公共缺口”“本轮不做”和证据。没有调用链就不能凭截图相似打勾。

## 13 本次结论与维护规则

本次完成的是全组件主要运行链/界面/API/数据边界审计和制作资料补充。运行代码、核心、模型、ROM、卡带和存档未改；没有新JAR，也没有本次构建、部署、群通知、推送或服务器重启。
