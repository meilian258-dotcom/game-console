## 3. 业务合同

家用公开：服务端校验与冻结卡带 → 按需选档并校验版本 → 独立询问允许/拒绝 2P → 加载和恢复 → 核心就绪 → 授予输入与旁观。

- 不存档但支持双人的公开内容仍询问；拒绝双人继续单人，Esc/取消则取消开局。私人和真实单人不显示假双人入口。
- `maxPlayers` 来自内容能力，`savePlayers` 是所选存档标签，`allowSecondPort` 仅本局许可。三者不再共用一个字段。
- 每步与原连接、设备/卡带身份、请求代次及阶段绑定；超时、换卡、权限改变、断线与旧响应不能启动新局。
- 正常关机先撤销输入并进入保存中；取得服务端持久结果后再释放正常事务。失败保留原好档、说明未确认成功；异常断线有限收尾，不永久锁设备。
- 服务器的最终保存结果由实际写入/协议结束/租约释放产生，不采信客户端布尔值冒充服务器落盘。私人结果仅代表本机保存。

服务端 READY 是开局提交点：提交前 Esc/取消/物理关机取消准备；提交后迟到的旧准备页取消不销毁已开始游戏，应使用实体正常关机。MD 在服务端激活前仅做必要初始化/引导帧与恢复，不推进游玩、不呈现音画、不接有效输入、不上传检查点；取消从头开局不会因此覆盖原进度。

## 3.1 新附属真正调用什么

| 层 | 本次公共入口 | 附属职责 |
| --- | --- | --- |
| 纯状态机 | `cn.piq.retro.flow.DeviceSessionFlow` | 无 MC/机型依赖；明确 maxPlayers、savePlayers、allowSecondPort；阶段与 revision，不处理磁盘或核心 |
| 权威编排 | `cn.piq.fcarcade.home.flow.HomeLaunchServer.start(player,key,adapter)` | `key` 绑定 system/维度/坐标/hardware UUID；服务端线程调用，单连接单准备/运行事务，世界最多32项 |
| 适配器 | `Definition / valid / list / select / load / cancelled` | 声明实际能力，冻结整卡与内容；校验连接/设备/保护/距离；异步列表与选择结果回调；不得在选择时删除旧档 |
| 共用界面 | `HomeLaunchNetwork / HomeLaunchScreen`，协议 `home-launch-1` | MD不再复制选档与2P开局页，沿DeviceScreen/FormLayout。FC旧管理接CartridgeSaveService；MD管理沿CartridgeSaveScreen/Network与ContentCards.saveLibrary，实际存储由MdPublicSaves/MdSaveCatalog适配 |
| 核心完成 | `Handle.ready / beginStopping / finished / fail` | 均在服务器线程；`ready` 前完成加载恢复并再次校验；正常结束等真实保存与 native owner 释放，不拿停止请求当完成 |
| 公共保存 | `NetplaySaveServer.openPrepared / activate / abort / awaitFinish` | 参数仍是服务器确定的 owner/profile/content/slot；准备可读不可写，READY后授权写；取消撤销队列写；正常结束用 retire，再等 FinishResult |
| 私人结束 | `PrivateHomeClient.stopCartridgeAndSave(system,pos)` | 取得原 owner 关闭 future，不另造“保存成功”；连接/system/目标必须匹配；本机结果不是服务器存档证明 |

准备/加载各有限时，关闭最长80秒；超时报告未确认成功并释放逻辑事务，不强杀原生线程、不卸载仍在使用的核心。运行器自身仍保留资源锁和并发限制。异步回调绑定 token/revision/原连接；重复回调、取消后回调或过期选择不再次 load。

`Adapter.valid` 在 READY 前使用，READY 后运行中的权限/席位/连接持续检查仍归机型适配器，不能仅注册新 API 就省掉运行期校验。私人自动恢复使用 `saveMode=0` 跳过服务器选槽页，不代表用户选择了“不存档”；私人真正保存模式继续由原卡设置和本机命名空间控制。

MD 正常公开停止同时等两类信号：服务器持久写入/FINISH/IO租约释放、精确主持连接的核心关闭回执。周期 SAVED 不能代替最终结果，退休前的旧检查点也不能冒充关机最终保存。未READY取消使用 abort，不保留最终写权限。NONE不创建旧档；私人不发公开保存数据。

FC 本轮沿用完整旧选档页（改名、删除、按键设置），将新游戏动作后接公共独立2P确认；非 Netplay 从头选择不再提前删旧档，同个人槽旧 ROM 仅在新数据持久成功后退役。FC 非 Netplay 仍沿既有快照收尾，不把本轮改动说成所有 FC/SFC/街机终止协议完全统一。RESET 再次就绪不重复消费开局状态。

FC 托管结束必须先确认最终快照没有报错，再写入并报告成功；已有周期快照不能掩盖最终捕获失败。该保护在最终审查中补入 r2，保留失败原因和旧好档，不伪称最终进度已保存。

## 3.2 内容名称与兼容

`Entry.name` 仍是安全物理文件名，旧 File/hash/CardId 不变；新增 `displayName` 用于列表、搜索与标题。原上传名以 UTF-8 原子写入独立的 `game-console/content-card-metadata/<namespace>/<system>/<hash>.name`，不占 ROM 配额。相同哈希再次上传保留已有库名，卡带改名只改该卡；本地与当前服务器页面按内容哈希和长度合并来源，不虚称已拉取未请求的全部服务器分页。

`Entry.equals/hashCode` 保持原物理身份语义，不包含 displayName；来源合并另用内容哈希＋长度。原始文件名不是磁盘路径授权，仍须长度、字符、UTF-8和无链接校验。

旧 hash 文件没有历史名称元数据时只能显示“未命名内容·短ID（名称缺失）”，不能编造原文件名。旧 ROM/存档不移动、不删除、不自动迁移；SFC 自有目录同类名称债务不在 ContentCards 修复覆盖范围。

本批主包协议为 `content-card-5`、新增 `home-launch-1`；MD为 `md-public-3`。客户端和服务器同时更换 FC76.34 / MD10；MD10 最低主包依赖已提升，不混装旧主包。保留原 core/ROM/save 身份和许可，Genesis Plus GX 仍为公开默认；旧私人兼容核心入口未在本轮删除。

## 3.3 街机根因及复用合同

不是对吃豆人或怒蜂首领加名称特判。本轮发现两个独立边界问题：

1. 公共 JNI 已将 libretro 逆时针值转为公共顺时针值，但 `CabinetVideoGeometry.textureUv` 的奇数旋转分支仍按逆时针取样，导致90°/270°相差180°。公共帧统一顺时针；旧 PNP7 与 NativeSnapshotCore helper 只在进入公共帧时转换一次，旧独立渲染成对路径不混改。
2. 四端口街机 Netplay 主持使用机柜时间线，观察者却走默认两端口构造，初始化被校验拒绝。`NetplayWatchContent.Preparation.cabinetTopology` 显式传递可信拓扑；观察者仍是 `host=false/player=false/port=-1`，不能输入或保存，不借旁观占席。

另补 FBNeo 的已旋转显示比例声明：`NetplayProfile.JniAspect.PRESENTED` 在适配边界变成公共未旋转 DAR；MAME已归一化，保持RAW，不能重复倒数。该显示元数据不进入核心/存档身份；旧构造器兼容保留。依据为既有核心源码和 [libretro接口旋转定义](https://raw.githubusercontent.com/libretro/RetroArch/master/libretro-common/include/libretro.h)，不是按像素宽高猜显示比例。

普通JNI玩家音画串流（MEDIA）仍沿 `CabinetRooms → WatchService → WatchClient`；本轮只读核对未找到同样的确定阻断点。用户的实际旁观现象是否还有MEDIA问题须在准确运行模式下用两个MC客户端复测。
