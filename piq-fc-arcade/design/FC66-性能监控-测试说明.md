# FC66：FC 性能监控与设备菜单整理

适用：game_console 0.31.0-alpha.66，Minecraft 1.21.1 / NeoForge 21.1.x / Java 21。2026-09-23 本地测试候选，不是稳定版；未安装、部署或重启任何游戏实例。

## 快速使用

启动一局 FC 游戏，输入 `/fc-debug on`，关闭聊天窗口，等待约 1 秒。左上角显示本机性能。输入 `/fc-debug off` 关闭悬浮窗。

- `/fc-debug`：性能面板，可以开关悬浮窗、切换设备、复制当前数据，以及进入原网络统计页。
- `/fc-debug status`：将当前采样摘要显示在本机聊天里；关闭监控时只提示如何开启，不自动启动采样。
- 调试螺丝刀 → 家用机“设备设置” → “性能”：直接打开面板。优先选中该位置已有会话；没有该设备会话时显示其他活动 FC 会话，设备名称/坐标始终可见。
- 监控本身不需要 OP。修改联机方式等仍由服务端验证管理员权限、机器身份、领地和空闲状态。
- 默认关闭；关闭面板且悬浮窗关闭后停止采样，最迟下一次 0.25 秒刷新。退出服务器清除悬浮窗与选择，不写客户端配置。

私人模式保留原行为：开菜单会暂停。测试私人 FC 时打开悬浮窗，再退出所有菜单并手持手柄。面板不会改变暂停、输入归属、存档或联网规则。

## 数据口径

| 项目 | 含义与边界 |
| --- | --- |
| 模拟帧率 | 最近十个完整 100ms 时间段内实际完成的核心帧数，约 1 秒窗口；不是 Minecraft F3 FPS，也不是视频接收帧率。首次约 1.1 秒建立窗口，暂停/无输入/卡住时旧帧会自然归零。 |
| 核心单帧平均/最大耗时 | `NesCore.runFrame()` 的墙钟时间，包括原生 worker 通信和等待；不包括调用后的 Java 画面拷贝、音频处理、编码或 Minecraft 渲染，不是 CPU 占用率，也不是完整端到端延迟。 |
| 已模拟帧 | 当前核心的累计帧序号；读快照/重置后可能回退，不能拿它当 FPS。 |
| 待模拟帧 | 已接纳的最新输入目标与已完成帧之差，不包括还在网络上的输入，也不是 RTT。少量缓冲正常；持续增长才值得结合帧率排查。串流本机执行者无此输入积压指标。 |
| 音频待取 | FC 工作线程输出给客户端、尚未取走的包数及按 44.1kHz 单声道样本计算的毫秒数；最多 12 包。不是声卡或整条音频链的缓冲。私人 FC 显示最多 6 个混合音画“输出待取”包，不虚构其音频时长。 |

约 60 FPS 是现有 FC 调度目标；追赶快照/历史可能短时超过，等待输入可能低于。低帧率不一定是核心太慢，还可能是暂停、输入供应或调度；最大单帧偶发尖峰也不能独自判定持续卡顿。

支持已有 FC 家用机、小霸王和 FC 街机客户端会话，以及私人 FC。多会话时可切换，自动优先控制席位/较近设备；各会话独立统计，不合算成一台机器的 FPS。只读取已存在会话，不启动额外模拟器，不强制启用旁观模拟。

本机只接收主持玩家/服务器音画时，没有远端核心计时，明确显示未上报。网络页保留接收视频 FPS 与模组载荷统计。当前面板不提供远端 CPU/内存、声卡缓冲、所有其他附属的核心性能或完整链路延迟。未接入 FC 会话表的纯媒体旁观路径不会凭空显示为本机模拟器。

采样用固定 16 个时间桶，关闭时逐帧路径不读时钟。读数据不会 drain 输出、轮询输入、运行核心或请求保存；不会记录 ROM 文件名、路径或发送性能数据。“复制数据”仅用户点击时写本机剪贴板，包含设备坐标与所见测量值。

## 截图菜单是否过时

三种模式仍是当前实际实现：玩家运行并发送音画、各端运行并同步输入、服务端运行并发送音画。libretro 是核心接口；本轮没有把 Minecraft 联机替换为 RetroArch Netplay。

页面改名“设备设置”，避免把模式配置当性能分析。底部为刷新、性能、网络、私人模式、关闭；模式说明放悬停提示。重复 OP/空闲文字精简，保留卡带存档提示与 FC“2P：开局选择”。服务端托管未开启时直接说明未启用，不再把这个情况统称为运行库错误；运行库/平台异常仍按既有检查报告。不会自动打开 serverHosting、修改已选模式或放宽权限。SFC 特有的保存方式边界仍保留，FC 性能按钮不假装支持 SFC。

## 安装与回退

1. 退出游戏/正常停服，备份实例、世界、配置、公开与私人存档。本文不是自动部署授权。
2. 双方 `mods` 使用本目录冻结的 `game_console-0.31.0-alpha.66.jar`，移出旧同 ID 主包留存；不要同时放两份，也不要安装 `build/libs` 中间包。
3. 不需要额外安装 RetroArch 或另换核心库。网络协议沿用 FC65 的 43；本轮核心、helper、公共桥、profile、存档格式、材质和语言资源字节不变。
4. 建议只装主包，在世界副本先测。Flash prototype.8 的依赖范围不接受 FC66，不能混装；SFC/GBA/街机附属组合本轮未验，不当作兼容承诺。
5. 从 FC64 或更早升级时保留 FC65 的存档边界：新版持久化包不能交给旧版读取，旧 WASM/新 libretro 不自动迁移；回退必须同时恢复升级前对应世界/存档备份。FC65 原生保存说明保留在历史指南中。

安装端源码依据：共同注册方块/物品、`FcNetwork` 协议43、服务端会话/卡带/存档授权与客户端显示/输入分离。新性能事件只订阅 CLIENT；服务端修改仅菜单提示文字，未增加性能网络包。
