# FC 基准交互统一（实施合同，2026-09-11）

各模拟器操作逻辑以 FC 为基准。FC 为基准，不重写已经运行的模拟器、输入位布局、音画协议与模型资源。

## 从实际 FC 代码核对的基准

* 家用机：已插卡并正确连电视后，空手右键领取手柄并开始；插入已写入卡带且条件满足也会启动。拿着自己的手柄右键绑定主机或电视归还；右键空气只提示，不结束游戏。
* 同一手柄放个人库存或暂存鼠标光标，不等于归还。输入置零，保留原局；重新拿回即可继续。空手再点同一主机取回原手柄，不生成副本。
* 主机/已连接电视均为交互点；距离以两者较近点为准，两端权限仍必须有效。
* Shift + 空手右键家用主机取卡，Shift + 持卡不插卡；电脑仍为写卡入口。
* P1 可先玩。允许多人后，其他玩家申请，P1 批准才加入当前局；不能把其他 MC 玩家自动分成同键盘 P2。
* 普通右键街机进入/退出；Shift + 右键配置。离开菜单或恢复焦点时，全部操作键松开后才恢复输入，不抢 WASD 和鼠标视角。

依据：HomeHardware.interactConsole / interactTv / insertCartridge；HomeControllerService.activate / useOn / tick / reclaim / usable；ServerArcadeSessions.startHomeConsole / requestSecondPlayer；ClientArcadeSession.updateControls / releaseControls。

## 本轮范围与分工

- FC24/SFC13/Native8 版本与依赖、街机邀请客户端、全量构建与最后 JAR 审核/合包、交付和维护记录。
- SFC 家用启动前置校验、精确手柄库存所有权与输入授权分离、归还/取回/双手/距离、焦点与菜单；保留 core/Playback/net/model。
- 通用街机允许多人/申请/审批的服务器 gate 和独立增量协议；保留固定 P1–P4 座位、两柜同画面与旧音画协议。
- 通用/Native 实际输入生命周期与中立重臂、独立审计。旧未使用透明 PlayScreen 不作为实际行为依据。Native 原有机柜几何固定为原 FC21/Native7 的值，避免新共享模型尺寸影响旧网格；原资源不变。

## 不混淆的能力边界

* 不借 UI 改名假称 SFC/Native 已支持 FC 同等级的服务端存档、续玩、排行榜。
* SFC 当前不支持 FC 的 P2 实体手柄投掷转交；保留安全限制，不在本轮扩展可转移租约。
* 原生核心没有暂停协议；失焦/菜单清本人输入不等于承诺暂停其他联机玩家或冻结核心。
* 单人/双人/四人上限取决于 ROM 和后端；连接两台机柜不会让双人游戏变四人游戏。
* 自动旁观、现有模型比例、ROM/core、原有音画流量限额和服务器权限检查必须保留。
