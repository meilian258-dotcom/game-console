# 方块电玩：SFC 输入延迟修复测试版

适用：Minecraft 1.21.1 / NeoForge 21.1.236 及同一 21.1 系列兼容环境；FC 0.31.0-alpha.46、SFC 0.1.0-alpha.27（合并 SFC core 0.2.0-alpha.9）。这是本地测试更新，不代表多人实机验收或公开发布批准。

## 安装与配套

- 客户端和服务端统一使用本包 FC46；使用 SFC 的两端同时更新为 SFC27。协议仍为36，但本次SFC失联保护依赖新客户端心跳，不能只换服务器或混用旧SFC客户端验证。
- 先备份世界、配置和存档，正常关闭游戏/服务器后替换。把旧同ID JAR移到实例外备份；只将本包两份JAR放入实际实例的mods。不要将外层ZIP放进mods。
- SFC27已经包含core9，最低依赖FC46。不要另装旧独立piq_sfc_home或piq_sfc_arcade。只玩FC可不装SFC。
- FC/SFC使用原有JAR内置运行环境；本次没有新增外置运行库。街机0.1.0、GBA8及其原有运行环境沿用，不包含在这次两JAR更新包。
- 安装端依据：FC注册公共方块/物品和服务端网络处理；SFC注册SfcHomeConsoleBlock和SfcHomeNetwork，客户端则有SfcHomeClient/播放器。不是根据依赖声明中的side猜测安装端。
- 本包不含商业游戏ROM、BIOS、世界或个人存档；不改用户现有按键配置、核心、模型、贴图、存档格式或网络协议。

## 修复范围

1. SFC本地输入同步在短时卡顿/光影切换后，按照完整输入序列逐帧追赶，不直接跳过模拟帧。追赶有CPU让出和持续时间上限，赶近后恢复正常速度；期间不把过时音频与中间画面继续播放给玩家和旁观者。
2. 正常SFC输入心跳由每10 tick缩短为每2 tick；服务端12 tick未收到有效输入时先清零该插口，不立即归还手柄。超过100 tick仍按原规则归还。以上约0.1秒、0.6秒和5秒是20 TPS下的值，不是低TPS服务器的墙钟保证。
3. 输入清零后，旧非零心跳不能重新激活卡住的按键；收到中立输入后才恢复。客户端输入采样间隔达到500毫秒时先释放输入，玩家需要松开游戏键/实体手柄回中，再重新操作。P1/P2独立计时，一口领取不延期另一口的失联保护。
4. 控制设置明确显示当前编辑机型、当前生效/待保存方案、真实按键和同键绑定说明。N是位置锁，只屏蔽移动；不会吞掉所有其它模组快捷键。

## 为什么K会触发光影

这次现场配置的SFC方案是“方向键＋小键盘”，K不在其中；Iris的开关光影绑定K，因此K按当前设计仍可操作光影。不是已证实的Iris绕过按键拦截。

FC、SFC和街机目前分别保存方案。在F7设置页选择当前设备，查看按键表；若想用字母功能键，明确选择对应方案并保存。本次不会静默替你切换方案，也不会修改光影或其它模组的键位。

## 验收步骤

1. 不开机取SFC手柄，确认当前方案的功能键不触发同键普通世界功能；归还后恢复。检查N只锁移动、Esc仍可用。
2. 小键盘方案下，K仍按原光影设置工作；改为包含K的字母方案并保存后，手持有效手柄时K应控制游戏，不切光影。
3. 本地同步正常游戏，使用一个不属于当前游戏方案的光影快捷键产生1—3秒加载停顿。恢复后松开所有游戏键，再按方向/功能键；确认不再持续落后数秒。检查声音没有积压长串重播。
4. 两人分别拿P1/P2，在其中一人短时卡顿时，另一人应正常操作。卡顿端恢复后松键再按；另一口取还不应延长卡住按键。
5. 测试开菜单、切出窗口、关机重开、Q归还、六格断线，以及服务端托管模式。超长卡顿仍可能安全退出控制，不承诺任意长停顿都无缝恢复。
6. 如仍异常，保留最新客户端日志，记录是否本地同步、谁开机、卡顿持续时间、恢复后是否已松键。新增追帧开始/结束/积压帧数日志用于定位；目前未取得本包在用户光影组合中的实机复测。

## FC磁碟机（FDS）

当前不能直接运行.fds磁碟映像：游戏库只接收.nes，现有核心没有FDS磁碟设备适配。仅修改文件后缀不行。若游戏另有.nes卡带版本，是否可玩取决于实际Mapper和核心兼容性。

未来FDS支持需要独立设计磁碟读写、插入/退出、换面、保存和联机同步，以及由玩家自备的BIOS加载路径；本次没有开发或打包FDS/BIOS。常见实现要求见Libretro Nestopia文档：https://docs.libretro.com/library/nestopia/ 。
