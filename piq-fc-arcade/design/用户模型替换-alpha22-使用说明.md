# 用户模型替换测试版 · FC22 / SFC10

本测试版接入双人街机、SFC 双手柄主机和独立卡带模型。模型原稿不变；游戏内效果仍需验收。

## 包里是什么

| 文件 | 用途 |
| --- | --- |
| `mods/piq_fc_arcade-0.31.0-alpha.22.jar` | 主模组，内置 FC；接入新双人柜模型、屏幕与摇杆/按钮动画 |
| `mods/piq_sfc-0.1.0-alpha.10.jar` | SFC 合并附属，包含家用模块和旧 SFC6 核心；替换主机、手柄、卡带和 AV 线端点 |
| `mods/piq_native_arcade-0.1.0-alpha.7.jar` | 原生街机附属，与上一包完全相同，未重新制作 |
| `piq-native-arcade/runtime/piq-native-helper.jar` | 与上一版相同的四口 helper，不放在 mods 内 |
| `预览/` | 真实导出网格的离线预览，不是 Minecraft 截图 |
| `checks/` | 本次检查记录；`SHA256.txt` 为包内文件校验值 |

SFC JAR 已包含 `piq_sfc_arcade` 和 `piq_sfc_home` 两个 ID，不要再同时安装旧的独立 SFC 核心/家用 JAR。保留本机现有 DLL、JNA、ROM 和 BIOS；本包不含这些文件。

## 外观与操作

- 双人柜按原稿比例接入：1.5 格宽、2 格高、1.1 格深；游戏显示面对齐新 4:3 屏幕，摇杆和按钮使用原分组动画。
- 为兼容上一版已经摆放的街机与通讯连接，保留原有 **2×3×2 的 12 格结构编号和放置检查**。外形和碰撞已贴合新尺寸，上排不碰撞，但仍是结构保留格，不能当作完全释放的建筑空间。不会自动拆改旧街机或迁移存档。
- **新双人柜本版只显示原稿配套默认贴图。** 旧皮肤和新模型使用不同 UV 布局，且旧存档没有布局标识，不能可靠识别；原皮肤哈希/数据保留、不删除，相关入口明确禁用旧皮肤应用。单人柜皮肤流程保持不变。未来若继续制作新柜自定义皮肤，需要增加明确的新布局标识，不能直接套旧模板。
- SFC 主机保留原始造型、贴图和桌面手柄比例。领取时隐藏相应桌面手柄、固定线段和插头；归还后恢复。插卡使用独立卡带，不再重复显示主机原稿中自带的旧卡。
- 手持手柄重新调整中心和握姿，增加原分组按键、方向键、L/R 肩键的按下反馈。物品展示不读取其他会话的输入；失焦/打开菜单时本地动画回到松开状态。
- SFC 主机端 AV 线对齐后部 MULTI OUT，电视端仍接现有 FC 电视的 RCA 接口。固定线材和动态 AV 线分开处理。暂未新增连接远端玩家手中手柄的世界长线。
- 卡带封面按原标签区居中适配，不拉伸封面比例。

本次没有重写启动、归还、邀请、联机租约或模拟器输入协议。原来的右键进入/再次右键退出、Shift+右键配置，以及通讯线连接两柜的操作保持。手柄/柜台外观动画只读取已有状态：主持端可以看到已有远端输入对应的柜台动画，客人只保证自己的本地操作动画；没有为他人按键动画增加广播包。

## 手动更新

实体手柄输入已接入 FC、SFC 和通用街机，但默认需要手动启用：输入 `/fc-gamepad`，刷新设备、选择已识别的标准手柄，启用并保存；松开按键、摇杆居中后再操作游戏。各客户端只控制自己的席位，不把本机第二只手柄自动分给 P2。Xbox、NS、PS 的具体型号/USB或蓝牙连接是否被识别，仍需实物测试；不是所有设备都保证免配置。

1. 所有人保存并退出游戏，服务器正常停服；备份旧 MOD、helper 和世界。
2. 客户端与服务器统一替换本包对应 MOD，避免新旧同 ID JAR 并存。SFC10 至少需要 FC22。
3. 如果已经使用上一版 FC21/SFC9/Native7 包，Native7 和 helper 不变；可保留原文件。更早版本如需更新 helper，将其放到实例根目录的同名路径，不放进 mods。
4. 先用备份世界测试。原摆放方块不需要为了刷新外观全部拆除重放；旧结构保留格的占位规则仍在。

这只是提供安装文件和说明，本次没有代为安装、删除或停服。

## 建议进游戏检查

- 双人柜四个方向的屏幕朝向、物品栏缩略图、前后厚度及走近时的碰撞。
- SFC 插入/取出卡带，P1/P2 领取与归还，桌面对应手柄/线/插头是否正确隐藏和恢复。
- 手柄 A/B/X/Y、方向键、Select/Start、L/R 动画，以及打开菜单、切换窗口后的松键。
- 多种电视与主机不同朝向时的 AV 线；已有卡带封面是否落在标签内。
- 好友加入/离开 SFC、两台通讯街机的原有联机流程。

已进行编译、自动回归、原始模型/UV/拆分网格与最终 JAR 范围审计；具体证据在 checks。此次未在真实 Minecraft 场景和多客户端中实玩，不将离线预览或 FML 元数据扫描当成游戏内视觉/联机验收。
