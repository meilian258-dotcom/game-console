## 参考与采用理由

2026-10-17 核对暮色森林官方 MC1.21.1 分支固定提交 `9e40a75721c716b2fdf80c16d1058fe718825e9f` 的 [TFCreativeTabs.java](https://github.com/TeamTwilight/twilightforest/blob/9e40a75721c716b2fdf80c16d1058fe718825e9f/src/main/java/twilightforest/init/TFCreativeTabs.java)：自身页面通过 `displayItems` 顺序输出，向已有页面加物品使用公开事件的定点插入。物品注册顺序与页面显示顺序可以独立安排。另见 [NeoForge 1.21.1 物品与创造页文档](https://docs.neoforged.net/docs/1.21.1/items/)。

采用这一公开 API 使用方式，不引入暮色森林依赖或复制其功能代码。FC76.59 的事件尾部重排曾用于兼容旧附属追加方式；本批迁移调用方后删除这层全页重排。既有 [FC76.59 验证记录](创造栏公开事件兼容修复-FC76.59.md)仍只适用于原版本，不作为本批测试结果。

## 附属如何接入

附属继续在自己的 mod event bus 注册 `BuildCreativeModeTabContentsEvent` 回调，调用主包 `cn.piq.fcarcade.registry.CreativeTabGroups.insert`。接口只处理方块电玩页，对其他页不作修改；普通物品示例：

```java
CreativeTabGroups.insert(event, CreativeTabGroups.Group.CONSOLES, YOUR_CONSOLE);
CreativeTabGroups.insert(event, CreativeTabGroups.Group.MEDIA, YOUR_CARTRIDGE);
```

`YOUR_CONSOLE` 和 `YOUR_CARTRIDGE` 表示附属自己的 `ItemLike`。需要保留自定义数据组件或特殊可见性时，传入原 `ItemStack` 并使用 `TabVisibility` 重载，不把它重新构造成裸物品。

| 分组 | 插入位置 |
| --- | --- |
| `CONSOLES` | 主包家用机之后、第一台街机之前 |
| `ARCADE` | 主包街机之后、第一台电视之前 |
| `COMPUTERS` | 电视之后、FC 卡带之前 |
| `MEDIA` | 主包介质与写卡工作台之后、视频线之前 |
| `ACCESSORIES` | 主包视频线与光枪配件之后、遥控器之前 |
| `TOOLS` | 主包工具之后、第一件家具之前 |

同一次调用按传参顺序添加；同组的多个附属按事件贡献顺序排列，不承诺跨附属固定的型号次序。电脑附属明确列出主机、内部配件、键鼠和连接器的顺序，不依赖物品注册表遍历顺序。

插入只移动本次新条目的位置，不移除或重新排列已有条目。父页与搜索页分别定位锚点；若其他模组已移除某一侧锚点，该侧追加到末尾，不因缺少可选附属而失败。已有相同组件的条目不重复添加，不覆盖其他模组加入的未知物品。
