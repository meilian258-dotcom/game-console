# 方块电玩：存档与串流可靠性修复测试版

适用版本：FC **0.31.0-alpha.54** / SFC **0.1.0-alpha.32**。环境：Minecraft 1.21.1、NeoForge 21.1.236、Java 21。日期：2026-09-17。

这是本轮测试候选的使用说明，不是稳定版或实机验收证明。最终构建结果、测试数量与文件哈希以交付包内的《验证结果.json》和 SHA-256 清单为准；本文不预填尚未完成的验证数据。

## 安装与范围

- `game_console-0.31.0-alpha.54.jar`：基础模组，包括 FC、小霸王、公共电视和同步组件；客户端与服务端均需更新。
- `game_console_sfc-0.1.0-alpha.32.jar`：SFC 家用附属，最低依赖 FC54；使用 SFC 时客户端与服务端均需安装。
- 正式 SFC 交付 JAR 沿用内嵌的原 SFC core9，不要额外重复安装相同 MOD ID 的旧核心。开发目录 `build/libs` 的薄包不是可直接交付的完整安装包。
- 只玩 FC/小霸王无需安装 SFC 附属。街机附属 0.1.1、GBA8 不属于本轮修改范围。

更新前正常退出游戏，安排停服并备份实例、世界和现有存档；将旧同 ID 模组移到实例外备份，再成套换入新版本。先在世界副本测试，不直接覆盖唯一正式存档。本轮没有自动安装、部署、发布或重启服务器。

FC 主协议仍为 39，家用媒体协议仍为 2，SFC 主协议仍为 7。未新增本轮线协议字段，但请两端统一使用 FC54/SFC32，以免修复行为不一致。

模组免费，不提供游戏 ROM、原厂 BIOS 或其下载链接；游戏文件由玩家在具备相应权利或许可的前提下自行准备。本轮不改变既有 ROM 库管理策略，也不删除用户文件。

## 本轮变化

### FC 管理员存档目录

修正管理员存档列表对同步模式和核心前缀的识别：识别本地输入同步、玩家音画串流、服务器托管，以及原 FC、Mapper19、光枪核心的现用个人存档命名空间。

此前部分玩家串流个人存档被目录过滤，并不代表磁盘上的存档文件已丢失。本轮修复列表识别，保留旧个人存档、旧三槽位与旧光枪个人键的兼容；不会自动迁移、合并或覆盖实际存档。未知、重复、错序前缀以及非法玩家 UUID/槽号不会被当成合法个人存档。管理员权限与原删除流程不变。

### SFC 串流断画面保护

适用于接收玩家音画串流或服务器托管音画的 SFC 控制端，不适用于正在本机运行核心的普通本地同步流程。

- 首次进入或合法媒体重置后，收到第一帧有效画面之前不允许盲控；首帧最长等待约 **60 秒**。
- 已经正常显示后，距最后一帧成功解码的视频约 **3 秒**仍无新画面，暂停输入并提示正在等待画面恢复。
- 自最后一帧有效视频起约 **15 秒**仍未恢复，按原离席流程退出本端控制，并给出超时提示；不是在 3 秒之后再额外等待 15 秒。
- 在超时前恢复画面时，需要先松开按键再继续操作，不重放断流期间的旧按键。
- 音频包、视频碎片或尚未完成解码的包不能充当有效视频心跳；超时后的迟到帧不会自行复活旧控制会话。

上述时间为本机单调时钟阈值，实际提示和退出执行受线程调度影响，不承诺毫秒级响应。该保护不会自动换主持、重新开机或恢复游戏进度；主持掉线仍按原规则安全停机。

### SFC 声音设备提示

本机音频输出失败时显示可见提示，不再只留下后台日志。提示会说明游戏仍在运行；检查系统输出设备后，正常关机并重新开机可以重试声音。声卡故障不等于模拟核心或画面已经停止，也不会因此自动重开游戏或更换输出设备。

### 存档提示按机型区分

调试螺丝刀的保存成功提示和页面底部不再对所有机型统一声称“存档仍在卡带菜单”：FC/小霸王保留原卡带存档说明；SFC 按当前同步模式说明本机恢复备份或独立服务器 SRAM。电视遥控器改为通用提示，以对应主机的存档能力为准。

### FC 光枪本地扳机查询

串流接收端没有模拟核心时，光枪视觉查询可读取本机已经授权并采样的扳机状态。仍要求当前连接、准确会话/代次、完整光枪绑定、唯一持枪、输入捕获和窗口焦点有效；不会读取另一个玩家的扳机，不会为动画启动新核心或发送额外输入包。

这不是新增“所有人都能看到他人光枪扣扳机”的网络同步协议。光枪命中、持枪手感和真实双端展示仍需实机验证。

## SFC 存档与恢复备份：两种能力不要混淆

### 本地输入同步 / 玩家音画串流

这两种模式仍仅提供运行核心玩家的本机恢复材料，不是服务器卡带存档，也不会在重新开机时自动恢复。纯串流接收端没有本地核心，不会凭空生成完整核心存档。

本轮本机备份防覆盖采用以下策略，实际实现与验证状态以本轮最终验证记录为准：

1. 每次创建 SFC 播放会话生成新的随机 UUID，写入独立目录：
   `piq-sfc-home/local-backups/<ROM_SHA256>/sessions/<会话UUID>/`。
2. 每次备份写为 `backup-<递增序号>-<随机后缀>.zip`，同一个 ZIP 包含 `state.bin`、`sram.bin` 和 `metadata.txt`，成组提交，避免状态与 SRAM 分别写入后混成不同进度。
3. 完成临时文件写入和强制刷盘后，使用原子移动提交。路径被文件占用、目录不安全、权限不足或不支持所需原子移动时拒绝新提交，不覆盖已有完整备份。
4. 仅在新备份成功提交后轮换本会话旧份，正常保留最近两份。若清理旧份失败，保留文件并记录警告；最多暂留三份，继续受阻则拒绝下一次新增，避免无限增长。新提交已经成功时，不因旧份清理失败而把它说成丢失。
5. 旧 `latest.state`、`latest.sram`、`latest.txt` 和其它会话目录均不改、不删。不同开局不再覆写同 ROM 的旧 `latest.*`。

不同会话之间暂不自动清理，历史备份会持续占用磁盘空间。请在正常关闭游戏后自行归档；在没有确认恢复可用前不要删除唯一副本。单份备份的状态上限为 128 MiB、SRAM 上限为 8 MiB，这些是安全上限，不代表每份都占满。

周期备份与正常退出时的备份仍是尽力执行。磁盘写入失败、进程崩溃或核心挂起可能丢失最近成功备份之后的进度。不要把目录存在、看到“备份中”或正常关闭窗口当成备份成功的证明；需要查看实际结果。此版本没有一键导入这些恢复包或自动续玩的功能，不能自行把 ZIP 改名为 `latest.state` 当作恢复操作。

### 服务端托管音画

`SERVER_MEDIA` 使用独立的服务器 SRAM 持久化，和上述玩家本机恢复备份是不同通道。它不是上述 ZIP 完整即时状态备份，不能自动把本机恢复包转成服务器进度，也不能把它理解为任意游戏位置的即时续玩。

### FC / 小霸王

仍沿用卡带存档策略和服务器最近确认快照。不同同步模式的存档不自动转换；异常停机可能丢失最后一次确认之后的操作。没有存档策略的游戏不会因此新增永久存档。

## 本轮没有证实修复的项目

- 用户曾反馈 FC 玩家串流开机崩溃，随后说明自行恢复。当前记录为**暂未复现，原因未确定**，不能将本轮改动称为该崩溃的已验证修复。如果再次出现，请保留崩溃报告、日志、模式、ROM 标识和发生步骤。
- 未实现 SFC 本机备份自动恢复、服务器卡带多槽位存档或跨模式进度迁移。
- 未新增 FC 光枪的他人扳机动画同步协议。
- 未修改电视/主机模型、贴图、WASM 核心或街机原生运行库；未因本轮备份改动清理用户旧存档。

## 建议人工验收

1. 先备份测试世界和存档；用 OP 检查 FC 不同同步模式、不同核心和三槽位的已有个人存档是否正确列出，未保存的条目不应凭空出现。
2. 两名玩家测试 SFC 玩家串流，再测试服务器托管。人为中断视频时确认约 3 秒暂停输入、约 15 秒退出；首帧未到时不能盲控，约 60 秒超时。
3. 在 15 秒前恢复视频：先前按住的方向不能自动继续，需要松开后重新操作。只发音频或无完整视频时不能一直保住盲控权限。
4. 在可恢复的测试音频环境中验证声卡不可用提示；确认画面与游戏是否继续，不要把没声音当成程序已退出。
5. 同一 ROM 连续开两局并触发备份：应出现两个会话目录；旧 `latest.*` 和上一局备份保持原样。当前会话正常只保留最近两份完整包。
6. 仅在独立临时测试目录模拟路径占位或写入失败，确认旧完整包不变且失败有提示/记录，不在唯一正式存档上试验权限或磁盘故障。
7. 分别打开 FC 与 SFC 调试页，切换三种同步模式，核对存档提示；SFC 本地/玩家串流不应声称能从卡带菜单自动续玩。
8. FC 光枪测试本地和串流接收场景：松键、失焦、开菜单、换手持、归还、断线重连后不得残留扣扳机状态。旁观者和其它光枪租约不能借用自己的本地扳机状态。

自动化检查不能替代 Minecraft 双端、实际音频设备、保护插件和磁盘故障条件的人工验收；本版仍按测试版交付。
