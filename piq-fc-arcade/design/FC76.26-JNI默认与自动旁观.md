# FC76.26 / GBA12 / 电脑11：JNI 默认与自动旁观

2026-09-29；Windows x64；Minecraft 1.21.1 / NeoForge 21.1 / Java 21。候选版本，非稳定发行。

## 改动范围

用户已实测 JNI 可用，要求全部默认 JNI。本轮把**已经接通的 JNI 入口**统一设为默认，不把尚未实现的后端通过改名伪装成完成。

| 入口 | 新默认 | 兼容与范围 |
| --- | --- | --- |
| FC 新放置家用机 | 管理终端“自动”时优先 JNI Netplay | 普通双数字手柄；光枪仍须选支持的原模式；旧机器与明确指定的默认模式不改 |
| FC JNI 房间参与/旁观 | Windows x64 自动允许本地启动 | 跟随房间协议，无需每位旁观者再手选；权限、内容、距离、核心身份检查保留 |
| FC / SFC / MD 私人模式 | 支持 JNI 的 provider 在 Windows x64 默认 JNI | 仍可在私人菜单显式选独立进程；重新打开菜单重新采用默认，不在运行中切换 |
| GBA 掌机 / 本人主持的单席机柜 | Windows x64 默认 JNI | 菜单或 `/gameconsole-gba-jni` 可切回本次连接的进程模式；重连恢复默认；服务器托管仍进程 |
| 电脑中的 PvZ | 未设置运行器时 Windows x64 默认 `jni-v1` | 保留本机已明确存下的 `process`；旧专用 `jni` 和未知值不自动升级；菜单可切换 |
| SFC / 街机 JNI Netplay、Flash、Java ME、其他旧公共模式 | 本轮不新增 | 各自运行器与网络方案不变；FBNeo 开发者 JNI profile 不等于街机已接入 |

JNI 是运行后端，不等同于同步模式。公共串流/本地同步不会仅因更改私人默认就变为 JNI Netplay。PvZ/GBA 的旁观仍接收主持端音画，不要求旁观者加载核心。老 PvZ 测试播放盒也不在本轮变更范围。

## 操作与风险

- 新 FC 默认入口在管理终端“新机默认 → 自动（FC JNI 优先）”。只影响新放置设备，旧 NBT 不回填；旧机可在同步菜单选择 JNI Netplay，双方需匹配主包。
- FC 本机默认允许参与/旁观 JNI 房间。`/gameconsole-jni-netplay off` 阻止本次连接的后续 JNI 启动；无参数命令显示状态或恢复确认。当前正在运行的游戏不切换，重新连接恢复默认。房间消息不能覆盖本机停用。
- 同 JVM 一个 JNI 核心，FC 选择优先操作/计算主持，其余可见 JNI 房间至多旁观一台，按距离及保留缓冲选择。先释放旧会话再尝试启动；若私人/GBA/PvZ 占槽，等待其退出，不强杀或强制卸载。
- JNI 故障可能使整个 Minecraft 崩溃；保留进程入口，但不在 JNI 启动失败时悄悄改用进程或另一套存档。非 Windows x64 不默认启动本轮 JNI。
- 原个人/卡带归属及 JNI 独立保存命名空间保留。FC JNI v2 与 RetroArch/普通存档、GBA JNI 与进程电池档、私人/PvZ JNI 与原档不互相导入覆盖。看不到旧进度时先检查是否换了后端，不删除原档。

## 配套安装

双方主包 FC `0.31.0-alpha.76.26`；使用 GBA 则双方 GBA `0.1.0-alpha.12`；使用电脑则双方电脑 `0.1.0-prototype.11`，PvZ 附属沿用 `prototype.11`。SFC 完整玩家包43、MD1沿用，不把 SFC 开发薄包或内部平台 JAR 装进 mods。同 ID 新旧包不能并存；先备份世界、配置与 game-console 数据，再正常停游戏/服务器换包。

安装端依据：主包有共同网络/方块实体与客户端显示，GBA 有 `GbaMod` 共同注册/网络与掌机客户端，电脑有 `ComputerMod` 共同注册/网络与程序客户端；并非仅凭依赖 side 推断。可选附属仍按已有版本指南使用，不表示全部附属已重构为 JNI。

验证明细在交付 `VERIFICATION.md`；MC 双玩家自动旁观、跨设备抢占/退出、旧世界以及长时运行未验证前不得标稳定。

## 开发接口

公共 `LibretroRuntimes.defaultBackend(adapted)` 仅供可信的、**已有真实适配**的客户端入口决定初值。Windows x64 且 adapted=true 才返回 JNI_TRIAL；不执行 DLL 探测，也不替服务器或网络协议选模式。`create(profile, owner, backend)` 和现有进程构造器仍显式、兼容；新附属不能只传 true 就宣称接通。

`JniClientPreference` 是客户端线程上的连接身份绑定停用策略；连接中房间更新不得 reset。PvZ 保留已有持久选择，读取设置失败不会因新的缺省值启用 JNI。核心、ABI、存档/网络身份未改变，无需分发新的 DLL。
