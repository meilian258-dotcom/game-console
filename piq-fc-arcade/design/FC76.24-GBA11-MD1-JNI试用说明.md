# FC JNI Netplay / GBA JNI / MD2 试用说明

2026-09-29，像素匠。适用 Minecraft 1.21.1、NeoForge 21.1、Java21。本地候选，不是稳定发行。当前执行 JNI 的玩家须为 Windows x64；服务器不因此要求 Windows。

## 安装组合

- 双方主包 `game_console-0.31.0-alpha.76.24.jar`。本版 home-sync-4 / netplay-5，不能与旧主包混连；原 RetroArch 默认路径保留。
- 使用 GBA 的双方更新 `game_console_gba-0.1.0-alpha.11.jar`；使用 MD 的双方新增 `game_console_md-0.1.0-alpha.1.jar`。
- 既有完整 SFC43、街机1.5.4、PvZ11、电脑10不变，本轮组合加载已核对；不代表给这些机型增加 JNI Netplay。内部 piq-retro-platform 不单装，SFC薄开发包不当玩家成品。
- 正常停止游戏后备份 mods/世界/game-console 存档，移走同组件旧 JAR 再放新版，不要重复装。ZIP、源码、说明不放 mods。

### 专服启动验证

FC76.24、GBA11、MD1 在 NeoForge21.1.248 测试服启动至 Done，日志列出的版本与安装组合一致。该结果只验证专服启动，不代表 Minecraft 真人手感或长时联机验收；客户端进服前仍须使用匹配组合。

## FC：JNI Netplay 的入口

1. OP 在空闲 FC 家用机的同步/网络设置页选择“FC JNI Netplay（试验 / 本机确认）”。它是新选项，不是旧“RetroArch Netplay”改名；本期仅NTSC普通双手柄，不支持这条路径的光枪、PAL时序或其他机型。
2. 每个操作/旁观客户端需确认本次连接的 JNI 风险。可用客户端命令 `/gameconsole-jni-netplay` 打开确认。确认仅本次连接有效，不能由服务器替玩家接受；未同意不会偷偷加载 DLL。
3. 按原卡带/个人槽和借用手柄流程开机、入席/旁观。仍有距离、租约、保护、资源权限和原始房间票据校验；JNI 不等于放宽权限。
4. 本机立即预测输入，收到权威操作后必要时恢复快照重演；有界12帧预测、状态摘要复核和晚加入种子。弱网超过窗口仍可能等待，不保证没有延迟或回滚。
5. 沿用已有个人/卡带/不保存归属，由已授权主持提交服务器；30秒检查点、网络页手动保存、正常停止最终提交。只有服务器确认才算提交成功。试验采用独立核心/profile命名空间，不读取或覆盖旧 RetroArch 进度。断网/崩溃只能保证最近确认版本。

固定 Mesen JNI Netplay r1 针对上游状态漏序列化的 `_isLagging` 补齐字段；只用于新试验通路，不替换旧核心，不把旧状态强转新格式。对应官方源码、补丁构建器、GPL在源码材料中。并非关闭CRC/忽略不同步。

## GBA：JNI 的入口

先执行 `/gameconsole-gba-jni`，阅读并接受本次连接风险，然后按原 GBA 掌机或本机主持街机流程启动。再次执行可关闭选择；重新连接默认进程。已经在运行的会话不会原地热切换。服务器托管仍走原进程，GBA不因此拥有Netplay。

固定原 mGBA DLL 不变；按原玩家/世界归属，在 `jni-trial-v1-mgba-e31759b/<ROM SHA>/sram.bin` 保存独立电池档。自动检查点和退出保存保留实际识别 SRAM/EEPROM长度；原进程档不覆盖，不自动迁移。当前不虚构未适配RTC/即时状态能力。

## MD2：新增附属的范围

用 AV 线把 MD2 主机与电视连接，插入 MD 卡带占槽物，空手借出1P手柄；手持它在主机6格内打开 `/gameconsole-private`，选择本机 `.md/.bin/.gen` 原始卡带文件。默认进程，私人菜单可本次确认 JNI。细节、键位、借还和存档见 [MD README](../../piq-md-home/README.md)。

首版是私人单人：空槽/插卡双状态、借出隐藏1P模型、实体卡带/手柄、公共私人输入/显示/音量、BlastEm实际音画/状态与SRAM保存。无公开双人、服务器目录、Netplay、CD、32X或SMD解交错；2P模型不是已开放操作席，物理卡带暂不承载跨玩家进度。AV连接可用，MD外接AV线实体绘制尚未做。模型公开分发许可待确认。

## 安全和回退

共享 JNI ABI1 在同一 Minecraft JVM 中同时只开一个原生核心，FC/GBA/MD/PvZ等竞争同一槽。另一个仍在关闭时需等待。JNI原生故障可能使整个MC崩溃；不强杀卡住的原生线程、不强制卸载DLL。测试先用世界副本。

回退：FC空闲时切回原RetroArch或串流；GBA关闭本次连接的JNI选择；MD重新打开私人页使用默认进程。不同后端档独立，回退不是自动进度转换。本轮不改街机退出/显示全局策略或其他机型联机默认值。

## 验证及限制

- FC完整check/jar：2558项，0失败/错误，9既有跳过；旧进程真实核心smoke通过。MD纯行为5项全过。
- 最终FC包：真实核心3个独立JVM，双人、晚加入旁观、断线重入、预测纠正、手动/最终保存及新JVM恢复通过；人工加入单向100ms延迟，状态摘要保持一致，无 `-Xcheck:jni` 警告。这不是Minecraft键盘到显示器延迟测量，不保证提速。
- 最终GBA：JNI真核心26断言；默认进程关闭/退出保存9场景354断言通过。MD原版进程及JNI各18断言，含音画/输入/SRAM写入、状态恢复、生产引擎退出重开后磁盘SRAM值保持。
- 最终七包在隔离NeoForge21.1.236专服启动至Done并正常stop保存退出，依赖/成品原件不变。并非连接玩家验收。测试超平坦配置的vanilla layers回退告警保留。
- MC真人菜单、MD模型/借还/保护插件、手感、长时弱网、多房间和客户端GPU兼容均待实测。

本次是范围明确的试用候选，不是稳定公开SDK；部分旧项目仍依赖历史基线成品做增量打包，附带源码不应宣传为全项目空仓库可复现。
