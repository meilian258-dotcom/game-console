# 方块电玩：玩家上传与服务端游戏库

适用：Minecraft 1.21.1 / NeoForge 21.1.236+，FC 0.31.0-alpha.55、SFC 0.1.0-alpha.33 成套测试版。
日期：2026-09-17。尚待真实游戏内人工验收，不是稳定版。

## 安装

服务器与每位玩家均安装本版 FC 主模组；需要 SFC 时双方再安装本版 SFC 合包。
先备份世界、配置和存档，完全退出游戏/正常停止服务器后移走旧 FC/SFC 同类 JAR，再放入新包。
SFC 合包已包含原 core9，不要同时安装旧的独立 SFC core/home 包。FC 内置原运行库，未增加新依赖。
街机附属 0.1.1、GBA8 未改动，本压缩包不重复提供。

## OP 设置

只允许 OP2 或服务器控制台运行。主命令 `/gameconsole content` 查看当前状态与用法。
FC、学习机与 SFC 家用卡带共用一套策略；不开放街机全局管理、旧独立核心管理或 GBA 上传。

```text
/gameconsole content rom true
/gameconsole content cover true
/gameconsole content access listed
/gameconsole content allow 玩家名
```

上例分别开启玩家 ROM/PNG 封面上传，并把在线玩家加入授权名单。`rom false`、`cover false` 分别关闭。
默认两个上传开关关闭，访问范围为 listed、授权名单为空，保持原先只有 OP 能使用工作台。

- `access all`：允许所有普通玩家访问卡带游戏库；上传仍由两个独立开关决定。
- `access listed`：只允许名单玩家访问。OP2 始终可管理。
- `allow <在线玩家>` / `deny <在线玩家>`：增减 UUID 名单，支持玩家选择器；不改变玩家的 OP 身份。
- `allowuuid <完整UUID>` / `denyuuid <完整UUID>`：调整离线玩家名单。
- `list`：查看授权 UUID，最多 1024 人。使用 all 时，移出名单不会禁止该玩家；需切回 listed。

配置保存在当前世界的 `serverconfig/game-console-content-server.toml`。
命令成功后持久保存、无需重启；配置写入失败会提示，不宣称成功。离线编辑配置前先正常停服。

## 玩家怎么使用

持一张完整 FC 或 SFC 卡带，右键自己有权操作的老式电脑。
有游戏库访问权限即可直接查看对应机型的服务器游戏列表，选择已有 ROM 写入手中的卡带，无需再次上传。
列表明确区分服务器已有文件与仅本地待上传文件。缺少上传权限时，对应按钮不可用并提示原因。
ROM 上传开、封面上传关时，只能上传 ROM；反之只允许上传 PNG 封面。
浏览玩家可以修改自己卡带的名称、选用已有 ROM 和清空/恢复已有封面；人数及 FC 全局存档策略仍仅 OP 可改。
距离、手中卡片身份、电脑权限、领地保护标准事件及原传输大小/并发/校验限制不变。

## 关闭和撤权

每个请求和服务端 tick 复验权限，关闭对应开关会取消尚未提交的上传，撤销访问会结束工作台编辑。
已经完整上传并 FINISH 提交后台存储的文件可能完成入库，但复验失权后不再写入卡带。
不删除已有 ROM/封面、不清空玩家卡带，不以关上传为由停止正在游玩的模拟器。
权限变化回执刷新按钮；也可以手动刷新/重开工作台。关闭再开启不是清除历史文件的操作。

本地输入同步中普通玩家的运行会话仍可自动下载 ROM。浏览游戏列表不等于新增“任意下载全部文件”入口；SFC 继续校验运行成员或有效 OP 编辑权限。
FC 原游玩下载接口本轮未重新收紧，不能把这套名单当成所有 ROM 字节访问的总防线。
本安装包不含游戏 ROM/BIOS；服主/玩家自行提供的文件可能保存在服务器并在游玩时传输给客户端。

## 电视闪烁修复（单独验收）

六款新电视（灰/红 CRT、两种桌面 LCD 和对应壁挂款）共用画面深度修复。
原动态画面与模型黑屏仅相距 0.00025 格，现改为 0.002 格，减少斜视时的深度竞争。
只调整共享显示面，模型/PNG、画面宽高/4:3、接口与按钮不改；FC、SFC、旁观和待机显示共用。
截图现象与此问题相符，但尚未用用户的光影实机复现，不能把几何测试当成现场已确认修复。
请在原光影下分别测试桌放/壁挂、近看/远看和左右移动视角；检查边框内嵌、关机黑屏、扫描线及光枪瞄准。

## 人工测试清单

1. 默认普通玩家打不开编辑，OP 可用。授权一名非 OP 后能看 FC/SFC 服务器目录，另一未授权玩家不能看。
2. 单独开关 ROM/封面上传：分别试合法文件、禁用按钮和修改过的客户端请求，不能绕过服务端校验。
3. 授权玩家能选现有 ROM 写卡，不能更改全局人数/存档；原 ROM 文件与其他卡带不受影响。
4. 上传中关闭开关或撤销名单，旧传输停止，不修改卡带；FINISH 后提交的文件可能留库，已有文件不删。
5. 重启后设置和 UUID 名单保留。all/listed 切换符合说明。
6. 两名普通玩家继续 FC/SFC 本地同步，缺缓存自动下载、现有串流/存档行为不变。

自动构建/测试和实际冻结 JAR 协议探针见压缩包中的验证结果；这些不代替 Minecraft 内双端、保护插件与真实上传实测。
