# FC61：卡带存档与加入设置

适用：Minecraft 1.21.1 / NeoForge 21.1.236，FC 0.31.0-alpha.61。2026-09-20 本地测试候选；不是稳定版，未安装、发布或重启游戏/服务器。

## 安装

先正常关机保存、退出游戏并备份世界。客户端和服务器同时换为包内 `game_console-0.31.0-alpha.61.jar`，同 MOD ID 只保留一份。双方都要更新：共同方块/物品、服务端卡带/存档权限与客户端控制界面及网络编码均有改动，FC/卡带/终端协议版本已升级，不能与 FC60 混用。

如果装了 Flash 播放盒，双方同时换为可选的 `game_console_flash_box-0.1.0-prototype.8.jar`；没装 Flash 不必添加。已有完整 runtime0.1.2 沿用。SFC36、Native0.1.1、GBA8 及对应运行库沿用，本包不重发；SFC 无新功能。没有包含 ROM、BIOS 或 SWF。

仅使用本交付目录的 JAR。源码 `build/libs` 中 FC61 是带两张未审核旧手柄草稿的编译中间件，不能安装；最终包从 FC60 冻结成品白名单更新类及中英文词条，保留模型、贴图、音效和三个 WASM 核心。

## 卡带怎么设置

在卡带工作台写入游戏后，点“存档方式”。有工作台访问权限的普通玩家也可修改所持卡带，不再要求 OP。游戏人数仍是管理员管理的游戏配置；存档方式不再修改整个服务器同名游戏的所有卡带。

| 方式 | 使用效果 |
| --- | --- |
| 不存档 | 每次重新开始，不保存也不恢复；切换方式不删除旧进度。 |
| 个人存档 | 卡带只记录模式。开机选自己的个人槽；换机器继续，换人则选那个人自己的槽。 |
| 卡带存档 | 进度绑定这张卡的唯一编号。换机器或把卡给别人，进度随卡走；已有进度时开机选择继续或重开。 |

成功保存的卡带显示 `【已保存进度】`。存档文件实际仍在服务器的世界存档目录，物品只记录卡带身份、模式和已保存标记，不把整份模拟器快照塞进物品。卡带模式固定使用一个进度位置；个人模式仍用个人槽。拆装卡带时编号和进度跟随电路板，不跟外壳走；用创造指令复制完整 NBT 会复制同一编号，不是新的独立卡带，同编号不允许同时开局覆盖。

正常关机并等保存完成后再取卡。卡带“从头开始”不会立刻抹掉旧文件，下一次成功保存才替换；删除具体存档仍需要确认。卡带转交、断服/关服/崩溃下最后快照的完整实机验证尚未完成，请先用世界副本试。

同一核心的公开本地同步、玩家串流和服务端托管共用卡带/个人存档标识；光枪、特殊核心仍隔离，不强行互读不兼容快照。私人模式仍是独立本机存档，不受本轮服务器存档更改影响。

### 旧进度

没有保存模式标记的旧卡，首次读取时把旧 ROM 设置固化到这张卡，随后不再跟随 ROM 全局配置。旧机器存档不会猜测归属并搬到某张卡，旧文件保留。旧公开个人档只在来源唯一、内容一致、目标不存在且没有活动会话时复制到统一位置；冲突不合并、不覆盖源文件，需要管理员核对。请勿把“更新后看到空槽”当成旧文件已删除。

## OP 个人存档清理

管理终端 → 个人存档：填写玩家闲置天数，`0` 为关闭（默认）。范围 0～3650 天，只统计实际游玩，不依据文件重命名时间。启用后周期检查；正在玩的玩家受保护，没有历史记录的玩家从首次检查起获得完整宽限期。

只清理个人存档；卡带存档、旧机器档和无法识别归属的档不会自动清理。符合条件的文件移入同存档目录的 `deleted-by-cartridge-manager` 回收目录，单次最多64份。回收文件仍占磁盘，不是安全擦除；如需恢复请先停机备份并核对身份，不要直接覆盖正在使用的存档。活动记录或磁盘读取失败时保守停止清理并记录日志。

## 2P 与操作提示

支持双人的 FC 会话开局只问一次“允许 2P / 不允许 2P”。允许后另一人可直接领取手柄/加入空位；不允许则只提示来加入的人，不给1P重复弹申请。仍检查游戏人数、空位、距离、连接身份和交互保护，不把单人 ROM 变成双人游戏。家用 FC 和 FC 街机都走此规则，其他街机平台的批准机制不变。

家用 FC 启动后显示 N 锁定/解除人物移动、F7 打开按键设置；改过绑定则显示实际键位。

封面页面固定显示：PNG，建议512×256（2:1），输入不超过2048×2048、8MiB。非2:1图片居中裁切，透明区域补白。

## 电视开机动画

开关机转场改用客户端单调时钟，不再使用世界刻数加游戏插值。服务器只同步电源状态；重复状态包不重启动画，重进区块不重播。动画时长仍约开机0.7秒/关机0.35秒。这只改电视转场，不代表游戏音画串流或服务器卡顿已经修好；多人服务器的实际流畅度待测试。

## 验证边界

最终数量以包内 `验证结果.json` 和 `outputs/fc61/delivery.json` 为准。自动化覆盖卡带拆装身份、保存模式协议、回收范围/闲置宽限、旧个人档复制冲突、2P权限路径和本地动画时间；部分是源码接线检查，不是Minecraft世界仿真。

FC 全量回归含8项既有 Windows 权限环境跳过。SFC36 原源码/原依赖构建回归且冻结成品字节不变，不宣称它与 FC61 已经双端实测。Flash8 与7自身29类和27项runtime文件不变，最终核对FC公开API及2个Mixin目标；签名兼容不代表Minecraft实机兼容。

建议实测顺序：普通玩家制作两张同ROM不同模式的卡 → 同卡换机器/转交 → 个人档换玩家 → 卡带继续/重开/正常保存 → 允许与拒绝2P各测一次 → 两人服务器看电视开关机 → OP终端清理开关。不得在正式世界加速系统时钟试清档。航空学、光影、异常断线以及长时间多人使用仍待验收。
