# 公共旁观管理与 Iris 屏幕兼容

维护：像素匠，2026-10-03。FC76.37 本地测试候选；不是已发布或已实机验收声明。

## 本轮范围

接续 FC76.36 / SFC44 / MD12 第一批多屏旁观，源码基线 `db1a99b`。范围为旁观资源管理和 Iris 屏幕兼容；不新增“一人主持多台机器”功能，也不新增限制改变已有机器行为。Iris 开启光影后屏幕不可见的报告未包含具体光影包及版本，实际兼容性仍需验证。

| 编号 | 要解决的问题 | 实现与验收范围 | 状态 |
| --- | --- | --- | --- |
| R01 | 满槽时知道哪些旁观在占资源，并能主动释放 | 复用公共网络诊断入口；逐源列出调用方式、准备/运行/关闭与真实资源占用，不改变四槽上限 | 代码、单元通过；菜单实测待验 |
| R02 | 暂停一个屏幕后不自动重新订阅，能恢复 | 精确来源、连接代次与有界偏好；关闭本屏不关机器、不停其他屏、不改输入/保存权限 | 行为/协议通过；MC 网络交互待验 |
| R03 | 旁观转操作、断线重连与重复启停 | 当前提供手动暂停、等释放、重试；自动等待同源释放再接管未做，图形场景待验 | 20 轮探针通过；自动等待接管未实现 |
| R04 | Iris 开光影街机屏幕不可见 | 对比共享街机/电视材质与 Iris 官方渲染拦截；横竖屏、普通/Iris、主持/旁观分别验 | 源码兼容补丁通过测试；具体光影实测待验 |

不做一人多主持、自动主持交接、低帧率视频预览、Opus、提高 JNI 并发上限；不替换核心、不迁移存档、不改家用开局/2P 授权，Flash/PvZ 开发验证机型继续暂缓。本轮不是新附属或整机补齐，既有附属差距仍见[全组件总览](全组件运行流程与复用接口总览.md)。

## 流程与公共边界

内容、选档、独立 2P 确认、主持/控制席、保存归属与正常关机保持原合同。旁观仍是只读 JNI Netplay 副本（或机型原有 MEDIA 单源路径），不是操作席，不写主持进度。

设备设置的网络入口 → 公共网络诊断 → 旁观管理 → 查看来源和实际调用方式 → 暂停指定旁观 → 等取消任务/原生实例真实终止 → 手动恢复自动旁观。关闭管理窗口本身不退出会话。满槽时不强制关掉无关源来掩盖容量不足。

本机暂停偏好不是服务器全服配置，不让客户端越过距离、内容、只读票据、人数或容量授权；断线/换服清理本连接偏好，未完成的原生关闭仍计入预算。

### 旁观管理怎么用

普通玩家可输入 `/fc-debug` → **网络** → **旁观管理**；已有家用设备设置的“网络”和街机的“托管帧率 / 网络”也进入同一个公共页面。不新增默认快捷键，也不要求为管理本机旁观取得管理员权限；服务器托管设置的原权限不变。

管理页按来源列出本机公共 Watch 的准备、同步、播放、关闭和暂停状态，可翻页查看。行内显示提供组件与坐标，悬停可看维度、来源及主持代次。这里只列已经接纳或暂停的本机旁观，不是全服机器选择器，不把正在操作的游戏列成可关闭的旁观。

| 显示 | 实际含义 |
| --- | --- |
| 音画串流旁观 | 沿原有 MEDIA 接收路径；不凭设备闲置配置推测主持端的具体运行方式。 |
| Netplay（核心待确认） | 尚在排队或准备内容，不能当作 JNI 核心已启动或已同步。 |
| JNI Netplay / 独立进程 Netplay | 按已经取得的运行配置区分；旧独立进程和 MEDIA 仍保留单源限制，不自动混入 JNI 多屏。 |
| 关闭中、占 JNI 槽 | 已请求取消或关闭，但资源可能仍在释放。只有准备任务真正返回、运行器终止且不再持有原生槽，关闭记录才消失；手动暂停记录可继续保留。 |
| 已暂停 / 等待恢复确认 | 本机不会为这一来源重建旁观。等待恢复确认时仍保持暂停；不是已恢复播放。 |

暂停绑定**本次连接 + provider + source + hostLease**，发送请求还绑定原 watch 租约与修订号；本机按钮也检查连接代次和精确行身份。它只暂停这一局，不是永久屏蔽某坐标：机器重开换主持代次、断线或换服后会重新按正常规则发现。每个连接最多保留 **64 条**暂停记录，达到上限时明确提示，不能挤掉旧记录。服务器只依据该玩家已有的真实旁观关系新增暂停项，并过滤后续自动订阅，不能拿原先 40 tick 的 Release 冷却代替暂停。

点击“恢复”或“全部恢复自动旁观”后，请等服务器确认。全部恢复使用有界顺序队列，单次只保留一个在途请求，发送至少间隔 5 tick；**精确来源、动作及序列号的成功 ACK 到达后，才移除对应暂停记录**。发送失败、确认超时或明确拒绝时保留暂停行及恢复按钮，可手动重试；旧 ACK 不能覆盖更新的选择。恢复只撤销本人的暂停偏好，仍须重新满足距离、内容授权、只读票据及可用额度，不保证立即出现画面。

同一来源收到新租约时，旧关闭记录可能暂时与新暂停行一起显示。**旧连接或已被新租约替换的关闭行只读**，不能用旧按钮影响新会话；恢复应使用当前暂停行。关闭管理窗口本身不退出游戏、不关机、不借还手柄，也不修改存档。

### 满槽后从旁观转为操作

本版的操作顺序是：**手动暂停对应旁观 → 等该路实际释放 → 确认可用槽位 → 重新领取手柄或重试原操作**。如其他自动旁观又占用空位，可继续暂停不需要的旁观；不强关别人的主机或自己的既有操作会话。准备中取消和关闭中的占用不会因画面消失就假报释放。

自动“等待同源关闭完成，再继续操作启动”的异步接管尚未实现。现有 `controlStarting(wire/descriptor)` 只发起同源异步关闭，FC/SFC/MD 等调用方随后可继续准备操作核心；在四槽已满、旧旁观尚未退出时，新核心仍可能被容量门禁拒绝。因此不能把本轮的管理页称为无缝接管、自动腾槽或新增一人多主持能力。

## 调研与实现依据

沿用现有 `WatchClient`、`WatchService`、`WatchNetwork`、`NetplayProcess`、`NetworkDiagnosticsScreen` 和 `DeviceScreen`。原网络诊断按优先级汇总一条会话并提示其他会话数量，不列完整关闭尾巴，不能代替逐路管理页。新增 `WatchManagementScreen` 展示公共快照，`WatchManagementState` 管理本机精确句柄与确认队列，`WatchPreferenceState` 保存有界的连接内暂停偏好；公共 Watch 协议由 `watch-3` 升为 **`watch-4`**，增加逐源偏好请求与回复。连接、来源和序列检查不替代服务器原有旁观授权；客户端与服务器须匹配本轮协议。沿用固定核心/运行器，不新增库或另造附属旁观框架。

Iris 调研固定于官方 1.21.1 分支提交 `eb7afb99f747cc8ed5ee4072119539035d33cefd`（阅读日期 2026-10-03）。[未知着色器处理](https://github.com/IrisShaders/Iris/blob/eb7afb99f747cc8ed5ee4072119539035d33cefd/common/src/main/java/net/irisshaders/iris/mixin/MixinShaderInstance.java#L92)会在相应世界渲染阶段禁用未识别 shader 的颜色／深度写入；这是公共 `ScreenRenderMaterial` 的源码兼容缺口，尚未实际复现用户光影包。

街机 `CabinetVideoDisplay`、FC `ArcadeBlockScreenRenderer`、MD/SFC 电视 `HomeVideoDisplay` 都经公共材质。仅当 Iris 公开 API 报告正在使用光影包时，选择其[可识别的原版 eyes 全亮 shader](https://github.com/IrisShaders/Iris/blob/eb7afb99f747cc8ed5ee4072119539035d33cefd/common/src/main/java/net/irisshaders/iris/mixin/MixinGameRenderer.java#L285)，仍使用自己的不透明、深度测试材质，不使用原版 eyes 的加法混合。未安装 Iris 或光影关闭沿用原 shader；已安装但 API 异常时一次警告后走已知原版材质回退。可选反射只发现一次，不增加 Iris 硬依赖，不修改用户全局选项。

不改绘制阶段、UV／旋转、模型／纹理／核心。光影包仍可影响色调、雾与泛光，具体包及版本未提供；这些效果、实际画面和遮挡仍需 MC 图形验收，不能由探测／材质契约测试代替。

## 验收及交付

分别记录单元/协议、真实核心、隔离专服、MC 图形多客户端和长期性能。合成 ROM 的帧推进、CRC 与资源释放不能证明 Iris 光影画面正确，也不证明全部机型/商业 ROM 通过。

验收至少包含：暂停 A 后 B 保持、超过原冷却仍不重订、恢复后只读重订、64 条上限及全部恢复完整排队、发送失败/超时/拒绝后恢复入口仍在、迟到 ACK 和旧连接消息无效、旧关闭行不能恢复新租约、准备中暂停、关闭中不假报空槽、四槽满后手动释放再加入、断线/换服与反复重连；光影关闭/开启/切换、三种柜形、横竖屏、近远/墙体遮挡与电视分别留证。

### 本轮验证结果

- Java 21 / MC 1.21.1 / NeoForge 21.1：主包 `check jar` 成功；SFC、MD、Native 显式指定新主包执行 `test`，不重建或冒充更新六个附属。FC2799、SFC500、MD102、Native119，共3520项，零失败/错误、9项既有跳过。首轮仅新界面未纳入完整界面清单而失败，补入该页及对应背景/控件检查后全量重跑通过。
- 打包桥验证397475项／544帧，双进程30帧恢复一致；最终冻结主包独立 JVM `-Xcheck:jni` 20轮，40次旁观重连、20次启动取消，共807检查、无JNI警告，四槽最终归还。合成FC ROM，不等同于真实多机型MC业务验证。
- 20轮耗时264.594秒。测量窗口263.767秒，平均约0.79逻辑核等效占用、堆峰613.20MiB、结束318.55MiB，39次GC；这是含探针和其他本机任务负载的短时观测，不是FPS/延迟验收，不是存活堆或原生内存测量，不能据此宣称无泄漏或性能提升。
- 最终7个JAR／8个mod ID／2668个class无重复；主包365项原生、模型、贴图及许可等受保护资源逐字节不变。19.09秒隔离专服启动到Done、正常stop、退出0；没有玩家进入，不是专服多人游戏实测。
- 未完成验收：实际旁观管理界面、MC多客户端和满槽转操作；真实混合机型/弱网/长时；具体Iris包的开关切换、横竖屏、电视及墙体遮挡。仍为候选，不标稳定。

探针、协议和材质测试各自分层，互不代替。

### 成品与安装范围

本轮仅新建 `game-console-0.31.0-alpha.76.37.jar`，SHA-256：`bf277c81675674eeb8f786b0cdbb312ed652b789ec3795fe6de45eb08dd69202`。该文件身份用于识别历史测试候选，不代表稳定发行。

客户端和服务端须配套升级主包76.37（`watch-4`）。退出游戏/停服后按服主授权备份同ID旧包再替换，不并放两份主包；继续使用完整SFC44（内含core9）、MD12、街机1.5.5、GBA14、电脑11、PvZ11六个原JAR，保持原SHA、前置及许可源码配套；不要额外安装内部平台、SFC薄包或独立core9。MD对应源码ZIP仍沿用[第一批指南](公共JNI多屏旁观第一批-20261003.md)中的固定配套，未重编核心。

Iris只是可选客户端光影兼容，不要求无光影用户安装，也不安装到专服。
