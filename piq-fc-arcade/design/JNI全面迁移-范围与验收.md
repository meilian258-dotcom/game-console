# JNI 全面迁移：确认范围与验收

2026-09-29，工作台 GC-110，维护者：像素匠 / Codex root。源码基线 `075e70c91bb1bb8ce8a829e73c18e644adcb6c6d`（FC76.26/GBA12/电脑11）。这是用户确认的制作要求和待办，不是新版本发行或完成证明。

## 1. 最新确认

用户明确限定：**现有 FC、SFC、GBA、街机、PvZ、世嘉 MD 全面接入公共 JNI；光枪必须适配；以后新增模拟器附属也以 JNI 为默认。** Flash 和 Java ME 不在本次迁移范围。

这替代了上一轮“只将已接入入口的默认值改成 JNI”的制作范围，但不抹去 [FC76.26 指南](FC76.26-JNI默认与自动旁观.md) 对已交付版本的实际限制。不能通过改菜单文案、默认布尔值或把旧进程包装成 JNI 名称来宣称迁移完成。

本轮按每个系统**已有的模式**迁移，包括适用的私人、公共运行、串流计算端、本地同步、Netplay、服务器托管、旁观与保存。没有的功能不因改 JNI 自动生成：例如 MD 公共联机、GBA 原生连接线联机，不在这次后端替换中擅自宣称新增。

## 3. 光枪专门验收

- 瞄准正确映射到游戏有效画面，黑边/缩放/屏幕旋转不偏移；FC 坐标与核心约定一致。
- 扳机按下/释放、快速射击、屏幕外射击/适用的装弹行为正确；失焦、退出、断线后释放输入，不粘枪。
- 普通手柄与光枪端口正确共存，切换时不残留旧设备状态。
- 本机、已有公共模式和 JNI Netplay 分别测试；联机输入须进入同步/回滚历史，不能只在本机画出准星。
- 保留服务端操作席、租约、距离及光枪权威校验；旁观者不能开枪。晚加入、转操作、退席、重连不复用旧输入。
- 用真实核心与有权使用的游戏验证命中、画面和保存恢复；模拟输入测试不能代替实际核心/MC 验收。不把 FC 光枪通过推广为 SFC/MD/所有街机光枪自动支持。

## 4. 公共设计与兼容底线

1. 共用 `LibretroRuntime` / `LibretroRuntimes` / JNI 桥，附属提供固定核心来源、SHA、许可、内容/固件规则、端口及保存能力；不重复打包公共类或每附属另造 DLL。
2. 正常玩家入口目标为默认 JNI，不再让每个旁观玩家手动同意/选择。失败须说明原因，不在运行中静默换核心或保存格式。旧代码及历史成品不是本轮可直接删除的玩家数据。
3. JNI 调用方式与进程隔离、串流/同步模式是不同维度。多实例方案需明确原生全局状态、回调线程、资源预算与挂死处理，不能仅取消 `ACTIVE` 锁。
4. 平台/架构逐项核对：现有桥为 Windows x64，服务端安装模组不意味着 Linux 能加载 Windows DLL。实际支持平台的托管单独验证；不支持的平台明确诊断，不悄悄继续旧后端却显示 JNI。
5. 保持现行距离、关机、权限、保护及全局配置合同。新全服运行预算/策略必须能从管理终端配置；本地路径、键位和音量不变成全服字段。
6. 旧协议、新协议及核心/选项/内容/保存身份明确区分。默认切换不等于旧即时状态可恢复；不重用未经验证的旧状态格式，不删除原档，不用空档覆盖好档。

## 5. 开发及验收顺序

先解决公共多实例和输入/生命周期边界，再迁移各组件运行工厂及已有模式；随后接齐通用同步/Netplay及各核心能力，最后统一默认与界面、回归保存和旁观。每项回填 J01～J11，不以完成最后一个组件代替整批完成。

测试分层：纯契约/单元 → 隔离 JVM 的实际软件核心和 PvZ 硬件核心 → 最终 JAR 的 MC 客户端/专服 → 多设备、多席/光枪、晚加入、远近返回、旧世界/旧档 → 弱网与长时资源。详见 [制作验收清单](功能制作验收清单.md)。JNI 本身不构成性能改善证据。
