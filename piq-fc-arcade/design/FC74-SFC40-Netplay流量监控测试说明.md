# FC74 / SFC40：Netplay 流量监控测试候选

适用：Minecraft 1.21.1、NeoForge 21.1.236、Java 21；内置 Netplay 核心运行仍需 Windows x64。2026-09-25。

## 配套安装

仅提供本地测试文件，未安装到用户实例、部署服务器或发布。退出游戏后，在测试世界副本中替换主包为 `game_console-0.31.0-alpha.74.jar`；所有参与测试的客户端和服务器使用同一组合。SFC 使用完整 `game_console_sfc-0.1.0-alpha.40.jar`，不能把源码构建的薄包与旧核心重复安装。街机继续用原字节 `game_console_arcade-0.1.3.jar`。

已有 PvZ 时须同时替换为 `game_console_pvz-0.1.0-prototype.6.jar`：旧 prototype.5 上限拒绝 FC74。PvZ6 仅更新元数据兼容范围，支持 FC70～74，不包含上游新优化 DLL，不增加 PvZ 联机。不用 PvZ 就不安装可选目录中的文件。

将被替换的旧 JAR 移到 mods 目录外保留；不要删除世界、游戏文件、运行库或存档。无需额外安装 RetroArch。本轮没有 ROM、BIOS 或 main.pak。

## 监控改动

- FC、SFC、共享街机按照实际已获准会话显示 `RetroArch Netplay`；原本地输入同步仍使用原名称，Netplay 原生旁观单独显示。
- 统计分为 Netplay、音画、游戏/资源、其他/旧同步，每类显示上传/下载速率及上传加下载累计。Netplay 包括按键、协议控制和核心状态同步，不把它误称为零流量；不解析或记录原生传输内容。
- ROM、封面及资源目录相关传输归游戏/资源；旧同步快照及管理消息归其他/旧同步。统计覆盖本机这个服务器连接的所有已埋点会话，不仅是标题选中的那台设备。
- `重新计数` 只清本机测量累计和速率，不关闭游戏、不清档、不改变服务器统计。断开/换服务器清零；隐藏监控或换维度不清零。
- 原生双向数据仅在实际交给 MC 连接发送、或成功解码且连接仍活动时计数；排队后被丢弃的数据不计发送。单向通道维持成功编码/解码计数。方向按本机视角，原生本地进程 IPC 不计。单人内存连接不计网络。
- 数字是压缩前模组载荷，不是网卡流量或运营商计费量，不含原版、其他 MOD、TCP/MC 包头以及旧 SFC core9 独立协议；1 KiB=1024 B、1 MiB=1024 KiB。服务端 `/gameconsole traffic` 增加 Netplay 分组，仍仅 OP2 可用。

## 建议验收

1. 在服务器与所有测试客户端更新整套版本，先确认设备设置勾选 `RetroArch Netplay（实验）`，不是旧本地同步。
2. 开机，等加入、游戏下载和初始状态同步完成，再打开“托管帧率 / 网络 → 流量监控”，点 `重新计数`。
3. 分别测仅 1P、加入 2P、加入旁观、旁观离开，每阶段清零并正常游玩 1～3 分钟；截图保留四类速率、累计及实际人数。另有电视/设备运行也会合并计入。
4. 缺缓存时“游戏/资源”应增加；已有缓存正常游玩不应持续下载整个游戏。Netplay 会有非零数据。若“音画”持续较高，确认是否有音画模式的设备/旁观；若“Netplay”持续较高，再查状态重同步而不是把它当作视频流。
5. FC74 沿用 FC73 的 SFC/街机原生旁观接入。仍需实际多人验证音画、角色切换及流量变化；本轮不宣称已解决 FBNeo 全状态 CRC 差异，未通过关闭校验掩盖流量问题。

构建及逐字节核验以交付目录 `VERIFICATION.md` 和 `SHA256SUMS.txt` 为准；自动测试不能替代真实 Minecraft 多客户端验收，不标稳定版。
