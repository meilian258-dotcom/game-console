# 内容库收尾、旧核心退役与公共接口

适用：Minecraft 1.21.1 / Java 21；NeoForge 最低支持仍为 21.1.229、默认编译 21.1.236。2026-10-04，像素匠与协作代理。本轮内容传输、大 ROM JNI、旧 SFC 目录收尾及 BlastEm 退役已形成测试候选；不是全部内容库业务或稳定 SDK 已完成，也不代表已安装或发布。

## 1. 本轮范围

用户要求先完成内容库收尾、清理全模组的 BlastEm 旧核心，并检查还有哪些逻辑适合公共接口。家用机不再补“其他玩家可见的按钮动画”；本人第一/F5 动画、持握与线材保留，既有 MD 远端动画不删除，街机动画要求不变。

| 项目 | 已查明的问题 | 本轮处理与边界 |
| --- | --- | --- |
| 街机内容包 | 清单可含一个游戏与四个 BIOS，但分片传输器仍最多三文件 | 将实际传输与清单上限对齐；不开放任意服务器路径或任意 ZIP 上传 |
| 大 ROM | 本机侍魂五约 79.31 MiB；旧传输和 JNI byte[] 加载有 64 MiB 门槛及多份复制 | 通过有界文件内容包接入 JNI；旧小文件接口保留，非 JNI 旧进程不假称支持大文件 |
| 旧 SFC 柜 | 仍注册可用，服务端正式 ROM 放在根目录 `sfc-roms` | 改为 `game-console/piq-sfc-arcade/roms`，保持实例级权限语义；旧源校验复制、保留原件，准备放后台 |
| BlastEm | 旧私人选择、profile、构建检查及打包仍有活动入口 | 新包拒绝旧选择且不携带旧 DLL；保留历史核心文件、许可、旧档和历史 JAR，不转换保存格式 |

不改 ROM 内容，不下载 BIOS，不移动或删除玩家保存，不更新核心 SHA，不调整联机席位授权。Iris 透明、此前闪退、MD 同步 RESET 和全部 SFC 开局迁移不属于本轮；Flash/PvZ 继续作为暂缓的开发验证机型，一人主持多台不推进。

## 2. 内容与目录合同

沿用[服务端目录与 BIOS 说明](服务端内容目录与街机BIOS-20261003.md)：服务器 `game-console/` 是共同入口，但实例级库、世界授权和私人缓存不是同一件事。统一可查找的位置，不合并世界权限，也不把客户端缓存当正式服务器库存。

文件内容包必须绑定本次认可的名称、大小和 SHA；传入路径不是信任凭证。读取及暂存拒绝链接和文件变化，取消／失败只清本租约的临时内容；大小、总量、数量和并发限制分别检查。禁止仅提高数字后让每位旁观者额外复制多份大 ROM 到堆内存。

本批额度分层：街机主游戏 ZIP 最多96 MiB，最多五件合计128 MiB；公共对象库仍2 GiB/768对象、索引1024项。传输仍24 KiB分片、有界并发。公共存储辅助文件最多64 MiB，但 FBNeo JNI 单 BIOS 仍最多16 MiB，不能把存储额度当运行支持。旧 MAME/进程路径仍最多64 MiB，超过时明确说明应使用已支持的 FBNeo JNI Netplay；不静默换核心。

真实大 ROM 验证发现公共 JNI 桥也存在64 MiB硬限制，因此桥的 full-path 接口一并改为96 MiB，非 full-path 仍64 MiB。这不是更换模拟器核心；桥 ABI 仍2、固定构建输入更新，新旧 DLL 各自保留。Java 用64 KiB缓冲流式校验、暂存；原生端为兼容 extended game-info 仍保留有界内容副本，核心本身也占用原生内存。低 Java 堆测试不能解释为整进程只占256 MiB，不能承诺大 ROM 多旁观零额外内存。

迁移只复制已校验内容，冲突不覆盖，失败明确报告；旧源保留。旧 SFC 的客户端本地 `sfc-roms` 与服务器新正式目录分别说明；服务端已有游戏不应因为客户端未缓存而无法选择。

## 3. 已接入的公共接口与后续计划

| 优先级／状态 | 可复用的职责 | 真实调用方与最小边界 |
| --- | --- | --- |
| 本轮接入 | 有界、可校验的文件内容包 `LibretroContentFiles` | 街机 JNI 控制者／旁观者复用公共运行器；旧 byte[] 小内容 API 不删除，保存身份和核心 SHA 不变；扩展内容额度后 `cabinet-game` 升为 7，两端配套更新 |
| 本轮接入 | 纯内容路径计算 `ServerContentPaths` | SFC 家用世界 scope 与旧 SFC 实例库使用同一基础路径规则；函数不做 IO、不代替授权，scope 不改变 |
| 后续优先 | 内容展示元数据与扫描结果 | MD/GBA 的 ContentCardNames/Catalog、FC 的名称 properties、SFC 的 SfcRomStore 仍各有逻辑。公共服务区分物理文件名、hash、库名和卡片名；SFC 上传名持久化仍需单独接入 |
| 后续优先 | 内容安全文件 IO | ContentCardStore/Names 依赖街机对象库的安全检查，SFC 另有重复。可下沉目录／文件／变化校验原语，不统一各库的删除权限和配额 |
| 复用现有，不新造 | 开局协调与持久保存 | FC/MD 已接 HomeLaunchServer 与公共卡带保存；后续迁 SFC 调用方。SRAM／快照、归属和兼容身份由适配器保持，不能强改全部磁盘格式 |
| 后续分批 | 类型化能力与状态快照 | HomeSystems.ServerHooks 与 CabinetBackends 的模式、忙碌、人数和禁用理由供设置页／诊断共同使用；声明不能替代后端实现，须跨家用／街机回归 |

以上是内部复用接口，不等于已发布稳定 SDK。需要升级主模组的公共合同必须明确最低主包版本，并验证既有附属；新增机器优先填写适配声明，不复制主包服务。新 Libretro 机型仍按[通用规范](机器制作与交互标准.md)阅读官方文档和核心资料。

## 5. 安装与仍待验证的范围

客户端和服务端应配套升级主包与本轮所用附属，尤其 `cabinet-game-7` 不与旧主包协议混搭；SFC47及街机1.5.7最低要求FC76.40。先正常关机等保存完成，退出实例并备份世界、game-console内容和保存，再替换对应旧JAR；同ID不能并存，SFC安装完整47、不另装内部core或薄包。JNI运行端仍以Windows x64为本轮验证范围，不因此宣称Linux支持。

正式内容位于服务器实例的 `game-console/`；自动复制旧SFC内容只在实际升级使用时执行，本次没有进入用户服务器做迁移。旧BlastEm保存不自动转GX；旧数据和对应历史环境保留用于单独恢复，不把它们交给新核心试读。

仍待Minecraft图形客户端、真人多人上传／开局／旁观、现有世界升级和弱网长时验收。SFC原上传名称持久化、公共目录元数据及完整HomeLaunch适配另排；Iris透明、此前AppHang和MD同步RESET未在本轮修复。Flash/PvZ暂缓，一人主持多台不推进。

本轮仅本地候选及管理台资料同步，不自动上传GitHub、不代装客户端／服务器、不发布游戏版本、不发群通知；保留人工稳定标记和历史记录。
