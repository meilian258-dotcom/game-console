# Server-hosted core adapters — FC39 development

Author: Codex / server_core39, 2026-09-14. Local development only; no installation, publishing, user ROM execution, server start or runtime binary changes.

## Integration contract

`cn.piq.fcarcade.server.hosted.ServerCoreRegistry` is a headless registry, not a permission/enable switch. The room authority must enforce enabled modes, backend availability, server-wide budgets, ROM ownership/sharing policy and slot permissions before calling `open` on a starter thread.

- `ServerCoreContext(gameRoot, saveRoot, ownerId, roomId)` defaults to legacy NES. The five-argument form accepts `NesCoreVariant` for explicit ZAPPER_V1 selection. A sixth optional `NesManagedState` delegates snapshot persistence to the FC home's existing permission owner. Four/five-argument compatibility is retained. All paths are server-owned captured values, never network paths.
- `roomId` is the **stable device UUID**, not an ephemeral session token; `saveRoot` should already be specific to the server world.
- `ServerCoreFactory.maxPlayers()`, `maxConcurrentSessions()`, `unavailableReason(context)`, `open(context, rom)`.
- `ServerCoreHandle` extends the existing common `CabinetEmulator`; `isTerminated()` is distinct from close requested / not ready. `reset()` and `offerZapper(packed)` are optional and throw when unsupported. Check `supportsReset()` / `supportsZapper()` first.
- `ServerCoreRegistry.find`, `backends`, `open`, `activeCount([backend])`, `closeAll`. Registration never loads native code, starts a process or enables hosting. Adapter ceiling is 32 WASM sessions and one Native / one GBA; administrator budgets must be lower as appropriate.
- Native/GBA `unavailableReason` reports only static installation/platform conditions. A temporarily busy process is rejected at open/admission, not used to silently change a device's configured/default synchronization mode.
- Capacity reservations include in-progress openings and retain closed handles until their exact owner/process has terminated. A failed starter releases its reservation. Root room management still owns global admission, cancellation, last-participant policy, input authentication and delivery.

## Platform and persistence matrix

| Core | Supported bundled runtime | Inputs | Reset | Persistence |
| --- | --- | --- | --- | --- |
| FC legacy | Windows / Linux x64 Wasmtime | two pads | yes | bounded full transient state |
| FC ZAPPER_V1 | Windows / Linux x64 Wasmtime | pads plus separately declared light gun | yes | separate module-specific full state namespace |
| SFC | Windows / Linux x64 Wasmtime | two pads | yes | SRAM, not full in-progress state |
| Native MAME media | Windows x64 | up to four ports (game-dependent) | no | no persistence in this bridge |
| GBA | Windows x64 | one pad | no | existing bounded SRAM store |

This is an implementation capability declaration, not an actual dedicated-server/multiplayer/platform performance acceptance result. Native/GBA retain their original global ACTIVE guards; integrated-server client sessions contend with the same limit. Only an instance-specific termination observation was added to NativeProcessSession; ownership, launching, input and shutdown behavior remain unchanged.

Native runtime is exclusively `gameRoot/piq-native-arcade/runtime`; GBA is exclusively `gameRoot/piq-gba/runtime`. The existing bridge pins verify helper/core/JNA identity. No development-directory search, silent runtime installation/download, binary rebuilding or library duplication is introduced. Existing supplied auxiliary Native BIOS ZIP staging remains unchanged; the room layer must keep ROM/BIOS authorization rules.

Default adapter persistence lives under `saveRoot/server-hosted-v1/<backend>/<owner UUID>/<stable device UUID>/`, then ROM and core-specific identity. Existing personal slots, ROM-adjacent saves, client profiles and user data are not imported, migrated, deleted or overwritten. FC/SFC use a new checksum envelope, size limits, an exclusive OS file lock, a previous-copy backup and atomic replacement; corrupt current saves fail closed and remain untouched. GBA reuses its existing independent SRAM store under the new root. FC home managed persistence is the explicit exception described below: it retains the home's NONE/MACHINE/PLAYER permission policy and uses distinct `server-home-v1|` slot keys.

## Worker and media rules

FC/SFC construction, all core calls, periodic saves and close occur on one daemon owner thread. The controls audit changed input buffering to independent per-port FIFOs, each bounded to 128 edges: different players advance in the same frame rather than accumulating a combined 160 Hz queue. `offerFrameInput` atomically admits a complete pad/gun update, and release clears only the specified port (plus the gun when releasing its reserved P2). Reset clears all pending input and stale output. Picture storage is latest-only; audio keeps a bounded 32768-short stereo-aligned tail (about 341 ms). Audio/video encoding and authenticated distribution are room-layer responsibilities.

FC audio is high-pass filtered, linearly resampled from 44.1 kHz mono to 48 kHz duplicated stereo with continuous fractional phase, then returned in the common `CabinetFrame`. Libretro A/B mapping is explicit; unsupported physical face buttons have no FC function. Zapper input uses the existing canonical `ZapperInput` format and is never silently consumed by a legacy or other-platform core.

WASM owner cancellation is cooperative: native/WASM calls cannot be force-stopped safely from another thread. A stalled call retains its capacity and does not imply termination. Native helper timeout isolation remains as implemented by the existing bridges; process isolation is not an OS sandbox. This version does not claim hard CPU/RAM sandboxing or automatic live migration between modes.

## FC home SERVER execution follow-up

- `FcHomeHostedRun` opens the pure NES factory on its worker; no fake ServerPlayer and no client backend are constructed. The existing `LockstepState` remains the authorized input merger, including the actual physical controller lease, gun lease, gun keyboard fallback and server ray tracing. Only the merged frame input is sent into the hosted handle. Forced release also clears pending core-side edges, without revoking another player's P1.
- `ServerArcadeSessions` snapshots the configured mode at power-on. LOCAL_SYNC follows the old branch unchanged, subject to the administrator's explicit local-mode switch; SERVER requires opt-in, static backend availability and a pre-reserved shared `HostedServerLimits.Lease`. The lease remains occupied through copy/open/run/close until actual termination. Media reserves the shared fair per-lease/server budget for every recipient copy and rotates the starting recipient. MEDIA remains unavailable.
- `FcHomeHostedNetwork` registers S2C-only state and complete audio/video batch messages. Callback delivery captures and rechecks the exact current Connection; streams additionally fence recipient UUID, session, epoch, source UUID and token. `ClientArcadeEvents` bypasses `ClientRomTransfers` for this lane. `ClientArcadeSession` never starts a ClientNesWorker in SERVER mode, never owns/upload snapshots, and uses only the bounded media decoder/audio output. Home invitation approval authority is separate from computing-host authority.
- Power is separate from controller ownership. Existing connected holders can keep playing after the original operator leaves; no new operator or personal-save ownership is invented. Physical invalidation, unloaded endpoints, a failed core, disabled hosting, startup timeout, or no remaining connected operator/controllers closes the run. The common watch provider declares a server-hosted source and accepts no client media upload, so bystander viewing does not depend on the original operator's network connection. Invitations still require the original current operator; control rights are not silently transferred.
- The reset button now resets the actual core, increments the original FC input epoch and rotates the media token. A core-owner callback acknowledges reset completion; pending snapshots/media and in-flight old-token batches are discarded before media resumes. Old keyboard reset packets remain rejected by the existing physical-button rule.
- NONE never writes a save. MACHINE and PLAYER use the existing bounded ArcadeSaveStore under distinct `server-home-v1|` keys; legacy saves are not automatically loaded or migrated. PLAYER uses the original three-slot selection, delete/rename authorization and PersonalSaveLease. Owner disconnect saves the last confirmed state then seals the lease, so later participants cannot overwrite it. A normal powered-session close signals the worker; subsequent server ticks collect its final confirmed snapshot before releasing the closing slot lock. During whole-server shutdown, only the latest already-confirmed snapshot is synchronously available; a stalled core cannot be assumed saved or terminated. This is not a claim of crash-proof last-frame persistence.
