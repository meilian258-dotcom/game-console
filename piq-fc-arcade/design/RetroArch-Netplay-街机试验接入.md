# RetroArch Netplay 街机试验接入

2026-10-10，像素匠。适用主包 FC76.49 和街机 0.1.5.11，Minecraft 1.21.1、NeoForge 21.1.229 及兼容的 21.1 版本、Java 21。客户端与服务器须一起更新，运行核心的客户端需要 Windows x64。

本批将街机的原版 FBNeo 接入既有 RetroArch Netplay，并提供其他附属可复用的后端选择和兼容校验接口。**这是显式试验路线，不是默认替换，也没有通过完整同步验收。** 旧 JNI 核心、设置和存档保留；本批不修改或重新编译任何模拟器核心。

## 怎样选择

1. 在独立测试环境安装同批主包和街机。无需另装 RetroArch，也无需为本入口填写 JVM 参数。
2. 关掉整组机柜，管理员用调试螺丝刀进入设备设置，打开 Netplay 后端页。
3. 明确选择 `RetroArch · 原版 FBNeo（实验，不存档）`，再点击启用此后端 Netplay。选择后端本身不自动开局；服务器确认后，对整组机柜下一局生效。
4. 选用合法、完整且与 FBNeo 匹配的游戏及 BIOS，按实体电源开机。加入申请、操作席和投币继续使用公共街机流程。
5. 结束时正常关机并等待回收。要回旧路线，关机后明确选择 JNI 兼容后端；失败不会自动切换。

`-Dpiq.arcade.mediaBackend=retroarch` 仍只控制 MAME 玩家音画串流，与此 Netplay 入口无关。不要用该参数验证是否选到了 FBNeo Netplay。

试验路线暂时只允许不保存：不读取、转换或覆盖 JNI 旧档。原有 JNI 保存偏好仍保留，切回后按原规则使用。不是核心没有保存能力，而是此组合的持久化闭环尚未验收。

## 实际调用和公共接口

| 环节 | 公共职责 | 街机适配 |
| --- | --- | --- |
| 声明 | `NetplayVariant` 注册受信后端，`NetplayLaunchSpec` 固定本局 ID、兼容摘要和保存能力 | 同时注册旧 `legacy` 与新 `retroarch-stock-v1`，指定各自固定核心、选项和四端口 |
| 选择 | `CabinetSyncSettings` 校验管理员、距离、保护与空闲状态；整组持久化 | 不用每位玩家的本机属性决定联机后端 |
| 开局 | `CabinetNetplay` 捕获本局声明，经 `CabinetRoomNetwork` 下发主持和加入者 | 本地只查已注册的受信 profile；不接受网络提供的 DLL 路径 |
| 旁观 | `WatchNetplay` 与 `WatchNetwork` 透传同一声明，准备前再次校验 | 原生只读副本；当前仍为空闲客户端的单源进程旁观，不扩展 JNI 多屏额度 |
| 内容 | `LibretroContentFiles` 与 `NetplayProcess.fileContent` 后台校验并暂存主文件和 BIOS | 保留原驱动名及授权清单，主 ZIP ≤96 MiB、最多四件 BIOS、单 BIOS ≤16 MiB、总计 ≤128 MiB |
| 输入 | 服务端操作席和投币权威保持；RetroArch 负责原生同步 | 街机仍将服务端确认输入交给计算主持的四端口，其他原生进程只读接收；不是绕过席位权限的直接 P2 网络输入 |
| 收尾 | 所有 RetroArch 角色异步关闭；先关闭认证 IPC，后台有限等待，再按需强制回收 | 诊断区分自然退出与强制结束；`close()` 不是完成信号，须等待 `terminated()` |

其他附属可复用以上入口，提供自己的固定 profile、内容规则、端口和能力声明，不复制进程、传输或 Netplay 算法。旧无变体接口保留原行为；这些是内部 API，不是稳定 SDK，也不代表 FC、SFC、MD、GBA 已迁移。

兼容摘要包含核心 SHA、资源身份、关键选项、设备及端口、采样率、内容预算，以及运行器 SHA 和 PNP7 协议。游戏与 BIOS 的身份另外由授权内容清单确定。不匹配时拒绝启动或加入；显示名称和 ROM 文件名不能代替校验。公共机柜、设置与旁观协议分别升级为 `cabinet-room-11`、`cabinet-sync-11`、`watch-5`，不能与旧主包混联。

## 状态和失败提示

本机音画就绪只说明该端产生了画面，不证明其他玩家已连接、追赶完成或整局同步正确。诊断显示实际角色、核心和运行器摘要、协议、输出状态及关闭方式；传输通道数量也不是同步成功证据。

缺少后端、兼容摘要不符、无权修改、正在运行不可改、内容加载失败、连接超时和关闭未确认分别反馈；不静默改核心或运行方式。运行环境检查只验证程序组件，不保证 ROM／BIOS 完整。内容缺件不自动下载游戏数据，旧保存及原内容均保留。

现有前端自主计时，没有精确暂停后激活接口。服务端授权和输入控制仍有效，但不能宣称与旧 JNI 的准备／激活能力完全等价。回滚、弱网、MC 双客户端、晚加入和长局仍需分别验收。

## 核心来源和复用依据

原版 FBNeo DLL 61,913,629 字节，SHA-256 `52343f65453c0e1fc06b3aa818b48ca4fed18361f7f336a684e9e3cffa5f5f3c`，版本报告包含 `GITa251c76`；另附上游提交 `a251c76229f1637e433b93e29845039752771b6d` 的源码。已核对来源和文件身份，但尚未以可复现构建证明该源码生成逐字节相同的 DLL。它与旧 state-v3 是不同资源，不覆盖旧文件。构建只校验和打包既有原版制品；保留来源与许可证，不包含 ROM、BIOS 或玩家存档。

运行器复用固定 RetroArch 1.22.2／PNP7，SHA-256 `1335c34b04d8c3e55afe010a421ff373d938929ec196a6e93a9657972fe034e1`，本批未改其原生代码。现有认证 IPC 用于输入和音画接入，联网仍使用 RetroArch 自身协议；不另造回滚算法。

2026-10-10 核对的上游依据：[Netplay 原理和协议](https://docs.libretro.com/development/retroarch/netplay/)、[FBNeo 格式与核心说明](https://docs.libretro.com/library/fbneo/)、[RetroArch 命令行](https://docs.libretro.com/guides/cli-intro/)。采用现成 host／connect、端口和只读旁观机制；上游能力说明不代替本模组实际验证。单独进程不是操作系统沙箱，也不保证不会出错。

## 验证边界

固定原版 FBNeo 的隔离双进程已实际进入《恐龙快打》双人游戏，直接双口与街机主持权威输入分别验证，原件未改动。旧成品基线的直接双人轮中，同 Netplay 模拟帧的 core state CRC 有 28／56 对不同；街机权威轮有 62／63 对不同。后者主持和参与端的状态采样代码路径不同，必须保留此限定。画面有序匹配不能证明完整模拟状态一致，CRC 差异也尚不能单独证明可见游戏已经分叉。

最终 FC76.49＋街机1.5.11 JAR 的隔离双进程复测使用真实公共 API 和包内核心，不用资源替换参数：54 项连接、文件及进程检查通过，双端有音画，脚本分别驱动 1P／2P 的动作可见，634 个参与端动作画面按顺序匹配。两端自然退出码均为 0，未强制结束，临时目录回收，原始内容及 JAR 保持不变。这里的参与端原生角色是只读旁观；两路操作经机柜权威主持执行，并非原生玩家席位直连测试。该轮同模拟帧 CRC 为 63 次比较、47 次不同，保留原始差异。修正保存提示前的同版本中间包另有 635 帧有序匹配、39／63 CRC 不同的记录，未覆盖；安装包以交付清单的最终摘要为准。

自动测试：主包 2,911 项、11 项既有跳过；街机 172 项、无跳过；两者均无失败和错误。主包包含后端保存提示随能力变化的回归测试。最终双 JAR 在隔离 NeoForge 21.1.236 专用服务器正常加载并正常停止，依赖、网络注册及两个实际版本均核对通过；这不等于图形客户端或真实多人测试。构建工具 Python 测试为 165 项、3 项跳过，未执行公开 CI 发布。

因此，本轮**没有通过逐字节状态一致、完整确定性或回滚验收**，不将其标为稳定路线，不用关闭 CRC、修改核心或归一化未知状态来通过测试。具体制品摘要见本批交付的验证清单；真实 Minecraft 多人、弱网长局和保存恢复仍待验证。

完整目标与分层验收继续采用[通用制作规范第 1.8 节](机器制作与交互标准.md#18-jni-与-retroarch-共存不把运行器等同于多人能力)。当前试验缺口不修改正式目标，历史 JNI 与 MAME 的结果也不重新标成本路线通过。

## 功能基线与验收追踪

本批只扩展公共街机后端，不新增机器外壳。按制作模板追踪适用项；“沿用”表示没有重写，不表示已完成本次 Minecraft 实机验证。

| B02 安装依赖 | FC76.49＋街机1.5.11 两端配套，原生运行端 Windows x64；最终双包专用服务器启动／停止通过，图形端待验 |
