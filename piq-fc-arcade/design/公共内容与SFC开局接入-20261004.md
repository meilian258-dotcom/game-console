# 公共内容与 SFC 开局接入

维护：像素匠，2026-10-05。基线 `096dfe5`；FC76.41 / 完整SFC49（core10）测试候选，不是稳定认证或全组件达标声明。

## 范围与结果

复用 ContentCardNames、HomeLaunchServer/Screen、HomeSystems、NetplaySaveServer，不复制另一套工作台、原生桥或会话系统。沿用原核心和保存身份，不换核心或迁档。

| 需求 | 本轮结果 | 边界 |
| --- | --- | --- |
| R01 可读名称 | SFC上传原名复用ContentCardNames，独立roms-names元数据 | 旧原名无法凭哈希恢复，卡标题与全局库名分开 |
| R02 扫描报告 | ContentScanReport供公共卡库和SFC复用，区分合法条目、拒绝、警告 | SFC列表协议仍独立，未改成公共工作台 |
| R03 设备状态 | DeviceSettingAccess区分可编辑、管理员限制、忙碌、只读诊断、读取失败；HomeSync使用实际原因 | 读取失败枚举供适配器使用，未把所有异常变成类型化协议；不解锁未实现模式 |
| R04 SFC开局 | 公开家用接共同确认/加载/就绪，JNI Netplay接旧档选择及保存收尾 | 其他保存轨、私人和机柜不强迁 |

## SFC实际流程

公开家用：实体电源 → 校验设备/电视/卡带/权限 → 按保存能力选档 → 独立询问是否允许2P → 加载/恢复 → READY → 控制/旁观 → 停止与保存确认。

- JNI Netplay不存档：不列档，仍按卡带真实人数决定是否问2P，旧档保留。
- JNI Netplay个人/卡带：显示原有一份进度，可继续或从头。旧格式不存名称/单双人标签，控件只读，服务端拒绝伪造修改；标签不决定本局2P许可。
- 保留个人 `sfc-personal|玩家UUID`、卡带 `sfc-card|CardId` 和原profile/content目录，每游戏一份，**不改成总三槽**。SFC旧值1个人/2卡带显式翻译为公共1卡带/2个人，仅作展示，不改NBT。
- 选择只读检查版本，真正打开时在写租约内复核。从头开始不立即删除原进度，首次成功提交才原子更新并保留备份。
- 启用保存的 JNI Netplay：`openPrepared` 允许恢复但禁止提交，READY后 `activate`；取消/加载失败 `abort`，正常结束 `awaitFinish` 等实际IO释放与持久化结果。保存停止中取卡提示稍后重试，不提前移走卡带。不存档分支不激活或等待已经释放的保存绑定。
- MEDIA/旧LOCAL_SYNC/托管也接公开开局与2P确认，但继续原保存机制；托管SRAM不会因公共页面“不存档”自动改变，私人入口仍独立。
- 准备回复绑定原连接、卡快照、机器、模式及公共代次；超时/失效丢弃旧回复。控制租约、卡人数及逐人加入审批继续由服务端检查。

## 公共接口合同

| 接口 | 调用与责任 |
| --- | --- |
| ContentCardNames | 后台IO；根由服务端提供；SHA定位、首个合法原名持久化，坏元数据不隐藏ROM；不可用显示名拼路径 |
| ContentScanReport | 不可变、有界entries/failures/warnings及公共摘要；不执行扫描或替代授权 |
| DeviceSettingAccess | 纯访问状态/原因；不支持与当前选中仍由模式策略区分，提交时重新授权 |
| HomeLaunchIo.read | 服务器线程发起，单IO线程/32排队上限，只读准备；回调服务器线程，由HomeLaunch复核代次；工作线程不得访问MC世界 |
| HomeLaunchServer.Adapter | definition/valid/list/select/load/cancelled；协调选档→确认→加载/超时，适配器保留资源与保存责任 |
| HomeLaunchNetwork.Row | metadataEditable新增，旧七参构造保留默认可编辑；只读行由服务端核对名称/人数未改 |
| NetplayLegacySlot | 后台inspect；写租约lease中核对版本，适配旧单检查点，不迁档或伪造三槽 |

`home-launch-2` 不能与旧协议混用，客户端和服务端主包同升级41。SFC49最低依赖41，MD14旧构造调用保留兼容。内部public类不等于稳定SDK。

## 全组件覆盖与基线

FC、MD、SFC公开家用已调用公共开局协调器；FC保留原完整选档编辑页，SFC仅Netplay旧档适配，不宣称所有保存链相同。Native街机继续公共机柜/投币/席位/Watch/Netplay；GBA继续内容卡/运行器及掌机保存；电脑仍有独立程序枚举和交接。类型差异不靠复制一张菜单消除，新机按能力接入。

## 安装与本地交付

MC1.21.1、Java21，NeoForge最低21.1.229、编译基线21.1.236；原生运行端沿Windows x64。正常退出实例、备份mods/世界/game-console后，由维护者在客户端和服务端同换主包41与完整SFC49；旧同ID移出mods保留，不并存、不装内部platform或SFC薄包/重复core。

仅换FC/SFC两件，MD14、Native1.5.7、GBA15、电脑12、PvZ12原SHA保留。GX 对应源码与许可继续随 MD 分发，源码 ZIP 不放 mods。

FC41 check/jar（含打包核心烟测）、SFC49 check/jar、MD14与Native1.5.7对新主包测试通过。新增覆盖原名持久/回退/失败重试/隔离、扫描拒绝、只读行编解码/伪造拒绝、旧单档版本/租约/备份、保存模式/归属、设备编辑理由。真实HomeLaunch载荷注册/方向/版本/codec往返回归通过。初次测试把流量统计包装误作原codec对象身份，修正测试后重跑，生产代码不变。最终FC2850/SFC528/MD106/Native122，共3606项，0失败/错误、11条件跳过。

最终七包八ID在21.1.229和21.1.236均Done→正常stop→exit0；双SFC容器、实际版本与载荷加载检查通过。完整SFC核对core10原SHA、类输出、AT/WASM与双ID；新两包非代码资源与上一版一致，五伴随包原样。
