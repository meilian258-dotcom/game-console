# FC76.5 运行临时目录修复候选

适用：Minecraft 1.21.1 / NeoForge 21.1.236 / Java 21，主包 `game_console-0.31.0-alpha.76.5.jar`。

## 修复内容

FC、SFC 及街机使用的 Netplay、通用 Libretro 和旧 FC 回退运行器，改用实际游戏实例下的 `game-console/runtime-sessions/`。每次会话一个独立工作目录，里面是重新解压的核心、游戏运行副本及临时配置；Java worker/JNA 的临时文件也放在这里。正常停止后回收，短暂文件占用会有限重试，失败写日志，下次启动再检查。

新目录有版本标记、跨进程锁、父子进程 PID 和启动时间。清理仅针对已结束且可确认身份的会话；正在运行、未知启动状态、无标记、符号链接/目录联接或非普通文件一律保留，不跟随链接。崩溃或强制结束后可在下次启动回收；极端启动瞬间崩溃且无法确认子进程的目录会保留，需人工核对，不承诺任何情况下零残留。

启动前保守预留空间，失败会明确提示“磁盘空间不足”，详细诊断包含运行路径。Netplay 传入相对游戏文件名，避免 Windows 原生程序命令行转换破坏中文路径。本轮没有更换核心、游戏文件、网络算法或正式存档格式，也未加入不可验证的核心共享缓存；每个活动会话仍有一份运行副本，不代表运行时零磁盘占用。

## 安装

1. 正常退出客户端；服务器由管理员安排停服和备份，本交付未代执行。
2. 将旧主包移出 `mods` 备份，客户端和服务器主包统一换成 FC76.5，同 ID 不并装。继承 FC76.4 的 `cabinet-room-8`，不要与 FC76.2/更旧主包混连。
3. 沿用街机 **0.1.5.1**、完整 SFC **alpha.41（含 core.9）**、GBA **alpha.10**、PvZ **prototype.9**、电脑 **prototype.5-r2**，Flash运行器 **0.1.3**；未使用的附属无需额外安装。
4. 重新启动游戏，在世界副本分别开关 FC/SFC/街机并进入/离开 Netplay。关掉设备或退出后检查 `runtime-sessions`：通常只剩零字节 `cleanup.lock`，这是固定互斥文件，不是残留游戏。

只更新运行路径不需要重新放置方块或重新导入游戏。主模组的共同方块、服务端会话和客户端显示/输入仍要求两端安装；此轮运行临时文件逻辑主要作用于执行核心的一端，不依据依赖 side 推断安装端。

## 旧 C 盘临时目录

本版不自动遍历/删除系统 Temp，也不删除旧版 `piq-netplay-*`、`piq-libretro-generic-*`。旧版仍运行时可能继续生成旧目录，必须更新并重启才会切换。

本机反馈时曾有 Netplay 518目录约27.8GB、generic 1673目录约6.3GB；用户授权删除后、执行前复查两类已0且C恢复约35.3GiB，本轮没有实际执行删除，不冒称代清理。其他人的客户端如有残留，应先退出全部相关游戏/核心进程、核对来源，再清理确认无用的具体目录，不能直接全删 Temp。

ROM 原件、服务器游戏库、已下载游戏缓存、正式存档和 `legacy-backup` 不属于本次运行副本回收范围。不能把 `game-console` 整个目录当缓存删掉。PvZ/Flash独立运行器及旧 WASM/JVM/加载器的系统缓存不在本轮覆盖范围；不承诺极长 Windows 路径兼容。

## 配套功能与验证边界

完整测试、冻结JAR真实核心验证和限制见工作区 `outputs/runtime-storage765/VERIFICATION.md`。本包为测试候选，未代装客户端/服务器、未发布/部署/重启；Minecraft真实多人、长期反复开关和真实客户端崩溃后恢复仍待验收，不标稳定。

## 开发者调用

共享类 `cn.piq.retro.storage.RuntimeWorkspace` 随主包提供，无MC依赖。主包初始化调用 `configure(原始实例根目录)`，不是传 `game-console`。核心工作线程用 `create(kind,保守磁盘字节预算)`、`directory()`、`start(ProcessBuilder)`，最后停止子进程再 `close()`；不要用它保存用户唯一数据。内置 kind 仅 netplay/libretro/fc-legacy，不开放任意路径删除API。清理日志类别为 `PIQ-RuntimeWorkspace`。
