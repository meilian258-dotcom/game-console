# 公共回放接口 v1 制作说明

维护者：PIQ。日期：2026-10-11。适用：Minecraft 1.21.1、FC76.53 与可选 Replay test.6。状态：测试候选，实机待验。

## 目标与范围

将主包的回放扩展点从私有实现注入改为主包主动调用的版本化接口，避免正常主包小版本更新反复修改补丁上限。本次不改模拟器核心、ROM／BIOS、保存身份、联机协议、录像轨道格式或独立 QuickMode 补丁，不安装／部署／发布，不新增机型。

| 需求 | 实现位置 | 验收 |
| --- | --- | --- |
| R01 主包内部重构与回放解耦 | `ReplayPresentation`、`ReplayAudio`、`ReplayGuard`；删除补丁 14 个 FC 私有 Mixin | 真实 API class／descriptor／实际调用点检查；拒绝缺失和未知合同 |
| R02 保持只读回放 | 核心、输入、发包、保存拥有者显式 guard；epoch 拒绝迟到结果；支持无保存退役 | 进入前拒绝不失效原会话；正常／错误退出；阻塞输出迟到、无保存关闭行为 |
| R03 小版本不决定兼容 | 新补丁 FC53 起无上限，加载时检验 v1；旧 test.5 保留 | Maven 边界与伪造描述、缺类、改签名、v2 拒绝 |
| R04 后续发布不漏合同 | Gradle 最终 JAR、snapshot staging／release 共用 verifier | 缺描述、重复归属、缺调用点阻止发布；行为单独回归 |
| R05 不改变正常游戏与旧数据 | 未装补丁无服务；原输出结果不变；无核心资源变更 | 音频短写／失败写、旧核资源逐字节对照；MC 正常游戏待验 |

## 复用与分层

沿用 ReForgedPlay 0.3 的录像生命周期、已有 `ScreenReplay`／`AudioReplay` 轨道服务、Sponge/MixinExtras 和主包公共电视／机柜。没有现成上游接口能代替本模组的世界屏幕与保存授权，因此只增加本模组提供者合同，不重新实现录像编辑器、网络或模拟器。

加载范围沿用 [NeoForge 1.21.1 Mod Files](https://docs.neoforged.net/docs/1.21.1/gettingstarted/modfiles/) 的 Maven 依赖范围；范围不是实际二进制兼容证明。实际 ReForgedPlay 构造、原失败处理和两个有／无 Iris 组合分别检查。未增加第三方运行依赖，原项目许可不变。

| 动作 | 主体／边界 |
| --- | --- |
| 正常游戏／录制 | 仍由原设备会话产生画面与最终音频；录制服务只收有界副本，无设备控制权 |
| 打开录像 | 原 Replay 关闭旧回放与兼容警告保留；构造前检查保存／无保存退役能力，再进入新回放代次 |
| 回放／跳转 | 原数据驱动呈现，不重新启动模拟器；禁止设备控制与保存，旧异步 epoch 不复活 |
| 失败／退出 | 原异常保持；清空回放状态和音画队列，无保存退役，不将失败状态说成正常关机 |
| 未支持的活动私人运行器 | 明确拒绝打开录像；用户正常保存并结束后重试，不强制丢档 |

内容选择、写卡、2P 策略、操作席与保存所有者不变；本轮不是新机型，B01～B16 功能基线不新增实现。实体外观、模型／贴图／线材／按钮和服务端权限不变。Replay 补丁客户端按需安装（`@Mod(Dist.CLIENT)`），主包原有两端要求保持。

## 合同与兼容策略

主包提供纯 Java 保护与 PCM 服务一次；MC 世界渲染合同仅限 1.21.1 客户端。附属不得复制 API，主包不得反向依赖可选补丁。v1 内签名与语义保持；需要破坏性更新时保留 v1 兼容入口或协同发布新版，不静默放行未知版本。

test.5 作为 FC46～52 历史组合保留；test.6 以 FC53/v1 为起点。仍访问内部类的 SFC、MD、原生街机、GBA、电脑和 PvZ 采用有界旧适配，后续逐个接入三项合同后再解除对应边界。Java ME 未验收，继续拒绝同装。不能把共享电视的画面捕获等同于其核心／保存已受保护。

画面／音轨格式及有界队列保持，细则见 [API](../../piq-replay-compat/API.md) 和 [玩家说明](../../piq-replay-compat/README.md)。无全局 Java 音频钩子、无系统混音采集、无新无限队列。已开始的原生调用或原子磁盘写入不能强制中断；回放入口检查与 epoch 阻止后续工作，未证明安全的活动私人会话拒绝进入。

## 验证和后续发布

实际结果统一记录到 [Replay 验收记录](../../piq-replay-compat/TESTING.md)。主包／补丁源码测试、最终包合同、真实 Mixin 变换与 Minecraft 图形／听感验收分开。自动测试通过不等于光影、多机、多人或所有附属的实机完成。

发布流程须包含：固定配套输入 → 构建和行为测试 → 最终 JAR 合同检查 → 有／无 Iris 实际变换 → 新／旧录像、退出恢复正常游戏的隔离实测 → 用户确认发布。普通版本更新不修改补丁上限；合同变更先完成迁移与回退说明。旧成品和录像保留，未自动迁移数据。
