# FC76.25 · JNI Netplay 游戏加载修复

2026-09-29；Minecraft 1.21.1 / NeoForge 21.1 / Java21；JNI 执行端仍仅 Windows x64。候选待 Minecraft 真人验收，不是稳定版。

## 修了什么

- FC 方块加载时，新 JNI Netplay 能力位 4 被全局新机默认值的旧校验拒绝，导致 `Invalid console defaults`。现在接受已知能力位 0～4；自动默认值仍只有原来的三种模式，不会自动启用 JNI，未知位仍拒绝。
- Mesen VRC7 初始化未同步 PRG RAM 访问控制，第一次保存恢复会变更状态，触发“核心不能精确恢复”。现在初始化时落实寄存器的权限。
- Mesen 公共恢复过程把“已映射但暂时禁止访问”的 PRG/CHR 页当成“未映射”删除描述信息，MMC3 游戏也因此启动失败。现在保留银行、偏移和禁止访问权限；不开放禁用的内存。
- 保留逐字节精确恢复、CRC、核心/ROM/选项身份、席位权限和保存失败保护。没有丢掉检查、清零差异字节或靠多跑启动帧掩盖问题。

## 安装与使用

双方只更新主包 `game_console-0.31.0-alpha.76.25.jar`。先正常关闭客户端/测试服并备份，将旧主包移出 `mods` 保留，再放入新包；不能同时保留两份主包在 `mods`。没有要求更新 GBA11、MD1、完整 SFC43、街机1.5.4、PvZ11、电脑10 或重新摆放主机。附属未在本轮重新构建。

ZIP、说明和原生源码包不要放进 `mods`。

FC 空闲时在同步设置选择 JNI Netplay，参与运行的玩家/旁观者仍须按既有流程执行 `/gameconsole-jni-netplay` 本机确认。默认进程模式和原 RetroArch Netplay 不替换。JNI 原生崩溃可能带崩 MC，仍是显式试验，不支持光枪 JNI Netplay，不意味着其他机器也接了 JNI 联机。

## 存档注意

新核心为 Mesen PIQ JNI Netplay r2；使用新的 `nes-jni-netplay-v2` 试验存档命名空间和核心摘要。FC76.24 的 r1 试验档留在原处，不自动读取、覆盖或迁移；新版从独立试验进度开始。普通模式、旧 RetroArch、个人/卡带的归属规则不变。不要手动改档头/文件名强行混用不同核心状态。

## 验证范围

完整独立源码克隆加固定输入构建 `check jar`：2560 项，0 失败/错误、10 项既有跳过；原三个包级冒烟通过。能力位新增回归在旧代码上确实失败，修复后通过；不能精确恢复的假核心仍被拒绝且不能保存。

最终候选在独立 `-Xcheck:jni` JVM 中对本地21个 ROM及原创 VRC7/MMC3 两个夹具完成：生产启动顺序、逐字节恢复、6轮各30帧带输入重演、音画输出、SRAM+状态恢复及关闭释放。旧 FC76.24 上两夹具和5个游戏出现同类失败，新版上述检查均通过。原 ROM 只读未改，未放进交付包或 Git。光枪游戏文件也参加了通用核心状态检查，这不代表光枪操作/联机已支持。

本机多 JVM/回环延迟测试不能代替 Minecraft GUI、真实专服、多客户端网络、长期稳定性或完整游戏通关；本轮这些项目待验。

最终包另通过三组各三个 JVM 的真实核心会话：原创 NROM 诊断程序（回环注入100ms）、汉化魂斗罗 MMC3（35ms）、Lagrange Point VRC7（35ms）。覆盖双席、晚加入旁观、2P断开重进、实际回滚、手动/正常关闭保存、第二次 JVM 启动恢复并继续前进100帧以上、JNI释放，无 JNI 检查警告。保存使用隔离临时存储回调，不冒称已测试 Minecraft 服务端实际落盘。
