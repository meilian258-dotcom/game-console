# FC75 / SFC40：Netplay 稳定性测试候选

适用：2026-09-25，Minecraft 1.21.1、NeoForge 21.1.236、Java 21；Netplay 运行端为 Windows x64。不是稳定发布版。

## 这次改了什么

- 退出、断线或取消启动时，统一清理本地监听端口、连接中和认证中的套接字；补上关闭与迟到连接同时发生时的保护。
- 2P/旁观连接独立清理，避免关闭后重新挂上连接；保留已有席位和只读旁观规则，没有放宽服务器授权。
- 区分等待主持端、核心退出、同步等待超时、接收积压和组件协议不匹配。诊断保留当前阶段、已接收帧数和原生日志，不再让日志中普通 DLL/ROM 字样遮住实际异常。
- FC 性能窗口显示准备、连接、启动、等待画面等当前阶段；“音画已就绪”仅表示本机音画桥就绪，不冒充网络握手或三端画面一致证明。原生帧耗时仍未采样。

主包没有修改原生前端、CRC 校验频率、网络协议或存档格式。配套街机014对 FBNeo 的 PGM 快照补充跨帧 CPU 周期余量，解决本轮三国战纪独立三端测试中的反复重同步；不代表所有街机高流量原因都已消除。没有新增 Netplay 存档、自动重连、PvZ 联机或 JNI 改造。

## 配套文件

客户端与服务端主包都换为 `game_console-0.31.0-alpha.75.jar`。按需搭配：

- SFC：完整 `game_console_sfc-0.1.0-alpha.40.jar`，沿用原包，不叠装旧独立核心或源码构建薄包。
- 街机：`game_console_arcade-0.1.4.jar`，使用固定哈希的 PGM 周期余量修补版 FBNeo；所有参与端一起更新，不与013混用。旧 MAME 运行库和旧同步保持原字节。不把诊断用的状态转储前端装入交付包。
- 已安装 PvZ：同时换 `game_console_pvz-0.1.0-prototype.7.jar`，旧 prototype.6 拒绝 FC75。PvZ7 仅更新兼容声明，支持 FC70～75；未换新 DLL，不改 main.pak 路径和保存目录。

正常退出后备份世界，在副本测试。同 ID 旧 JAR 移到 mods 外保留。无需另外安装 RetroArch；不要删除 ROM、BIOS、世界、运行库或存档。ZIP 的“可选PvZ”目录只在原本使用 PvZ 时安装。“源码”目录不要放入mods，它含本次修改的完整FBNeo源码与构建说明，保留独立许可证，不按主模组GPL重新许可；不是公开发布许可审查通过证明。现有 Flash8 不适用于此组合；GBA 新组合仍待独立核对。

## 建议你这样测

1. 选关闭存档的测试卡带/游戏，设备选择 `RetroArch Netplay（实验）`，让朋友作为 2P 和旁观分别加入。
2. 正常玩几分钟，然后归还/领取 2P 手柄、离开并重进；确认旁观音画与操作席位正常，不出现额外权限。
3. 主持关机或退出时，其他玩家应结束本局。重新开局后再次加入；本版不提供主持迁移或自动续局。
4. 加入过程中取消、短暂断网再手动重进；异常时复制运行环境诊断。请保留发生时谁是主持、2P、旁观及当前阶段。
5. 测流量前等游戏下载和初始同步完成，在流量监控中重新计数，保留 Netplay、音画、游戏/资源、其他四类速率截图。计数是整个当前连接的压缩前模组载荷，不是网卡流量；Netplay 不是零流量。

真实 Minecraft 多客户端、弱网络和长时间测试尚待完成。自动三进程验证、构建结果与精确文件哈希见同目录 `VERIFICATION.md`、`verification.json` 和 `SHA256SUMS.txt`。未自动安装、部署、发布或重启服务器。
