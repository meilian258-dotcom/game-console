# 方块电玩 FC63：libretro 启动修复测试版

适用：Minecraft 1.21.1、NeoForge 21.1.236 及以上的 21.1.x、Java 21，主模组 `0.31.0-alpha.63`。开发基线为 NeoForge 21.1.236，本次反馈实例为 21.1.250；具体实机组合仍按下方验收边界核对。2026-09-21 编写。当前是本地修复候选，不是正式稳定版。

## 修复什么

FC62 在这次 HMCL 实例中启动后黑屏，诊断为 `FC native worker exited during startup (1)`。本地复现发现：游戏 JVM 的 IPv6 优先设置使父进程监听 IPv6 回环地址，而独立核心子进程按默认设置连接 IPv4 回环地址，两端地址不一致，导致核心在连接阶段退出。不是缺 ROM、需要安装 RetroArch，或缺少页面所列街机/GBA 附属。

FC63 将内部通信固定到本机 IPv4 回环地址，并让核心子进程使用明确的 IPv4 参数；不修改 Minecraft 连接服务器的网络设置，不开放公网端口。另保留有限长度的核心启动错误，后续异常可从“复制诊断”取得更具体的原因。

本轮不更换 Mesen、worker、原生库或运行档案，不改协议 42、手柄、光枪、模型贴图及存档结构。与 FC62 相同核心/ROM 的新格式存档按原身份规则使用；FC61 及更早的 WASM 快照仍不自动转换或覆盖。FC62 的历史原始文件与交付包保留。

## 安装

1. 关闭游戏和测试服务端，先备份世界及模组数据。使用独立测试配置或世界副本。
2. 将双方旧主模组移到 `mods` 外备份，再放入本次交付的 `game_console-0.31.0-alpha.63.jar`。同一 MOD ID 不得同时保留两份。单人只需更新该实例。
3. 不要安装 `build/libs` 中间包；其两张历史未审手柄草稿在冻结交付时恢复为上一版正式字节。最终 JAR 和 ZIP 的 SHA-256 见同目录 `SHA256SUMS.txt` 与 `验证结果.json`。
4. 只测 FC 不需要额外下载运行库或安装 RetroArch。不要与 Flash prototype.8 混装，其依赖范围仅接受 FC56～61；其他附属未在本轮修改或验证。
5. 不必更改 HMCL 的全局 IPv6 参数，也不应为本修复删除旧存档、重装 Java 或游戏。此次不自动替换玩家实例文件、重启游戏或发布正式服。

## 验证与边界

已在冻结 FC62 上复现：父 JVM 的 `java.net.preferIPv6Addresses=system` 和 `true` 启动失败，`false` 可启动。FC63 新增启动/诊断专项共 7 项已通过；最终全量 `check jar --offline --rerun-tasks` 共 2229 项、0 失败、0 错误，8 项既有 Windows 符号链接权限环境跳过，源码捕获前后相同。最终冻结 FC63 在 `system`、`true`、`false` 三种父 JVM 参数下均启动成功；每组独立启动两个核心，恢复后连续 30 帧画面一致，状态大小 283744 字节。日志校验见包内 `验证结果.json`。FC62 的历史 1709 项 worker 探针不记作本轮重新测试。

本轮冻结 JAR 为 35,802,717 字节，SHA-256：`EA76D5983B26815509131197855E2116B7D1AF9FA77D0B1DFD3CB257E4C4C5DD`。所有 `core/` 运行库、worker、运行档案字节与冻结 FC62 相同；除父桥及其内部类、诊断提示和版本元数据外，其他交付条目保持不变。

需要在游戏里复验：开机出现游戏画面及声音、N/F7 提示正常，个人/卡带档可保存继续，两台主机同时运行不串线，关机后子进程退出。真实 Minecraft 单人/多人、航空学/光影、Linux 执行及跨系统同步仍须分别验收，不能由独立核心测试替代。

Windows x64 是本次本地验证环境。Linux x64 二进制沿用已校验版本，但本机未运行 Linux 验收；macOS/ARM 不作支持承诺。仍沿用既有 FC mapper 允许集、NTSC 核心配置及 60 帧会话调度，不是新增机型或 PAL 原速支持。

## 如果仍黑屏

进入“模组设置 → 运行环境”，点击“复制诊断”，连同该实例的 `logs/latest.log` 和模组版本反馈。不要因通用运行环境页面显示其他附属未安装，就补装本次没有使用的附属。反馈日志前可检查并遮去不希望公开的本机路径等信息。
