# 方块电玩功能行为与配置规范 v1

定位更新：2026-10-03。通用制作目标与完整流程统一见[机器制作与交互标准第 1 节](机器制作与交互标准.md)，实际源码入口／接口／差距见[全组件运行流程与复用接口总览](全组件运行流程与复用接口总览.md)。本文仅补充距离、配置和权限等细则，不另定开局顺序，不能用旧版本缺项缩减新附属功能。

本文的源码“现有”描述基于 2026-09-28 的 FC76.15、完整 SFC41、电脑7，不代表当前全量能力。[2026-09-30 功能覆盖快照](附属功能基线与现状对照-20260930.md)保留 B/C 条目和当时差距；[FC76.21／SFC42 保存指南](Netplay存档-FC76.21-SFC42-使用说明.md)保留当时 Netplay 检查点、保存通道和候选验证记录。历史正文中的“当前”均限对应版本；新的制作目标以通用规范为准，运行现状须核对源码。

这份文件回答的是：**离多远释放操作、离多远停止旁观、菜单该放哪些按钮、全服配置应在哪里改、改完影响谁。** 后续开发同类功能按这些规则对齐，不再由每个附属各定一套。

标记含义：**现有**指基线代码已存在，非实机验收结论；**统一要求**是后续制作的行为合同；**待统一**表示已有实现还未满足，不能因写了文档就算修好。用户最新明确要求优先。本文不更改任何游戏代码。

附属开发可查[以 SFC 为蓝本的历史制作说明](../../piq-sfc-home/design/以SFC为蓝本-附属制作说明.md)，不能把其当时运行器默认值当新机路线。线程、事务、版本交付等工程约束见[模组制作规范](方块电玩模组制作规范-v1.md)。

## 1. 先统一四个概念

| 名称 | 具体含义 | 不等于什么 |
| --- | --- | --- |
| 退出操作 | 释放玩家的操作席或手柄租约，清空按键 | 不一定关机，也不一定停止观看 |
| 停止旁观 | 取消该玩家的旁观订阅，停止为其请求画面/同步内容 | 不停止其他人的会话 |
| 隐藏画面 | 本地不显示、不上传该屏幕纹理 | 主持可能仍需运行和给附近玩家发送 |
| 关机 | 结束这台设备/这组街机的运行会话并清理相关资源 | 不删除所选游戏、ROM、正式存档 |

设备电源、操作席、旁观订阅、核心进程必须分别管理。禁止把“没渲染”“某个人走远”“1P松开操作”直接当作所有设备统一关机条件。

## 2. 距离规则：按什么位置、多少格、超出做什么

### 2.1 默认值与边界

| 编号 | 场景 | 标准/当前数值 | 超出后的行为与例外 |
| --- | --- | --- | --- |
| DIST-01 | FC/SFC有线手柄 | **6格，含边界**，距主机，不是电视 | 服务端释放不再有效的控制租约并清空输入；不把操作者退出等同于全机关机。现有规则 |
| DIST-02 | 街机操作席 | **8格，含边界**，距对应机柜锚点中心 | 普通操作席超距退出；已运行的计算主持可继续提供计算，但不能借此保留远程操作权限。现有规则 |
| DIST-03 | 固定屏幕显示/自动旁观 | **默认16格**；街机全服可设 **1～128格** | 街机超距隐藏游戏画面，跳过不可见画面的纹理创建/上传；不隐藏机柜本体，不直接关机。街机现有；其他新固定设备以16格为默认目标 |
| DIST-04 | 已建立的旁观订阅 | 显示/旁观范围 **R + 4格退出缓冲**；默认20格 | R内可发现并加入；已经旁观的人允许在缓冲区短暂保持订阅，超过退出阈值停止旁观，避免边界反复建连。现有公共规则 |
| DIST-05 | 家用新机默认旁观范围 | 管理终端提供8/16/32/64格预设；底层合法范围4～64，默认16 | **只影响之后放置的适用家用设备**，不能称为覆盖旧机器。现有，与街机全服规则不是同一字段 |
| DIST-06 | 实际点击方块/按钮 | Minecraft正常交互距离、遮挡与保护校验 | 上述6/8格是租约/会话规则，不是把右键距离扩大到6/8格；不可穿实体机身或墙操作 |

距离使用同维度的三维距离平方比较，不能只比较水平距离；边界测试必须覆盖恰好等于阈值及刚超出。屏幕/旁观按实际关联显示端的位置；连接多台街机时按可用的最近显示端判断，不只盯着主柜。

### 2.2 一眼能核对的例子

- 街机旁站着一个普通玩家，距离15格：可以加入旁观并显示画面。
- 原本正在旁观的人走到18格：画面不显示，订阅可能仍在4格缓冲内，**不承诺已经零流量**。
- 继续走到21格：默认阈值下退出旁观。返回16格内重新发现/订阅，不能继续用旧租约。
- 一个100格外、没有参与会话的普通玩家：不会因为“在服务器在线”就加入街机重型音画/Netplay/ROM同步；仍可能收到Minecraft正常区块信息或登录时的小份全服规则。
- 主持走远但附近还有有效玩家：是否仍计算取决于会话角色与安全条件，不能为了停止主持本地渲染而把其他人踢掉。

### 2.3 必须明确保留的差异

当前电脑程序操作界面是8格，电脑串流/显示部分仍使用**32格**；它尚未统一为16格。本次仅记录，不改电脑。手持GBA不能机械套用“距放置主机6格”或街机空席关机逻辑。

新增固定屏幕附属应采用统一范围服务；确有差异时，在能力说明和菜单中写明，不得藏一个额外硬编码距离。控制、旁观、渲染、音量衰减分别注明，不许只写一个含糊的“距离”。

## 3. 街机关机：唯一现行规则

下面是**街机规则**，不是要求把FC/SFC家用机、电脑、GBA一并改成街机。

| 编号 | 管理终端字段 | 默认值/范围 | 精确语义 |
| --- | --- | --- | --- |
| POWER-01 | 最后一人右键退出立即关机 | 关 | 开启后，仅当最后一个有效操作席主动退出且满足关机条件时，整组关机；仍有2P/3P/4P操作就不关 |
| POWER-02 | 无人占席倒计时（秒） | **60秒**，0～3600；**0禁用** | 所有操作席空了才开始；有人重新入席就取消。无人按键、看过场不算空席 |
| POWER-03 | 显示/旁观距离（格） | **16格**，1～128 | 只管理显示/旁观范围，不是无人关机半径，不与倒计时共用判断 |

组合：立即关机关闭、倒计时0＝不按退出/空席自动关机；立即关机开启、倒计时60＝最后一席主动退出优先立即关机，其他空席情况按倒计时处理。旁观者不是操作席，不因有人看画面就取消空席倒计时。

不再采用历史“16格内没有玩家就关机”，也不再用每台机每秒遍历周围玩家来实现空席关机。**按入席/离席等事件维护截止时间，运行中的房间检查到期即可**；已有旁观发现、租约续期与安全校验仍会运行，不能宣传为零轮询、零CPU。

离线、主持失效、换维度、设备移除/卸载等安全终止不由“不自动关机”开关豁免。该选项不承诺强加载区块、离线运行、主持迁移或跨重启恢复游戏进度。

物理电源开关：关机保留所选游戏，再开机不重新选 ROM，但仍按通用规范第 1 节执行该类型适用的开局／保存／加入确认；没有选择才提示去选游戏，资源缺失则明确报原因。启动上次所选游戏≠从上次进度继续。电源点击只执行一次通断和一次音效，动画／红灯与服务端状态一致；三种机柜的点击位置须与模型吻合，邻柜空选框不能挡住露出的开关，实际遮挡仍有效。

## 4. 设备配置菜单应该有哪些内容

下面统一的是**入口含义和权限**，不要求所有按钮挤在一个页面。只有设备确实支持时才显示对应能力；不支持要禁用并给原因，不得做能点但无作用的假按钮。

| 编号 | 页面/按钮 | 所有同类设备的统一要求 | 当前参考/差异 |
| --- | --- | --- | --- |
| UI-01 | 标题与状态区 | 设备名、当前游戏显示名、实际文件名或可追踪ID、运行状态、当前模式；连接组注明主/副关系 | 街机菜单已有当前游戏/核心信息；各附属状态字段仍需逐项核对 |
| UI-02 | 游戏/内容入口 | 清楚区分“服务器游戏”和“本地游戏”；列表具备刷新、搜索/分页、选择后的确认；本地选择不暗中成为全服共享 | 街机游戏库已有两入口；SFC卡带用写卡/编辑流程，电脑为程序路径选择，不强改成同一列表 |
| UI-03 | 同步 / 网络 | 仅列实际支持的玩家串流、本地同步、服务器托管、实验Netplay；显示当前模式、切换条件及不可用原因 | 家用与街机已有页面；支持掩码/平台注册应限制入口，不能只抄四个按钮 |
| UI-04 | 关机 / 屏幕距离 | 街机设备页只展示全服有效值与“由管理终端统一设置”的说明 | FC76.15已有只读入口；不能保留看似可保存的旧单机覆盖项 |
| UI-05 | 运行环境 | 检查结果、缺少的运行库/核心、重新检查、补齐方式、复制诊断、返回 | 公共运行环境页已有；游戏内不强行替换运行中的文件，提示退出世界后安装 |
| UI-06 | 控制设置 | 打开公共控制设置，展示本设备按键/手柄映射与冲突；运行中按键不能穿透菜单误触 | SFC复用公共输入体系；新增平台可能还需扩展公共按键profile |
| UI-07 | 音画 / 性能 | 本机音量、画质、网络限速等个人偏好明确写“本机”；不会顺手改变全服规则 | 现有入口分散在同步、网络等页，统一导航仍有待整理 |
| UI-08 | 私人模式 / 加入同意 | 仅适用设备显示；标明可见范围、授权对象以及更改前是否必须停机 | 家用同步设置已有私人模式、外部家用机加入需同意入口；不代表每个后端都有 |
| UI-09 | 保存 / 刷新 / 返回 | 编辑页有保存和返回，服务器状态页可刷新；加载中禁用保存，失败保留输入，成功反馈实际生效范围 | 街机全服页已有保存、刷新、返回及修订冲突控制 |
| UI-10 | 游戏资料编辑（管理员） | 显示名、支持人数、横/竖屏标注、比例；服务器统一保存，普通玩家只读 | 街机现有资料编辑；人数标签不修改PGM玩家数，横竖标注不等于核心已正确旋转 |
| UI-11 | 维护设置（如PGM/DIP） | 只允许OP且服务端复核；明确写支持哪些游戏、如何保存、何时清除 | 现有kov维护入口，不是通用DIP编辑器；“按机器保存、换游戏清除”尚待实现 |

按钮文案须区分“退出操作”“结束游戏/关机”“关闭菜单”“停止旁观”。点“返回/关闭”不得意外关机；程序有单独“结束当前程序”时须如实命名。普通玩家可正常操作游戏，不因有运行环境问题就要求其修改服务器全局配置。

缺资源提示必须说明：哪个设备/模式、缺什么、在哪里处理；“操作未完成，查看运行环境”可作为摘要，但复制诊断中要有实际错误，不能只给摘要。

## 5. 哪些配置必须放进管理终端

**GLOBAL-01：凡是影响其他玩家、服务器资源/权限、所有设备行为的配置，必须有管理终端入口。** 不得要求管理员挨个修改机器，或只在某个玩家的客户端配置文件里保存全服设置。

当前管理终端以OP权限使用，服务端还须复核在线身份、连接、持终端等条件；客户端藏按钮不算权限保护。

| 终端页 | 应有按钮/字段 | 生效范围与存储归属 | 现状 |
| --- | --- | --- | --- |
| 玩家权限 | 全体/仅授权名单、选用服务器游戏/封面、上传本机游戏/封面 | 服务端内容策略；操作时复核，不是只有打开菜单时检查 | 已有这些开关；完整名单编辑GUI不能假称已实现 |
| 新机默认 | 自动/玩家串流/本地同步/服务器托管；默认旁观范围 | FC76.26 自动对可用的 FC 优先 JNI Netplay，其他机型沿原策略；只给新放置家用机初值，旧机器不回填；世界SavedData | 已有，不是街机全服覆盖；JNI 平台/存档限制见 FC76.26 指南 |
| 街机全服 | 最后一人右键退出立即关机；无人占席秒数含0；显示/旁观距离；保存/刷新/返回 | **统一覆盖所有适用的新旧街机**；`piq_arcade_server_rules` SavedData；设备页只读 | FC76.15已有；当前原生街机范围，不宣称所有未来后端自动继承 |
| FC个人存档 | 不活跃清理天数、保存；0禁用 | 服务端FC个人存档保留策略；不能连卡带共享存档一起删，使用中跳过；不是SFC/街机策略 | 已有，合法0～3650天；76.21页面明确标注FC |
| 管理工具 | 单机设置/指令入口、本机网络/托管帧率、全服流量、开启/关闭流量监控 | 菜单必须标明“本机”与“全服”；监控按需开，不能永久给所有玩家广播明细 | 已有工具入口，不等于所有按钮都是全服配置 |
| 附属专属全服配置 | 每个附属的公共权限/运行限制/统一默认，保存、刷新、返回 | 由主模组协调终端入口与服务端持久化/同步；说明影响旧设备还是仅新设备 | **统一要求，通用插件式终端扩展API待补齐**，不可只注册后端就声称已接入 |

管理终端不应收集/统一保存玩家本地磁盘路径、个人键位、客户端音量、私人游戏文件。它们属于本机设置。服务器可设资源使用上限；本机偏好只能在允许上限内选择。

### 5.1 配置优先级必须写清

1. 全服强制规则适用的字段：**服务器有效值唯一权威**，客户端和单机旧NBT不得覆盖。
2. 新机默认：只在放置时初始化；允许的单机配置之后独立保存，不能称为强制全服。
3. 本机偏好：只影响该玩家；不得关闭服务端权限、放大操作距离或冒充OP。
4. 设备自身数据：所选游戏、连接关系等存设备；维护数据须按设备+游戏身份隔离，不能混入全服规则。

保存时校验类型和边界，携带当前修订，冲突要求刷新；不能显示成功却只写到本机。新旧客户端协议不兼容时明确拒绝/提示配套版本，禁止静默套错数值。规则变更按活动会话生效，不为更新全服值遍历加载所有世界区块。

## 6. 附属必须复用的共同行为

| 编号 | 统一要求 |
| --- | --- |
| COMMON-01 | 接入公共设备/控制租约/旁观/内容权限入口。系统ID、会话ID、玩家UUID、租约、ROM摘要分开；客户端可视状态不当作授权凭据 |
| COMMON-02 | 操作者可以影响输入，旁观者不能。退出、失焦、租约作废或连接变化必须释放输入，不能卡键；迟到包不作用于下一局 |
| COMMON-03 | ROM/封面首次获取需授权与大小/摘要校验；不得向全服在线玩家无差别发送。远离停止会话与文件下载策略分开；断点续传未实现时如实提示 |
| COMMON-04 | 运行目录按公共`game-console`存储入口，缓存、临时核心、正式存档分开；正常退出释放句柄，异常重启只清理已确认不在用的会话目录 |
| COMMON-05 | 存档必须记录游戏/核心/格式身份。模式不支持保存则禁用入口并解释；Netplay不支持保存不能“成功”写空文件 |
| COMMON-06 | 原生核心和重型IO不阻塞Minecraft主线程；可取消、有超时、有数量/大小上限。缺能力不要注册可用标志 |
| COMMON-07 | 所有全服设置可从管理终端找到；同名字段使用同语义、同单位。附属当前接口不够时先协调扩展，不能自行做第二套全服权威 |

## 7. 当前缺口清单：不能被这份规范掩盖

- 电脑显示/串流32格尚未与固定屏幕默认16格对齐；家用与街机配置的生效范围本来就不同。
- 附属菜单和全局终端扩展尚非完整统一SDK；`CabinetBackends`/`HomeSystems`等现有入口不能代替所有业务实现。
- PGM按机器持久化、切换游戏清除仍是独立待办（工作台GC-098），不是本次文档成果。
- 大ROM下载断点续传仍是独立待办（GC-102）；本规范没有把“缓存存在”写成“已有续传”。
- 本次没有运行Minecraft、打新JAR或修改现网，现有候选的实机、多人和性能验收仍保留原状态。

## 8. 开发验收：照这些场景逐项打勾

- [ ] DIST：主机6格手柄边界、街机8格操作边界、16格显示与20格旁观退出边界；上下高度、跨维度、主副屏分别测试。
- [ ] DIST：100格外普通玩家不建立重型会话；主持走远与普通旁观走远分开测试；返回时不会复用过期租约。
- [ ] POWER：1P退出但2P还在不关；所有席退出启动60秒；重新入席取消；0禁用；过场无按键不关。
- [ ] POWER：立即关机开/关与倒计时0/60四种组合；普通退出和主持断线的安全终止分别验证；关机后物理按键能重新启动所选游戏。
- [ ] UI：支持的按钮能完成动作，不支持的有原因；本地/服务器游戏不混淆；返回不关机；加载/超时/冲突不会假保存。
- [ ] GLOBAL：普通玩家伪造保存被拒；两管理员同时修改不静默覆盖；修改影响旧/新街机并持久化到世界；不改变家用机/电脑规则。
- [ ] GLOBAL：修改“新机默认”不强改旧家用机；本机键位/音画/磁盘路径不变成全服配置。
- [ ] COMMON：缺ROM/运行库、超大输入、旧包、主持退出、重入、资源释放均有可追踪结果。
