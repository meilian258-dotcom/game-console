# 方块电玩 / Game Console 开发进度与功能说明

文档版本：v1.0　｜　更新日期：2026-09-16　｜　维护：Codex / 项目作者

适用基线：FC `0.31.0-alpha.44`、街机附属 `0.1.0`、SFC `0.1.0-alpha.25`、GBA `0.1.0-alpha.8`。

本文是项目内部的开发总览和交接文档，集中记录功能、进度、技术边界、成品、验证和后续工作。它不是“全部功能已稳定”的声明，也不是公开发布授权。2026-09-16 本轮只核对源码、历史验证记录和成品哈希、整理文档，没有重新运行全部测试、启动 Minecraft、安装或发布模组。

首发计划保持：**先发布 FC 主模组，再逐步发布 SFC、街机、GBA 附属。** “街机本地同步正式化”只说明该功能取消实验标记，不等于整个项目通过所有验收。

### 状态用语

- **已实现**：当前代码/成品具备该路径，不自动代表所有场景实测通过。
- **自动验证通过**：对应版本的具体自动测试或构建检查通过，见第 10 节；不是游戏兼容数量。
- **用户反馈可用**：用户实际反馈成功，但只覆盖当时的环境和玩法。
- **待验收**：已有实现，缺少完整实机/多人/兼容性证据。
- **未实现 / 建议项**：不能作为当前功能宣传；建议项也不等于承诺排期。

## 2. 平台、名称与组件关系

当前目标环境：Minecraft **1.21.1**、NeoForge **21.1.236 起的 21.1 系列**、Java **21**。不能使用更早的 21.1 版本；更换加载器、Minecraft 大版本或其他 CPU 架构不在本次验证范围内。

对外名称为“方块电玩 / Game Console”。内部 `piq_*` 注册 ID、配置目录、存档目录等为兼容旧世界保留，不能为了去掉可见 PIQ 字样而随意改名。作者和上游许可证署名也不能当作界面品牌一并删除。

| 源码组件 | 职责 | 玩家安装方式 |
| --- | --- | --- |
| `piq-fc-arcade` | FC/学习机及共享方块、电视、机柜、控制、网络、ROM/存档管理 | FC 主 JAR |
| `piq-retro-platform` | 共用接口和运行平台代码 | 随主模组编译，不另装一个 JAR |
| `piq-sfc-home` | SFC 家用硬件、控制、会话及通用机柜适配 | SFC 附属 JAR，依赖主模组 |
| `piq-sfc-arcade` | SFC 模拟核心组件 | core alpha.9 已打入 SFC alpha.25，不能再重复装旧独立核心 |
| `piq-native-arcade` | 原生街机音画后端及定制 NeoGeo 快照同步后端 | 街机附属 JAR，依赖主模组 |
| `piq-gba` | mGBA 接入、单人机柜、手持掌机、电池存档 | GBA 附属 JAR，依赖主模组；运行库另配 |

主模组提供共享机柜，不表示只装主模组就能运行 SFC、GBA 和原生街机游戏。内部旧 FC 街机入口、旧独立 Native 验证机柜与当前通用机柜也不是同一条功能路径。

## 3. 已实现的设备与玩法

### 3.1 FC、学习机及卡带

- FC 红白机、学习机、实体卡带、裸 PCB/空壳、写卡电脑和 AV 接线。
- 主机电源、复位与电视独立开关；从对应设备进入游戏，不再通过右键电视直接打开游戏选择。
- 实体手柄可领取、归还、双人加入；第二席按当前会话规则申请/审批。附近玩家可自动旁观，不必占用控制席。
- 卡带写入和 ROM 管理、封面与存档策略设置；服务器共享内容的权限校验、缓存及去重。
- FC43 新增独立 Mapper19 路径，FC44 保留：已对指定《赤色要塞》汉化版本做离线运行验证；**不是全部 Mapper19 游戏兼容保证**。N163 扩展波形音频未实现，不能宣传为完整 N163 硬件复现。

### 3.2 光枪

- 光枪支架可放置，用数据线连接 FC；枪可独立取下，不要求先运行游戏。
- 左键扳机，准星映射电视实际游戏区域；有屏外射击路径。
- 光枪占物理第二控制口，可与 P1 手柄并用；不能再同时借出普通 P2 手柄，也没有双光枪模式。
- 持枪保留适用的 FC 按键操作能力，但服从席位权限，不会夺取其他玩家的 P1 控制权。
- Mapper19 核心不支持光枪；“连接了光枪就不能使用所有手柄”的旧问题已按端口职责拆分处理。
- 光枪与普通有线手柄采用各自距离/权限规则，不能将手柄“6 格自动归还”直接套到光枪。

### 3.3 SFC

- 用户提供的主机、卡带和手柄模型已接入，包含实体取还、线材及按键动画路径。
- 双人本地输入同步、附近旁观、P2 中途加入、摘要检查和单端恢复均有实现。
- 恢复时尽量只修复落后的客户端，避免一律让主持端停住；初次加入的初始化阶段仍可能短暂停顿。
- 家用与通用机柜路径均有实现，但**最多两个控制口**，不能因连了两个双人柜就变成四人 SFC。
- 存档范围见第 7 节：本地恢复备份与托管 SRAM 是不同能力，不能写成已具备 FC 的完整个人三槽体验。

### 3.4 街机

- 单人、双人通用机柜，游戏/核心选择、外观设置、席位申请、联机与旁观。
- 数据线可连接兼容机柜，两端显示同一局画面，且世界中可见连接线。
- FC44 恢复通用机柜“正在使用：玩家名”显示，数据来自实际控制席，旁观者不占席；新显示仍需实机退出/断线/双柜回归。
- 0.1.0 正式提供固定 `kof97.zip` / `mslug2.zip` 配置的本地输入同步。校验 ROM、BIOS、核心及配置身份，**不是只检查文件名**；地区版、修改版和重新压缩的包可能不匹配。
- 普通音画路径仍用于其他兼容街机游戏。原生模拟器支持某款游戏，不等于本模组已对该游戏完成所有联机验证。

### 3.5 GBA

- 单席机柜与手持小掌机均有版本。掌机主手右键开关，Shift＋右键进入选择/设置；副手空闲时使用双手姿态，副手有物品时不吞掉副手物品。
- 手持掌机的画面和声音面向本机持有玩家，不是其他玩家均能观看的共享掌机屏幕。
- 机柜可旁观，并有玩家托管/服务端托管路径；只有一个控制席。
- 电池 SRAM/EEPROM/Flash 保存与退出收尾已有实现，不能等同“任意帧即时存档”。
- 使用 mGBA 的 HLE 启动路径；没有实现 GBA 原机通讯线、宝可梦交换/对战或四人原生联机，也没有承诺光照/运动传感器游戏兼容。

### 3.6 电视、音光、线材和家具

| 功能 | 当前行为 / 边界 |
| --- | --- |
| 家用电视 | 当前注册五种家用电视；勿沿用旧文档“六款”的计数 |
| 电视电源/音量 | 关机黑屏；开机无信号为彩条和提示音；有效游戏信号出现后停止无信号音；音量键可用 |
| 灯光 | 电视开机绿灯并提供方块光照；FC/SFC 电源指示有亮灯效果，但不额外提供场景照明 |
| 电视关机 | 会结束连接设备的游戏；不是仅把画面隐藏、核心继续无限运行 |
| 扫描线遥控器 | 已有电视扫描线开关，按电视独立保存；它不是尚未实现的“同步调试工具” |
| AV 线 | 连接家用主机与电视；与光枪/机柜数据线职责不同 |
| 数据线 | 连接光枪支架与 FC，或兼容的两台机柜；提供可见连线，不做绳索碰撞/绕障碍物理 |
| 有线手柄 | 持有人与主机的有效距离为 6 格；超过后回收对应手柄，不因此强制停止别人的控制席或整局游戏 |
| 长凳 | 11 木种、两格长、两人可坐；空手右键入座，按原版潜行下座 |
| 马扎 | 11 木种、单人；空手右键入座，Shift＋空手右键展开/收起；有人时不能折叠 |
| 创造物品栏 | 家具已合并到游戏机同一页；家具共 22 款，没有连续机械折叠动画 |

## 4. 统一交互与输入规则

### 4.1 电源、持有道具和控制权相互独立

正常体验可按“放置接线 → 插卡/选游戏 → 开电视及主机 → 取手柄/光枪 → 操作或旁观”进行；手柄和光枪也允许提前取下。**拿到道具不等于无条件启动核心或获得其他玩家的席位。**

主机开机后，电视可以显示游戏，未领取控制权的人只能观看。手柄可右键主机非按钮部位归还，光枪可右键支架归还。点电源/复位等功能区时应执行对应按钮，而不是把所有右键统一成取还。

常规右键流水提示已经减少；必要错误、权限反馈、占用信息及电源/复位等悬浮提示仍保留，不能理解成完全静默、失败也不提示。

### 4.2 键盘与 N 锁定

当前新配置默认 **WASD + JKL / IOP**；锁定键默认 **N**，控制设置默认 **F7**。可选方案为：

1. 方向键 + JKL / IOP。
2. 方向键 + 小键盘 1–6。
3. WASD + JKL / IOP。
4. 自定义键盘布局。
5. 跟随 Minecraft 按键设置。

默认交互：拿起有效手柄后，游戏功能键立即生效并隔离标准原版/模组同键行为；未锁定时 WASD 仍可在世界走动。按 N 后，WASD 转给模拟器并屏蔽主动走路、跳跃、潜行和冲刺；再按 N 恢复并行移动，**不是关闭所有游戏按键**。放回手柄后恢复正常。

N 不锁视角，不免疫重力/击退，也不是服务端强制定点。独立方向键方案不必等待锁定才发送模拟方向。GUI 打开、失焦、换手和失去权限时清理输入，恢复接管要求按键回中，防止“松手仍一直按着”。

新配置参考：FC A=K、B=J；SFC B=J、Y=L、A=K、X=I、L=O、R=P；街机按钮 1–6=J/K/L/I/O/P；开始 Enter，选择/投币 Backspace。**实际以设置页为准**：旧配置、自定义和“跟随 Minecraft”不会被这张参考表覆盖。

旧默认 Z/F8 仅在可识别且无冲突的条件下迁移；不强改用户自定义，不重写原版 `options.txt`。直接绕过标准输入系统读取设备的第三方模组仍需单独兼容测试。

### 4.3 USB / 蓝牙实体控制器

已有默认启用、设备选择/自动选择、按系统独立映射、按钮捕获、死区与测试页面。设备只控制当前玩家已取得的席位，不会插入一个实体手柄就自动占用网络 P2。Xbox、PlayStation、Switch 等控制器受系统映射影响，尚不能宣称所有型号都实测兼容。

## 5. 联机同步：实现方式、默认值和限制

### 5.1 三种方式到底差在哪里

| 模式 | 谁运行模拟器 | 网络主要传什么 | 优点 | 当前代价 / 风险 |
| --- | --- | --- | --- | --- |
| 本地输入同步 LOCAL | 每个控制端运行同一核心 | 输入、摘要、加入/修复/检查所需快照；旁观仍为音画 | 控制端可本地生成画面，不持续向每个控制者串流整幅图像 | 核心/内容必须一致；仍有快照流量，CPU 不集中但每个控制端都要计算 |
| 玩家托管音画 MEDIA | 开局的主持玩家 | 其他玩家输入到主持端，主持端音画经服务器分发 | 客户端核心差异少、能覆盖较广游戏范围 | 主持电脑承担模拟和编码；受主持上行、服务器中转和网络延迟影响 |
| 服务端托管音画 SERVER | 服务器工作线程或受管理的辅助进程 | 客户端输入上行，服务端音画下行 | 不要求某个玩家电脑一直计算；便于集中管理 | 服务器增加 CPU、内存和下行负载；需要可运行的核心及明确启用 |

没有统一实测数据可保证“固定每人多少 KB/s / 多少 CPU”。分辨率、帧率、声音、人数、旁观者和恢复快照都会改变负载。当前不能把本地同步宣传为“只传按键、零画面流量”，也不能把服务端托管宣传为“无延迟”。

### 5.2 当前支持矩阵

| 设备 / 后端 | LOCAL | MEDIA | SERVER | 未设置时默认 / 席位 |
| --- | --- | --- | --- | --- |
| FC 家用机、学习机 | 已接通 | 未接通，入口禁用 | 已接通 | 本地；最多 2 口 |
| 旧 FC 街机入口 | 原固定路径 | 不属新三模式范围 | 不属新三模式范围 | 固定原本地；最多 2 口 |
| SFC 家用机 | 已接通 | 未接通，入口禁用 | 已接通 | 本地；最多 2 口 |
| 通用机柜 SFC | 已接通 | 已接通 | 已接通 | 托管启用且可用时优先托管，否则本地，再否则允许的玩家串流；均最多 2 口 |
| 通用机柜 Native | 固定 KOF97 / MSlug2 配置 | 已接通 | 已接通 | 托管启用且可用时优先托管，否则玩家串流；本地 2 口，音画最多 4 口且依游戏 |
| 通用机柜 GBA | 未接通多人本地同步 | 已接通 | 已接通 | 托管启用且可用时优先托管，否则玩家串流；1 口 |
| GBA 掌机 | 本机单人，不是网络 LOCAL | 不适用 | 不适用 | 本机单人 |

已有机器的显式设置保留；后端不支持或服主禁用时要明确反馈，不能无提示替换用户所选模式。服务端模式是真正运行核心，不是伪造一个玩家充当主持。

### 5.3 谁能切、在哪里切

- 家用机：非按钮区域的空手交互入口，或准星对准设备使用 `/home-sync`。
- 通用街机：Shift＋空手右键，在当前模拟器的“同步 / 网络”入口选择。
- 更改由服务端校验管理员权限（OP 2）及机器空闲状态，连柜两端都需空闲；不能在游戏中热迁移整局。
- “创造模式专用同步调整工具/调试遥控器”目前仍是设计建议，**没有新增这个物品**。已有电视扫描线遥控器与此无关。

服务器配置为世界的 `serverconfig/piq-sync-server.toml`，源码默认值如下；本次没有改动任何服务器配置：

```toml
serverHosting = false
allowPlayerHosting = true
allowLocalSync = true
maxHostedRooms = 2
hostedBytesPerSecond = 2097152
```

全服家用/机柜托管共享容量，默认最多 2 局，可设 1–4；启动和关闭收尾期间也占位，真正终止后释放。各原生适配器还有单执行实例限制，调大总上限不等于能同时开四个 Native 核心。带宽预算包含接收者副本，旁观另有预算，不代表无限人数。

### 5.4 退出、断线和主持交接

| 路径 | 当前生命周期 |
| --- | --- |
| 家用本地 / 通用机柜 LOCAL 或 MEDIA | 主持端退出仍结束本局；没有普遍无缝主持迁移 |
| 旧 FC 街机路径 | 另有成员保留与角色补位逻辑，多人时 P1 断线不一概结束；不能套用通用机柜主持退出规则 |
| 通用机柜服务端托管 | 原控制者离开，剩余有效控制者可继续；管理者按规则重选，旧申请失效；无人或设备失效后清理 |
| FC 家用服务端托管 | 原开机者离开，已有有效控制者可继续；个人存档写权和邀请权限不会因此随意转移 |
| SFC 家用服务端托管 | 仍依赖原 Host 权限模型，原开机者离线/换连接会结束；不要与通用机柜混写 |

旁观者不占控制席，不能凭收到画面绕过邀请、接管存档或变成主持。

## 6. 数据线连柜与四人玩法边界

连接是**两台兼容机柜配对**，不是无限串联。现有检查包含同维度、距离、交互权限、设备空闲及已有连接关系；两端连上后共享房间和画面，保留各自外观。

硬件席位组合为 1+1、1+2、2+2，但实际人数还受核心、同步模式及游戏支持限制：

- Native 音画模式：最多四口；支持相应人数的游戏才可以四人。
- Native 当前本地同步：最多两口，可用一台双人柜或两台单人柜；不是两台双人柜四人本地同步。
- SFC：始终最多两口。
- GBA：单席，无原机通讯联机。

数据线视觉上类似家用机接电视的线，不表示底层同步变成原主机硬件电气串联。单纯增加模型或连接两个显示器不会扩展游戏本身的玩家数。

## 7. ROM、缓存与存档

### 7.1 上传下载与缓存

共享游戏由玩家提供，经过服务端权限和内容校验后存储、复用；不因他人上传过就绕过权限。上传去重已实现：匹配的服务端对象复用，只补缺失的 ROM/BIOS 内容；“正在上传”不应被当作每次必须完整重传的设计。

ROM 和 BIOS 分开验证，另有长度/哈希、路径、会话、连接和席位检查。这里记录的是已实现防护，不宣称系统不存在漏洞。模组不提供商业游戏 ROM 下载源；用户或商业游戏 ROM、用户 BIOS 和玩家存档不得混入交付。完整上游源码中有明确来源/许可的开发回归 ROM 或空存档夹具应单独核对，不按扩展名一律删除，避免破坏对应源码完整性。

### 7.2 各平台存档不能混为一谈

| 平台 / 路径 | 已有能力 | 明确边界 |
| --- | --- | --- |
| FC | 关闭存档 / 个人存档 / 机器共享三策略，个人三槽和写权租约 | 策略按 ROM 身份管理，不是每张实体卡独立开关；个人三槽是对应命名空间下玩家的全局三槽，**不是每个 ROM 各三槽** |
| FC 特殊核心及托管 | 普通 FC、光枪、Mapper19、服务端家用采用隔离命名空间 | 不自动把旧核心/旧模式存档转换成新模式可读格式；接管席位不等于获得原主人的存档写权 |
| SFC 本地家用 | P1 恢复备份 `latest.state/latest.sram/latest.txt` | 不是自动读取的服务器个人存档，也不是 FC 个人三槽 |
| SFC 服务端托管 | 实际读取/保存游戏 SRAM，并隔离玩家/机器、ROM 和模块身份 | 电池存档不等于任意帧快照；不自动迁移本地备份 |
| GBA | 电池 SRAM/EEPROM/Flash，周期及正常退出保存、原子替换/备份 | 按服务器/世界、玩家与 ROM 隔离；不是即时存档或跨服云同步；不自动覆盖 ROM 旁用户原有 `.sav` |

更新不能删除旧世界、配置、ROM、个人存档或未知文件。模式切换前需明确告知存档隔离，而不是让玩家误以为存档丢失。

## 8. 首次安装、运行库和平台支持

### 8.1 玩家拿到什么

| 使用范围 | 模组文件 | 额外运行文件 |
| --- | --- | --- |
| 只玩 FC | FC44 一个 JAR | 核心及支持平台的 Wasmtime 随包；不需另装 SFC/街机 |
| FC + SFC | FC44 + SFC25，共两个 JAR | SFC core alpha.9 已内含，不重复装旧核心 |
| FC + 街机 | FC44 + 街机 0.1.0，共两个 JAR | Windows x64/JVM amd64 从街机 JAR 补齐六项固定库；ROM/BIOS 自备 |
| FC + GBA | FC44 + GBA8，共两个 JAR | 执行核心的一端仍需三项 GBA 运行文件，不能由街机附属代替 |

GBA 三文件位于对应实例 `piq-gba/runtime/`：`mgba_libretro.dll`、`piq-gba-helper.jar`、`jna-5.14.0.jar`，不放在 `mods/`。现有三文件合计约 4.85 MB。

街机 JAR 约 124.73 MB（十进制），内置六项库解压后约 432.7 MB；FC JAR 约 30.80 MB。运行库不是游戏 BIOS。自动补库复用匹配文件、补缺失文件，对冲突文件明确报错，不静默强制覆盖，也不从网络临时下载可执行文件。

### 8.2 安装端和运行端

客户端/服务器均需匹配的主模组和用到的附属；联机不能靠只给开局者装一个附属解决。原生运行库则看**谁执行模拟器**：

- 本地同步：每个控制端都执行核心，均要满足运行环境。
- 玩家托管：主持端执行；仅媒体接收者/旁观者不用执行该核心。
- 服务端托管：服务器执行，服务器也要满足对应运行环境；不能沿用旧文档“服务器永远不需 DLL”。

FC/SFC 的打包环境覆盖 Windows/Linux x64 Wasmtime；Native/GBA 当前执行核心要求 Windows x64。Linux 可以承担不执行 Windows 核心的中转/音画接收职责，但不能加载 Windows DLL。这不等于已经完成 Linux 专服实机验收，也不承诺 macOS/ARM。

### 8.3 BIOS 与发行边界

FC/街机当前交付不附商业游戏 ROM 或用户提供的 `neogeo.zip`；GBA 为 HLE 启动。**SFC 核心内存在 64 字节 SPC700 启动固件，来源/许可仍需核对**，因此不能把“所有附属绝无任何 BIOS/固件字节”当作已核实结论。

后续公开发行还需核对上游模拟器和依赖许可、精确对应源码、预编译依赖的构建/来源资料、模型贴图及保留商标的使用依据。本节是工程发行待办，不是法律结论，也不以“免费”替代这些核对。
