# 街机本地同步实验：FC33 / Native11

这是测试包，不是自动更新或安装器。现有街机直接切换模式，没有新机台。现有 FC/NES 与 SFC 家用操作不改；SFC19、GBA2 保留原版本。

## 安装范围（请先退出游戏并备份测试世界）

1. 服务器和所有客户端统一使用包内 `mods/` 的 FC33、Native11；使用 SFC/GBA 的玩家保留配套 SFC19/GBA2。同一模组只放一份，旧 JAR 先移出 mods 备份，不叠放。不要额外叠加旧独立 SFC 核心包，SFC19 已含两个历史 ID。
2. 要参加街机本地同步的 **Windows x64 客户端**，将包内 `piq-native-arcade/runtime-snapshot-v1/` 放到该 Minecraft 实例目录下，不放 mods 内。三文件必须齐全；不要改名或替换 DLL。
3. 原 `piq-native-arcade/runtime/` 不删、不覆盖，它供“传画面”模式使用。本包不重复提供原来的通用大 MAME DLL；只有实验运行库时，未验证的其它街机游戏仍需要原运行库才能玩。
4. 专用服务器只需模组，不运行模拟器，也不需要上述 Windows 运行库。旁观者沿用媒体画面，不占控制席位。

本包不包含商业 ROM、BIOS、玩家存档，也不会替你上传游戏。源代码、MAME 原始源码、最终五补丁及重建说明另提供同名“核心源码”配套包；源码不是游玩的必装文件。

## 选择与启动

- 管理员 Shift＋空手右键现有机台 → **同步/网络** → **本地同步（实验）**。全部相连机柜必须空闲；配置仅对下一次开局生效，不能在运行中热切换。
- 管理员在现有游戏管理页选择/明确共享合法 `kof97.zip` 或 `mslug2.zip`，配套 `neogeo.zip` 必须同目录并纳入共享清单。之前缺 BIOS 的旧绑定需要重新选择；不会自动上传你未选的目录。
- P1 正常右键开局；朋友按现有邀请/审批流程加入 P2。加入端先校验游戏、BIOS、运行库身份，再接收完整状态并追帧，完成前不能控制；主持端不需要暂停。
- 仅两款已核验 ROM 集，且字节必须匹配下方摘要。其它版本/改版/同名不同集明确拒绝；可在结束本局后选回传画面，不会替换你的文件。
- 实验最多 **2 个席位**：一台双人柜或两台单人柜连接可用；双人柜之间形成3/4席的串联不能启用实验模式，传画面原能力仍保留。

## 预期与限制

- 本地控制玩家分别运行核心；每300帧比较完整状态摘要，每1800帧（约30.4秒）上传主持快照。快照约3.33MB，持续状态payload约0.88Mbps，加入/纠偏还要下载状态；有旁观者时另有音画流。不是只传按键，也不是零带宽。
- 每次加入需加载核心、传状态和追赶，实际耗时取决于电脑/网络。慢端恢复超时只退出该端，主持人继续；主持人离开仍结束整局，不支持无缝主持迁移。
- 固定核心真实59.1856Hz/48kHz，不做超频。因此《合金弹头2》原硬件在密集场景的减速不会仅靠同步模式消失。
- 只在可信朋友/备份测试世界试用。客户端会在隔离子进程中加载固定核心与游戏数据；哈希/进程隔离不是操作系统级安全沙箱。
- 离线核心/协议/生命周期验证不等于两台 Minecraft 公网真人验收。以随包 verification 报告为证据，首次请两人实测下表。

## 两人验收清单

1. 同一游戏开局：P1正常玩，P2申请并获准；双方看到相同局面，各自按键只控制自己的角色。
2. P1继续玩约2分钟，P2退出再加入；P1不中断，P2追上后音画正常、没有历史音频爆发。
3. P2切后台/开GUI/归还控制，角色按键不粘连；P1退出后房间结束，朋友可从已共享游戏重新开新局。
4. 附近不右键的玩家可旁观；单人柜数据线两端显示相同画面。
5. 关局后切回传画面，原其它游戏/SFC/GBA照常；运行中不能改模式。缺运行库、错BIOS、第三席应明确拒绝，不应卡死或偷偷重开主持局。
