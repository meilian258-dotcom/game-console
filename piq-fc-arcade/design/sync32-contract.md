# alpha32 联机优化工作合同

2026-09-12，像素匠。范围为联机优化和游戏内同步模式切换；不改变 ROM、BIOS、存档和模型。

## 范围与分工

- 服务器机柜游戏绑定与受控内容分发、原版风格模式/诊断界面、带预算媒体自适应、最终构建/集成/交付/留痕。
- 通用机柜确定性核心 API/worker、模式权威与协议、逐帧输入/加入状态/单端纠偏及回退，主要所有权 CabinetClientBackends/CabinetRooms/CabinetRoomNetwork/RoomLedger。
- SFC 家用持续校验与仅异常端重同步、SFC 同步 core 适配和家用/机柜共用核心执行逻辑、真实双 WASM 测试。
- MAME 真核双实例确定性与快照验证，仅通过的核心/游戏开放实验性本地同步；不可靠则保持明确禁用与证据，不伪造可用开关。

## 约束

1. FC32/SFC19/Native11（如变更）成套协议；GBA2兼容检查，必要时另发新版本，不能破坏其存档作用域。
2. 旧 FC/NES 稳定锁步不整体重写。共享 ROM 不意味着共享个人进度，启动者更换默认新局/自己的存档，不做未经验证的无缝 Host 迁移。
3. 服务端绑定 backend+机柜身份+游戏内容清单；不收客户端绝对路径。只同步明确选定 ROM 与允许的 BIOS/父集，不同步 DLL/helper/JNA/可执行代码。内容哈希、扩展名、数量/容量/频率、操作权限和异步前后实际连接/lease/hardware均验证。
4. 模式是机器的会话配置：空闲时切换，下次启动生效；运行期间不直接替换核心或覆盖进度。参与者能力和内容一致性不满足时给具体原因，不暗中退回不同步的运行。
5. 视频指标区分核心产帧、编码、网络发收、渲染和丢弃；不以固定 20→60 替代实际优化。保持每连接背压、有限队列、参与玩家优先和全服旁观预算。
6. 新同步必须实际跑两核心验证；普通模拟器冒烟、源字符串测试不是实际 Minecraft 多人验收。状态导入前绑定 ROM/core/build/session/epoch/frame/lease/connection/期限，落后补帧无历史音频。
7. 所有产物新目录，旧 FC31/SFC18/Native10/GBA2 JAR 和交付 ZIP 保持；构建前后源码围栏、资源/模型保护、final-JAR 测试、依赖/重复类/专服侧检查后再交付。
