## 3. 交互约定

- 主模组内置 FC，SFC / 原生街机 / 后续模拟器作为附属；保留好友联机和自动旁观，不将远端 P2/P3/P4 当作同键盘玩家。
- 操作尽量对齐 FC；右键机器进入，再右键退出。Shift+右键配置，皮肤在第一级菜单；本轮键盘改动不替换旧机器交互。
- UI 要居中、较小、原版风格，不要铺满屏幕或模糊文字。
- 默认 F7 打开统一设置，命令 `/fc-controls` 也可进入；原 `/fc-gamepad` 保留。
- 默认 F8 为本人操作锁：进入模拟器控制模式时禁止主动走动，再按解除；不结束会话、不重启核心、不锁鼠标视角、不干预别人的输入。不是免重力/免击退的世界冻结。
- 四套键盘方案分别按 NES / SFC / ARCADE 保存：现有方案、方向键+小键盘、WASD+JKL/IOP、自定义键位。
- 具体新预设：方向键或 WASD 控方向；小键盘 1～6 或 J/K/L/I/O/P 控功能；Enter 开始、Backspace 选择/投币。
- ARCADE 按键1～6对应协议 bits 0/1/8/9/10/11，按顺序映射1～6或JKLIOP；SFC为 B/A/Y/X/L/R。不要混用 SFC B/Y/A 的位序导致街机 J/L/K。
- WASD 方案初始为自由移动，需按操作锁才玩；现有方案和小键盘初始允许边移动边玩。解除操作锁后本人键盘/手柄都暂停向模拟器送输入，当前游戏会话保留。

## 4. 已实现的代码入口

源码链接相对于本文件。

### 共享键盘与 GUI

- [KeyboardInput.java](../src/main/java/cn/piq/retro/client/KeyboardInput.java)：宿主 attach/poll/pause/release、有效控制权、焦点、热键和按键路由。
- 同目录 `KeyboardConfig`、`KeyboardConfigStore`、`KeyboardControlState`、`KeyboardRouting`：纯配置/状态/路由，可离线测。
- 配置保存在实例 `config/piq-keyboard.properties`，显式保存、原子写入、版本竞争检查；不能写入 MC 的 `options.txt` 来禁用移动键。
- [KeyboardHandlerMixin.java](../src/main/java/cn/piq/fcarcade/mixin/KeyboardHandlerMixin.java)：真实 `KeyboardHandler.keyPress(JIIII)V` 的 HEAD 可取消注入，只在客户端注册。
- [ControlSettingsScreen.java](../src/main/java/cn/piq/retro/client/ControlSettingsScreen.java)：统一入口；同目录 `KeyboardBindingsScreen` 为自定义草稿、`ControlPanelLayout` 负责最大440×284布局、`ControlLabels` 为动作名称。
- [共享键盘详细交接](unified-keyboard-handoff-20260911.md)。

重要约束：

- 使用已有宿主输入身份与控制权，不额外抢一次全局 owner。只有当前连接、当前机器、有效租约的本人才能输入。
- 切方案/失焦/打开 GUI/解除锁时清本人输入，恢复需所有绑定键松开、摇杆回中后重新按下，防卡键。
- 不吞 Esc、鼠标视角或右键；按键拦截必须早于原版 KeyMapping.click，不能只用事后 InputEvent.Key。
- 旧方案保留实际 MC 主键、备用键以及 Reset/Mute。若旧功能占用 F7/F8，禁用对应新热键并提示 `/fc-controls` 重绑；保存也校验实际冲突。
- 旧 FC/SFC 的临时 UNKNOWN 解绑不再新增，历史未恢复的键位日志恢复逻辑仍保留。

宿主接入：FC `ClientArcadeSession` / `ClientArcadeEvents` / `ArcadeKeyMappings`，共享柜 `CabinetClientBackends`，SFC `SfcHomeClient` / `SfcHomeKeys`，Native `NativeArcadeClient`。本轮没有改服务器席位协议、Native helper 或旁观网络逻辑。SFC 柜使用 SFC 配置，但旧柜 LEGACY 的 O/P 保持原样。

### 实体手柄

- `GamepadConfig.defaults()` 改为启用、空 deviceKey 表示自动选择首个标准映射设备；已有明确关闭设置不强行开启。坏配置安全关闭。
- `GamepadInput` / `GamepadMixer` 仍受当前有效 owner、焦点和输入模式限制，不接管世界或其他玩家。
- [GamepadSettingsScreen.java](../src/main/java/cn/piq/retro/client/GamepadSettingsScreen.java)：连接反馈、实时按钮/轴、死区、各系统映射；`GamepadDeviceScreen` 为独立设备列表。
- 映射按物理“上/下/左/右方面键”标注，避免 Xbox / NS / PS 的字母布局误导；是否识别取决于系统和 GLFW 标准映射，不能承诺所有手柄即插即用。
- 无标准映射设备可见但不可选；捕获绑定要求先中立，失焦或设备身份变化重新等待中立。手柄页单独保存，取消不写配置。

## 5. 光枪进度与下一步设计

### 核心已完成的部分

- [独立光枪核心交接](zapper-core-20260911.md)。
- Java `NesCore` 新增默认可选接口 `supportsZapper()`、`setZapperState(x,y,offscreen,trigger)`、`stateNamespace()`；旧核心默认不支持。
- [ZapperWasmNesCore.java](../src/main/java/cn/piq/fcarcade/core/wasm/ZapperWasmNesCore.java) 仅显式构造时使用新 `/core/nes_zapper_v1.wasm`，旧宿主仍用旧核心。
- Rust `native/nes-rust` 的 zapper feature 默认关闭；独立 FFI 在 `native/nes-zapper-ffi`，用 `native/build-zapper.ps1` 构建，不能覆盖旧模块。
- 原生输入是256×240、port2 `$4017` 的光感/扳机；保留P2 D0。模拟器硬件port2不是MC玩家P2，单人枪可接硬件port2并保留手柄1操作菜单。
- 新模块 SHA `C8D8824E5CAF727678C642E6B0539DEAA7C0084F33524D96779D90C7B5DA79EF`；旧模块 SHA `110711E30B64444414A8BE2D0A3B1AB45A442CC9B9452AC7D74DAAB508C933FF` 不变。
- 新快照使用独立magic/版本、模块SHA、ROMSHA、baselineSHA和分配指针校验。后续宿主必须用 stateNamespace 隔离存储，不能把新旧 WASM 全内存快照混读。

光枪测试样本：Mapper 0 的 `.nes` 文件。Mapper0，24592字节；SHA `6412CFDEAF5618C8352E1F8FB7DC226D8C280D5ECFA1FD3250858F1EC48E5907`。两实例同菜单同时间线，在frame661给(98,138)瞄准与屏外射击，得到001000对000000，10断言通过、原ROM哈希不变。这是离线ROM核心验证。

游戏 ROM、BIOS、内存状态与私有测试画面不得进入公开发行资料。

### 尚未实现，后续要做

1. 注册枪和展示支架、领取/归还与当前主机绑定。区分枪本体/扳机和支架/盘线，不能整套模型拿在手里；接第一/第三人称握姿、动画及动态线。
2. 枪口沿源坐标 -X。扳机pivot `[9.52327672,4.03390858,8.204]`，本地Z转8°约0.07秒；通过运行时矩阵实现，不能把8°塞进不支持它的静态模型旋转。源变换已烘焙，不再重复应用。
3. 用实际 AV 连接的电视锚点和当前显示风格计算视线到有效画面的交点。大CRT/宽屏/旋转/黑边沿 ScreenSurfaceGeometry，不按整个玻璃猜尺寸。接世界遮挡、距离、维度、断线/卸载与有效本人租约验证。
4. 瞄准位置只是传感器输入，鸭子命中仍由NES ROM判断；不能用MC世界亮度或鼠标点击鸭子图块直接加分。
5. FC为确定性逐帧输入同步，不能只给本机实时塞坐标。枪坐标/屏外/扳机必须进入有界权威帧记录、重放历史、快照与加入流程，远端旁观不获得控制权。不要误套通用街机图像流协议。
6. 失焦、打开GUI、归还、断线、离开距离等应明确释放扳机/转屏外，拒绝陈旧会话或乱序输入。
7. 再做单人游戏内大电视测试、两名真实客户端/旁观测试、已有FC/SFC/街机回归后，才可交付“光枪能在Minecraft里玩”的版本。

这是一份接续方案，**不是本次记录时已实现的功能**。
