# 方块电玩：首次安装与更新说明

本套为本地测试版：主模组 FC alpha.40、SFC alpha.24（已合并 core alpha.8）、街机 alpha.15、GBA alpha.8。适用 Minecraft 1.21.1、NeoForge 21.1.236 起的 21.1 系列、Java 21。客户端和服务器使用同一套，不混放旧版同 ID 的 JAR。

## 只玩 FC 或 SFC

1. 完全退出 Minecraft，把 `block_arcade-0.31.0-alpha.40.jar` 放入实际游戏实例的 `mods` 文件夹。
2. 要玩 SFC，再放入 `block_arcade_sfc-0.1.0-alpha.24.jar`。它已经包含 SFC 核心，不要另装重复的旧 SFC 核心包。街机和 GBA 附属不是 FC 的必需品。
3. 启动游戏。FC/SFC 所需的模拟核心与 Wasmtime 运行环境随 JAR 提供，通常不用额外安装下面的离线运行库包。现有二进制范围是 Windows x64 / Linux x64，不包括 macOS、ARM64；本轮未进行 Linux 实机验收。

游戏文件需自行合法准备；安装运行库不会附送、下载或生成商业游戏，也不负责补街机 BIOS/父集合。

## 本机要运行街机或 GBA

加上对应附属 JAR：`block_arcade_cabinets-0.1.0-alpha.15.jar` / `block_arcade_gba-0.1.0-alpha.8.jar`。这两种附属当前使用 Windows x64 外置核心，不是“只装 JAR 就自动联网下载”。

1. 取得本次附带的原封不动 `piq-runtime-pack-v1.zip`。放到实际游戏实例的 `piq-runtime-packs` 文件夹，与 `mods` 同级；不用解压，不能放在 `mods` 内。文件夹不存在时可以创建。
2. 启动到主菜单。缺库时通常自动出现“方块电玩 · 运行环境”；没弹窗时，从“模组 → 方块电玩 → 设置”打开。
3. 点击“重新检查”，确认找到离线包，再点“一键补齐”。等需要的项目显示就绪，返回主菜单进入游戏。

正确的摆放示例：

```text
实际游戏实例/
  mods/
    block_arcade-0.31.0-alpha.40.jar
    block_arcade_cabinets-0.1.0-alpha.15.jar  （可选）
    block_arcade_gba-0.1.0-alpha.8.jar         （可选）
  piq-runtime-packs/
    piq-runtime-pack-v1.zip
```

HMCL 开启版本隔离时，“实际游戏实例”通常是该版本目录，不一定是启动器总目录。运行环境页的“游戏目录”按钮可以定位。离线包不能改名；约 127 MB，完整安装展开约 438 MB。只装 GBA 附属时仅安装 GBA 所需的三文件，但提供的 ZIP 必须保持完整九文件格式。

首次补缺只能在退出世界、未连接服务器时执行。成功补齐后重新检查即可，没有强制重启要求；新增或替换模组 JAR 必须重启游戏。安装器只写缺失项、校验大小和 SHA-256，正确旧文件复用；错误版本不自动覆盖。建议使用本地可写 NTFS 目录，网络盘或不支持硬链接的文件系统可能无法安装。

## 缺库或安装失败怎么办

- “未找到离线包”：检查上面的实际实例、文件夹和文件名。外层“方块电玩测试包”不能代替内层运行库 ZIP；程序不会自动下载。
- “版本冲突/校验失败”：在运行环境页复制诊断，完全退出相关游戏或服务端，先备份再处理诊断列出的准确冲突文件。不要清空整个模组数据目录，也不要从不明网站找同名 DLL。
- 文件都在但开不了：点“重新检查”。启动时的快速提示只检查文件存在性；正式检查才计算哈希。系统平台、临时目录权限或被隔离的文件也可能导致加载失败，复制诊断和日志排查，不要直接关闭安全软件。
- 单独看到 `mame_libretro.dll`、`piqneogeo_libretro.dll` 缺失：分别对应普通街机和实验本地同步核心；用配套离线包补齐，不是把 DLL 放进 `mods`。
- 只玩 FC/SFC 却报 Wasmtime 加载失败：确认系统为受支持的 x64 平台、模组包完整、Java 临时目录可写可加载；上述 Native/GBA 离线包不能修复 Wasmtime。

## 多人时谁要安装运行库

| 玩法 | 谁真正运行模拟核心 | 街机/GBA 外置库放哪里 |
| --- | --- | --- |
| 玩家托管音画 | 开局托管玩家 | 该玩家实际游戏实例 |
| 服务端托管音画 | Minecraft 服务器 | 实际服务器根目录 |
| 街机实验本地同步 | 各参与客户端 | 每个参与客户端的实例；仅目前已验证的两席游戏配置 |
| 手持 GBA | 本人电脑 | 本人实例；仍是本机单人 |

仅接收托管音画或旁观的玩家不运行第二个模拟核心，仍需装服务器要求的匹配模组。主菜单缺库提示目前按安装的附属检测，不看服务器采用哪种模式；这种玩家可以返回，不必为了旁观安装全部外置库。以后自己托管或用手持 GBA 时再补齐。

服务器没有运行环境 GUI，也不会自动解压/下载。要开街机或 GBA 服务端托管，服主须在 Windows x64 服务器停服时，从离线包按原相对路径取对应三件套：

- 普通街机：`piq-native-arcade/runtime/` 内的 `mame_libretro.dll`、`piq-native-helper.jar`、`jna-5.14.0.jar`。
- GBA：`piq-gba/runtime/` 内的 `mgba_libretro.dll`、`piq-gba-helper.jar`、`jna-5.14.0.jar`。

实验本地同步的客户端另用 `piq-native-arcade/runtime-snapshot-v1/` 三件套。不要混用不同组的 helper。FC/SFC 服务端仍用 JAR 中的 Wasmtime，不用上述两组外置库。按既有同步说明设置世界的 `serverconfig/piq-sync-server.toml` 中 `serverHosting=true`，重启并在测试世界验收；默认不启用服务端模拟。

## 这次改名和旧世界

显示名暂定“方块电玩”（英文界面 Block Arcade）；设备恢复 FC / SFC / GBA / 小霸王学习机（SB-926）等名称。机身恢复既有原图，FC 主机铭牌去掉 Nintendo 字样。其余原机贴图可能仍有原品牌，这是按恢复请求处理，不等于取得品牌或外观授权。

内部 `piq_*` mod ID、配置/存档/运行库路径保留，避免改名导致旧物品丢失、存档找不到或库无法识别。因此这里的必要技术路径仍含旧前缀；日志标识、作者与第三方许可归属也保留，不是残留的游戏品牌标题。旧 JAR 先移出活动 `mods` 并保留备份，再放新版，不能仅因文件名不同就同时保留。

本轮不改同步协议、模式能力、N 锁定、输入、ROM 同步或存档格式；不同同步模式的存档仍独立，不自动转换。同步入口仍沿用上一版，调试遥控器尚未加入。此前同步策略测试说明的功能边界仍适用，但本次安装版本与运行库步骤以本文为准。
