# 同步策略与 N 锁定测试说明

这是一套配套测试版：FC alpha.39、SFC alpha.23、街机附属 alpha.14、GBA alpha.7。客户端和服务器请使用同一套；不要混用旧协议附属。只交付文件，不自动安装、发布或修改现有实例。

## 默认策略与实际支持

| 设备 | 无自定义配置时的默认 | 本版可以切换的范围 |
| --- | --- | --- |
| 家用游戏机（FC）、大霸王学习机 | 本地输入同步 | 本地输入同步 / 服务端托管 |
| 家用游戏机（SFC） | 本地输入同步 | 本地输入同步 / 服务端托管 |
| 原有 FC 街机入口 | 原有本地输入同步 | 本版仍固定，不伪装成已接通三种模式 |
| 普通街机柜的 SFC 后端 | 可用且服主启用时优先服务端托管；否则本地输入同步（服主允许时），再否则玩家托管 | 玩家托管 / 本地输入同步 / 服务端托管 |
| 普通街机柜的原生街机后端 | 可用且服主启用时优先服务端托管；否则玩家托管 | 玩家托管 / 已验证游戏的实验本地同步 / 服务端托管 |
| 普通街机柜的 GBA 后端 | 可用且服主启用时优先服务端托管；否则玩家托管 | 玩家托管 / 服务端托管，单控制席位 |
| 手持 GBA | 本机单人 | 仅显示模式说明；不增加虚假的四人联机或 GBA 通讯线 |

已经手动保存的同步选择不会被默认值覆盖。明确选中的模式不可用时，会说明原因并拒绝开机，不会在后台偷偷改成另一种；服主禁用所有可用方式时也不能开机。FC/SFC **家用机的玩家托管控制仍未接通**，按钮显示不可用；本地同步的附近旁观仍可接收画面。

原生街机的实验本地同步仍仅限已核验的 `kof97` / `mslug2` 固定核心配置、最多两席。这不限制玩家托管和服务端托管原有的四端口能力。

## 在哪里改

- 家用机：双手空、普通右键主机机身的非按钮区域，打开“同步方式”；也可瞄准主机输入 `/home-sync`。电源、重置按钮仍优先执行本来的操作，Shift 取卡等操作不变。
- 街机：Shift＋空手右键打开第一级配置页，点击“同步 / 网络”。设置针对当前后端，连接的两台街机作为一组处理。
- 手持 GBA：主手持掌机，Shift＋右键进入设置，点击“同步说明”；该入口明确说明本机单人边界。

只有管理员能修改，普通玩家可以查看。正常关机、结束正在进行的开机或加入请求之后才能切换；旧核心还在保存或关闭时也不允许切换。切换设置本身不会强行归还手柄，不会停止正在运行的游戏。

## 服主启用服务端托管

服务器加载核心模组后生成该世界的 `serverconfig/piq-sync-server.toml`。默认不启用服务端模拟，需服主明确设置：

```toml
serverHosting = true
allowPlayerHosting = true
allowLocalSync = true
maxHostedRooms = 2
hostedBytesPerSecond = 2097152
```

建议停服后修改，重新启动再测试。`maxHostedRooms` 是家用机和普通街机共用的上限，包含正在启动、正在关闭的核心，范围 1–4。音画预算按每位参与者的副本计费，托管会话分配持续额度并轮流服务参与者；旁观另外受现有旁观预算限制。

FC/SFC 服务端核心沿用打包的 WASM 运行环境。原生街机及 GBA 的服务端托管目前要求 **Windows x64 服务器**，并在实际服务器游戏根目录的 `piq-native-arcade/runtime` 或 `piq-gba/runtime` 放置该附属要求的运行库。不是把 DLL 放进 `mods`。本版不会偷偷下载、运行外部可执行文件，缺少依赖时对应选项说明原因。

游戏文件必须已经通过既有授权上传/同步流程进入服务器库；本版不附带商业游戏，也不绕过上传权限。服务端托管的参与者只接收音画，不在各自客户端运行模拟核心。

## N 锁定与存档

拿起手柄后仍按现有规则进入控制模式，默认按 **N** 切换固定站位，再按一次解除；归还后恢复原有控制。Z/X 不再被默认锁定键占用，交给游戏对应功能键。

新配置默认 N。旧版能够识别的默认 Z/F8 会安全迁移；实际自定义键、CUSTOM 方案或占用了 N 的游戏映射会保留并提示，不强行重排。可在“控制方式”中检查当前实际锁定键。

**本地与服务端模式的存档独立，不自动转换。** FC 的无存档、机器存档、个人槽仍由原有权限规则管理；服务端状态使用独立键。SFC/GBA 托管使用各自独立 SRAM/电池存档目录。切换后看不到另一模式的进度不等于旧存档被删除，请勿为了找进度反复覆盖保存。

## 建议实际联机验收

1. 先保留默认本地同步，验证 FC/SFC 双人邀请、Z/X 游戏键、N 固定站位、归还和六格断线，确认旧玩法没有回退。
2. 关机后切到服务端托管：开机、领取 P1/P2、另一玩家不领取手柄直接旁观；分别测试按住/松开、失焦、归还、重置和关机。
3. 街机测试 P1 离开、P2 继续，之后新玩家领取空出的 P1；连接两台双人柜时核对四个端口和两块屏幕。
4. 在 `maxHostedRooms = 2` 时，同时开启两局服务端托管的家用机/街机，第三局托管应提示容量不足；关闭一局后等待其实际退出，再开第三局。本地同步和玩家托管不占这个额度。
5. 保存并关机、重新开机后核对进度，确认个人槽不能读写其他人的记录；不同模式不互相覆盖。
6. FC 服务端家用会话允许原开机玩家离线后其余有效控制者继续。**SFC 服务端家用目前原开机玩家离线仍结束该局**，这是保留的生命周期边界，尚未改为独立无人值守主机。

本轮自动化验证覆盖编译、输入队列、协议和连接身份、容量/带宽、关闭与存档边界，以及自制测试程序的核心/媒体链路。没有完成两台真实 Minecraft 客户端的多人实测、真实网络延迟测试或所有游戏兼容性验证；请先在测试存档和测试服务器验收，不直接替换正式服。
