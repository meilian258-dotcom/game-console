## B. 模式能力

状态描述本批新路线；“不支持”表示此接口未提供，并不声称模组或核心永远不需要该能力。

| 模式 | 状态 | 操作人数／旁观 | 边界与证据 |
| --- | --- | --- | --- |
| 本地单人 | 实验 | 一人占席；核心最多四口 | 必须显式 opt-in；MAME 隔离音画／输入首验通过，MC 待验 |
| 本地多人 | 实验 | 最多四个数字端口；游戏／联柜／席位另限 | 输入合同存在，真实多人未验 |
| 玩家音画串流 MEDIA | 实验 | 沿公共机柜容量／观看范围，不新增无界观众承诺 | 当前唯一业务接入；MC 主持／操作／旁观待验 |
| 服务器托管 | 不支持（本批未接） | 新 LOCAL 无服务端人数声明 | 原工厂继续 JNI，未迁移 |
| 逐帧本地同步 | 不支持 | 无 STEP／帧推进控制 | 旧 snapshot 路线独立保留 |
| RetroArch LOCAL | 实验 | 通用配置 1～4 个数字口，Native 固定四口 | 自主计时；没有暂停／RESET／运行中恢复 |
| RetroArch Netplay | 不支持（此入口未接） | 无网络房间／席位／观众入口 | LOCAL 不走 NetplayNetwork／relay，不传 host/connect 参数；后续共享模拟方向另验 |
| JNI Netplay | 不支持（此入口） | 旧 FBNeo 最多四口，属于兼容路线 | 原接线／独立保存身份不变，不据 LOCAL 验证重新认证 |
| MEDIA 只读旁观 | 实验 | 沿既有公共订阅范围与容量 | 只收音画，不发输入／写档；MC 晚加入、返回、重连待验 |
| Netplay／混合多屏旁观 | 不支持（本批未迁移） | 不承诺新并发 | 不把 JNI 四槽映射为四进程 |
| 原生通讯／游戏内联网 | 不支持 | 无 | 不提供 GBA Link、模拟街机网络或任意核心网络接口 |

## C. 内容与保存

| 字段 | 当前合同 |
| --- | --- |
| 文件 | Native 主内容原驱动名 `[a-z0-9_]{1,32}.zip`；一个主文件加最多四个伴随文件。LOCAL 适配暂存主文件上限 96 MiB，单伴随 16 MiB，合计 128 MiB；上游选择／传输的更严格限额仍有效 |
| BIOS／依赖 | 用户自行合法提供同目录 `neogeo.zip`、`pgm.zip`、`qsound.zip`、`qsound_hle.zip`；不自动遍历任意父集合、不下载 ROM／BIOS、不更换 ROM 集 |
| 来源／授权 | 既有公共游戏库／服务器授权下载；LibretroContentFiles 只检验文件身份，不授予上传、读取他人内容或执行权限 |
| 标识／暂存 | 原名、长度、主／伴随 SHA 固定；后台 inspect／stage，拒绝链接、重名／保留名、逃逸、超限和读取后变化；只向独占工作区 CREATE_NEW，不覆盖来源 |
| 多盘／换盘 | 不支持；不能由 ZIP 支持推定光盘／换盘支持 |
| 下载／断点续传 | 沿原公共传输；本批没有新增断点续传或后台离远下载承诺 |
| 目录责任 | 正式游戏库仍为实例根 `game-console/piq-cabinet/server-games/`；临时 RuntimeWorkspace 由会话持有和回收；不清理原内容或玩家存档 |
| SRAM／RTC／即时状态 | 公共层检查点封装可容纳 state≤16 MiB、RAM≤4 MiB、RTC≤64 KiB；不是每个核心均支持。Native MEDIA 未绑定 persistence，故没有本入口长期保存／恢复闭环 |
| 记忆卡／NVRAM | 无独立业务适配；不能用完整状态可能含币数代称 NVRAM 运营设置持久化 |
| 选项 | 沿 NativeJniMediaSession 固定选项，关闭核心自动保存和配置读写；选项进入 LOCAL 身份，不提供任意运行期配置 |
| 独立身份 | `PIQ-RetroArch-LOCAL-save-v1`／`PNP7-pad12` 加运行器 SHA、核心 SHA、内容名、设备／端口／采样率、选项、固定依赖名／SHA／长度；内容身份含主摘要及按名称排序的伴随摘要 |
| 归属／提交 | 通用 API 的 persistence 必须启动前由可信调用者绑定；调用者负责权限、档主和原子持久化。Native 本入口未绑定，不自动读写旧 JNI／Netplay／进程档 |
| 迁移／冲突／异常 | 不迁移、不合并、不覆盖旧档；磁盘满／坏状态／最终提交失败须保留旧好档，但本街机持久化业务尚未实现，不能提前标实测通过 |

## D. 输入、音画与交互

| 字段 | 当前声明 |
| --- | --- |
| 端口 | Native 四口数字手柄 device=1；逻辑 1P～4P 对应核心 0～3，主副柜仍由 CabinetSeats 分配，游戏和注册容量另限制 |
| 输入 | 复用 NativeJniInputBuffer 有界边沿队列，每次原生 PNPI 消费；12 位掩码，MAME 按钮交换只在适配边界执行一次，不按渲染帧重复消费 |
| 释放／投币 | 原逐口 release、退出保留已确认 coin 边沿；关闭清全部输入。实体扣币仍由 CabinetCoinService 授权及接受后完成，运行器不扣物品 |
| 菜单／失焦／断线 | 沿公共输入及租约释放；本批合同测试不代替 MC 真键盘／手柄及断线验证 |
| 特殊输入 | 不支持 LOCAL 光枪、模拟轴、触屏、压力、震动、任意键盘／鼠标；FC 光枪迁移缺口保留 |
| Test／Service／DIP | 原服务端管理权限不变；本批不新增运营设置保存，普通玩家不能借本机后端选择取得 OP 权限 |
| 视频 | PNP7 软件四字节像素，Java 转公共 ABGR；宽高≤1024，比例／旋转只归一化一次，保持动态尺寸；四向／竖屏／Iris 实机待验 |
| 音频 | Native 固定 48 kHz、16 位立体声；有界汇集所消费帧音频。固定内容隔离探针取得非零 PCM；MC 听感／同步仍待验 |
| FPS／硬件渲染 | 自主原生时钟；不宣称 Java 固定逐帧或与 MC tick 同步。无硬件渲染上下文／帧导出适配 |
| 模型／开关／动画 | 原机柜／席位／电源／动画和管理 UI 不改；公共设备完整交互和真人视角待回归 |

## E. 生命周期、权限与预算

- 电源、核心、操作席、订阅、显示可见性继续分开。归还／退席不等于整机关机；复用公共 ServerCabinets／CabinetRooms 和旧会话代次检查，不因 LOCAL 准备就授权输入。
- 本机选择是 `piq.arcade.mediaBackend`，缺省 `jni`、显式 `retroarch`，非法值失败；不来自服务器包或保存内容，不热切换正在运行的局。
- 输入提供者须无阻塞；构造／绑定／start／close 和呈现查询不在调用线程执行核心或文件 IO。实际 inspect、hash、提取、进程／保存工作归后台 owner。
- 核心资源及扩大预算须匹配可信 profile；依赖仅允许明确固定的 libc++／libunwind 声明，Native 只声明 libc++。不运行游戏目录 DLL，不因固定 MAME 较大而开放任意资源。
- 内容最多五件／128 MiB；原生视频≤1024×1024，PCM 每包≤32768 字节；有界帧队列，Native 一次最多取六帧，汇集音频另有上限。输入溢出报告失败并停止，不丢掉任意边沿后假称继续正确。
- 关闭清输入、停止新工作；`close()` 不作完成信号。`terminated()` 成功才确认子进程退出及工作区删除，错误／超时不假报成功。当前可能强制结束，不能等同正常原生卸载；新会话资源占用须等真实回收处理。
- 操作 8 格、发现 16 格、订阅退出 20 格；空席默认 60 秒、最后主动退出立即关机默认 false，均沿原服务端设置。音量、观看和远处主持按 MEDIA 服务处理，不改变全服强制规则。
- 上传／选择由 CabinetSharedGames 和原管理权限控制，入席／端口由 CabinetRooms／CabinetSeats，投币由 CabinetCoinService；旁观只收获准音画，无输入／存档权。100 格外不新增全服核心帧、内容或输入广播，实际网络与范围回归待验。
- JNI 四槽不是新进程并发预算；CPU／内存／网络／FPS、多机同时运行、弱网及长局均待验证。诊断不分发 ROM／BIOS 正文；日志与错误中的本地路径应按现有脱敏规则处理，专项核验待完成。

## F. 测试与结论

主包最终全量重跑通过，2879 项（0 失败／0 错误／11 跳过）；街机 160 项（0 失败／0 错误／0 跳过），双方构建通过。关键测试、前期测试夹具失败原因和相对证据入口见[制作记录第 6 节](统一RetroArch后端-20261009.md#6-验证与交付边界)。跳过不算覆盖；没有给其他机型旧结果重新认证。

Mesen LOCAL 使用最终生产 JAR 与 `./原文件名` 路径完成真实保存、关闭及重开恢复，`PASS checks=182`；这只验证公共 LOCAL 保存通道，Native MEDIA 尚未绑定 persistence，仍无街机进度闭环，FC 也未因此完成迁移。

真实 MAME 适配器：三次各 120 帧，检测到非零 PCM，输入诊断有 24 种不同画面摘要，坏 ZIP 原生拒绝，实际 PID 退出及目录清理确认，结果 `PASS checks=26377`。此前裸文件名进入 OSD 的失败已修为仅 LOCAL 使用 `./原文件名`，旧 Netplay 参数不变。探针使用仓库生成器产生的原创 26 字节 8080 诊断，不是商业游戏；来源、SHA 和复现入口见制作记录。最终 JAR 专服启动、MC 单机／真实多人、听感、四口、晚加入、断线、长局、弱网、无缓存干净构建及商业 ROM 兼容均待验证。

结论：候选待验收，非稳定发行；人工验收者／时间：未验收。完整迁移、Netplay、持久化与其他特殊能力是未完成项，不因写入声明而开放。本文不包含安装、部署、发布、推送或重启授权。
