# FC76.23 启动崩溃修复

日期：2026-09-29。适用：Minecraft 1.21.1 / NeoForge 21.1 / Java 21。

## 修复内容

76.21/76.22 的 Netplay 存档消息把同一个 `piq_fc_arcade:netplay_save` ID 分别注册到服务器方向和客户端方向；NeoForge 在同一协议内按 ID 唯一登记，第二次注册导致启动失败。

76.23 改为一次双向注册，再按实际收发方向分派。保留主线程处理、服务端权限验证、原消息字段、协议版本、存档格式、大小/速率限制与流量统计。没有删除保存功能或忽略注册异常。FC/SFC/街机共用这条修复，不需要为本次修复重建附属。

## 安装

服务端和客户端都使用 `game_console-0.31.0-alpha.76.23.jar`；停止相应游戏进程、备份后，将旧主包移出 `mods` 保留，再放入新包。不要两个版本并存。ZIP、文档、源码补充不能直接放入 `mods`。

已有配套保持：完整SFC43（含core9）、街机1.5.4、PvZ11、电脑10；GBA10和Flash独立运行器0.1.3沿用。不安装内部平台JAR或SFC开发薄包。

本次不迁移或清理世界、ROM、卡带、个人存档；模型纹理、JNI桥、模拟器核心和Netplay原生程序均沿用76.22字节。JNI仍默认关闭，FC/SFC只有私人试验入口，不因本次修复扩展联机支持。

## 客户端另一处显卡崩溃

另一次客户端日志显示，在启动加载画面的 `GLFW.glfwSwapBuffers` 调用中，NVIDIA `nvapi64_impl.dll` 访问违规。这与服务端的重复注册是两个独立故障记录；该次崩溃时未见PIQ JNI桥或模拟器核心加载证据。

测试中通过将 `config/fml.toml` 的 `earlyWindowControl=true` 改为 `false` 绕过 NeoForge 早期加载窗口。修改前应完整备份配置；该绕过不等于修复显卡驱动，也不能仅凭日志存在录屏钩子认定其他程序有错。

要回退，仅在游戏关闭时恢复该字段为 `true`，或在确认没有后续配置改动时恢复完整备份。客户端需用76.23重新启动实测；如仍崩溃，应提供新时间的 `hs_err_pid*.log` 和 `latest.log`，不能继续使用旧报告判定。
