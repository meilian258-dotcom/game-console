# 服务端内容目录与街机 BIOS 修复

维护：像素匠。日期：2026-10-03。基线 `d27ea98`，目标候选 FC76.38 / 完整 SFC45（保留 core9）。本文件是该批历史实施与验证记录，不是线上部署或稳定版声明。

2026-10-04 后续见[内容库收尾与核心退役](内容库收尾与核心退役-20261004.md)：FC76.40/街机1.5.7 补齐实际五文件传输与 JNI 大 ROM 文件加载，完整 SFC47 内含 core10 并将旧独立柜服务端 `sfc-roms` 收到共同入口。下文64 MiB和core9未改写的例外仅适用于本历史批次；存档、世界授权隔离及迁移留源原则继续有效。

## 1. 本轮需求、范围与依据

该版本统一服务端 ROM/BIOS 的实例根入口，并处理上传后的原名查找与 JNI Netplay BIOS 清单问题。

本轮处理现行 FC、SFC 家用、MD/GBA 内容卡和通用街机所用内容路径；街机上传、授权下载与托管共用新路径。保留客户端目录按钮、ROM 身份算法、全部存档、游戏内权限及核心版本；不实施实际服务器数据迁移、用户实例安装、推送、发布或重启。Flash/PvZ 验证机型不扩展。旧冻结 core9 独立街机的 `sfc-roms` 属于历史链，未改写冻结核心，明确列为例外，不声称历史所有入口都已统一。

检索与复用：2026-10-03 核对 `ConsoleStorage`、各内容 Store、`CabinetSharedGameData`、`CabinetSharedGames`、`NativeNetplayContent`、JNI `loadBundle` 及 `NetplaySaveServer`。沿用现有哈希去重、传输限额和授权清单，不再创建机型专用上传协议。阅读 [Libretro FBNeo 官方 BIOS 说明](https://docs.libretro.com/library/fbneo/#bios)：核心会搜索 ROM 同目录与 system 目录；本模组将获授权清单按原名暂存，并将暂存根提供给核心。上游支持列表不等于本模组已接入所有 BIOS。

### 1.1 实际原因

- 通用街机过去写在 `WORLD/game-console/piq-cabinet/shared-games/objects/<SHA>.data`。原文件名在世界 SavedData 清单里，并非上传成乱码；搜索 `samsho.zip` 自然找不到同名 ZIP。
- 当前客户端已存在 `neogeo.zip`，后续侍魂缓存也已含 BIOS；日志却在核心加载之前报告 ROM / BIOS 身份不匹配。服务端过早按旧机柜清单建立保存身份，客户端之后上传新游戏／补 BIOS，导致双方本次身份不一致。
- 独立缺陷：清单允许 5 件，但暂存路径仅接受文件索引 0～2。修正为受 `MAX_FILES` 约束的 0～4，未扩大配额。

### 1.2 本次开局合同

机柜／模式／席位校验 → 建立本局联机授权（暂不登记保存身份）→ 主持上传或下载本局内容 → 服务端逐文件校验 → 用此次确切 ROM、BIOS、核心 profile 绑定保存身份 → 提交清单及内容授权 → 回复成功 → 客户端读档并加载核心 → 就绪。

首次没有旧清单也能走上传；同一局内容绑定一次，同清单重复确认幂等。不同清单必须关机后重开，不能运行中换 BIOS。客机／旁观不能登记或替换档主。内容提交失败只终止精确本局，拒绝迟到读写，不关闭后来新开的局。未保存模式仍校验身份；没有关闭校验、删除或自动迁移旧存档。

## 2. 去哪里找文件

`SERVER` 是服务器实例工作目录（不是世界目录）。单人游戏的 `SERVER` 为该游戏实例目录。现行路线共同入口是 **`SERVER/game-console/`**，里面保留机型／用途分类，不混成一个平面文件夹。

| 内容 | 相对于 `SERVER/game-console/` 的位置 | 说明 |
| --- | --- | --- |
| FC ROM | `piq-fc/roms/` | 原入口不动，安全化原名和元数据保留 |
| MD 内容卡 ROM | `content-cards/piq_md_home/md/` | 原哈希文件名不动；原名在 `content-card-metadata/piq_md_home/md/` |
| GBA 内容卡 ROM | `content-cards/piq_gba/gba/` | 原哈希文件名不动；原名在 `content-card-metadata/piq_gba/gba/` |
| SFC 家用 ROM / 封面 | `world-content/<世界scope>/piq-sfc-home/roms/`、`covers/` | 同一根下按世界隔离；scope 由相对世界路径生成，迁电脑保留实例相对布局即可 |
| 通用街机 ROM + BIOS 实体数据 | `piq-cabinet/server-games/objects/<SHA>.data` | 相同字节去重，不同版本 BIOS 不互相覆盖 |
| 街机原名／文件位置索引 | `piq-cabinet/server-games/indexes/game-<原名摘要>--<内容ID>.json` | 可搜索 `samsho`；列出 ROM / BIOS、完整原名、SHA、字节数及相对对象位置 |
| FC / MD 服务器共享封面 | `piq-fc/shared/covers/` | 原共用库不变，不等于 MD 本地封面按钮打开 FC 目录 |

街机正式数据用 `server-games`，**不是**客户端的 `shared-games` 缓存；集成服也不会把正式库存算进客户端缓存配额。索引是可读收据，不是可编辑授权库，也不是游戏文件。不要把 `.data` 原地改名为 `.zip`，不要删除与其他游戏共用的 BIOS 对象。需要导出时保留原件，根据索引复制并使用记录的原名。

世界内 `data/piq_cabinet_games_v1.dat` 继续保管机柜／后端与清单绑定；仅有根目录文件或 JSON，不会自动出现在另一世界的游戏菜单。玩家存档仍按原世界／个人／卡带／机器规则保存，不能把 `WORLD` 整个移走。索引只在该内容成功校验／选择时生成，不把所有未使用历史对象立即重新导出。

## 3. BIOS 怎样准备与同步

以现有 FBNeo 街机上传路线为例：

1. 本地准备有权使用、与核心 ROM 集匹配的原名游戏 ZIP；不要把内部文件随意改名或拿不同核心的集合混用。
2. 所需 BIOS ZIP 放在**选中游戏的同一目录**。目前共享清单只接入 `neogeo.zip`、`pgm.zip`、`qsound.zip`、`qsound_hle.zip`，程序会把该目录中存在的这四种文件纳入本次清单；不是自动推断该游戏只需要哪一个，也不是任意 BIOS 自动发现器。
3. 在获准上传的机柜里重新选择该本地游戏并确认上传。单独把 BIOS 放到远程某个目录，不会修改已绑定的旧清单；补 BIOS 后需按完整流程重新上传并重开本局。
4. 服务端分别校验并去重 ROM / BIOS；主持、参与者、JNI 只读旁观按同一授权清单下载，运行时恢复原名。纯音画串流观看端不因观看就运行或下载核心内容。
5. 在 `indexes` 查看本次清单是否确实包含 `neogeo.zip`。文件缺失会注明原名；有文件不等于版本匹配，仍需核心实际运行验证。

同名不同 SHA 的 BIOS 可以共存，旧档身份仍包含原 BIOS 摘要；换 BIOS 不会自动转换旧档。本版不下载／附带商业 BIOS，不提供万能 BIOS 文件夹，也不新增 split parent ROM、任意子目录或所有上游固件的传输支持。

限制保持：单件最多 64 MiB，最多 5 件，总计 128 MiB；街机对象库 2 GiB / 768 项，索引最多 1024 项。已查到本机 `samsho5.zip` 大于 64 MiB，本次未靠放大限额让它通过；它需要后续单独评估大内容支持。当前 GBA 路线使用 HLE，不因本次目录改造新增外部 BIOS 支持。

## 4. 旧目录兼容与安全

- 街机只按**当前世界已授权清单**从旧 `WORLD/game-console/piq-cabinet/shared-games/objects/` 校验复制所需对象到新目录；不扫描其他世界，不删除原件。新目录已有但损坏时明确失败，不拿旧文件静默覆盖。
- SFC 首次后台使用对应库时预检、复制旧世界 ROM / 封面，失败可重试，源文件保留；重启会再核对旧源并补缺。空、过小、超限或格式无效的旧文件逐项警告、留源跳过，不拖住合法内容；同名目标冲突及链接仍拒绝。新目录是管理／写入入口，旧源仍作兼容材料，手工删新库旧文件后可能被重新补回；不要把删除新件当作永久退役。
- SFC 内容按原字节复制，原规范化 ROM SHA（去 copier header 的规则）不变。世界隔离保留；实例迁移需一起备份世界和 `game-console`。特殊跨盘外置世界不能生成相对 scope 时明确报错，不偷偷采用会随换电脑改变的盘符身份。
- 路径解析不做磁盘 IO；复制、哈希、索引由既有有界 IO／托管工作线程执行。保留大小、数量和队列限制；拒绝链接／junction、目录冒充文件、同名异内容冲突及读取中变化；校验完成才发布。
- 本次内容兼容复制不调用 `ConsoleStorage.root` 去搬整个世界组件，不顺带迁移保存、配置或运行中临时目录；现有存档初始化路径保持不变。正式数据和客户端缓存分开。

## 5. 验证与交付状态

最终 FC76.38 `check jar`、SFC45 `test jar` 及现有 MD12、街机 1.5.5 对新主包的测试均成功。共 3561 项：FC 2823、SFC 517、MD 102、街机 119，0 失败／0 错误；10 跳过为 FC 9 个既有排除和 SFC 1 个当前 Windows 无符号链接创建权限的夹具。覆盖新旧库、保留原件、拒绝冲突／路径、五件上传、并发配额、Unicode 索引、SFC 规范化哈希／世界隔离、首次上传／补 BIOS 后保存身份、迟到与失败收尾；不把跳过项计为通过。

最终主包搭配未改的街机 1.5.5 / FBNeo state-v3，使用用户已有 `samsho.zip`、`samsho2.zip` 和 `neogeo.zip` 隔离验证：两款各 900 帧变化画面及非零音频、180 帧本实例／跨实例保存恢复回放一致，四实例短时 JNI Netplay、50 ms 单向模拟延迟、手动／最终保存和新实例重开成功。进程全部 exit 0，无 JNI 警告，四原生槽归还；三份源文件的 SHA、大小和修改时间未变。这不是 Minecraft 上传 END 的双客户端实测，不代表所有 NeoGeo ROM 集。

完整 SFC45 使用 home45 与原 core9 合并，core9 的 62 个非合成条目原样保留。七包 8 个 ID、2676 个类无跨包重复；FC 1405 / SFC 247 类与编译输出逐字节一致，模型、贴图、AT、WASM、原生核心和许可保留。打包工具 10 项测试通过。最终七包在隔离 NeoForge 专服正常启动、正常 `stop`、exit 0，启动至退出 15.59 秒。套装仅更新主包与完整 SFC45，其余五件保持原版本；不等于实际游戏服务器已更新。

Minecraft 专服双客户端、现有世界升级、真实磁盘故障及不同 BIOS 集长测仍需验收；本轮不处理已经单独定位但尚未修复的 Iris 黑色画面透明问题，也不把 Java AppHang 当作本次存储修复的已解决故障。

适用 Minecraft 1.21.1 / NeoForge 21.1.236 / Java 21；原生游戏运行端沿原 Windows x64 要求。本批只替换以下两件，其余 MD12、街机1.5.5、GBA14、电脑11、PvZ11 五件保持原 JAR；共七个玩家 JAR，不另装内部平台、SFC home 薄包或重复 core9。
