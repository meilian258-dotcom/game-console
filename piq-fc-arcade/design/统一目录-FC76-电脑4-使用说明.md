# FC76 · 统一数据目录与电脑固定视角（2026-09-26）

本地测试候选，尚未进行 Minecraft 图形界面、多客户端或真实存档升级验收，不是稳定发布版。没有自动安装、迁移玩家文件、部署或重启。本指南覆盖下表版本；项目 README 中更早的安装路径和版本组合属于历史记录，不要混用。

## 安装组合

Minecraft 1.21.1、NeoForge 21.1.236、Java 21。使用原生游戏运行器的客户端目前要求 Windows x64；Flash 还需 .NET 6 Desktop Runtime 和 WebView2。专服是否执行核心取决于原有托管配置，不因安装附属自动变成运算端。

| 文件 | 安装与用途 |
| --- | --- |
| game_console-0.31.0-alpha.76.jar | 必需主包，客户端和服务端同装 |
| game_console_computer-0.1.0-prototype.4.jar | 要用电脑时双方同装 |
| game_console_pvz-0.1.0-prototype.8.jar | 要运行 PvZ 时双方同装，核心/host 内置 |
| game_console_sfc-0.1.0-alpha.41.jar | 可选完整 SFC 合包，双方同装，已包含原 core9，不再叠装旧核心 |
| game_console_arcade-0.1.5.jar | 可选街机，双方同装，沿用 0.1.4 的 FBNeo/原 MAME 和 helper |
| game_console_gba-0.1.0-alpha.9.jar | 可选 GBA，双方同装；运行端仍需原三件套运行库 |

主包和这些附属必须一起升级到配套版本。不要叠装同 MOD ID 的新旧 JAR；不要用 build/libs 中未冻结的草稿。旧 SFC/街机/GBA 附属有防混装检查，旧电脑/PvZ 的依赖范围也不接受 FC76。**不要安装旧 Flash8 JAR**：电脑已带 Flash 接口，仍使用原 Flash 0.1.2 完整运行器。

1. 正常退出所有使用这个实例的游戏/服务端进程，备份整个实例和世界。先复制一个世界/实例测试，不在有进程写存档时迁移。
2. 在备份完成后，把要更换的旧 JAR 移出 mods 保留，再把主包和自己需要的新附属放入双方 mods。配套 ZIP、源码 ZIP、运行器和说明文档都不能直接放 mods。
3. 如果旧 Flash 运行库已完整安装，首次启动会一起迁移，不必重新复制。首次安装者将配套目录中的 `客户端运行库/game-console` 合并到实际客户端实例根目录，得到 `game-console/piq-flash-box/runtime/FlashBox.Helper.exe`。完整复制，不只拿 EXE。相同目录存在时先核对，不覆盖不同版本的文件。
4. GBA 保留原 `mgba_libretro.dll`、`piq-gba-helper.jar`、`jna-5.14.0.jar` 三件套；已有文件自动迁移到 `game-console/piq-gba/runtime`。本包没有更换或附送 GBA 运行库，缺少时仍需安装原配套三件套。
5. 启动后先检查运行环境、旧游戏和旧进度，再在副本测试电脑四角点击、退出重进及原 FC/SFC/街机模式。失败时保留日志与备份，不手动删除进度目录。

## 固定视角怎样进入

默认选择固定视角模式。先把电脑装好、连电视和键鼠、开机，在电脑的程序设置中选择硬件测试、PvZ 或 Flash 及本机文件。

1. 右键已连接的键盘/鼠标，获得这台电脑的操作权。
2. 松开鼠标，用准星自行瞄准电视里的有效画面。
3. **右键一下，固定当前视角。** 不会自动转向电视，也不会自动移动玩家。这一下右键不会传入游戏。
4. 松开按键后，鼠标只移动电视上的光标，左键按游戏规则操作。可到画面四角；黑边、其它设备、墙壁遮挡和超距仍不可操作。
5. **Esc 退出操作**，释放键鼠并暂停本机程序。切出窗口、打开菜单或失去操作权同样清除按住状态。

程序设置中可切回原来的“准星操作”，并调整固定光标速度。本地记忆设置在 Minecraft 规定的 config 目录，不发送给服务器。固定视角不打开全屏 GUI，不使用背景模糊。

## 新目录与自动迁移

实例数据统一到 **实际游戏实例/game-console/**。保留原子目录名字，避免破坏运行库离线包内部条目：

```text
实例/game-console/
  piq-fc/                 FC 文件
  piq-sfc-home/           SFC 文件
  piq-native-arcade/      街机运行库和数据
  piq-gba/                GBA ROM / 运行库 / 本地存档
  piq-cabinet/            共用机柜数据
  piq-computer/games/     自行整理的 PvZ、Flash 文件
  piq-pvz/saves/          PvZ 玩家/内容隔离进度
  piq-pvz/logs/           PvZ 运行器日志
  piq-flash-box/runtime/  Flash 完整运行器
  piq-runtime-packs/      运行库离线包
  piq-private-home/       原私人模式数据
  legacy-backup/          首次迁移时的原目录归档
  .migration/            迁移标记，请勿删除
```

各世界的数据仍在 **各自世界目录/game-console/**，不把多个世界或服务器的存档合并。mods、config、加载器 natives-* 等 Minecraft 自身目录不动。外部自选游戏目录（例如另行选择的游戏文件夹）不移动。

首次启动对已知旧 piq-* 目录执行：检查路径与冲突 → 复制缺少文件 → 逐文件字节校验 → 将原目录归档到 legacy-backup → 写迁移标记。不删除原始字节。遇到同名不同内容、链接或校验失败会停止迁移并报错，不覆盖新旧数据，也不以空档继续。可能已有部分组件完成迁移，需依据日志逐项核对。

电脑、共用机柜以及 GBA 掌机记住的内部旧绝对路径会重新指向新位置；外部路径保持原样。PvZ 的 main.pak 必须带原来的 properties 文件夹，Flash 选择 .swf。移动前后存档的玩家/世界/内容身份、模式和核心格式不变。

**legacy-backup 是迁移时快照，不是持续更新的备份。** 玩过新版后不要直接换回旧 JAR：旧版会另建根目录并造成新旧进度分叉。若必须回退，先备份全部新数据，再按对应组件核对或恢复升级前完整实例/世界；不要拿迁移快照覆盖新版进度。检测到旧版重新创建目录时，新版会拒绝再次导入，避免复活旧进度。

## 联机与已知限制

- FC/SFC/街机原有同步模式和 Netplay 逻辑保持；这次是目录与电脑输入改造，不是新的网络实现。Netplay 仍有流量，实验存档/迁移主持限制、NeoGeo 完整状态差异等旧问题不因此消失。
- **电脑的 PvZ / Flash 目前仅本机运行，尚无其他玩家音画旁观和鼠标交接。** 服务器上的键鼠占用权限不等于游戏已经联机。GBA 手持掌机也仍是本地单机。
- Flash 仍是原两组五键/鼠标左键、JPEG 画面和系统音频；不保存 SharedObject，不宣称任意 SWF 都兼容。PvZ 核心与原生 host 没有更换，也没有新增 FPS/音画优化。
- 隔离测试发现原 PvZ 核心在生成缓存文件总路径达到 Windows 260 字符边界时会报缺资源并退出。更深的新目录使长实例路径更容易碰到这个既有核心限制。当前没有修复核心的长路径能力；请在短路径实例副本测试。若日志出现 `missing resource compiled/reanim/...`，先核对完整 properties 和路径长度，不删除已有存档。本次常规短路径启动和指针覆盖另行记录于验证报告。
- 固定鼠标的实际 Minecraft Mixin 加载、光标观感、不同显示比例/第三方输入模组以及真实用户升级仍待验收。自动测试和独立原生进程不代表已完成游戏内测试。

公共 API：`cn.piq.retro.storage.ConsoleStorage.root(originalInstanceOrWorldRoot)` 初始化并迁移，`location(...)` 仅定位，`rebind(originalRoot, oldAbsoluteFile)` 处理内部旧绝对路径。必须传原实例/世界根，不能传已经带 game-console 的路径，避免嵌套。附属不再直接在原实例根建立 piq-* 目录。
