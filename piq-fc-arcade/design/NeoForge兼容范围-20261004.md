# NeoForge 1.21.1 兼容范围候选（2026-10-04）

当前状态：229/236 两轮源码构建、回归/核心探针、七件最终包冻结及静态一致性检查已完成；229/235/236 隔离专服均通过加载、正常启动与停止，图形客户端、多人和 Iris 未验。**仍是测试候选，不是稳定发行或全玩法验收。** 下文列出精确文件 SHA 与分层结果，不把一层通过写成其他层通过；若后续发现最低版本不兼容，应提高下界，不带失败结果放行。

## 1. 本轮只解决什么

本轮仅将方块电玩当前七件玩家包的 **NeoForge 编译版本** 与 **运行最低版本声明** 分开，仍限定 Minecraft **1.21.1**、Java **21**：

| 项目 | 本轮候选值 | 含义 |
| --- | --- | --- |
| Minecraft | 1.21.1 | 没有升级或降级 MC 世界格式 |
| 默认编译 NeoForge | 21.1.236 | 不为降低安装门槛而自动更换日常编译基线 |
| 本批最低 NeoForge | 21.1.229 | 源码编译、探针及隔离专服已通过；实际验收边界见第 6 节 |
| 核验点 | 21.1.229 / 21.1.235 / 21.1.236 | 分层记录，不代表这些版本的全部玩法已通过 |
| Java | 21 | 没有制作 Java17 或 Forge1.20.1 版本 |

拟支持范围为达到候选下界的 NeoForge **21.1 系列**，不是任意更高 NeoForge 或 Minecraft 版本。允许加载的元数据范围、源码/字节码检查、专服启动、客户端加载和实际游玩是不同验收层，不能互相替代；没有覆盖全部中间或未来构建的测试。

已经使用 21.1.236 或更高兼容 21.1 版本的玩家，**不需要为本轮主动降级 NeoForge**。整合包中其他 MOD 的最低版本、互斥关系和安全更新要求仍然有效；方块电玩放宽自身下界不等于整套 MOD 都能降到 229。以所有已安装组件的共同兼容范围为准，原来能正常运行的组合先保留。

## 2. 为什么不放到任意更早版本

NeoForged 官方于 2026-05-11 公布网络对象分配相关漏洞修复：恶意构造的客户端数据包可能使服务器崩溃，Minecraft1.21.1 分支的修复版包括 **21.1.229**。因此，本次把229作为不低于该已知修复的候选安全下界，而不是仅凭“源码似乎用不到新API”继续放宽。官方建议与详情见 [Mitigating Network Vulnerabilities](https://neoforged.net/news/mitigating-vulnerabilities-network/)（2026-10-04核对）。

这是选择本轮下界的一项依据，不是“229没有任何漏洞”的保证；官方安全修复也不能替代方块电玩自己的验证，第 6 节单独列出实测范围。后续若发现更高的功能/API或安全最低要求，以核实后的较高下界为准；不会自动向玩家安装加载器或额外修复MOD。

### 完整 SFC 的 core9 例外

SFC独立 `build/libs/piq_sfc_home-*.jar` 是薄开发包，不能安装代替完整SFC。当前完整包有家用与旧街机 **两个MOD ID、两组依赖声明**；只更新家用模板仍会被内嵌core9的旧NeoForge下界阻挡。

本轮完整SFC已对**新输出包**中core9的NeoForge最低依赖作明确白名单调整，两组依赖owner均正确使用229下界；core9原版本号、原冻结输入JAR与SHA，以及其62个非metadata/manifest条目均保持不变。原core9输入SHA256为 `d562770c8fd05d2d0837e4614259b315825d354df2178ae7b8931265dec050c5`。没有重写旧冻结JAR、重编旧core、改变AT/WASM/类/模型/许可或删掉core9。打包回执已记录元数据例外及受保护条目的逐字节结果，因此不能把整份core9元数据描述为“完全没变”。

这不代表旧独立SFC core发布线得到新版兼容认证。不要另装独立core包，避免重复MOD ID；也不要求玩家安装内部 `piq-retro-platform` JAR。

### 不在本批范围

Flash盒、Java ME附属与旧独立SFC core不纳入本次放宽、重建和组合认证；它们的旧下界和主包依赖仍按原版本处理。电脑现有Flash运行桥并不等于独立Flash盒MOD。Forge1.20.1、更高Minecraft、其他操作系统原生核心适配均未实施。

## 4. 后续安装与回滚规则

本轮构建/验证完成且明确交付后，才使用最终列出的候选文件与SHA；开发中不要从 `build/libs` 或文件名最大版本推断可以安装。

1. 保留当前可用JAR和世界/配置/存档备份，正常退出客户端、按现有授权维护服务器；本文不授权自动换包或重启。
2. 主包与**原先已经安装、仍需要使用的本批附属**一起换成同批候选，两端对应组件保持配套。不强制给原来只装FC的玩家加装全部七件；整套原有七件则成套替换。
3. 同一MOD ID只放一份。SFC使用完整46，不同时放薄包或独立core；电脑12如安装PvZ，则使用PvZ12。
4. 不因“方块电玩最低229”主动降低236或其他MOD要求更高的加载器；先核对整合包全部依赖。不要把1.21.1世界放到Forge1.20.1测试。
5. 先在隔离实例与世界副本核验加载、设备操作、保存/恢复、旁观与适用联机。失败保留日志，停止使用该候选，恢复原配套JAR；不删除、转换或覆盖用户ROM、BIOS和旧好档。

本轮没有改变原生运行端的Windows x64限制、第三方许可、MD对应源码分发以及电脑/PvZ/Flash的既有运行库或自备内容要求。游戏版本发布、线上部署和远程重启仍需单独授权。

## 5. 开发入口与验证边界

共同策略位于 [neoforge-compat.properties](../../source-control/neoforge-compat.properties)，[Gradle适配](../../source-control/neoforge-compat.gradle)读取默认编译版与独立的 `neo_min_version`。默认仍编译236；`-Pneo_version=21.1.229` 或235仅指定本轮编译测试目标，不暗改已声明的最低版本。拒绝非21.1、低于floor及其他MC；最低值只能审核后编辑共同策略，不能使用 `-Pneo_min_version` 临时覆盖。

FC/SFC家用/MD/街机/电脑/PvZ使用该Gradle策略；MD在资源处理时展开元数据。GBA通过 [build_current.py](../../piq-gba/tools/build_current.py)读取相同策略，在最终JAR生成前展开最低值并拒绝残留变量。GBA依赖目录仍须显式提供本次真实NeoForge版本，脚本没有自动下载/切换加载器能力。固定原生输入仍按 [BUILDING.md](../../source-control/BUILDING.md)校验，不绕过哈希门禁。

在仓库根使用真实Python3.11+，可运行不启动MC的策略与打包工具单测：

```powershell
python -B -m unittest discover -s source-control -p "test_neoforge_compat.py" -v
```

最终七件冻结候选可逐件传入 [neoforge_compat.py](../../source-control/neoforge_compat.py) 的 `--jar` 参数，并用 `--neo-version 21.1.229`核对所选测试目标。它检查七JAR/八ID、完整SFC两个依赖owner、共同下界、MC范围和未展开变量；结果明确不等于二进制运行验证，也不代替真实Maven版本范围与游戏组件互依赖检查。
