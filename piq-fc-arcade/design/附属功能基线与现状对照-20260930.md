# 方块电玩：附属功能基线与现状对照

日期：2026-09-30 · 维护者：像素匠（Codex root）。

目的：把 FC、SFC、原生街机已形成的使用流程整理为新附属的检查依据，避免“核心能运行”就交付、却遗漏拷卡、线材或螺丝刀。**统一玩家操作与权限合同，不强迫所有核心拥有相同联机能力，也不要求直接复制 FC 的 NES 专用实现。**

## 1. 本次范围、依据与状态

- R01：核对 FC/SFC/街机的内容、实体、工具、距离、配置、保存和联网规则，见第 3～6 节。
- R02：给新附属列必做项、条件项和交付验收步骤，见第 7～9 节。
- R03：用户确认 MD 接线不显示、螺丝刀右键无效均发生在 MD 主机；连同前一条拷卡界面反馈记录原因与缺口，见第 2 节。
- 本轮只做源码诊断和制作资料整理；**不修改运行代码、不构建新 JAR、不把 MD 缺口标为已修复**，不迁移卡带/存档，不部署或推送。
- 源码核对基线：`53ef5a65704e3d2a040818c918caad4c7429f020`；当前交付组合 FC76.28、完整 SFC43/core9、街机1.5.4、GBA13、MD3。MC1.21.1 / NeoForge21.1 / Java21。文中的“源码已有”不是本轮 Minecraft 实测，也不是稳定版结论。
- 复用调研：本轮是已有功能盘点，不新增核心/桥，沿用仓库已有方案。实际读取共同 AGENTS、行为规范、制作规范、SFC 蓝本、公共层 README，以及第 10 节源码；未重新选型或下载上游核心。新附属开工仍须独立完成官方文档/上游方案检索，不能用本次内部盘点替代。
- 状态词：**源码已有**＝调用链/实现存在；**部分接入**＝只有一部分流程；**未接入**＝缺少必要适配；**待实测**＝不能以源码存在推断游戏内正确。

行为默认值仍以[功能行为与配置规范](方块电玩功能行为与配置规范-v1.md)及最新明确用户决定为准。本文件补足功能覆盖检查，不另造第二套全服配置或稳定 SDK。旧 SFC 蓝本中的版本、默认进程、保存限制须按其历史日期理解。

## 2. 本次 MD 反馈：三项都没有完成统一

| 编号 | 反馈与源码事实 | 原因 / 后续正确补齐方式 | 本轮状态 |
| --- | --- | --- | --- |
| MD-01 | MD/GBA 打开“游戏卡带 · 老式电脑”简化页；FC/SFC 打开完整卡带工作台 | `ContentCartridgeItem` → `ContentCards.open` → `ContentCardClient.Writer`。复用了电脑、权限和部分传输基础，但未复用完整工作台；列表行直接触发写卡，缺独立选中预览/确认、搜索、名称/封面编辑、保存策略等能力；空列表提示也缺。应提取已有工作台的可复用呈现与动作合同，保留各机型数据适配，不能复制 NES 校验给 MD | 已定位，未修复 |
| MD-02 | AV 连接可以建立，线却不可见 | `MdBlock` 接了 `HomeHardware.useCable`，但没有 MD 线材渲染器/注册。FC 的渲染器只注册 FC 实体；SFC 另有自己的 AV 适配，不会自动替 MD 画线。应复用公共电视插口与线网格，加 MD 插口/包围盒/朝向适配及缓存；连接 ID、双方端点和卸载状态必须校验，不能画永久装饰线 | 已定位，未修复 |
| MD-03 | 螺丝刀点 MD 不能打开设置 | 工具会识别 `ExternalHomeConsoleBlockEntity` 并进入 `HomeSyncSettings`；`MdMod` 没覆写 `synchronizationSettingsAvailable()`，继承默认 `false`，因而被设置入口拒绝。通过工具权限/命中检查后，源码会提示“此机型不支持同步设置”；非 OP/未命中等则是另一个拒绝分支 | 已定位，未修复 |

不能只把 MD 的 `synchronizationSettingsAvailable()` 改成 `true`：当前页面和默认模式掩码主要针对公共同步，MD 实际仍是私人单人，尚无公开串流/本地同步/托管/Netplay/旁观。应先让“设备诊断/配置入口”能表达私人单人能力，再给已实现的功能入口；不支持的模式明确禁用。不能为了打开菜单假报联机支持。

MD 卡带还残留“私人模式占槽物”名称，应随实体内容卡功能整理；这是文案债务，不是新的游戏格式。MD 现有 ROM 身份、私人保存、新旧核心及 JNI/进程隔离应保留，工作台统一不授权自动迁移或覆盖旧档。

## 3. 现有机型对照：有哪些相同、哪些不能直接等同

本表“街机”指当前原生街机/公共机柜路径；SFC 共用机柜后端单列限制，不把它等同 SFC 家用。

| 方面 | FC 家用 | SFC 家用 | 原生街机 / 公共机柜 |
| --- | --- | --- | --- |
| 游戏载体 | 实体 FC 卡带及服务器内容身份 | 独立 SFC 卡带/内容身份，不能插 FC 卡 | 设备选中游戏/后端，不要求虚构家用卡带 |
| 拷卡/选游戏 | 老式电脑完整工作台；本地/服务器来源、搜索、预览、确认写入、名称、封面 | 已使用公共 `CartridgeWorkbenchLayout`，但仍有 SFC 专属编辑协议/服务 | 游戏库服务器/本地切换、搜索/分页、刷新、确认使用；内容来源与运行模式独立 |
| 游戏资料 | 卡带名称/封面；游戏人数由管理员设置 | 同类名称/封面/人数入口 | 管理员设置显示名、人数、横竖标注、比例；不直接改游戏内 PGM/DIP |
| 插拔与物品 | 插卡/退卡、卡带身份、手柄借还分开 | 独立卡带、两手柄端口与借用租约 | 操作席/投币/通讯线按后端真实能力；不套卡带流程 |
| 电视连接 | 公共 AV 权威连接、扣还线；FC 有 AV/手柄线渲染 | 公共 AV 连接，另有 SFC AV/手柄线渲染适配 | 自带屏幕；通讯线是机柜关系，不是电视 AV 线；现行走背部底沿/地面 |
| 物理操作 | 电源/复位/手柄命中与运行状态衔接 | `SfcApplianceControls` + `HomeApplianceService` + 服务端钩子 | 三种柜型开关正面左下，状态姿态/灯光/音效；摇杆/按钮按席动画 |
| 螺丝刀 | OP 工具打开设备设置 | 已声明设置可用性、真实模式/忙状态；可进公共设置页 | 设备调试页；投币配置另有创造模式管理员等条件；不能绕过服务端权限 |
| 电视遥控器 | 电视显示/声音，不负责主机模式 | 使用同一电视入口 | 不把电视遥控器当街机配置工具 |
| 控制与席位 | 公共按键/手柄捕获，端口和租约，光枪另有适配/保存边界 | 公共 SFC 输入 profile，借还和主持计算职责分开 | 后端声明席位数，主副柜映射，退席只清该席，投币与普通按键分开 |
| 联网 | 已有串流/本地同步/托管/RetroArch Netplay；另有 FC JNI Netplay（普通双手柄范围） | 已有对应家用模式；不能把 FC JNI Netplay 自动当 SFC JNI Netplay | 按核心/provider 的能力逐项开启，不是所有 MAME/街机 ROM 都同样支持 |
| 旁观 | 公共发现/授权/显示；按具体运行模式供流或本地运算 | `SfcWatchProvider/Client`、本地旁观与 Netplay 内容准备分别实现 | 按连接组有效屏幕/范围订阅，不向全服广播重型数据 |
| 保存 | 按模式与卡带设置：不保存/个人/卡带；光枪与 JNI 等隔离身份需保留 | 家用 Netplay 有个人/卡带/不保存；原串流/本地同步的恢复备份、托管 SRAM 是其他保存路径 | 当前 FBNeo Netplay 有不保存/个人/主柜机器策略；其他核心/模式不能借用“已支持”结论 |
| 全服配置 | 管理终端权限、新家用机默认等 | 复用适用政策；附属具体能力需注册/校验 | 管理终端“街机全服”控制关机/距离，适用新旧机柜；不是逐机覆盖 |

特别保留：SFC 家用 Netplay ≠ SFC 共用机柜 Netplay；后者当前 `SfcCabinetProvider` 没有自己的 `prepareNetplayFactory` 实现。JNI 是核心调用后端，串流/同步/Netplay 是运行和网络模式，界面与文档必须分开标注，不用一个“JNI模式”混写所有能力。

## 4. 距离、电源和退出：不能只设一个“距离”

| 规则 | 当前数值 / 归属 | 触发结果 |
| --- | --- | --- |
| 实际右键/螺丝刀 | 原版交互距离与真实遮挡；螺丝刀服务端取 `min(6, blockInteractionRange)` 且需 OP2 | 只授权当前命中的设备，不扩大到有线租约距离、不穿墙 |
| 家用 AV 两端 | 同维度，两端锚点距离 ≤ 8 格；公共连接账本 | 这是连线长度，不是操作者/旁观距离；占用/身份冲突拒绝，退线不重复返还 |
| FC/SFC 有线操作 | 玩家距主机中心 ≤ 6 格 | 超距释放该控制租约/输入；公开局不能简单等同整机关机；私人会话按其有效性安全停止 |
| 街机操作 | 距对应机柜锚点中心 ≤ 8 格 | 退出无效操作席；与计算主持、其他席位分开 |
| 适用家用旁观 | 默认16；底层4～64，管理终端常用8/16/32/64 | 当前“新机默认”只初始化新家用机，不回填旧机；不是所有后端已自动接通 |
| 原生街机显示/发现 | 默认16，合法1～128，管理终端全服强制 | 超距停止显示/无用纹理工作，不直接关机；机柜本体照常受 MC 渲染 |
| 已建立公共旁观 | R + 4 退出缓冲；默认超过20退出 | 16～20 区域不能说零流量；多屏按有效的最近显示端判断 |
| 街机无人占席 | 默认60秒，0～3600，0禁用 | 最后一席离开才计时；再入席取消，看过场不等于空席 |
| 街机主动退出即关 | 默认关 | 打开后仅最后一名有效操作者主动退出才整组关机，不能关掉其他席 |

检查使用三维平方距离、同维度和实际端点身份。一个100格外普通在线玩家不能仅因在线就收 ROM/音画/Netplay 状态；正常区块信息和少量全服配置仍可能同步。需要测量才能声称具体省多少性能。

电源、核心执行、操作席、旁观、画面五者独立。关机保留所选游戏，再开机运行它；是否继续进度由真实存档能力决定。主持断线、拆机、卸载、失效连接等安全停止不被“倒计时0”豁免。不新增按每台机器每秒扫描全服玩家的关机机制。

GBA 是物品掌机：已有右键举起/放下、Shift右键开关机、两手插卡规则，不能硬套家用 AV 或街机空席策略。电脑仍有独立8格操作/32格显示规则；本轮不改它。

## 5. 菜单合同：新附属不能只提供一条命令

以下是制作目标导航，不是声称当前所有菜单已统一。具体按钮按能力显示，但“无对应功能”和“入口漏接”必须区分。

```text
老式电脑 + 适用卡带 → 卡带工作台
  游戏库 / 封面、搜索 / 刷新 / 分页、来源与当前卡信息
  选中预览 → 明确写入；保存名称；支持的存档策略；返回
螺丝刀 + 固定设备（OP）→ 设备设置 / 诊断
  当前游戏、电源、执行后端（JNI/进程）、真实运行/网络模式
  支持的模式与切换条件；控制设置；运行环境/复制诊断
  本机音画/网络；适用的存档入口；刷新；返回
管理终端（OP）→ 全服权威配置
  玩家内容权限、新机默认、适用全服策略、管理/诊断
```

- 卡带机最低操作体验对齐 FC/SFC：列表不能“点中即改卡”；明确服务器/本地来源、预览和写入确认，拒绝无权限上传；空目录、无匹配、加载中、超时、错误是不同状态。不得另做两个大按钮就称完整同步。
- 名称/封面/卡带存档等需有真实数据支持；不能只加按钮。某项确实不适用时，能力表明确说明，经需求确认，不静默遗漏。ROM 身份用内容摘要，改名不能换错保存身份。
- 螺丝刀诊断不能被“此核心没有 Netplay”一并屏蔽。现有 `HomeSyncSettings` 尚把入口绑定同步可用性，这是公共接口待补齐处；后续修复需分离诊断入口能力与联网能力，不能伪造支持掩码。
- 工具优先级、单击/长按节流、空手/AV/卡带/手柄行为要一起验证，工具不能顺带开机、借柄、拔卡。运行中必要设置只读，不能为了看诊断强制关机。
- 本机 JNI/进程和核心选择标为本机偏好；全服/设备/卡带设置分开。未支持的模式禁用并说明，返回只关闭页面，不结束游戏。
- 加载时不保存，失败保留草稿，超时不假成功；服务端再验证 OP、租约、电脑/主机身份、连接与权限，不能只在 UI 藏按钮。

## 6. 配置与保存：每一项都要有归属

| 类型 | 入口与权威 | 旧设备/其他玩家影响 |
| --- | --- | --- |
| 内容浏览、使用服务器 ROM、上传 ROM/封面 | 管理终端“玩家权限”，服务端复核 | 权限撤销影响未完成操作；上传/使用/维护权限不能合并 |
| 家用新机默认模式/旁观范围 | 管理终端“新机默认” | 只初始化新机；未知能力不能强开模式，旧机设置保留 |
| 街机退出即关、空席秒数、显示范围 | 管理终端“街机全服”，单机页只读说明 | 对适用新旧街机统一生效；不扫描强加载全世界，不改家用/掌机 |
| 选中游戏、AV/主副柜关系、允许的设备模式 | 设备持久数据及服务端规则 | 重载保持合法设置，不恢复旧租约为新权限 |
| 卡带名称/封面/进度策略 | 老式电脑/卡带入口与服务器内容/保存校验 | 只改声明目标；管理员游戏资料与玩家卡带草稿分开 |
| 按键、音量、个人画质、运行器偏好 | 客户端配置/公共控制和诊断入口 | 不伪装全服值，不绕过权限/操作距离 |
| 清理个人进度 | 当前管理终端“FC个人存档” | 当前不是全机型清理器；不能自动删除 SFC/MD 或共享卡带档 |

任何新的全服字段，功能说明必须填：默认值、合法范围、权威保存位置、终端入口、即时/重启生效、旧设备规则、并发修订、撤权处理。现有终端还不是任意附属字段自动注册的完整 SDK；缺接口就登记最小公共扩展，不把字段藏到某玩家文件里。

保存必须逐模式声明 SRAM/RTC/即时状态/NVRAM/核心选项、归属及写入方。FC/SFC 的个人/实体卡带、街机个人/主柜机器、MD 私人本机保存不是同一个键。30秒检查点、手动保存、正常关机保存、开机恢复只适用于真正接通的路径。服务器落盘确认、原子替换、备份、并发锁、坏档拒绝都要验证。旧 WASM/进程/JNI/不同核心档不强行混读。

PGM/Test/DIP 仅 OP，进入维护页与运营配置按机器持久化是两回事。当前通用维护入口按后端能力开放，不是所有 MAME 的通用 DIP 编辑器；按机柜保存、换游戏清除的专项语义仍不能用普通完整状态存档冒充。

## 7. 新附属功能门槛：必做与条件能力

“基础完成”要求所有适用的 B 项通过；核心能起画面只能称“核心试验”。用户可以选择先拿明确列缺口的候选，但不能把未做项标“不适用”来宣布完整。最终逐项记录 `通过 / 失败 / 待验证 / 不适用及理由`。

| ID | 必做项目 | 适用范围 / 验收底线 |
| --- | --- | --- |
| B01 | 先查复用与官方方案 | 每个新附属独立读官方/公共层/相近附属，留来源、许可、版本、比较和必要适配；不另复制桥 |
| B02 | 装载与依赖 | 主包+附属双方可加载，专服无客户端类错误；缺前置明确报错，无公共类/ID重复；完整SFC不混薄包 |
| B03 | 正规内容入口 | 卡带机工作台按第5节；街机用公共游戏库。合法格式/大小、来源、明确上传确认、权限、失败保卡 |
| B04 | 实体介质流程 | 有介质的设备：插入/取回/换卡、空卡拒绝、堆叠与背包满、重载、失败不丢/不复制；现有卡和内容兼容 |
| B05 | 接线业务与可见线一起验收 | 有线设备：连接/解绑/扣还、两端状态、插头坐标、四向线网格、包围盒/裁剪、远近/卸载/重连；纯掌机不适用AV |
| B06 | 电源与物理互动 | 开/关/再次启动已选游戏；电源状态/灯光/音效/动画/命中一致；复位/弹卡等按模型实际能力 |
| B07 | 控制与动画 | 声明的所有端口/光枪等逐一适配；借还、身份/租约、公共重绑、失焦/菜单/退席释放，动画对应真实席位 |

## 8. 复用接入顺序与真正缺少的公共能力

1. 先确定外壳类型（家用/机柜/掌机/程序）及 B/C 清单，写“不做哪些模式”，确认必需功能不能遗漏。
2. 从公共模型、布局、权限、设备钩子、输入、存储、旁观和桥接入口开始查；上游核心复用与 MC 使用体验适配分别完成。
3. 家用卡带优先共用完整工作台结构；当前 FC 与 SFC 已共用布局但各有业务实现，MD/GBA的 `ContentCards` 还不是等价的完整工作台。后续提取公共呈现/动作合同，机型只提供格式、资料和保存能力适配，避免再建第4套简化页。
4. AV 连接账本与线材网格是两条接线。公共 `HomeAvCableMesh/UserTvCableMesh` 可复用，机型必须补自身插口、包围盒与渲染注册；不要让公共层依赖附属私有 SFC 类。
5. 工具入口能力与同步模式能力应拆开；私人单人设备应有只读诊断/适用本机设置，真实网络能力掩码仍为未支持。接口尚待实现，不虚构 `registerDeviceSettings` 已存在。
6. 需要全服配置扩展时协调公共终端与服务端协议；不是在附属另写一个绕过终端的配置文件。主包确需更新时说明最小扩展与 FC/SFC/街机回归范围。
7. 按能力启用运行/旁观/保存，最后从最终 JAR 做玩家流程验收；不能先把所有支持位打开再留给用户试错。

以上是后续适配路线，本轮没有实现这些公共接口或开启 MD 多人。

## 9. 每个新附属必须走一遍的玩家验收

| 场景 | 观察点 / 证据 |
| --- | --- |
| T01 新卡写入 | 老式电脑→浏览/搜索→来源/预览→确认→成功；空目录、坏ROM、无上传权、取消均清晰且原卡不坏 |
| T02 原卡/旧世界 | 写好的卡和旧连接仍可读；更新不要求无理由重新拷卡/拆机；换名不换错进度 |
| T03 接电视 | AV两端依次点击；业务连接和实体线均存在，四向/不同电视/高度/视锥可见，断线消失且只返一次 |
| T04 工具优先级 | OP螺丝刀开设置，普通玩家不能改；不因工具点击触发电源/借柄；运行中诊断可读，敏感操作拒绝有理由 |
| T05 真正重开 | 插卡→电源→游戏→关机→同一电源重开，无需重新选ROM；启动失败有实际诊断 |
| T06 操作与退出 | 各端口独立输入/动画，松键/失焦/菜单不粘；归还不偷关他人局；手柄超6/席位超8按规则 |
| T07 远近与无观众 | 默认内侧/边界/外侧/缓冲退出/回来；100格普通玩家不收重型流，主持与观看角色分开 |
| T08 策略 | 街机最后一席立即关开/关×倒计时0/60；重入取消，过场不关；家用不误套此策略 |
| T09 保存 | 每个声明模式保存→退出→重入；两玩家/两卡/两机/同名ROM不串档；坏档/磁盘满不毁原好档 |
| T10 生命周期 | 断线、死亡、换维度、拆机、卸载、启动中关机及迟到回复；旧会话不能影响新一局 |
| T11 管理与UI | 终端全服/新机默认生效范围正确，撤权/并发冲突有效；多GUI缩放、长名称、图标与创造分类可用 |
| T12 配套发行 | 最终七包或实际声明组合专服/客户端加载；资料、成品SHA及固定最新目录一致，不标未经人工验收的稳定版 |
