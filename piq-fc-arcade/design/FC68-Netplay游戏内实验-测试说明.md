# FC68 游戏内 RetroArch Netplay 实验测试说明

适用：2026-09-24，Minecraft 1.21.1 / NeoForge 21.1.x（构建 21.1.236）/ Java 21，FC 主包 0.31.0-alpha.68、网络协议44。Netplay 执行端仅 Windows x64，固定 NTSC；Minecraft 服务器只转发，不执行新增原生程序。尚未进行真实 Minecraft 双电脑验收，不标稳定。

## 安装与开启

1. 先备份，在单独的客户端/服务器与世界副本中测试。把旧 FC JAR 移出 mods 留存，服务器和每位玩家统一换为 `game_console-0.31.0-alpha.68.jar`，同 ID 只留一份。
2. 成品在 `方块电玩-FC68-Netplay实验-20260924`，不要使用中间 build/libs 包。运行组件已内置，不需要另装 RetroArch，不用单独下载 DLL，也不需要开新的网络端口。
3. 另做一张普通 FC 测试卡带，存档方式选“关闭”。不要直接拿已有进度的卡带试验。测试双人时，游戏本身与游戏库人数均需支持双人。
4. 主机关机后，用调试螺丝刀打开设备设置，或瞄准主机输入 `/home-sync`，由 OP2 选择“RetroArch Netplay（实验）”。这只修改当前主机，原三种模式保留。
5. 接好电视、插卡、开机。开机玩家选择允许 2P，并拿 1P 手柄；另一玩家拿 2P。仍用 N 锁定/解锁人物移动、F7 设置按键。开机玩家不拿手柄时，游戏仍运行但其输入为零。
6. 附近旁观沿原本范围与本地自动旁观上限接入，不需要拿手柄。首次载入、2P 领取/归还、旁观重新接入会进行原生同步，可能短暂等待。
7. 比较完先正常关机，再切回“本地输入同步”，用同一个游戏和同一网络对比。回退旧 FC 包时使用升级前备份，不让旧版本直接读试验世界。

## 本轮边界

- 保留 LOCAL_SYNC / MEDIA / SERVER_MEDIA；FC 单机设备可额外选择 Netplay 实验。
- 固定 RetroArch 1.22.2 与 Mesen，Windows x64 客户端；服务端只转发受控会话字节，不执行此原生程序。
- 音画在 Minecraft 电视显示，实体手柄仍经原有权限领取。主持端 P1、另一玩家 P2；旁观只读。
- 上游 TCP Netplay 封装于已有 Minecraft 连接；原生端口仅 127.0.0.1，不开放公网、不启用大厅或 UPnP。
- 实验仅普通 FC 家用机、关闭存档的卡带。从头开始，不读写现有卡带/个人进度，不支持光枪、街机设备及附属 Netplay；保持其他附属原实现。首测建议只装 FC68，暂不混测 SFC/GBA/街机/Flash。Flash prototype.8 不能与 FC68 混装。
- 主持退出时结束，不承诺无感迁移。低延迟、观战、异常退出、长时间与真实双机结果须分别验证。
- 用户报告原 FC 联机基本正常但偶有卡顿；流量面板始终为 0，此次不修流量面板。

游戏由每个参与端的独立 RetroArch/Mesen 进程运行；服务器按实体手柄权限转发原生 Netplay 数据，不是服务端模拟或音画串流。原生 Netplay 与旧逐帧同步不同时推进。本轮不宣称比原模式更快：Minecraft TCP 连接仍可能受拥塞影响，需要实际对比。

实验中的重置按钮提示关机重开；主持断线或原生端退出会结束本局，不自动换主持。归还手柄撤销原生控制能力、按键清零；远端从控制转旁观会重新同步。切换手持物使实体手柄授权失效时，需要重新领取/持有手柄。不要用于需要保留进度的游戏。

性能页会注明 Netplay 独立进程尚未采样，`/fc-client` 状态诊断显示原生接收帧数；原 FC 单帧耗时不能当成 Netplay 性能。原流量监控为0的问题暂未修复，Netplay 数据也未纳入其统计。

## 请重点测试

- 两位玩家能否同时操作，音画速度是否正常；连续玩10～20分钟，记录卡顿/声音断续。
- 2P 归还再领取能否加入、旁观者能否中途看到相同进度；拒绝2P时是否确实不能控制。
- 主持退出、断线、关机后其他端是否停止；重开是否从头开始。
- 同机游戏对比旧“本地输入同步”，注明网络延迟、人数及谁卡顿。不要把一次主机/核心跑分当成真实联机结论。

异常请附 FC68、使用模式、两端 `logs/latest.log`、出现时的操作和截图。原生启动/运行错误会写入日志；不要公开包含私人 ROM 路径或账号信息的完整日志。
