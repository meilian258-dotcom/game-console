# FC65 原生存档接入测试说明

适用：方块电玩主模组 `0.31.0-alpha.65`，Minecraft 1.21.1 / NeoForge 21.1.x / Java 21。构建基线 NeoForge 21.1.236。2026-09-23，像素匠。

这是阶段2的本地候选，不是正式稳定版，不代表服务器或 Minecraft 多人验收。阶段1独立文件工具的全部能力不能直接算作本版公开存档能力。

## 本次做了什么

把公共 libretro 原生 SAVE_RAM/RTC 接入 FC 的现有持久化流程。保存时在核心所属线程、不推进下一帧的情况下，捕获完整快照和原生数据，装入同一个有校验、上限2 MiB的 PFP1 保存包，交给原有存档容器保存。

- 玩家主持音画 / 本地输入同步：主持端上传保存包；服务器按原来会话身份、连接、epoch、帧号和写入权限检查。恢复主持进度时交给持久化读档接口。
- 服务端托管：核心周期保存和正常终止保存均使用新接口；家用机继续由会话管理归属，无管理的柜机继续使用原 HostedSaveFile。
- 私人模式：正常“结束并保存到本机”将包写入原 ZIP 的 `state.bin`；`sram.bin` 仍为空，不另建与快照不同步的第二份权威数据。
- 旁观 / 中途加入：只下发包内完整快照，仍按原 PLR1 + 输入历史追帧；不额外发送原生区域。完整快照自身仍可能包含游戏内存，不能把这理解为隐私隔离。
- 个人档仍按玩家/槽位；卡带档仍按卡带电路板编号。卡带所有权、并发写入保护、不存档选项、OP个人档清理规则均没有变更，也没有改成整个服务器按游戏统一保存。

## 恢复顺序与旧档

“继续游玩”必须回到同一个时刻。因此先验证保存包、ROM与快照档案，再按精确核心/选项身份恢复原生区域，最后恢复完整快照；不会在恢复快照之后用另一份 SRAM 覆盖它。原生区域身份不匹配时不导入该区域，只尝试按原有 PLR1 校验恢复完整快照；这不是跨核心兼容承诺。

旧 PLR1 / 既有 WASM 存档入口保留，各核心命名空间仍隔离。新格式不能送给旧客户端，因此 FC 网络协议42→43，两端必须一起升级。完整快照的 PLR1 格式及 Mesen 配置身份不变，公共子进程协议使用阶段1的v3，不能单换 helper。

本阶段是“把原生保存数据可靠地带入既有流程”，**没有新增“仅用游戏内原生存档启动”、导入导出 `.sav`、跨核心迁移或新的保存模式按钮**。“从头开始”、复位的含义不变。没有使用阶段1独立 `LibretroMemoryStore` 绕过现有玩家权限；它只作为公共工具随代码提供。

## 必须知道的限制

- 玩家主持/本地同步家用机的物理关机沿用既有逻辑：保存服务器最近确认的快照，并非等待关机最后一帧新快照。断线或拔线也不能保证最新进度。这一轮没有重做关机握手。
- 服务端托管和私人模式在正常结束时采集最终保存；异常退出仍不能保证最近进度。公开 ArcadeSaveStore 的原子替换策略保持，**没有新加上一份自动备份**；HostedSaveFile/PrivateSaveStore保留其既有备份机制。校验不是签名，也不是断电恢复保证。
- RTC只有通用字节接口/文件单元测试，真实 Mesen 没有非空RTC；未验证GBA实时时钟、文件型NVRAM/EEPROM、跨系统、Linux和磁盘故障。
- 这次只改FC和共用桥，不迁移SFC/GBA/街机/Flash，不接入RetroArch Netplay。Flash8与FC64及以上不能混装；其他附属组合仍待复验。

## 安装与回退

1. 先退出测试客户端/服务器，备份完整世界、模组配置及公开/私人存档目录，并保留FC64旧JAR。在世界副本测试，不直接升级正式服。
2. 仅使用 `game_console-0.31.0-alpha.65.jar`。客户端和服务器的 `mods` 都换为同一FC65；旧同ID包移出 `mods` 备份，不能同时加载。`build/libs/piq_fc_arcade-0.31.0-alpha.65.jar` 是中间件，含源树既有未审贴图草稿，不能当交付件。
3. 原生运行组件已内置，不另装RetroArch或手换worker。共用方块注册、服务端会话/权限和客户端渲染输入均需要主包，不是由依赖`side`字段推断两端要求。先不混装其他附属。
4. 新保存包不向FC64回写兼容。回退必须同时恢复旧JAR及升级前的世界/存档备份；不能只换旧JAR后继续用FC65写过的档。没有自动迁移或删除旧世界。

## 建议的游戏内验收

在独立世界副本，用自己有权使用的电池存档游戏，并保留原始存档副本：

1. 个人模式：玩家A保存、关机/重进后继续，换机器再继续；玩家B拿同卡只能打开B自己的个人槽。
2. 卡带模式：A保存后将卡交给B、换机器，B继续同一进度；另一张独立卡不能串档；不存档卡不落盘。
3. 对三种公开模式分别测试保存、加载、2P加入、旁观中途加入/退出；确认旁观者不会成为存档写入者。
4. 私人模式使用“结束并保存到本机”，等待成功后再开；公开和私人进度不互相覆盖。
5. 分别记录正常结束、主持离线、硬拆机器的结果；对比最近已确认快照，不能把硬关机误当逐帧保证。
6. 核验旧FC63/64测试档仍能在FC65读取，以及错误ROM/光枪模式不会串档。测试损坏文件仅在复制品中进行，不修改唯一原档。
