# 方块电玩 · AI 开发协作规范

维护者：像素匠 / 方块电玩维护组。初版：2026-09-28。

这是开发约束和开工入口，不是功能完成报告。适用于方块电玩主模组、公共层及附属；工作区根 `AGENTS.md` 将本文件作为这些组件的共同规则。路径均相对于本目录。不得把本文件要求的目标写成已存在的 API 或已验证功能。

## 1. 开工前必读与需求追踪

2026-09-29 起，源码使用根目录 [GIT_WORKFLOW.md](../GIT_WORKFLOW.md) 的标准 Git 单仓库流程：先查状态/归属、按任务分支及暂存、审核 diff 和检查后提交；不得再以输出目录副本替代版本控制。独立克隆不包含维护机私有的根维护手册/后台资料，其通用协作入口为本文件与 Git 指南；回到原维护工作区仍须履行下面的留痕及台账规则。首次基线不是稳定版本，既有功能故障不因迁移而视为修复。

1. 阅读工作区根 [AGENTS.md](../AGENTS.md) 和 [Codex维护手册.md](../Codex维护手册.md) 中“方块电玩现行协作约定”、对应负责人及最新交付记录；历史段落标注的“最新”不能覆盖更新记录。
2. 先阅读 [机器与附属通用制作规范](design/机器制作与交互标准.md)。这是所有已有及未来方块电玩设备的统一成品体验入口，已在同一文档包含设备类型／适用功能、电源灯、接线、控制器、介质、存档、工具菜单、12 张内嵌参考图和验收清单；不写成某台机器的修复说明，不把私人单人原型当完整家用机。按本文确定应做成什么样，按类型适配，不照搬截图临时状态、不把图片当实机验收结果。[参考图集](design/机器交互参考图集.md) 仅作原序查图索引，无须另读才能补全玩家规则。开发接口与兼容细则再按需查 [功能行为与配置规范](design/方块电玩功能行为与配置规范-v1.md) 和 [模组制作规范](design/方块电玩模组制作规范-v1.md)；具体版本／故障／验收进度记在组件文档与维护记录，不混入通用要求。
3. 阅读本次组件的 README、构建脚本和相关源码。新增或补齐附属必须逐项对照 [附属功能基线与现状](design/附属功能基线与现状对照-20260930.md)，在功能说明中填写 B01～B16 与适用 C 项的实现/验收状态；拷卡、线材可见性、螺丝刀入口不能因核心能运行而漏掉。新增附属必须再读 [SFC 制作蓝本](../piq-sfc-home/design/以SFC为蓝本-附属制作说明.md) 和 [公共层说明](../piq-retro-platform/README.md)，先填 [附属能力声明](design/附属能力声明模板.md)。
4. 按 [功能制作说明模板](design/功能制作说明模板.md) 列出本轮全部需求、改动范围、明确不改的部分和验收方法。连续消息是同一清单的补充；不能只做最后两条。新要求替代旧要求时标记替代关系，不把相互冲突的历史方案一起实现。
5. 诊断/解释请求先给证据，不擅自改功能；制作请求才在授权范围内实现。发现规范与最新明确需求不一致，记录新决定并同步相关条款；含糊且影响结果时先澄清。

新增或补齐机器还必须阅读[全组件运行流程与复用接口总览](design/全组件运行流程与复用接口总览.md)，对照全部相关外壳/运行模式的“操作 → 界面 → 请求/权限 → 核心 → 保存/旁观 → 收尾”。该总览区分当前接入、历史独立链、未实现和建议扩展；不能只读某个旧附属README、复用菜单布局或看到某个Screen类就推定业务接通。更新相关流程时同步总览并记录源码版本与验证范围；不得把现状缺陷抄成制作目标。

完整业务目标只在通用制作规范第 1 节维护：家用校验 → 按需选档 → 独立 2P 确认 → 加载／恢复 → 就绪授权；街机、掌机、电脑／程序、外设采用其中对应策略。开局身份、保存确认、取消／异常终态和再次继续一起核对，填写功能说明 1.2 并验收 F 项。旧工程文档不再各自指定顺序，重复或冲突的旧目标应替换；历史源码事实、保存兼容和参考图保留。文档更新本身不代表公共流程已经完成。

先确认现有修改、素材草稿和成品归属；保留无关改动，不回退、覆盖或顺手重构其他组件。需要跨组件扩展时先说明受影响接口和回归范围，按组件公开调用说明协作。

## 2. 组件边界与“通用优先”

| 目录 | 职责与边界 |
| --- | --- |
| `piq-fc-arcade`（本目录） | 主模组：内置 FC、电视/公共机柜、权限/会话/内容服务、公共界面与管理终端 |
| `../piq-retro-platform` | 内部公共源码库：纯接口、输入/帧、桥与存储基础；不得反向依赖主模组/附属实现或 MC 世界对象 |
| `../piq-sfc-home` / `../piq-sfc-arcade` / `../piq-md-home` | 家用附属与各自核心／输入／保存适配；按相近设备查真实调用链，不把某机型私有类型强加给新系统 |
| `../piq-native-arcade` / `../piq-gba` / `../piq-j2me-arcade` | 各自核心、资源/profile、内容格式、输入/保存适配和真实能力 |
| `../piq-computer` / `../piq-flash-box` / `../piq-pvz-addon` | 电脑与程序适配、相应运行器；公共接入边界不等于所有程序已插件化 |

- 保持“主包含 FC，其余可选附属”。公共库随主包提供一次，不能要求玩家另装内部平台 JAR；附属不得重复打包公共类、worker 或同包名桥。
- 共性修公共层，差异放 profile、能力声明或清晰的适配器；禁止为每个附属复制下载、权限、旁观、菜单、生命周期或原生桥。
- 当前可复用入口包括 `HomeSystems`、`HomeApplianceService`、`CabinetBackends` / `CabinetClientBackends`、`WatchProviders` / `WatchClient`、`ServerCoreRegistry`。先核对实际签名和线程/权限合同；注册成功不等于运行闭环完成。
- 已有接口够用时，新附属原则上只更新自身。确实缺少公共能力时，先列出最小公共扩展、兼容策略及调用方，再更新主包；不得为了某个游戏名在公共层散布特判，也不能承诺以后主包永不需要升级。
- 公共协议/API 改动说明兼容范围、是否要求两端升级，并回归现有使用者。内部 `public` 类不等于稳定 SDK，规范版本不等于二进制 API 版本。

### 新功能先检索、先复用（2026-09-30 用户确认）

- **每次制作新的附属都必须执行，不能因做过上一台机而跳过**：开工先阅读该核心官方文档、公共层与相近附属的调用说明，查找仓库可复用代码和上游现成方案。先填写功能说明 2.1 的来源/日期/比较/结论，再写实现；交付逐项核对验收清单 R05。无检索记录不得标为制作规范合规完成。
- **使用 Libretro 的新机器，制作前必须阅读 [libretro/docs 官方文档仓库](https://github.com/libretro/docs)的相关文档并查找有用信息和现成方案。** 可结合[官方文档站](https://docs.libretro.com/)检索目标核心、格式/BIOS、输入/外设、选项、音画、保存、联机及许可等适用内容；记录阅读日期、具体页面/仓库路径、采用结论与待验证限制。不能仅打开首页、凭记忆或因之前做过其他核心而跳过；无法访问或缺少条目如实记录并补齐依据，不能伪称已阅读。上游文档不替代本模组适配与实测。
- 新增机器、后端、工具或公共能力前，先查仓库已有实现及调用说明，再查官方文档、成熟上游项目和官方制品；不能先写一套，交付后才发现现成方案。已有功能的小修可注明沿用原方案，不为凑调研而增加依赖。
- 在 [功能制作说明模板](design/功能制作说明模板.md) 记录检索日期、来源、候选比较、真实能力/未验证项，以及采用或不采用的具体理由；查不到或无法访问如实记录，不凭记忆说“没有现成的”。详细选型要求见 [模组制作规范](design/方块电玩模组制作规范-v1.md) 第 2.1 节。
- 默认复用已有公共接口和满足要求的可信上游制品，只补模组必要适配；自行编译上游不等于自研核心，但也不是默认必经步骤。确需自编译、补丁或自建时，先给出可核对的缺口、验证依据及维护成本。
- 核心能力清单/扩展名、官方 Netplay 标记和“支持存档”仅作选型依据，不能直接当作本模组已支持；换核心须独立验证音画/输入、生命周期、各模式及保存身份，不直接覆盖 DLL 或旧存档。本规则不授权自动重构或替换现有核心。

### Libretro / JNI 必须遵守的边界

- 已确认的架构方向：新增模拟器附属以公共 JNI 为默认接入路线，不以“仅私人模式／只改默认值”代替完整适配。FC、SFC、GBA、街机、PvZ、MD 及既有光枪的迁移范围见[全面迁移范围与验收](design/JNI全面迁移-范围与验收.md)，Flash／Java ME 不因该历史迁移范围被改动。具体已接入模式查技术总览与组件最新记录；多实例、光枪、保存和旁观逐项验证，不把迁移目标当完成报告。
- 当前公共 `LibretroProcess(profile, AddonClass.class)` 是软件画面的独立进程 / JNA 路径；附属类指定其核心资源归属，公共 worker 和 JNA 仍归主包。不要照抄 PvZ 专用桥给每个核心。
- 通用 JNI 的目标是公共生命周期、环境回调、输入、音频及帧传递，视频按软件帧缓冲/OpenGL等能力分支；附属提供可信核心、内容/BIOS规则、选项、端口和保存适配。共性不能写死 PvZ 的 `main.pak`、800×600 或 44.1kHz。
- 若用户要求推进通用 JNI，先用至少一个软件渲染核心和一个硬件渲染核心验证，再宣称通用；不能仅换 DLL、改名字或提供一个接口就称全部支持。核心需按自身几何、像素、采样率、时序和线程约束适配，转换到约定的公共输出格式。
- JNI / JNA 是调用方式，不自动带来 Netplay、确定性、本地同步、保存兼容或旁观加速。模式必须分别实现和验证；不支持的入口禁用并说明原因。
- 共享模拟会话以 **JNI Netplay 为优先完善项**，详见通用制作规范第 1.8 节。不能以 JNI 单人／玩家音画串流能运行替代，也不能只解锁菜单或长期禁用后就称整机完成。开工填写功能说明 1.3，交付逐项核对 N10～N15 的回滚、双人开局／端口、只读旁观、保存及异常收尾；真实核心测试与 MC 双客户端、弱网长测分别记录。原生掌机通讯、纯外设等不硬套共享输入，不适用须给机制依据。
- 运行器默认和已接通平台以实际版本说明为准；[FC76.26 JNI 默认指南](design/FC76.26-JNI默认与自动旁观.md)是该次交付的历史范围，不是全组件现状。保留所支持的显式运行器选择、原生崩溃警告与独立保存，不做运行中或失败后的静默切换。不要在 MC 进程里做崩溃／恶意输入探针，不强杀原生线程或卸载仍在使用的库。
- 本条规定架构方向，**不授权当前任务实施 JNI 重构**。[PvZ10 专用桥说明](../piq-pvz-addon/design/PvZ10-JNI试验说明.md)保留历史证据，不能再照它另造每核心专用桥；当前公共接口及缺口查技术总览。

## 3. 距离、操作、旁观与关机

必须分开管理：电源、核心运行、操作席、旁观订阅、画面可见性。退出操作 ≠ 停止旁观 ≠ 隐藏画面 ≠ 关机。不能为了某个玩家不看屏幕而停掉附近其他人的会话。

| 场景 | 现行行为基准 |
| --- | --- |
| FC/SFC 有线手柄 | 距主机 6 格含边界；超距释放控制租约和输入，不等同整机关机 |
| 街机操作席 | 距对应机柜锚点中心 8 格含边界；计算主持与操作权限分开 |
| 街机显示/发现旁观 | 全服默认 16 格，可设 1～128；超距不上传/绘制不可见屏幕，不隐藏机身、不直接关机 |
| 已有旁观订阅 | R + 4 格退出缓冲；默认超过 20 格退出，16～20 格不能承诺零流量 |
| 真实按钮点击 | 仍遵守 MC 正常交互距离、实体遮挡和保护；6/8 格租约距离不是扩大右键范围 |

距离按同维度三维平方距离计算；显示/旁观使用实际关联显示端，连接组考虑最近有效屏幕。普通 100 格外玩家不得仅因在线就加入重型音画、ROM 或 Netplay 同步；正常区块信息及小份全服配置可能仍同步，不能称绝对零数据。

街机的唯一现行关机组合：

- “最后一人右键退出立即关机”默认关；开启也必须等最后一个有效操作席主动退出，2P/3P/4P 仍在时不关。
- “无人占席倒计时”默认 60 秒，范围 0～3600，0 禁用；全部席位退出才计时，再入席取消。看过场/不按键不是空席，旁观者不是操作者。
- 立即关机关闭 + 倒计时 0 ＝不按退出/空席自动关机；断线、主持失效、卸载等安全终止仍有效，不承诺离线托管或强加载。
- 用入席/离席事件维护截止时间，活动房间低成本检查到期；不再新增“每台机每秒扫描附近玩家”的自动关机逻辑，也不恢复历史“16 格内无人关机”。现有租约/发现检查不代表可以宣传零轮询。
- 关机保留所选游戏和有效设置；物理开机不重新选 ROM，仍执行通用规范第 1 节适用的开局确认链。缺游戏／资源明确提示，重新启动所选游戏不等于自动恢复游戏进度。

这些是街机策略，不自动改 FC/SFC 家用、GBA 或电脑。当前电脑操作 8 格、显示/串流 32 格仍是独立实现，不能在文档中冒称已统一到 16 格；要改需单独需求和验证。

## 4. 设备菜单与管理终端

同类设备统一入口含义，按真实能力显示，不要求所有系统拥有相同功能：

- 状态区：设备名、当前游戏显示名与可追踪文件/ID、来源、运行状态、模式；连接组显示主副关系。
- 内容页：服务器游戏 / 本地游戏、刷新、搜索/分页、明确的选择确认；读取失败不显示成“服务器没有文件”。卡带写入和电脑程序路径流程保留各自语义。
- 配置入口：同步/网络、公共控制设置、运行环境/复制诊断、本机音画/性能、适用的私人/加入授权设置、返回。无能力时禁用并解释，不做假按钮。
- 街机关机/显示页只读展示全服有效值并指向管理终端；游戏资料编辑（名称、人数、方向、比例）只给管理员写、普通玩家读。
- 维护/Test/PGM/DIP 只给 OP，执行时服务端再次验证席位、租约、目标和内容权限；不能只藏按钮。人数标签不修改游戏内部玩家数，“能进 Test”不等于已实现 NVRAM 持久化。
- 编辑页有保存/返回、服务器状态可刷新；加载时不准保存，失败保留输入，冲突要求刷新，成功反馈实际生效范围。“返回/关闭菜单”不得误关机。

影响其他玩家、服务器资源/权限或所有设备行为的设置，**必须从管理终端找到**，不能只存在某台机器或某玩家客户端文件里。分清四类归属：

1. 全服强制：服务端保存/验证/同步，覆盖适用的新旧设备，旧 NBT 或客户端不能覆盖；街机当前规则属于此类。
2. 新机默认：只初始化新设备，明确写“新机默认”，不冒称强制旧设备。
3. 设备数据：所选游戏、连接关系、合法单机设置；维护数据若实现须按设备和游戏身份隔离。
4. 本机偏好：键位、音量、路径、运行者 JNI 试验选择等，不上传为全服设置，不扩大服务端权限/预算。

全局字段记录默认值、范围、保存位置、生效时机和修订冲突规则。保存由服务端复核 OP/连接/终端等条件，不扫描加载所有区块来回填值。现有通用终端插件扩展 API 不完整；接口不足时协调补齐，不另造一套全服权威，也不因只注册后端就声称全局设置已接上。

## 5. 安全、性能、内容与保存

- 服务端权威验证玩家连接、维度/距离、席位/租约、内容权限及保护；客户端显示状态不是授权凭据。投币、卡带、线材、配件扣还防重复、防重放，失败不吞物品。
- 每次异步工作绑定世界/连接/设备/会话代次。关机、换服、换游戏后丢弃旧回复；退出、失焦、撤权时释放该席输入，不能清别人的输入或让按键穿透菜单。
- 核心调用由拥有线程执行；IO、解压、哈希、启动/等待和大状态处理不阻塞 MC 主线程/渲染线程。任务可取消、有超时和队列/大小/并发/带宽上限，卡住不能假报已关闭。
- 客户端类与服务端隔离，后台运行器不得直接访问 MC 世界。原生库固定来源/版本/架构/SHA/许可，不执行服务器或游戏文件指定的任意 DLL/命令；独立进程也不是 OS 安全沙箱。
- 复用 `ConsoleStorage` 的 `game-console` 根和 `RuntimeWorkspace` 的所有权/锁/进程身份规则；正式内容、缓存、临时目录、配置和存档分开。只清确认属于本会话且不在使用的目录，绝不宽泛删除系统 Temp、ROM 原件或玩家存档。
- 网络列表/文件分片按实际编码与发送预算分页、有界重试并复核授权；不能简单调大上限或无视发送失败。路径拒绝逃逸/重解析点，压缩内容限制数量、体积及膨胀；本地文件选择不隐式上传公开。
- 内容身份不能仅用文件名。同步须校验核心、游戏/固件、关键选项和协议；串流、本地同步、Netplay、服务器托管、旁观分别验证，不因支持存档就开放联机。
- SRAM/RTC、记忆卡、即时状态、NVRAM、核心选项分别声明。保存按实际归属隔离，记录游戏/核心/格式身份，使用原子写、备份和并发保护；失败/坏档不能覆盖原好档，未知格式不擅自迁移。
- 性能结论必须测量核心、编码、网络、解码/纹理等具体环节，报告场景和环境；不能把 JNI 替换本身写成“旁观不卡”。优先复用缓存、按需订阅、跳过不可见纹理工作，不为每帧扫描目录/全服玩家。

## 6. 模型、互动与物品入口

- 对外名称统一为“方块电玩 / Game Console”，附属英文采用 `Game Console: <机型>`；交付 JAR 用根 `source-control/release_artifacts.py` 的明确映射命名，详见 [命名规范](../source-control/BRANDING.md)。保留内部 `piq_*` / `cn.piq.*`、源码目录、构建中间件、存档路径、作者及第三方署名。旧冻结包不覆盖；改名不是新构建，SFC 薄包不能冒充完整玩家包。

- 模型、按钮命中、屏幕、插口共享几何来源；四朝向、贴墙、并排柜、多方块、旧机器一起验证。选框简洁，碰撞与按钮容差分别处理；空选框不能挡住可见按钮，真实机壳/墙体不能穿透。
- 现行三种街机开关在正面左下、投币口左侧；小翘板姿态、红灯与一次成功通断的音效跟随服务端状态。摇杆/按钮动画按真实席位显示，松开回中，单人/竖屏柜也要接齐。
- 街机通讯线走背部底沿/地面；电脑键鼠用主机接收器，组合鼠标在操作者右侧。后续明确需求可变更，不能无意恢复历史方案。
- 旋转元数据、宽高比与显示策略只转换一次，检查横竖屏/镜像/拉伸/屏幕贴合。离线模型预览不是 Minecraft 实机验证。
- 物品栏图标清晰、大小/视角协调；创造物品按用途分组，接公共排序，不抢原版第一页。隐藏退役测试物品先处理正常入口，保留旧注册 ID/世界兼容，不直接删旧世界中的内容。
- 模型、贴图、声音保留来源/许可和可编辑源。不能把未批准的素材草稿混进正式交付。

## 7. 构建、验证与可复现交付

先看实际项目构建脚本、版本和依赖，不能把固定历史脚本当通用打包器。现有基础命令示例（在对应目录执行）：

# piq-sfc-home：SFC 开发产物，尚不是完整玩家安装包

1. 单元/契约：距离边界、状态/租约、权限、长度/分页/截断、并发保存、异常和旧数据。
