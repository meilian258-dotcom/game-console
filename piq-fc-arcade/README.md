# 方块电玩主模组

方块电玩把可操作的游戏机、电视和街机带进 Minecraft。游戏画面显示在世界里的屏幕上，玩家可以拿手柄游玩、邀请朋友加入，或站在旁边观看。

本目录是主模组源码：内置 FC/NES，同时提供电视、视频线、通用机柜、写卡工作台、控制设置及附属共用的内容和会话服务。它不只是一个模拟器核心；SFC、MD、原生街机等由可选附属增加。

第一次了解项目请看[仓库首页](../README.md)；准备试玩请直接看[玩家指南](docs/玩家指南.md)。

## 安装前需要知道

- 目标环境是 Minecraft 1.21.1、NeoForge 21.1 和 Java 21；当前最低声明为 NeoForge 21.1.229，不是 Forge 1.20.1 或其他 Minecraft 版本的安装包。
- 客户端和服务器都要安装主模组，附属按同批配套清单安装。使用原生模拟器的运行端目前以 Windows x64 为支持目标，不能从服务端能够启动推断所有平台都能运行游戏。
- 主包已经提供内部公共库，不要另装 `piq-retro-platform`。WaterFrames 是可选兼容对象，不是必装前置。
- GitHub 已有[整套测试版](https://github.com/meilian258-dotcom/game-console/releases/tag/full-test-20261007-r1)，它不是下文的新开发候选。网页的 Code → Download ZIP 是源码，不能放进 `mods`；测试版不等于稳定版，不从不同批次随意拼包。
- 不附带商业游戏 ROM 或 BIOS。请自行准备有权使用的内容，服务器上传还需服主授权。

## 先玩一台 FC

1. 准备 FC 卡带、主机、电视、视频线和老式电脑。拿卡带右键老式电脑，在工作台选择游戏并确认写入；可以按权限设置卡名、封面和保存方式。
2. 摆好主机和电视，用视频线连接两端，把写好的卡带插入主机并打开电视。
3. 右键主机的实体电源，按当前保存方式选择进度。FC76.50 起的未发布候选读取设备的 2P 许可，默认允许，不再每次询问；管理员可在关机时用螺丝刀改为禁止。旧公开测试版仍可能弹出开局询问。
4. 领取主机对应的手柄，等待游戏就绪后操作。朋友能否领取第二手柄取决于本局许可、卡带人数和端口占用。
5. 归还手柄只是退出自己的操作。需要结束游戏时正常关机，并确认适用的保存完成；不要用强退游戏代替保存。

默认 `F7` 打开控制设置；改过键后以自己的绑定为准。电视遥控器管理显示和声音，管理员用调试螺丝刀打开设备设置，用管理终端管理全服规则。

本地游戏和服务器游戏不是同一个目录。优先使用工作台的“ROM 目录”按钮；正式服务器内容位于实例根 `game-console/` 下，按机型和用途分类。不要把内部哈希文件直接改名或把旧存档搬到另一核心目录。

## 街机和多人

通用机柜由主包提供外壳、屏幕、席位和管理入口；安装相应附属后，菜单才会出现对应游戏系统。FC 原有会话和各附属的运行链并不完全相同。

- 家用机使用实体手柄；街机使用操作席和适用的投币规则，不能把两者的加入步骤互相照搬。
- 玩家音画串流由一端运行游戏，其他人接收画面和声音；JNI Netplay 由参与端运行兼容核心并同步本局。JNI、RetroArch 是运行层信息，不等于所有机器已经支持同一种联机；RetroArch 本机运行也不自动启用 Netplay。
- 已接入公共 JNI 旁观的机器可以逐台观看，受本机实例预算限制；这不代表一个玩家能同时主持任意多台机器。
- 私人模式不公开本局音画和进度。菜单中未接通、服务器禁用或运行中不可改的选项会有各自限制，不能靠换名称或解锁按钮获得能力。

## 当前状态和限制

目前仍是测试候选。源码版本见本目录 `gradle.properties`；配套关系、已验证项目与未验场景以对应交付说明为准，不凭版本号认定稳定。

FC76.54 开发候选整理设备体验：不再自动弹出运行环境页，错误改为限频的本机聊天摘要，手动诊断仍保留；新街机按真实能力选择 JNI Netplay，旧设备显式模式不改。PGM 运营设置与 SFC 存档工作台的适配、版本组合及逐项验证状态见[本批说明](design/设备体验与PGM运营设置-20261012.md)。

FC76.53 增加[公共回放接口 v1](../piq-replay-compat/API.md)，配套可选 Replay test.6。后续主包按接口合同兼容，不再要求每次小版本升级都修改 Replay 上限；最终 JAR 构建与快照发布增加合同检查。FC76.46～76.52 仍配旧 test.5。附属的旧专用适配、Iris 与 ReForgedPlay 版本仍各自核验，不代表所有未来版本已验证；本候选未安装或正式发布。

FC76.51 延续 FC76.50 的家用菜单及默认策略，修补公共 JNI 会话在追赶帧时未及时回收已确认历史的问题：容量不足时不先发送或消费输入，保留原窗口与 CRC 检查。完整 `check jar` 通过；它没有替换 SFC 核心，不能单独作为 SFC 2P 断线修复包。未修改上游核心的对照和后续接入边界见 [SFC 候选验证](../piq-sfc-home/design/SFC-JNI核心候选验证.md)。

后续方向是整个模组统一 RetroArch 后端，JNI 暂时保留兼容。当前 FC76.49／街机1.5.11 增加[街机 RetroArch Netplay 试验入口](design/RetroArch-Netplay-街机试验接入.md)：管理员在设备菜单显式选择原版 FBNeo，服务器为全局参与者固定同一后端，默认不变、旧档不迁移。隔离双人操作已跑通，但同模拟帧状态 CRC 存在差异，完整同步验收未通过；不要当作稳定版替换现用路线。此入口无需启动参数，暂不保存进度。

此前的 MAME 音画串流试用仍由 `-Dpiq.arcade.mediaBackend=retroarch` 单独控制，它不是 Netplay 开关。FC、SFC、MD、GBA 尚未迁移；Minecraft 多人和长局仍待验。首批记录保留在[统一 RetroArch 后端制作记录](design/统一RetroArch后端-20261009.md)。

公共流程、存档及旁观已被多个组件复用，但不是所有历史机器、保存格式和运行模式都统一完成。FC76.43 已修正 Iris 下公共屏幕误用加法混合通道的问题；隔离 GPU 检查通过，具体光影包仍需 Minecraft 实机验证。范围和配套见[光影与 MD 图标修复说明](design/光影透屏与MD图标修复-20261006.md)，不能据自动测试宣称全部光影兼容。
