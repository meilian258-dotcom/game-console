## ROM 使用

把你合法拥有的 `.nes` ROM 放入 `<Minecraft 游戏目录>/fc-roms/`。当前版本自动加载按文件名
排序后的第一个 ROM，关闭界面再重新打开可重新扫描。

项目、源码包和发布 JAR **不包含任何商业 ROM**，也不会通过服务端向客户端下载 ROM。
单元测试所用 NROM 由测试代码即时生成，只包含无限跳转和自行设置的中断向量。

兼容性受模拟器核心支持的 Mapper 限制。当前核心支持 Mapper 0、1、2、3、4；其他
Mapper 会在进入 WASM 前显示具体编号，不再只报告模糊的 `unreachable`。带 512 字节
iNES Trainer 的 ROM 会先移除 Trainer 再交给核心。

## 客户端、服务端与多人演进

服务端使用维度、街机锚点、机体模式和临时会话 ID 管理 P1、P2 与观众；会话不写入世界存档。

同步型在 `0.9.0` 使用低带宽输入锁步：

1. 右键后客户端只提交第一个本地 ROM 的 SHA-256；服务端不接收 ROM 内容，只允许相同哈希
   的玩家进入同一会话。
2. 客户端只在按键变化时上传 8 位状态、会话 ID、重启代次和递增序号；服务端限制每人每 Tick
   最多接受 8 个输入包。
3. 服务端每个 20 TPS Tick 广播一次 P1/P2 状态和目标帧，所有客户端各自在本地推进 3 个
   NES 帧，因此内部仍是 60 FPS，网络不发送画面或音频。
4. 新参与者加入时全员从内存重新启动，以保证没有状态快照时也能从相同帧开始；P1 可按 R
   请求全员重启。当前不支持无重启的中途加入。
5. 自动测试已验证两份相同 WASM 核心在 180 帧双手柄输入后输出逐字节一致。

云端型目前仍使用本地原型路径。后续由服务端从自己的 `fc-roms` 读取 ROM，以 60 FPS
运行核心，按受限帧率发送压缩差分画面和关键帧；不会广播约 14.7 MB/s/观看者的原始 RGBA。

## 声音和性能

- 存档：按当前需求不提供，不创建或读取 `fc-saves`。
- 声音：WASM 按帧导出 44.1 kHz `f32` APU 采样，客户端经过直流高通与限幅后转换为
  16 位小端单声道 PCM，由独立 Java Sound 线程播放。最多排队 4 个模拟帧，超限丢弃最旧音频；
  `M` 可立即静音，再次右键退出或离开有效距离会停止并清空播放。音量读取 Minecraft 主音量和
  唱片/唱片机分类。
- 性能：旧 Chicory 路径实测每帧平均 `165.321 ms`、P95 `187.166 ms`，只能达到约 6 FPS。
  改用 Wasmtime4j/Wasmtime 后，同一自生成 NROM 实测每帧平均 `2.774 ms`、P95
  `3.425 ms`，RGBA 取帧平均 `0.173 ms`。GUI 每次最多补跑 3 帧，防止掉帧后形成
  “死亡螺旋”。
- 线程：当前单人方块会话在客户端渲染帧事件中运行。加入观战或多个街机后，应使用每会话单线程执行器，
  画面通过双缓冲交给渲染线程，所有 Minecraft 世界访问仍回到对应主线程。
