# Flash 播放盒 README 历史存档

本文件汇总早期 README 的版本技术记录。它记录旧播放盒的指定主包组合和验证结果，不是当前整套方块电玩的安装指引；请先读[Flash 组件入口](README.md)。

以下为历史技术记录。

# 方块电玩：Flash 播放盒 / Game Console: Flash Box

当前原型8（FC61兼容补丁）。命名遵循[Game Console 规范](../source-control/BRANDING.md)，交付名为 `game-console-flash-版本.jar`。这是历史播放盒，不因改名扩大主包兼容范围；内部 ID、运行库路径和旧包保留。

适用版本：`0.1.0-prototype.8`，2026-09-20。仅拓宽 FC 依赖至 `[0.31.0-alpha.56,0.31.0-alpha.62)`，编译使用 FC61；Flash 自身 Java 类、模型、Mixin 和 runtime0.1.2 不变。双方主包用同一版本；有 Flash 才把双方附属换为 `game_console_flash_box-0.1.0-prototype.8.jar`。SFC 非必需。运行器安装方法与下列原型7相同，已完整安装 0.1.2 的客户端无需换运行器。

原型8需核对最终 FC61 的 API、Mixin、自身类与运行库，并将报告绑定实际交付 SHA；报告成功状态和制品身份均须匹配。不新增 Flash 联机、存档或性能功能，未完成 Minecraft 组合实测。以下记录原型7及更早版本的安装范围，不作为原型8实机结论。

## 原型7历史说明

适用版本：`0.1.0-prototype.7`，2026-09-19。独立播放盒用视频线连接现有电视；**仅供本机功能试验，不是首发正式版，也不是跨电脑双人/省流同步成品。**

原型7仅做 FC60 依赖兼容，声明支持 FC56／FC57／FC58／FC59／FC60；Flash 自身 Java 功能、Mixin、模型和运行器不变。主包的共用实现仍须逐版核对，不能把本次描述为所有依赖类逐字节未变。继续使用原型3的 `runtime/publish-0.1.2`；已经完整安装该运行器的玩家不必重新替换 runtime。下述原型3功能与限制继续适用，本补丁不新增游戏能力。FC60 组合以本节后列出的最终冻结兼容报告为准，未生成报告前不视作已经核对。

原型3重点：新增“看电视操作”，不显示大预览面板也能控制本机Flash；鼠标转视角，键盘操作小游戏并锁住MC人物移动/交互，Esc退出接管，右键回预览。画面通道改用JPEG减少捕获耗时（轻微有损压缩），保留PNG诊断路径。请同时更新本版附属JAR与配套runtime，不要混用原型1/2的helper；真实实测与限制见包内验证记录。

森林冰火人只是第一份测试样本。生产运行器按普通 SWF、键鼠输入和两组可配置键位工作，没有按游戏名写专用启动分支。其他游戏仍需逐个验证，不能据此承诺全部 Flash 兼容。

## 这一版有什么

- 新增独立播放盒，复用主模组的视频线、电视连接身份、拆线与退线账本；不更改 FC/SFC 原有实现。
- 创造模式 OP2 空手右键播放盒，打开本机 SWF 路径输入及预览界面；加载前不执行文件。
- Ruffle 真实执行 SWF；输出 640×480 画面，两个输入端口和鼠标。原型1已有光明神殿运行记录，原型2截图显示界面与电视出图，但MC接收约8FPS仍卡；不能以截图认定完整交互已通过。
- Esc只隐藏已就绪游戏的操作界面，不关闭电视会话，也不把世界里的WASD当游戏按键。右键原盒子继续操作；运行器尚未就绪时Esc取消启动。断线、失去权限、超出盒子8格、拆机拔线或切换另一台盒子停止。其他菜单/失焦/世界暂停时暂停，回到世界或本操作界面自动恢复。重新进入先松开按键才能继续输入。
- 只有明确点击“看电视操作”才接管世界按键；电视须开机且已有首帧。鼠标仍转视角，键盘两组游戏键不再移动MC人物，也不触发重叠快捷键/攻击/互动。Esc归还世界操作、游戏继续；右键回预览点游戏菜单。失焦、其他菜单或电视关机退出接管，回来需重新手动进入；不自动重新抢键。首版不在世界里用鼠标点Flash画面，没有新增实体手柄。
- 退出后仍按住的旧键/鼠标会暂时隔离到松开；若在窗口外松开，切回后可能需要把原键/鼠标再按放一次，世界画面的小提示会明确显示“已退出接管”和解除松键保护的方法。
- Java 使用 JAR 内固定的 27 项 SHA-256 校验运行器文件。它不信任用户可替换的外部清单来决定执行内容。

## 安装（先在世界副本测试）

本节只说明 Flash 组件。原型7兼容补丁仅替换附属 JAR，不重发运行器；若它随 FC60 更新包交付，主包安装以总安装说明为准。**不含游戏 SWF、ROM 或 BIOS**。

1. 客户端及服务端都使用 Minecraft 1.21.1、NeoForge 21.1.236 或兼容的 21.1 版本、方块电玩 **FC `0.31.0-alpha.56` 至 `0.31.0-alpha.60`**。双方使用同一 FC 版本；依赖范围为 `[0.31.0-alpha.56,0.31.0-alpha.61)`，不宣称兼容 FC61 或更高版本；SFC 非必需。
2. 先正常退出游戏、备份测试世界，再将 `game_console_flash_box-0.1.0-prototype.7.jar` 放入双方对应实例的 `mods`。同 MOD ID 只保留一份。**本次没有自动安装、停服或重启。**
3. 已完整安装原型3的 runtime 0.1.2 时无需替换。首次使用者请将原型3完整包的 `piq-flash-box/runtime` 整个目录放到**实际运行 SWF 的客户端游戏实例根目录**，使程序位于 `实际实例/piq-flash-box/runtime/FlashBox.Helper.exe`。不要放到 mods；不要只复制 EXE。服务端不需要此 Windows 运行器。
4. 执行端暂限 Windows x64，已有 **.NET Desktop Runtime 6** 和 **Microsoft Edge WebView2 Runtime**。本包不自带这两项系统组件、不自动下载安装。缺少时不要反复替换游戏文件；先查看本机运行器日志。现用 .NET 6 是本机原型依赖，后续正式版需迁移到受支持的运行环境，不推荐为生产服部署此技术验证版。
5. 完整重启对应测试实例后，检查模组加载日志。原型1/2已有Minecraft运行记录；沿用原型3的世界控制、JPEG传递及主包共用走线仍需在 FC60 下实机复验。遇到错误请保留日志，不用于正式世界。

两端安装依据是共同方块/物品/方块实体注册、服务端接线及菜单授权，以及客户端画面/输入实现；不是根据依赖声明的 side 猜测。只有菜单授权走服务器，本版本没有上传 SWF、输入、音画或存档的 C2S 通道。

## 怎么试

1. 使用创造模式 OP2。在方块电玩物品栏找“Flash 播放盒”，或执行 `/give @s piq_flash_box:player_box`。
2. 放置播放盒与新版桌面电视，优先同一平面、横向间隔约两格。拿视频线按现有方式连接两台设备，并打开电视电源。
3. 双手空着右键播放盒主体。在界面粘贴有权使用的 **本机 SWF 完整绝对路径**，再点“加载 SWF”。Java 入口上限 32 MiB；不能填网页、ZIP、文件夹或改后缀的 H5。
4. 点击预览中的游戏菜单进入游戏。P1 用方向键，动作键空格；P2 用 WASD，动作键左 Shift。森林第一部主要使用方向键与 W/A/D。这是**同一电脑两套按键**，不是服务器第二位玩家已经可以加入。
5. 在预览里点菜单进入关卡，再点击“看电视操作”。大预览消失，可转视角看实体电视，用上述键位操作小游戏；MC人物此时不走动。松开按键后再操作；Esc退出控制，游戏仍播放，玩家恢复移动。控制模式下右键返回预览，可继续用鼠标点游戏菜单。普通Esc/“返回看电视”只退出预览、不接管世界按键。
6. 需要结束游戏时点“停止”。超过播放盒8格、拆线/失权/断线等仍会停止；切出Minecraft或其他菜单暂停并退出世界接管，回来不自动重新抢键。没有实体手柄领取、远端席位或存档。

其他 SWF 的按键可通过客户端 `piq-flash-box/bindings.json` 映射，格式见运行器目录 `README-runtime.md`。不要为了换一款游戏修改 Flash 源码。运行器日志位于 `实际实例/piq-flash-box/logs/`。

## 已验证 / 待验证

原型1已完成：实际运行器加载森林第一部、鼠标通过菜单进入第一关、P1/P2分别移动、松键、暂停恢复及退出；光明神殿运行记录和截图显示电视收图，但界面模糊、Esc停机和稍卡。

原型3：Java新增世界输入状态和JPEG/PNG先验校验/内存解码测试；最终测试数量及冻结JAR/helper联动结果见随包 `verification.json`。不把独立运行器测试冒充Minecraft实测。状态栏“画面接收约X FPS”是Java接收图像频率，不是游戏模拟帧率或Minecraft FPS。解码器复用/显式内存缓存，不修改其他模组的全局ImageIO设置。

原型4兼容核对：Flash 实际引用的 21 个 FC／retro 类族（49 个 class，含内部类）在 FC56／FC57 JAR 中逐字节一致，两个 FC Mixin 目标签名一致；核对编译与原有32项测试结果，并比较原型3／4 JAR 条目。没有新增 Minecraft 实机或运行器性能测试结论。

原型5兼容核对：在 FC58 成品冻结后复核其公开依赖签名与两个 FC Mixin 目标；与原型4逐项比较自身 JAR 内容，运行器仍为同一 0.1.2 固定清单。共用走线变化需连同 FC58 验收，不新增 Minecraft 实测或运行器性能结论。

原型6兼容核对：只更新版本及依赖元数据，构建后比较原型5的29个自身类、全部非元数据条目和27项运行库；对最终FC59重新检查依赖类、公开／保护成员及两个Mixin目标签名。必须将成功报告绑定最终成品 SHA 才视为核对通过；元数据兼容不代表新增Minecraft实测、性能或联机结论。

原型7兼容核对：只更新版本及依赖元数据，构建后比较原型6的29个自身类、全部非元数据条目和27项原 runtime0.1.2 文件；对最终 FC60 重新检查依赖类、公开／保护成员及两个 Mixin 目标签名。成功报告必须与最终 FC／Flash SHA 一致，准备脚本或旧版报告不能替代。Minecraft组合、性能和联机结论不扩大。

前版同机PNG关卡捕获约10FPS，定位CapturePreview平均约82ms为主要耗时。原型3森林第一关15秒对照PNG约10.08、JPEG约21.17图像/秒，P95帧间隔约111.1→55.0ms；光明神殿第一关样本，最终冻结运行器PNG约9.80、JPEG约21.30图像/秒，捕获平均84.42→26.46ms。每种格式/游戏各一次稳态样本，并非受控实验室或长期性能保证。并未达到30帧，不承诺MC开光影也达到21帧。JPEG是有损压缩，不是无损像素同步；本次没有可靠输入延迟毫秒对比。具体样本/边界/最终版本见验证记录，运行器0.1.2位于 `runtime/publish-0.1.2`，旧发布目录保留。

未完成：原型3 Minecraft世界控制的进入/退出、鼠标视角/按键隔离、失焦和菜单/关电视保护、JPEG显示和最终流畅度实机复验；远端双人、完整通关、声音听感、双端确定性/网络输入同步、中途加入、快照与存档。本版不标稳定，也没有允许公开发布的含义。

## 已知限制

- 外观使用临时模型和原版材质，后续再定稿。首版没有生存合成配方或掉落表，仅创造 OP 测试。
- 视频线使用主包的共用路由。新版四种桌面电视以及两种壁挂电视已做几何调用检查；**旧款电视暂不绘制线材；贴墙并正好垂直在接口下方的摆法可能连接成功但不绘线**。先按上述桌面摆法验收，不代表已解决任意地形走线。
- 声音来自本机 WebView 系统输出，未接 Minecraft 音量/距离衰减；关电视只影响电视显示，不保证关闭运行器音频。请用“停止”结束预览。
- 截图与输入调度已分开，捕获频率以随包实测为准，目标值不等于实际游戏帧率；JPEG虽更快仍有截图/解码成本，不是省流网络协议。其他游戏和Minecraft内实际流畅度需复验。
- Flash SharedObject 进度不保留，关闭即丢失；不提供存档迁移保障。
- 外部网页请求、导航、下载和宿主脚本接口被限制，但这不是任意恶意 SWF 的安全认证。不要运行来源不明文件；依赖外网资源的游戏可能不能工作。WebView 系统组件行为不等于游戏自身资源请求。
- 快速启动后立即退出，WebView 可能短暂锁住一个空临时目录；会记录清理告警，不删除其他浏览器资料或强杀其他浏览器。
- 客户端Mixin兼容声明覆盖FC56／FC57／FC58／FC59／FC60无信号画面/提示音，并在明确世界控制时拦截原版键盘事件；不写服务器信号/NBT。FC60 必须通过上述最终冻结核对，与其他模组的快捷键需实测，升级到后续主包前须重新适配。

## 后续顺序

先验收播放盒在 MC 内能用，再做通用远端席位/输入；省流路线单列实验：固定时钟、随机、资源加载及输入顺序，比较两份隔离运行器。没有确定性证据之前，不开放所谓“本地同步正式模式”。森林冰火人之外还要增加不同 AVM/鼠标/计时特征的游戏样本。
